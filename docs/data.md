# どこに何を持つか

エージェントと denpa は同じものを両方が持ちうる。持ち主を決めておかないと、
画面と実際が食い違ったときにどちらが正しいか分からない。

**分け方は 1 つだけ。「機材の今」はエージェントに都度聞き、
「電波から読んだもの」と「後から要るもの」は denpa が自分の DB に持つ。**

エージェントは中身を読まない (NIT も SDT も EIT も読まない。[agent.md](agent.md))。
読むのは全部こちら側で、足場は `packages/arib/` (`@danything/arib`) と `src/lib/ts/` にある。

以下の設定の「チューナー」「チャンネル」は、設定の「受信」の節 (`/settings/reception#tuners`・`#channels`)。

## エージェントに都度聞くもの

denpa は写さない。聞けなければ、その部分だけ出さない。

| もの                                                     | エンドポイント                   | 使うところ                                                           |
| -------------------------------------------------------- | -------------------------------- | -------------------------------------------------------------------- |
| チューナーの空きと、いま誰が使っているか                 | `/denpa/tuners`                  | 予約の衝突解決、設定の「チューナー」                                 |
| 選局できるチャンネル (スキャンの結果)                    | `/denpa/channels`                | 局の取り込み、番組表の取得                                           |
| スキャンの結果を預ける                                   | `PUT /denpa/channels`            | チャンネルスキャン                                                   |
| 繋いである機材を書き換える                               | `PUT /denpa/tuners`              | 設定の「チューナー」                                                 |
| 放送そのもの                                             | `/denpa/stream?type=…&channel=…` | 録画、ライブ視聴、番組表の取得、ロゴ収集、チャンネルスキャン         |
| チューナーを使い始めた・離した・局が入れ替わった、の通知 | `/denpa/events` (SSE)            | 設定の「チューナー」の更新、ロゴ集めでの選局の共有、局の取り込み直し |
| スクランブルを復号させる                                 | `/denpa/decode`                  | エンコードの前の B25 の復号                                          |
| カードリーダーの状態                                     | `/denpa/card`                    | 設定の「チューナー」                                                 |

**写さない理由は、写した瞬間に嘘になるから。** チューナーの空きは秒で変わる。
チャンネル定義は「いま何を選局できるか」そのもので、写しを見せるとスキャン直後なのに
古い顔ぶれが出る。

**チューナーの使い方は 1 つしかない。** 物理チャンネルを丸ごと開くだけで、サービス単位・番組単位の
開き方は無い。局を選り分けるのも (`packages/arib/src/service-filter.ts`)、番組の切れ目を見るのも
(`packages/arib/src/eit.ts`) denpa。

## denpa が持つもの

`DENPA_DB` の SQLite。画像だけはファイル (局ロゴは `/data/logos/` の PNG、切り抜きは `ENCODED_DIR/clips/` の AVIF)。

| もの                                           | どこから                                                                                 | なぜ持つか                                                                                                                                                 |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 局 (`services`)                                | エージェントの `/denpa/channels` (元は SDT)                                              | 局が消えても、その局の録画は残る。行は消さず、直近の取り込みで見かけなかったものは画面に出さない (`currentServices`)                                       |
| 番組表 (`programs`)                            | 放送波の EIT を denpa が自分で読む                                                       | 下記                                                                                                                                                       |
| 局ロゴ                                         | 放送波の CDT / データカルーセルを denpa が自分で読む                                     | 下記                                                                                                                                                       |
| 予約・録画・ルール・設定                       | denpa 自身                                                                               | エージェントは持たない                                                                                                                                     |
| 引き継いだ録画の履歴                           | EPGStation の残っている録画 (ルールで録ったもの)・EDCB の録画済みの一覧 (引き継ぎのとき) | よそで録った回をルールがまた録らないように (下記「同じ回は最初の放送だけ」)。録画の一覧には出さない                                                        |
| 切り抜き (`clips`)                             | 観る画面・追っかけ・ライブで撮った 1 コマ                                                | 番組名・局名・字幕は撮ったときの値を写して持つ。番組表が流れても、録画を消しても残す ([library.md](library.md#切り抜き))                                   |
| ニコニコとの連携 (`niconico_link`)             | 設定の「連携」の「実況」で連携したとき (denpa-hub の中継)                                | 実況に書き込むのに要るトークン。世帯で 1 つ。暗号化して置き、鍵は DB の隣の `niconico.key` ([architecture.md](architecture.md#ニコニコとの連携-denpa-hub)) |
| 受信の記録 (`channel_reception`)               | 番組表の取得がチャンネルを開いたときの成否                                               | 放送の一覧から作った BS / CS には受信できないチャンネルも入る。その局を番組表・ライブ・ルールから外す ([下記](#bs-と-cs-は放送の一覧から作る))             |
| チャンネルの書き換えの記録 (`channel_changes`) | 放送の一覧が変わってチャンネルを書き換えたとき                                           | お知らせの 1 行に出す ([下記](#再編に付いていく))                                                                                                          |

局の内部 ID (`services.id`) は `networkId * 100000 + serviceId`。番組の ID は
`局の内部ID * 100000 + event_id`。**この作り方は変えられない。** 録画も予約も
これを参照していて、変えると過去の録画が辿れなくなる。

### 番組表を写している理由

電波に出ているのは「いま流れている番組表」だけで、放送が終われば消える。

- **予約は番組表より長生きする。** 録画が終わったあとも「何を録ったのか」は残る
- **録画に付ける名前と概要は、録ったときの値で固定したい。** 番組表は放送直前まで
  書き換わるので、後から引き直すと別の名前になることがある
- **ルールの判定と衝突解決は SQL でやる。** 数千件の番組に JOIN と索引で一気に当てる
- **チューナーが塞がっていても画面は出る。** 番組表と予約一覧は読めるべきもの

### 番組表の集め方

**番組表を持っているのが denpa なので、集め方もこちらで決められる。**

|          |                                                                |
| -------- | -------------------------------------------------------------- |
| 並列     | チューナーが空いているだけ並べる                               |
| 順番     | 番組表が薄い局から                                             |
| 打ち切り | EIT 自身が「どこまであるか」を言っているので、揃った時点で離す |
| 録画中   | 同じチャンネルなら選局を共有 (チューナーは増えない)            |

終わりの判定は `packages/arib/src/eit.ts` の `ScheduleProgress`。EIT のセクションは 8 本ずつの
セグメントに分かれ、`segment_last_section_number` が「このセグメントで実際に使っている
最後の番号」を言う。**使っていない番号は永久に来ない**ので、そこまで揃えば終わり。
「0〜last_section_number が全部」で待つと、いつまでも終わらない。

`table_id` も同じ。1 つの `table_id` が受け持つのは 4 日ぶんで、基本は `0x50` から、
詳細は `0x58` から始まる。8 日ぶんの放送なら流れてくるのは `0x50` `0x51` と
`0x58` `0x59` だけで、**`0x52`〜`0x57` は永久に来ない**。`last_table_id` まで全部を
待っていた頃は、詳細を積んでいる局が一度も「揃った」にならなかった。

**バージョン (`version_number`) も `table_id` ごとに別々**に振られるので、`table_id` ごとに持つ
(局に 1 つだと、基本と詳細を行き来するたびに数えたものを全部捨てる)。

**もう過ぎた時間帯のセグメントは流れてこない。** セグメントは 0:00 から 3 時間ずつの枠で、
`table_id` と節番号から枠の時刻が決まる (`0x50` が当日 0:00 から 4 日ぶん=32 枠、`0x51` がその次)。
「空でも先頭の 1 本は来る」として待つと必ず取り残される。実機では 14 チャンネルが全部上限の
600 秒を使い切り、欠けはどの局も 0:00 から今までの枠で、時計が進むと 1 つ増えた (電波の欠けでは
起きない現れ方)。過ぎた枠の番組は、まだ未来だった数日前に取り込んである。

「見えていない先頭は飛ばす」という時計を使わない直し方は採らない。カルーセルの途中から
読むと、まだ来ていないだけの先頭まで飛ばして `0x51` を揃ったことにし、4〜7 日先が丸ごと落ちる。

**「揃った」で閉じるのは denpa だけ** (よそは時間で打ち切る。Mirakurun もバージョンは `version[table_id]`)。
判定が間違っていると、開きっぱなしのうえ先の日ほどタイトルが埋まらない状態 (実機の TBS1 は
3〜5 日後が 0) で黙って取りこぼす。

| いつ                                 | 何を                                                                                                                                                                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 起動直後に 1 回                      | 番組表を集める。薄い局からなので数分で画面に出る                                                                                                                                                                                    |
| 30 分ごと (`EPG_COLLECT_INTERVAL`)   | 集め直すべき局を選び直す                                                                                                                                                                                                            |
| 1 分ごと (`CHANNEL_SYNC_INTERVAL`)   | 局だけを取り直す (スキャンの結果はここで届く)。BS/CS の局が無ければ放送の一覧から入れる ([チャンネルスキャン](#チャンネルスキャン)の節)                                                                                             |
| 録画している間ずっと                 | 物理チャンネルを丸ごと開いているので、その EIT も只で読める。5 分ごとに書き出し、番組表の取得がそこへ行く手間を省く。延長への追従も同じ流れから ([下記](#放送の延長に追従する))                                                     |
| 誰かがチューナーを開いたら           | その選局を共有して局ロゴを取得する。ロゴが無い/1 週間より古い/(地上波で) 小さいロゴしか無い局だけ                                                                                                                                   |
| 10 分ごと (衛星のロゴが足りないとき) | 衛星のチューナーが空いていれば、ロゴを積んだ中継を開いて待つ (分からなければ探す。ダウンロードの期間中は番組表の取得には譲らない)。読みかけは残すので、取り上げられても続きから ([logo.md](logo.md#衛星は共有だけでは揃わなかった)) |
| 録画をエンコードするとき             | CM 検出用のロゴをその録画から覚える (覚えていれば当てるついでに育てる)。チューナーは使わない ([logo.md](logo.md#cm-検出用のロゴは録ったものから覚える))                                                                             |
| スキャンが終わったら                 | 局を取り込み直して、番組表を集め直す                                                                                                                                                                                                |
| 「番組表をいますぐ集める」を押したら | 全チャンネルを、録画とライブ以外からは取り上げる優先度で (下記)                                                                                                                                                                     |

「集め直すべき局」は、番組表が 3 日先まで埋まっていない (`EPG_MIN_COVERAGE`) か
6 時間行っていない (`EPG_CHANNEL_INTERVAL`) もの。前者は再起動しても分かるので、
Pod が入れ替わっても全チャンネルを回し直さない。

**ただし行った直後は行き直さない** (`EPG_CHANNEL_RETRY`、既定 2 時間)。開いても EIT が 1 件も来ない
チャンネルが毎回上限 (`EPG_CHANNEL_TIMEOUT`) まで開きっぱなしにならないため。チューナーを使えなかった回は数えない
(録画に譲っただけの局まで休ませると番組表が古くなる)。

**番組表に出てこない局 (データ放送・ワンセグ) は「薄い」と数えない。** ほぼ全局がこれを積んでいる
地上波が、毎周回丸ごと対象になるため。

**開くのはチューナー 1 台につき 1 人**で、種別をまたいで 1 つの列を引く。種別ごとに台数ぶん並べると、
BS と CS を同時に集めたとき衛星の 2 台を二重に数え、溢れたぶんが 409 で落ちる。

### 衛星の番組表

**BS は初回だけ 1 中継で全局の基本を入れて詳細は TS ごと、CS はいつも 1 中継で取得する。**

**BS はどの中継にも他の中継ぶんの番組表 (他 TS: `0x4F` / `0x60-0x6F`) が流れている。**
普段は自 TS ぶん (`0x4E` / `0x50-0x5F`) だけ読み、他 TS ぶんは**初回だけ**読む (`packages/arib/src/eit.ts` の
`EpgReader` の `other`)。

#### 実測 (実機 / BS03:16432 / 20分)

| 何                            | セクション | 番組     | 詳細の記述子 | TS    | 局     | 最後に新しいものが来た時刻 |
| ----------------------------- | ---------- | -------- | ------------ | ----- | ------ | -------------------------- |
| `0x4E` いま/次 (自 TS)        | 6          | 6        | 18           | 1     | 3      | 3 秒                       |
| `0x4F` いま/次 (他 TS)        | 140        | 135      | 37           | 25    | 45     | 783 秒                     |
| `0x50-57` 番組表 基本 (自 TS) | 96         | 169      | 0            | 1     | 3      | 355 秒                     |
| `0x58-5F` 番組表 詳細 (自 TS) | 66         | 165      | 1003         | 1     | **1**  | 177 秒                     |
| `0x60-67` 番組表 基本 (他 TS) | 2592       | **8720** | 0            | 25    | **45** | 360 秒                     |
| `0x68-6F` 番組表 詳細 (他 TS) | 128        | 195      | 1172         | **2** | **2**  | 180 秒                     |

- **6 分までに全部出そろい、残りの 14 分は何も増えない。** 周期が長くて取りこぼしているのではない。「最後に新しいものが来た時刻」はバージョンの書き換えも数えて
  いるので、揃った時刻はこれより早い (WebTS.app は約 3 分で揃うと言う)
- **詳細は、各局が自分の中継にしか流していない。** 他 TS ぶんの詳細が来たのは 45 局中 2 局。
  番組表用の別の PID (`0x26` / `0x27`) にも何も来ていない
- 一方、中継ごとに開いて取り込んだ実機の番組表では、BS のメイン局は大半の番組に詳細が付いている
  (BS-TBS 252/268、NHK BS 192/228、WOWOW は全件)。サブチャンネル (BS朝日 2・3 など) は 0 件。
  **1 中継で済ませると BS の詳細がほぼ全部消える**
- CS は実機の番組表で詳細がほぼ全局 0 件 (中継ごとに開いていても)

#### 実測 (実機 / CS04 / 20分)

| 何                            | セクション | 番組 | 詳細の記述子 | TS  | 局  | 最後に新しいものが来た時刻 |
| ----------------------------- | ---------- | ---- | ------------ | --- | --- | -------------------------- |
| `0x50-57` 番組表 基本 (自 TS) | 305        | 716  | 0            | 1   | 5   | 178 秒                     |
| `0x60-67` 番組表 基本 (他 TS) | 2318       | 7102 | 0            | 8   | 38  | 179 秒                     |
| `0x58-5F` / `0x68-6F` 詳細    | **0**      | —    | —            | —   | —   | —                          |

**CS は番組表に詳細を流していない** (自 TS ぶんにも)。中継ごとに開いても取れるものが変わらないので、
**いつもネットワークごとに 1 中継で全局ぶんを読む** (`epg-collect.WHOLE_ONLY` / `networkSweeps`)。
約 3 分でそのネットワークの全局の基本が 7 日先まで揃う。集め直すかどうかもネットワークで 1 つの
時刻で決める (中継ごとの時刻だと、開かなかった中継が「行っていない」に見えて毎周回読み直す)。

WebTS.app はネットワークごとに 1 つの TS しか選局せず、他 TS ぶんで全局を埋めている
(Mirakurun・EDCB も同じ前提、とコメントにある)。速さを取って詳細を捨てる選び方。

**BS は両方取る。** 初回 (そのネットワークの局に番組が 1 件も無いとき) だけ、1 中継を列の先頭で
読んで全局の基本を入れ (`epg-collect.firstSweeps`)、
そのあと同じ周回の続きで中継ごとに回って詳細を足す。画面に番組が出るまでが、中継を
1 つずつ回る数十分から約 6 分になる。

- **全局読みは、来るはずの局 (DB にある局) が全部見えて揃えばすぐ閉じる** (WebTS.app・Mirakurun と同じ)。
  見かけた局が揃っただけで閉じると、まだ 1 度も来ていない局を置いていく。受信できない局が
  混ざっていて全部は見えないときは、新しい局がしばらく出てこないことを待って閉じる
  (`EPG_SWEEP_SETTLE`、既定 1 分)
- **受信できない局が残っていても、ほかの局が埋まっていれば走らない。** 毎周回 1 中継を
  塞がないため。行った直後は休ませる (`EPG_CHANNEL_RETRY`)
- 全局を読んだ中継は自 TS ぶんの詳細もそこで取れているので、続きでは回らない。
  揃わないまま上限で切れたときだけ、列の後ろへ戻して読み直す
- 初回の BS の全局読みに使う中継は、いちばん長く行っていないもの。受信できない中継に当たり続けない
- CS の全局読みに使う中継は、受信できるかをいちばん長く確かめていないもの (一度も確かめていないものが先)。
  番組の行の時刻は全局読みでネットワークの全部の中継が同じになるので、それで選ぶといつも先頭の中継ばかり開き、
  ほかの中継がずっと「確認中」のままになる。周回ごとに中継を替えるので、どの中継も順に確かめられる
- CS の全局読みが受信できなかったときは、同じ周回のうちに次の中継で読み直す (ネットワークごとに 1 回まで)。
  受信できない中継の番が来ても番組表は止まらない。どれも受信できないとき (アンテナの不調) に全部の中継は開かない
- 続きの途中で再起動すると、残りの中継は「行ったばかり」に見えるので、詳細が足されるのは
  次に集め直すとき (`EPG_CHANNEL_INTERVAL`、既定 6 時間) まで延びる
- 他 TS ぶんの番組名は詳細の無いまま入るので、ルールの探す所の「詳細」はその間 BS で
  当たらない。詳細が入れば当たり直す

#### 衛星のチャンネルの名前は中継器と TSID

衛星のチャンネルは `BS15:16625` のように中継器と TSID で呼ぶ (`satellite.ts`)。`BS15_0` のような
相対の番号は、何本入っているかが中継器ごとに違い、**無い番号を指すと復調器は先頭の TS を返す**
(断らない) ので、既知の TS の写しが出る。予告なしに詰められることもある (2025-02、TSID は変わらず番号だけが詰まった)。
TSID で呼べば写しは出ず、詰められても名前が変わらない。

`services.channel` には最後に取り込んだ名前が 1 つしか入らないので、「最後に集めた時刻」は名前ではなく局から引く
(名前で引くと、写しだった枠が永久に「一度も集めていない」ことになって周回のたびに開かれる)。

### 入れたばかりのときの「番組表をいますぐ集める」

普段の番組表の取得は低い優先度 (`epg` = 3) で開き、録画・ライブ・スキャンと、ダウンロードの期間中に衛星のロゴを当たりの中継で待つとき (4) に譲る (ふだんのロゴ (1) には勝つ)。
ただ**入れた直後は番組表が空**で、そこでスキャンが動いているといつまでも画面に何も出ない。

設定の「チャンネル」のこのボタンを押している間だけ優先度 8 で使う。録画 (10) とライブ (9) からは
取り上げず、スキャン (5) からは取り上げる。上の 2 条件も無視して全チャンネルを
薄いほうから回る (集め終えた直後に押して 1 本も回らないのでは意味が無い)。
走っている周回があれば、その回の優先度を上げる。開くのは 1 チャンネルずつなので次に開くところから
効き、仕切り直すより早い。

### 読みながら少しずつ書く

1 チャンネル (全局読みなら 1 中継) を読み終えるまで待たず、**30 秒ごとに読めたぶんを書く**
(`epg-collect.collectChannel`)。今日・明日の番組は先に流れてくるので、開いて数十秒で
番組表が埋まり始める。揃うまでの時間そのものは変わらない (実機の地上波は 1 チャンネル約 1 分)。
予約の組み直し (`settle`) は周回の終わりにまとめて 1 回。

### スキャン中に流れてきた番組表も取得する

スキャンは局情報 (NIT・SDT) が揃うまで数秒〜十数秒選局している。その間に流れてくる番組表
(いま・次と今日ぶんくらい) も読んでおき、局を DB に入れた直後に書く (`scan.ts` の `runScan`)。
**読む時間は延ばさない** (スキャンが遅くなる)。スキャンが終わった時点で番組表が空にならない
だけで、続けて走る番組表の取得が埋める。

### 消えた局の持ち物は片付ける

取り込みで見かけなかった局は、**番組表を消し、まだ始めていない予約を取り消す** (一覧から戻せる)。
残すと、選局できない局の番組が検索に引っかかり続け、予約は始まるのを待って失敗する。局の行は残す。
消すとその局の録画や過去の予約が辿れなくなる (画面から外すのは `currentServices`)。
映像の無い局 (データ放送・ワンセグ) だけは、何も紐付いていないので行ごと消す。

- **1 回見かけなかっただけでは片付けない** (`SERVICE_FORGET_AFTER`、既定 30 分)。エージェントから欠けた一覧が
  返った拍子に、現役の局の予約がまとめて取り消されないため
- **1 局も取れなかった回では何もしない。** 起動直後や不調で空が返ることがあり、「全部消えた」と
  読むと番組表が丸ごと消える

### チャンネルスキャン

**設定の「チャンネル」から実行する。** 地上波の走査は Mirakurun に合わせてある。BS と CS は総当たりせず、
放送の一覧 (NIT) から作る ([下記](#bs-と-cs-は放送の一覧から作る))。

- 地上波 13〜62ch を総当たり (「地上波 (CATV)」を選ぶと CATV の C13〜C63 も。[tuners.md](tuners.md#catv-で受ける))
- 1 チャンネル最大 30 秒。NIT と SDT が両方揃って受信できたとみなす (SDT だけでは
  どのネットワークのものか分からず、設定に書けない)。局名も SDT から `packages/arib/src/aribtext.ts` で読む
- 録るに値するサービス種別だけ残す
- **回すのは denpa。** 1 チャンネルずつエージェントに選局を依頼し、流れてきた TS を読む。
  エージェントに読ませると、ARIB の文字符号から局の選り分けまで 2 箇所に持つことになる
- チューナーの台数ぶん並べる。**録画中でも実行できる。** 選局は取り合いの決まりに従うので、
  録画中のチューナーが使われないだけ (空きが無ければ待つ。飛ばすとそのチャンネルが設定から消える)
- **途中で中断できる** (十数分かかる)。中断したときは設定を書き換えない。途中までの結果で
  上書きすると、まだ回っていない局の定義が消える

失敗は「何も来なかった」(配線・デバイス指定を疑う) と「電波は来たが NIT/SDT が揃わなかった」
(受信環境を疑う) に分け、エージェントが返した失敗理由も 1 行添える。**揃わなかった
チャンネルだけもう一度回す。** NIT は 10 秒に 1 回しか来ないので、選局が落ち着くのが遅れると
1 回も入らないことがある。

1 チャンネル読み終えたら接続ごと切る。エージェントはそれを合図に選局を畳む
([agent.md](agent.md#選局は利用者が切るまで終わらない))。畳みそこねると、以降が全部
「受信できませんでした」になる。

**探した種別だけを差し替える** (地上波だけのスキャンで全部を置き換えて BS と CS が消え、
BS の予約が録れなくなったことがある)。1 件も見つからなければ失敗として、今までの局を消さない。

見つけた顔ぶれは `PUT /denpa/channels` でエージェントに預ける。読んだのは denpa だが、
控え (`channels.json`) はエージェントが持つ。アンテナに何が映るかは機材ごとの話で、
エージェントを増やせば顔ぶれも変わるから。**局を増やすのはスキャンと放送の一覧だけ** (次の節) で、番組表を何回
集め直しても増えない。預かったエージェントは何も再起動せず、`channels` を知らせるだけ
(使っている録画も切れない)。

#### BS と CS は放送の一覧から作る

**中継器に 1 回合わせて NIT を読めば、ネットワークの全部の TS がそろう** (`satellite.ts`)。衛星の NIT には
TSID・周波数・サービスの一覧が全部の TS ぶん載っていて、BS はほかの TS の局名 (SDT[other]) も流れている。
本番の BS は、NIT が 2 秒、26 TS・39 局の名前が 10 秒でそろった (2026-11-03)。中継器を 1 つずつ当たる総当たりは
数分かかっていた。

- 最初に合わせる中継器 (入口) は規格の周波数で、BS-15・BS-1・BS-3 の順に試す (CS は CS-2・CS-4・CS-8)。
  中継器の周波数は再編でも変わらない。CATV で一部の中継器しか通らない家のために 3 つ持つ
- チャンネルの名前は中継器と TSID (`BS15:16625`)。中継器の番号は NIT の周波数から出す。4K/8K の中継器
  (BS-7・BS-17) とほかの種別の周波数は入れない
- CS はネットワークが 2 つ (6 と 7)。NIT[other] にもう片方の TS と周波数は載るが、サービスの一覧が無く、
  SDT[other] も自分のネットワークの分だけ (本番で確かめた)。なので NIT[other] の周波数から、もう片方の
  ネットワークの中継器を 1 つ開く
- **CS は NIT[other] がそろうまで待つ。** NIT[other] は NIT[actual] と別に流れてくるので、NIT[actual] と局名が
  そろったところで打ち切ると、ネットワーク 7 が丸ごと一覧から落ちる (2026-11 に起きた)。NIT[other] を読めなかったときは、
  残りの入口も開く (CS-2 と CS-4 はネットワークが違う)。NIT[other] が流れてこない家では、入口ごとに上限 (30 秒) まで待つ。
  一覧を作り直すとき・スキャン・録画が選局できなかったときだけなので、そのままにしている
- **CS は、ネットワークが欠けた一覧で置き換えない。** もう片方のネットワークを読めなかったら (チューナーが塞がっている、
  その中継器が受信できない)、そのネットワークは今のチャンネルを残し、1 時間あけて読み直す。NIT[other] に
  載っていないネットワークは、無くなったものとして残さない
- 放送に名前が無かった局は、前の控えの名前か `BS 101` のような仮の名前にする (番組表の列見出しを空にしない)
- NIT は「放送されているもの」で「その家で受信できるもの」ではない。受信できない中継器も一覧に入る (次の段落)
- 読めなかった種別は控えを書き換えない

**受信できるかは、番組表の取得のついでに確かめる** (`reception.ts`)。確かめるために選局は増やさない。
番組表の取得が中継器を開いたときの成否を `channel_reception` に残し、2 回続けて受信できず、その間に同じ種別の
ほかのチャンネルは受信できていれば「受信できない」と決める。

- 1 回の失敗では決めない (一時的な不調がある)。同じ周回の失敗は 1 回と数える (1 時間のうちの失敗)
- 失敗に数えるのは、エージェントが「選局できない」と返したときと、開けたのに上限まで待っても何も来なかったときだけ。
  チューナーの空き待ち・ほかの要求に譲ったとき・エージェントに繋がらないときは数えない
- その種別がどれも受信できなくなったときは決めない (アンテナかチューナーの問題で、チャンネルの問題ではない)
- 決めるのは BS と CS だけ。地上波はスキャンで受信できたものだけが入っているので外さない
- 受信できないチャンネルの局は、局の取り込みで見かけなかったことにする。番組表・ライブ・検索から外れ、
  しばらくすると番組と予約が片付く ([消えた局の持ち物は片付ける](#消えた局の持ち物は片付ける)と同じ)。ほかの中継器から届くその局の番組表も入れない
  (入れるとルールが録れない予約を立てる)
- 番組表の取得は受信できないチャンネルにも行き続けるので (2 時間ごと。CS は全局読みの順番が来たとき)、1 回でも受信できれば戻る
- 設定の「受信」の「チャンネル」では、局を外したチャンネルにも「受信できません」、まだ確かめていない
  衛星のチャンネルに「確認中」と出す

**スキャンしなくても、BS と CS は最初から並ぶ** (`satellite-lineup.ts`)。その種別の局が控えに無いとき、
1 分ごとの取り込みのついでに放送の一覧を読んで預ける。前のバージョンの名前 (`BS15_0`・`CS02`) が残っているときも
作り直す (エージェントが選局できない)。エージェントの一覧に無いネットワークの局が、局の表に前の名前で残っているときも
作り直し、そのネットワークを読みに行く (上の CS のネットワーク 7 が落ちた家を、上げたあとの最初の取り込みで直す)。
NIT[other] に載っていなかったネットワークは放送から無くなったものとして、起動し直すまで読みに行かない
(局の表の行は消えないので、覚えておかないと 1 時間ごとに選局し続ける)。
予約とルールは局の ID で持っているので、名前が変わっても残る。
読めなかったとき (CS でネットワークが 1 つでも読めなかったときも) は、1 時間あけて試し直す。スキャンの最中は入れない。

#### 再編に付いていく

**BS と CS は、放送の一覧が変わったらスキャンし直さずにチャンネルを書き換える** (`lineup-follow.ts`)。
市販のテレビと同じやり方で、中継器を移った局や新しい局にも付いていく。地上波は付いていかない
(地上波の NIT には自分の TS の分しか載らず、ほかの局の行き先が分からない)。

- 番組表の取得が衛星の中継器を開くたびに、最初の 20 秒だけ NIT と SDT も読む。version が前に確かめたものと
  同じなら何もしない。今の一覧と違えば、そのネットワークのチャンネルを放送の一覧で置き換える
- **同じ version の変わった一覧を、5 分以上あけて 2 回読んでから書き換える。** 放送に古い情報が混ざることがある
  (2026-08、NHK のアップリンクから古いチャンネル情報が送られ、一部の市販機で 6 局が選局できなくなった)
- 予約とルールは局の ID で持っているので、チャンネルの名前が変わっても外れない。書き換えたあとの新しい
  チャンネルは「確認中」で、受信できるかは番組表の取得が確かめる (上の段落)
- サービス ID が変わった局 (局の統合・終了と別の局の開始) は、古い局がいまの局の一覧から消え、それを指すルールは録画しなくなる。
  ルールの一覧の上に、同じチャンネルの局・同じ名前の局を候補に出し、人が選んで付け替える (`rule-remap.ts`。自動では付け替えない)
- 録画が衛星のチャンネルを選局できなかったら、入口の中継器を開いて放送の一覧を読み直す (同じ種別は 10 分に 1 回まで)。
  録画は掛け直すたびに局のチャンネルを引き直すので、書き換えたあとは新しいチャンネルで録る
- 書き換えたら、録画・番組表・ライブの上のお知らせの 1 行 (「BS のチャンネルが放送で変わったため、受信できる
  チャンネルを書き換えました (新しい局 1、終わった局 1)」) と通知の「チャンネルの変更」で知らせる。お知らせは
  設定の「受信」を開くか 24 時間たつと消える。書き換えの記録 (`channel_changes`) は 30 日で消す

**地上波は付いていかず、知らせるだけにする** (`ground-watch.ts`)。市販のテレビも「再スキャンしてください」と知らせる。

- 2 回続けて選局できず、その間にほかの地上波のチャンネルは受信できているチャンネルを知らせる
  (「T27 を続けて選局できません。周波数が変わった場合は、地上波をスキャンし直すと選局できます」)。局は外さない
- 番組表の取得が地上波のチャンネルを開いたときに SDT も読み、そのチャンネルの局 (テレビ) をスキャンの結果と比べる。違えば知らせる
  (スキャンと同じ SDT で比べる。知らせたことは覚えておかないので、再起動すると次に読むまで出ず、続いている通知は 1 度送り直す)
  (「T16 の局が、受信できるチャンネルと違います。地上波をスキャンし直すと、新しい局を選局できます」)
- お知らせの 1 行は BS・CS の書き換えと同じ場所に出し (書き換えのほうが先)、起きたときに通知の「チャンネルの変更」も送る。
  スキャンし直すか、受信できるようになれば消える

### 時刻合わせ (TDT / TOT) は持たない

放送波の時刻 (TDT / TOT) と自分の時計を突き合わせる作りのものもあるが、denpa は**やらない**。
録画の開始と終了は壁の時計で決めていて、ライブの「放送から N 秒」も PCR とサーバの時計で出す
(TDT は局ごとに固定でずれているため。[stream.md](stream.md#遅延は2つある))。大事なのはホストの時刻で、そちらは NTP の仕事。

### 通知はエージェントから来る

エージェントは起きたことを `GET /denpa/events` (SSE) で流している。

| イベント   | denpa の使い道                                                     |
| ---------- | ------------------------------------------------------------------ |
| `tuners`   | 設定の「チューナー」を更新する。開いた選局を共有してロゴを取得する |
| `channels` | 局が入れ替わった。取り込み直して番組表も集め直す                   |

スキャンの進み具合はここに乗らない (回しているのは denpa 自身なので、自分の画面へ直接流す)。
途切れたら繋ぎ直す。黙って止まることもあるので、**定期実行を保険に残してある**。

**黙っている間もエージェントは 30 秒ごとにコメント行 (`: keep-alive`) を流し、繋いだ時点で
ヘッダも送る。** これが無かった頃は最初の通知まで 1 バイトも来ず、Bun の `fetch` が黙った接続を
5 分で切るので、深夜に選局が 5 分止まると「チューナーに繋がりません」→「繋がりました」が
1 時間おきに鳴っていた。

### 自動予約は「番組表に当て直す」

**ルールから作った予約は、足すだけでなく外れたものを消す。** 番組表を取り込み直す
たびに当て直す。

**消すのであって「取り消し」にはしない。** 取り消しは*人が押したこと*の記録で、ルールはそれを
二度と作り直さない。番組表が動いただけのものを取り消しにすると、条件に戻っても永久に立たない。

**取り消しは放送単位で効く** (物理チャンネル・タイトル・開始時刻 ±10 分。`rules.ts` の
`canceledBroadcasts`)。番組 id だけで当てていた頃は、枝番違い (23608 / 23609) や別の event_id で
載り直した回が立ち直って録れていた。ルールを消すと取り消しの記録も消す。

**手違いで消すほうが、余分に録るより高くつく。** 次のものは引っ込めない。

- 手動の予約と、録り始めたもの
- 番組表からその番組ごと消えているときと、タイトルが空の番組。「条件から外れた」のか
  「まだ読めていない」のか区別が付かない (タイトルが空は実機で 23,000 件中 11,000 件)
- もうすぐ始まるもの (`RULE_RETRACT_GRACE`、既定 1 時間)。番組表は直前まで書き換わる
  ([新] が付く、サブタイトルが入る、誤字が直る) ので、その拍子に外れても録っておく。
  ただし**ルールごと消された/止められたぶんは直前でも引っ込める** (人が押した結果なので)

**ルールを足したときは、そのルールしか見ない。** 新しいルールは他の予約を外せないので、
全ルール × 全番組 (実機で 318 × 25,608) を回し直す理由が無い。

#### 枝番の局で同じ放送は 1 本だけ録る

局は分割放送のために枝番を持つ (TOKYO MX なら 23608 / 23609。SDT の名前はどちらも
「TOKYO MX1」)。分割していない間は同じ回が両方に載り、実機ではルールが両方に当たって 2 本録れ、
**2 つのエンコードが同じ名前のファイルへ同時に書いて中身が壊れた** (片方は `ENOENT`、残ったほうは
復号で 145 行のエラー。再エンコードすると 0 行)。

そこで同じ物理チャンネル・同じ時刻・同じタイトルなら同じ放送とみなし、枝番の小さいほうだけを
予約する (中身が違えばタイトルが違うので両方残る)。番組表が空の枝番を隠す `airing` では足りない。
あちらは番組が 1 つも無い局を落とすだけで、中身の入った写しは隠せない。

#### 時間帯と曜日は番組の始まる時刻を日本時間で見る

ルールの時間帯と曜日 (`rules.time_from` / `time_to` / `weekdays`。決め方は `#lib/rule-time.ts`、当てるのは
`rules.missOf` の 1 か所)。

- **見るのは始まる時刻だけ。** 19:00〜20:00 なら 19:30 に始まる 2 時間の番組は入り、18:50 に始まって 19 時台に
  かかる番組は入らない。EPGStation も始まる時刻の「時」で見ていたので、移したルールが同じように当たる
- 時間帯は 0:00 からの分で持ち、`time_from` 以上 `time_to` 未満。`time_from > time_to` は日をまたぐ
  (23:00〜02:00)。同じ値は 0 分とも 24 時間とも読めるので、保存のときに断る。両方 NULL はいつでも
- **曜日は始まる時刻の暦の曜日。** 日をまたぐ時間帯でも曜日を前の日に寄せない。「金 23:00〜02:00」は
  金曜の 23 時台と金曜の 0〜2 時に始まる番組で、土曜の 1 時は入らない。深夜アニメの「金曜 25 時」は
  土曜を選ぶ。EPGStation と同じ決め方 (`week` は番組の始まる日の曜日) なので、移したルールの当たり方が変わらない
- 日本時間はサーバの TZ に頼らず +9 時間で出す (日本には夏時間が無い)
- **時間帯と曜日は絞り込みで、それだけでは条件にならない。** キーワード・局・ジャンルのどれかが要る
  (「平日 19 時台 全局」はその時間の全局の番組を録ってディスクを埋める)。無いルールは今までどおり当てず、
  下見の理由も「条件なし」。引き継ぎで時間帯や曜日だけのルールが来ても飛ばす

#### 同じ回は最初の放送だけ録る

ルールの「同じ回は最初の放送だけ録る」(`rules.dedupe`、`episode.firstAirings`)。`[新]` のような
ゆるい条件では、同じ回が局を替えて何度も流れる (MX → BS11 → 地方局、地上波と BS の同時放送)。

- **同じ回** = シリーズ + 話数 + 副題 (`episode.episodeOf` / `sameEpisode`)。話数は `#12` `第12話` のほか
  `Chapter 15` `Episode.2` `EP108` も読む (`Season 2` `Part 2` `Vol.3` は読まない)。
  `第2期` `第2クール` のような期と、`「東京リベンジャーズ」三天戦争編` の先頭の鍵括弧に続く編の名前は、
  話数ではなくシリーズの側に入る (`parseTitle` の `arc`)。編がどちらにも書いてあって違えば別の回
- **副題を出さない局もある** (`東京リベンジャーズ 三天戦争編▼第52話` と、同じ回に副題を付ける局)。
  片方に副題が無ければシリーズ名が同じものを同じ回とみる。編を書かない局 (`東京リベンジャーズ #51`) も、
  作品名が同じなら同じシリーズ。ただし**相手が 1 つに決まるときだけ**束ねる。`X #5` に副題の違う
  `X #5「A」` と `X #5「B」` の両方が当たるなら、どちらにも寄せない (取り違えて録り逃すより、1 本多く録る)。
  **期 (`第2期`) は書かないものと束ねない**。`X #1` は期を書かない 1 期の回かもしれないので、`X 第2期 #1` とは別の回
- **タイトルに話数も副題も無ければ、概要 (無ければ詳細) から読む**。`#18「月下の花」` `第十八話「…」`
  `Chapter 15「…」` の形式。タイトルは「薬屋のひとりごと FRIDAY ANIME NIGHT」のような飾りだけで、話数は概要にしか
  無い局がある。括弧の無い話数は行の先頭のものだけ (地の文の「第 3 話から登場」は読まない)。続きが短く文になって
  いない 1 行 (`Chapter 15 百足坑道の主`) なら副題として読む。「前回」「次回」と同じ文の話数も読まない。
  録画済みの回も、録画が持つタイトル・概要・詳細から同じに読む
- **タイトルに話数だけあれば、副題は概要から足す** (話数がタイトルと同じときだけ)。話数の後ろの `◆枠の名前`
  `▼出演者` も副題とは限らないので、概要に副題があればそちらを使う。こうして足した副題・括弧の無い副題・
  印の後ろは**確かでない副題**で、揃えば同じ回の決め手 (飾りの違う局とも束ねる) にするが、食い違っても
  別の回にはしない (足す前と同じく、副題の無いものとして見る)
- **副題の後ろの `【…】` は枠の名前として副題に入れない**。TBS は `#30「副題」【アガルアニメ】`、BS日テレは
  `第30話　副題` のように、同じ回でも枠の名前と括弧の有無が違う。入れると副題が食い違い、別の回として録る
- **シリーズ名は局ごとの飾りを許す**。先頭の「アニメ」、後ろの枠の名前、`＜…＞` `【…】` は局で違う。
  飾りを並べて消すのではなく、片方の芯 (いちばん長い語) がもう片方に入っていれば同じシリーズとみる。
  これは**副題まで揃うときだけ** (芯が 3 文字以上のとき)。話数だけで緩めると、1 期の再放送と「X 2」の同じ話数がくっつく。
  BS朝日の先頭の `アニメA・` (と `ドラマ・`)、BS日テレの先頭の `アニメ　` は枠の名前として外して比べる。テレ朝は同じ回に副題を出さず
  `【ヌマニメーション】` を付けるので、外さないとシリーズ名も副題も揃わない。「・」で始まる先頭の飾りはほかにも多い
  (`新・` `続・` `ザ・`) ので、外すのはこれだけ
- **話数と概要 (30 文字以上) がぴったり同じなら、タイトルの飾りや副題の有無が違っても同じ回**
  (`ロンブー亮の… #42` と `【釣りの日SP】ロンブー亮の… #42`)。シリーズ名は同じか片方がもう片方をそっくり
  含むものだけ (曜日ごとの枠 `… Monday #4` / `… Tuesday #4` は同じ番組紹介を持つ)。確かな副題が食い違うもの、
  シリーズ名の数字が違うもの (`汚職特捜班 5 #6` / `6 #6`) は別の回。**話数の違う回にも出てくる概要は
  番組紹介とみて使わない** (見比べる放送と録画の中で。数字を除いて比べるので「エピソード 6」+ 番組紹介 も弾く)
- **放送が話数を言っていれば、それを先に使う** (シリーズ記述子。[下記](#シリーズ記述子の話数と再放送の印))。局が回として送っている値なので、
  タイトルや概要の書き方を読むより確か。記述子を載せない局・予約・引き継いだ履歴は、タイトルと概要から読んだものどうしで突き合わせる
- **話数も副題も無い番組は時刻をまたいで束ねない** (毎日の「ニュース」が初回しか録れなくなる)。
  同じ時刻に同じタイトルが流れる同時放送だけ束ねる。タイトルが「X 第2期」だけのものもここに入る
  (概要に話数があればそちらで見る)
- いちばん早い放送を録る。**それと重なる放送があれば字幕付き (`[字]` / 🈑) → 衛星** の順で選ぶ
- **選んだ放送がチューナー不足で弾かれていたら** (予約が `conflict`)、次の放送も立てる。
  当て直すのは番組表が動いたときなので、立つのは次の当て直しから
- **録ってある回は立てない** (直近 30 日の録画。失敗したものは数えない。再放送は録り直す好機)。
  これが無いと、最初の放送を録り終えて番組表の「これから」から抜けた途端、次の再放送が
  「いちばん早い放送」に繰り上がる。EPGStation や EDCB から引き継いだ録画の履歴 (`recorded_history`。
  [migrate.md](migrate.md#録画の履歴)) も録ってある回として見る。こちらは期間で切らない
  (引き継いだときから増えないので重くならず、引き継いだあとの一挙放送は何か月も先のことがある)。
  履歴はタイトルしか持たないので、回はタイトルだけから読む
- **録り始めにもう一度見る** (`rules.duplicateAtStart`)。局によっては話数を放送の直前の EIT[p/f] にしか載せない。
  実機の BS日テレは、数日前の番組表ではタイトルにも概要にも話数が無く (詳細はシリーズのあらすじで、シリーズ記述子も無い)、
  放送の直前の p/f の概要に「第5話　副題」が入る。予約の時点では同じ回と分からず、MX の `＃６` と両方を録っていた。
  そこで録画は、録り始めてからその番組の p/f を待ち (最初の塊から最大 15 秒。`pf-event.PF_WAIT`)、番組表の行と録画の行の
  タイトル・概要・詳細・シリーズ記述子を書き直す (空では塗り潰さない)。そのうえでこのスイッチのルールの予約なら、
  予約を立てるときと同じ判定を録ってある回に当て直し、同じ回なら録画をやめてチューナーを返す。書いた数秒ぶんのファイルと
  録画の行は消し、予約は「録画しない」(`skipped`) にして「同じ回を TOKYO MX1 で録画済みなので録画しません」の理由を持たせる。
  録り始めた時刻は残すので、スケジューラはもう一度録り始めない (手で予約し直せば録る)
  - 相手にする録画は、これより先に録り始めたもの (録画中も入る)。同時に始まった同じ回が、互いを録ってある回とみて両方やめないため
  - p/f が届かないとき、書き直しても回が読めないときは録る (EIT が来ないせいで録り逃さない)。手動の予約と、
    入れていないルールも当たる番組は見直さない
  - 書き直した録画の行は、あとの放送と突き合わせるときにも使う。BS が先に流れれば BS を録り、その録画が p/f の
    「第6話」を持つので、あとの MX の `＃６` は予約の時点で外れる
  - 開始マージン (既定 10 秒) より長く待つことがあるので、番組の冒頭に入ってからやめることもある
  - 開始の通知 (`recording.started`) は見直したあとに送る。やめた録画には送らない
- 外した放送にもう予約が立っていれば、条件から外れたときと同じ扱いで引っ込める (同じ猶予)。
  最初の放送の取り合いが解消して次の放送が要らなくなったときも同じで、直前 (猶予の内) なら残す
- 見比べるのは**入れたルールが当たった放送どうし**。予約を受け持つのは先に当たったルールだが、
  それが入れていないルールでも比べる相手に入る (そこで録るなら、それが最初の放送)。
  外した放送に入れていないルールも当たっていれば、そちらが受け持って録る
- 手動で別の局の同じ回を予約してあっても、
  ルールはいちばん早い放送をもう 1 本立てる (1 番組 1 予約なので、同じ放送が 2 本になることはない)
- 更新で「同じ回は…」が送られてこなければ今の値のまま (編集画面は必ず送る。入れていない
  ルールが別の経路からの更新で黙って変わらないように)

**列を足す前のルールは 0 (入れない)**。黙って振る舞いを変えない。画面で新しく作るルールは
入った状態で始まる。

#### 前の回は録らない

ルールの「前の回は録らない」(`rules.skip_earlier`、`episode.earlierAirings`)。途中の回から追い始めた
シリーズ (EPGStation から移ってきたときなど) で、前の回の一挙放送や再放送を録らない。

- 同じシリーズで、**その放送より前に始まる録った回・予約した回のうち、いちばん大きい話数より小さい**
  話数の放送は立てない。相手は録った回、引き継いだ履歴、立っている予約 (`scheduled`)、
  入れたルールが当たった放送。録らない予約・放送 (チューナー不足・コピー禁止) は相手にしない。**録った回は期間で切らない** (失敗は除き、消したものは行が残っている間
  入る)。1 期を数か月前に録り終え、2 期の頃に別の局で 1 期が流れるのを外すため。全部は読まず、当たった放送の
  シリーズ名 (`recordings.series`。索引あり) で引く
- **その放送より前に始まるものだけ比べる。** 番組表には来週の回も載っているので、時刻を見ないと
  今週の 5 話が来週の 6 話のせいで録れなくなる。そのため、4 話より**前に**流れる 1〜3 話の一挙放送は外さない
  (EPGStation や EDCB で録っていれば、上の「同じ回」が引き継いだ履歴で外す)
- **シリーズは名前がぴったり同じもの** (`Episode.series`。編・期まで含む)。二期や、編ごとに 1 話から数え直す
  番組 (`X 〇〇編 #1`) は前の回にしない。名前の違う局どうしも比べない (録る側に倒す)
- 話数の読めない放送は外さない。話数の読めない回は相手にもならない
- 外したあとの扱い (引っ込める・入れていないルールが受け持つ・更新で送られてこなければ今の値) は
  「同じ回は最初の放送だけ」と同じ。下見の行には「前の回」と出る

**新しく作るルールも切った状態で始まる** (列を足す前のルールも 0)。番組名が同じまま 1 話から数え直す
シリーズ (毎年の新シーズンを同じ名前で流すものなど) を黙って飛ばさないため。

### コピー禁止の番組は録らない

市販のレコーダーに揃えて、**コピー禁止の番組は録りません** ([Discussion #760](https://github.com/danything/denpa/discussions/760))。
見るのは**デジタルコピー制御記述子** (0xC1) の先頭 2 ビット (digital_recording_control_data) で、
`11` がコピー禁止 (`00` コピー可・`01` 事業者定義・`10` 1 世代のみ)。1 世代のみは今までどおり録ります。
記述子は EIT の番組ごとと PMT に入ります。実機で調べた限り、いまの地上波・BS (WOWOW を含む) に
コピー禁止の番組はありません。

- **番組表に持つ** (`programs.copy_never`)。EIT の基本の表 (と p/f) から読む。詳細の表には
  記述子が載らないので、詳細だけ届いた回で印を外さない (`EitEvent.copyNever` が `null` = 言っていない)
- **予約の時点で止める。** ルールが立てた予約は「録画しない」(`skipped`) になり、理由
  (「コピー禁止の番組なので録画しません」) を持って録画の一覧の予約の側に出る。チューナーの割り振りには入れない。
  番組表で禁止でなくなればふつうの予約に戻る (`scheduler.resolveConflicts`)。放送が終わっても
  「録画しない」のまま理由ごと残し、録り逃し (`missed`) にはしない。意図して録らなかったものを失敗に
  見せないため。録り逃しの一覧・件数には入らず、録画の一覧 (`/`) の「完了した予約も表示」で見られる (2 週間で片付く)。手で予約しようとしたもの (番組表・ライブの録画ボタン・アプリの API) は
  同じ一文で断る。「同じ回は最初の放送だけ」のルールは、禁止の放送を弾かれたものと同じに扱い、
  禁止でない次の放送を録る
- **録り始めてからも PMT を見る** (番組表が古い・無いときの備え)。禁止のあいだは保存しない。
  本編を書く前に禁止なら (開始マージンで前の番組のぶんを書いていても) 録画をやめてチューナーを返し、録画は「コピー禁止の番組なので
  録画しませんでした」で失敗になる。本編の途中で禁止に変わったときは止めず、そこまでのぶんを残して
  禁止のあいだだけ書かない (戻れば続きを書く)
- **観るのはそのまま。** ライブは保存しないので、禁止の番組もふだんどおり観られる。
  ライブを止めたり戻したりできるのはブラウザが持っている数分ぶん ([stream.md](stream.md#追っかけ再生とライブは別物)) で、
  これも今は変えていない。コンテント利用記述子 (0xDE) の「一時蓄積」は扱っていない。
  録画中の録画を先頭から観る追っかけ (`/chase/<id>`) は録画のファイルを読むので、禁止の番組には出ない

### シリーズ記述子の話数と再放送の印

EIT の番組ごとに**シリーズ記述子** (0xD5、ARIB STD-B10 第 2 部) を載せる局がある。どの局が載せるかは
実機で確かめていない。読むのは `packages/arib/src/eit.ts` (`EitSeries`)。

| 項目                | 持つ列                | 扱い                                                                                                                         |
| ------------------- | --------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| series_id           | `series_id`           | **局の中でだけ決まる番号。** 別の局の同じ番号は別のシリーズなので、比べるときは局と組にする                                  |
| repeat_label        | `series_repeat`       | 0 はオリジナル。それ以外はオリジナルと期間の重なる再放送。**0 でも初回とは言えない** (重ならない再放送は 0 で来ることがある) |
| episode_number      | `series_episode`      | 何話目か。0 (決まっていない) は NULL                                                                                         |
| last_episode_number | `series_last_episode` | 全何話か。0 (分からない) は NULL                                                                                             |
| series_name_char    | `series_name`         | シリーズ名                                                                                                                   |
| program_pattern     | 持たない              | 編成の型 (不定期・帯・週 1 回・月 1 回・同じ日に何話か・長い番組を分けたもの)。読むが使っていない                            |
| expire_date         | 持たない              | シリーズの有効期限。読まない                                                                                                 |

- **番組表に持つ** (`programs.series_*`)。記述子は基本の表 (と p/f) に載り、詳細の表には載らないので、
  詳細だけ届いた回では前のまま (`EitEvent.series` の項目ごと無い = 言っていない)。基本の表が載せずに来たら外す
- **録画に写す** (`recordings` の `series_episode` `series_last_episode` `series_repeat`)。番組表の行は 24 時間で消える
- **番組の詳細に出す。** 「第 3 話 (全 12 話)」、全何話と同じなら「第 12 話・最終回」、再放送の印が 0 でなければ「再放送」
  (`arib.seriesLabels`)
- **同じ回の見分けでは、タイトルや概要の話数より先に使う** ([上記](#同じ回は最初の放送だけ--新-で当てると同じ回が何度も来る))。
  載せる局と載せない局で話数の数え方が違えば (シリーズ通しとクールごと)、その間では同じ回と見なされないことがある
- シリーズでルールを当てる (「このシリーズを全部録る」) のはまだ無い

### Gガイドは使わない

市販のテレビの番組表に出る番組の画像を取れないかと、放送の Gガイド (株式会社 IPG の番組表のサービス) を調べた (2026-10-31)。
**放送で届く Gガイドに画像は無く、EIT と同じ種類の文字の番組表なので、使わない。**

- **届き方。** BS は 768ch (BS-TBS と同じ中継 `BS01:16401`)、地上波はデータ放送の 1 サービス (主に JNN 系列)。普通のデータカルーセル (DSM-CC) で、
  中のファイルは MIME の宣言が無い独自の形式 (仕様は公開されていない)
- **中身。** 本番で 1 周ぶん受けて、ファイルの名前・大きさ・先頭の数バイトと、画像の印・URL の有無だけを数えた (中身は写していない)。
  約 100〜140 個で合わせて約 1.25MB、日ごとの大きいもの (`SI11`〜`SI81`、30〜115KB) が番組表。
  PNG・JPEG・GIF の印も、`http://`・`https://` も、画像の拡張子も無い。**外から画像を取る先も放送では送っていない**
- **テレビの画像はネットから。** ネットに繋いだテレビがメーカーや IPG のサーバに問い合わせていると見られる。
  Web サイト (bangumi.org) の利用規約は自動での収集と、似たサービスを作ることを禁じている
- EIT より先 (約 9 日) まであるのが違いだが、独自の形式を読むほどの価値は無い。
  番組表に画像を出すなら、録ったポスターを同じ番組の次の回に流用するのが現実的 (まだ作っていない)

### 放送の延長に追従する

番組表の時刻は予定で、野球が延びれば後ろもずれる。追従の元は録画中の TS に流れている
**EIT[p/f]** (いまと次の番組) で、EIT[schedule] と違って実際の放送に合わせて書き換わる。
問い合わせる相手が要らないので、同時録画の本数にも響かない。

1. 録画は物理チャンネルを丸ごと開き、`ServiceFilter` でその局だけを書き出す
2. 同じ TS の EIT[p/f] で、「放送中」の番組が録画中のもの (event_id 一致) なら終了時刻を見る。
   `running_status` が全部 0 (未定義) の局があるので、そのときは節の番号で決める (section 0 が現在。`packages/arib/src/eit.ts`)
3. 後ろへ動いていたら予約と録画の終了時刻も動かす (動かさないとスケジューラが元の時刻で止める)。
   前へ動いても縮めない。まだ流れているのに切ると取り返しがつかない

EIT[p/f] を流さない局でも、番組表の時刻どおりには録れる。

**ライブで観ている局も同じ元で追う** (`server/live.ts` → `epg.followOnAir`)。開いている TS の
EIT[p/f] (いまと次) が番組表と違えば番組表に写し、`programs` の通知を出す。ライブの画面と
テレビのアプリはこれで読み直すので、延長・繰り下げ・差し替えでも出ている番組が放送とずれない。
写すのは番組表と食い違ったときだけ (p/f は数秒おきに来るが、ふだんは同じものが繰り返されるだけ)。
観ていない局は放送を読んでいないので、画面は番組表の予定の終わりで読み直す。

**残っている穴**: 競合の計算は録画中のものも (延びた終わりまで) 数えるが、延びた時点では計算し直さない。
次に計算し直す (番組表の取り込み・予約やルールの変更) までは、後ろの予約は前の割り振りのまま。
同じ物理チャンネルなら選局を共有するので実害は無いが、別チャンネルでチューナーが埋まっていると後続が録れないことがある。

## 消えないものは置かない

DB に残り続けるものには必ず期限を切る。1 台のサーバで何年も動かすので、
放っておくと一覧が伸びて探すのが遅くなる。

| もの                                                           | いつ消えるか                                                                                                        |
| -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 番組表 (`programs`)                                            | 終わってから 1 日                                                                                                   |
| 終わった予約                                                   | 2 週間 (取り消し・録り逃し・録画しないか、もう録り始めたもの)                                                       |
| 削除済みの録画の行                                             | 同上                                                                                                                |
| CM 検出の材料 (`cm_materials`)                                 | 録画の行と一緒に                                                                                                    |
| エンコードの記録                                               | 同上。ただし録画ごとに最新の 1 件は残す (一覧の状態表示がそれを見ている)                                            |
| 局 (`services`)                                                | 消さない。画面から外す (上記)。映像の無い局だけは行ごと消す                                                         |
| ログインの控え (`sessions`)・ペアリングコード (`device_codes`) | 期限が来たら                                                                                                        |
| アプリに渡したアクセストークン (`api_tokens`)                  | 消さない。取り消しても `revoked_at` を付けて残す (いつ・誰が許したかを設定画面に出すため。端末の数だけしか増えない) |
| ルール・設定・局ロゴ・通知先                                   | 消さない (ユーザーが入れたもの)                                                                                     |
| 切り抜き (`clips`)                                             | 自動では消さない (人が撮ったもの。画面で消す)                                                                       |
| 引き継いだ録画の履歴 (`recorded_history`)                      | 消さない。引き継いだときから増えない (EPGStation・EDCB が残していたぶんだけ)                                        |
| ニコニコとの連携 (`niconico_link`)                             | 外すまで消さない。行は多くて 1 つ (連携が切れたらトークンだけ消して `lost_at` を付ける)                             |
| 受信の記録 (`channel_reception`)                               | 控えからそのチャンネルが消えたら                                                                                    |
| チャンネルの書き換えの記録 (`channel_changes`)                 | 30 日たったら                                                                                                       |

## この分け方で困るところ

- **チャンネルの顔ぶれだけは両方が持っている。** denpa の `services` (前回の取り込み
  時点) とエージェントの `channels` (いまのスキャン結果) は、取り込むまでの間だけ食い違う。
  スキャンが終わったその場で取り込む (`scan.ts`) ので、設定の「チャンネル」は denpa の側だけを出す
- **番組表を持っているので、集め直すまでは古い番組が残る** (終わった番組は `pruneOldPrograms` が 1 日で消す)
