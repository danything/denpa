# EPGStation からの引き継ぎ

**録画・録画の履歴・ルール・手動予約を、EPGStation から denpa へ移します。** 設定画面から実行し、
何度走らせても二重にはなりません (録画・履歴・ルールは取り込み済みを飛ばす。手動予約は予約し直す。下記)。

環境変数の一覧は [config.md](config.md)、保存先の構成は [library.md](library.md)。

## 先に用意するもの

**次の2つが見えていないと実行できません。**

| 何を                                                                                                                  | どうやって                                               | 変数                                                    |
| --------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------- |
| EPGStation の録画置き場                                                                                               | その PVC (かディレクトリ) を denpa の Pod にマウントする | `EPGSTATION_RECORDED_DIR` (既定 `/epgstation-recorded`) |
| EPGStation v2 の MariaDB (`recorded`・`video_file`・`channel` / `recorded_history` / `rule` / `reserve`。v1 は見ない) | denpa から届くところに置く。読むだけ                     | `EPGSTATION_DB_*` (既定は [config.md](config.md))       |

録画置き場が見えていないと、設定は実行の欄を出しません (`migrate.available`)。「引き継ぎ元 ○○ が
見つかりません」と出ていれば、まだマウントできていません。**`charts/` にも `compose.prod.yml` にも
雛形は入れていません。** 1回きりで外すものなので、手元の EPGStation に合わせて足してください。

## やり方

**先に番組表を集めておきます。** 空のまま走らせると手動予約だけ入りません (下記)。

1. 設定の「連携」の「EPGStation からの引き継ぎ」 (`/settings/integrations#migrate`)
2. **「取り込む」を外したまま実行する。** 何が入るかを出すだけで、ファイルも
   データベースも触りません。件数と、飛ばされるものの理由がログに出ます
3. 問題なければ「取り込む」を入れてもう一度実行する

数百GBのコピーになるので、開始だけ受けて裏で進みます。進み具合は同じ節に出ます。

**既定はコピーです。** 元が残るので、中身を確かめてから EPGStation 側を消せます。
空き容量が足りないときだけ「コピーではなく移動する」を入れてください。

## 何が入って、何が入らないか

**順番は録画の履歴 → ルール → 手動予約 → 録画**です。いちばん長い録画のコピーを最後にするので、
途中で止めても予約は動き出します。

### 録画の履歴 (`recorded_history`)

EPGStation は録画を消しても、**ルールで録った番組の名前・局・終わりの時刻**を履歴に残しています
(既定で 90 日。向こうの `recordedHistoryRetentionPeriodDays`)。これを「録ったことのある回」として移すので、
ルールの「同じ回は最初の放送だけ」が EPGStation で録った回を録り直しません。4話から追っている
ところへ1〜3話の一挙放送が来ても、履歴に残っていれば録りません ([data.md](data.md#同じ回は最初の放送だけ--新-で当てると同じ回が何度も来る))。

- **効くのは「同じ回は最初の放送だけ」を入れたルールだけです。** EPGStation で「重複を避ける」にしていたルールは、入れた状態で取り込みます (下記)。
  「前の回は録らない」も履歴を相手にします
- 録画にはしません。録画の一覧や番組表には出ず、ルールが見るだけです (`recorded_history`)
- ルールより先に入れます。ルールが当たり出したときに、もう録った回を予約しないように
- 回はタイトルだけから読みます (履歴は概要を持たない)。二期 (`第2期`) は別のシリーズのままです
- 取り込み済みは `source` の `epgstation:<id>` で見分けて飛ばします (ルールと同じ)
- 表が無ければ (古い版など) ログに残して先へ進みます
- 手で録ったものや時刻指定のものは、EPGStation が履歴に残さないので入りません

### ルール (`rule`)

キーワード・除外キーワード・キーワードを当てる範囲 (番組名・説明・詳細説明)・種別 (GR/BS/CS/SKY)・
局・ジャンル・時間帯と曜日・有効かを移します。当てる範囲も引き継ぐのは、denpa の既定に寄せると説明まで
見ていたルールが黙って当たらなくなるためです。名前はキーワードをそのまま使い、空なら
`EPGStation #<id>` になります。

- 時刻指定のルールは入りません (denpa に当たるものが無い)
- 時間帯と曜日 (`times`) はルールの時間帯と曜日に写します。向こうの `start` (時) から `range` 時間ぶんが
  `start:00`〜`(start + range):00` に (23 時から 3 時間なら 23:00〜02:00)、`week` のビット (日曜 0x01〜土曜 0x40) が曜日になります。
  どちらも番組の始まる時刻で、曜日は始まる日で見るので、当たり方は変わりません ([data.md](data.md#時間帯と曜日--番組の始まる時刻を日本時間で見る))。
  denpa のルールは時間帯を1つしか持てないので、時刻の違う時間帯を2つ以上持つルールは飛ばします (時刻の同じものは曜日をまとめます)
- 「同じ回は最初の放送だけ録る」は、EPGStation の「重複を避ける」(`avoidDuplicate`) をそのまま写します。
  引き継いだ録画の履歴と合わせて、EPGStation で録っていた回を引き続き避けます。避ける期間 (`periodToAvoidDuplicate`) は
  写しません (denpa は直近の録画と引き継いだ履歴で見る)。「前の回は録らない」はオフで入ります
  (要るルールは、ルールの一覧で行を押して検索の画面で入れてください)
- キーワード・局・ジャンル・種別がどれも空のルールは飛ばします (全番組に当たるため)。
  時間帯や曜日だけで絞っていたルールも同じです (その時間の全番組に当たるため。denpa でも時間帯と曜日は絞り込みとしてだけ効きます)。
  種別だけのルールは入り、その種別の全番組に当たるので、下見のログで確かめてください

> [!IMPORTANT]
> **エンコードの設定は移しません。** コーデックもCMの扱いも denpa では全体設定です ([library.md](library.md))。
> 引き継いだあとに設定の「録画」 (`/settings/recording`) で決め直してください。

### 手動予約 (`reserve`)

**移すのは `ruleId IS NULL` のものだけです** (ルールから作られたものは、ルールを移せば denpa が作り直す)。
除外印 (`isSkip`) の付いたものと、終わった番組も飛ばします。

**denpa の番組表にその番組が無いと入りません。** 番組表を集める前に走らせると「番組表に無いので
取り込めません」が並ぶので、埋まってからもう一度実行してください。走らせ直すと、手動予約は
取り込み済みでも予約し直します。二重にはなりませんが (番組ID の UNIQUE)、denpa 側で取り消した
ものも予約に戻ります。

### 録画 (`recorded`)

元のTSとエンコード済みの両方があればエンコード済みを取り、置き場は「denpa 自身が録ったとき」と同じに
揃えます (EPGStation の `video_file.type` で分ける)。

| 向こうの型        | 置く先                 |                                    |
| ----------------- | ---------------------- | ---------------------------------- |
| `encoded`         | 保存先 (`ENCODED_DIR`) | 完成品として扱う。サムネイルも作る |
| それ以外 (元のTS) | 作業領域 (`RAW_DIR`)   | denpa 側で再エンコードできる       |

元のTSを保存先に置くと denpa からは「エンコード済み」に見え、**再エンコードできず、エンコード済みとして巨大な MPEG-2 が
並びます。** サムネイルも保存先に置いたものにだけ作ります (作業領域は画面に出ない)。

- 元のパスは3通りで探します (EPGStation は相対でも絶対でも持つ)。見つからないものは `missing` として
  ログに残し、行も作りません
- 取り込み済みは飛ばします。EPGStation の ID の符号を反転して `program_id` に入れるので、denpa の
  番組IDと衝突せず、止めて再開しても二重に入りません (ルールは `source` の `epgstation:<id>` で見分けます)
- **ファイルを置き終えてから行を入れます。** 置く先と同じフォルダに書きかけ
  (`.epgstation-<id>.<拡張子>.migrating`) として写し、最終の名前へ rename してから DB に入れます
  (rename と DB は1つのトランザクション)。途中で止まっても失敗しても「ファイルの無い録画」は残らず、
  書きかけは次の実行の頭で消します。移動でも、元を消すのは DB に入れ終えてからです
- 行があってもファイルが1つも無いもの (先に行を入れていた前の版が途中で止まった跡) は取り込み済みと
  見なさず、同じ行のまま置き直します。denpa 側で消したもの (`deleted_at`) は戻しません。
  ファイルマネージャなどで外から消しただけで行が残っているもの (元のTSだけの録画など) は、EPGStation 側に
  元が残っていれば置き直されます
- 移動のとき、取り込み後に元を消せなかったものは失敗にせず、ログに残して先へ進みます

## 済んだら

**マウントと `EPGSTATION_*` を外します。** マウントが残っていると設定に実行の欄が出たままになります (`EPGSTATION_DB_*` は残っても使われないだけ)。

元の PVC は、denpa 側で中身を確かめてから消してください
(コピーで取り込んだ場合、消すまでは EPGStation もそのまま動きます)。
