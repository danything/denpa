# IT930x の機材

PLEX・e-Better・Digibest の USB / PCIe チューナーのうち、USB ブリッジ IT930x を積んだ機材です
(PX-MLT5 系・PX-MLT8PE・DTV02A-4TS-P・PX-Q3・PX-W3 系と、受信機が 1 つの機種)。
**ホストにドライバもファームウェアも入れず、エージェントが USB を直に持ちます** (Linux は usbfs、Windows は WinUSB、Mac は IOKit。[#1578](https://github.com/danything/denpa/issues/1578))。
Linux は `/dev/bus/usb` が見えれば動き、`px4_drv` (DKMS) もカーネルモジュールも要りません。
同時に取れるチャンネルは受信機の数だけです。内蔵カードリーダーのある機種は、それも使えます。

チューナーの一覧は [tuners.md](tuners.md)、Windows で使うときは [install-windows.md](install-windows.md)。エージェントの中でどう扱っているかは [agent.md](agent.md#it930x-の機材を直に持つ作り)。

「Amazon で見る」は広告のリンクです ([tuners.md](tuners.md))。

## 設定

- **挿してあれば、受信機を自動で見つけます。** `device` は `it930x:<USB のポート>:<受信機>` (`it930x:4-12.1:0`)、
  名前は「PLEX PX-MLT5PE 4-12.1 #0」のようになります。挿すポートを変えると別のチューナーになります
- **受信できる種別は、受信機ごとに決まっています** (上の表)。受けられない種別は設定で選べず、選局も機材に触る前に断ります。
  CXD2856ER の受信機は、自動で見つけたときは地上波・BS・CS を選んだ状態で並びます。ケーブルとスカパー！プレミアムを受けるときは、設定のチューナーで種別に足します
- 受信機の番号は px4_drv と同じ並びです
- **PX-Q3 系は、USB デバイスが 2 つ見えます。** それぞれを 4 つの受信機として挙げるので、チューナーは 8 つです (`it930x:4-1:0`〜`3` と `it930x:4-2:0`〜`3`)。
  2 つの USB デバイスは、USB のシリアル番号 (15 桁。先頭の 14 桁が同じで、末尾が 1 と 2) で同じ筐体と見分け、末尾が 1 の側を先に並べます。
  片方の受信機を使っている間は、もう片方の電源も入れておきます (px4_drv の既定と同じ)。片方しか見つからないときは、記録に出して見つかった側だけを使います。
  シリアル番号は Linux では sysfs、Windows ではデバイスのパスから読みます (Windows の読み方は確かめていません)。Mac では読みません。
  読めないときは電源を連動させず、内蔵カードリーダーは 2 つの USB デバイスの両方を挙げます (カードの無い側は飛ばされます)。理由は記録に出ます
- **PX-MLT8PE の 2 つの USB デバイスは、別々の機材として扱います** (同じ筐体と見分ける方法が、公開の資料にありません)。電源も連動させません
- **機材は最初の選局で開いて電源を入れ、エージェントが動いている間は開いたままです。** 受信機を使い終えても、設定にその機材のチューナーが残っている間は、受信機をスリープにするだけで電源は切りません。
  受信機を全部設定から外すと、30 秒待ってから電源を切って閉じます (短い間に電源をオン/オフしないため。その間にまた使えば開いたまま)。エージェントを止めると、すぐ閉じます。
  PX-Q3 系は、片方の USB デバイスの受信機を設定に残している間、2 つとも電源が入ったままです。
  受信機が 1 つの機種だけは、受信機を開いている間だけ電源を入れ、カードだけを使うときは入れません
- 最初の受信機の初期化に失敗したときは、電源を入れ直して 1 回だけやり直します (TC90522 の機種。カードや、PX-Q3 系のもう片方の USB デバイスの受信機がその機材を使っているときは、入れ直しません)
- **地上波の受信機は 2 → 3 の順に使うのがよいとされています** (PX-Q3・PX-W3 系)。アンテナの入力は受信機 2 のチューナーを通って受信機 3 へ渡るとみられ、PX-W3U4 で受信機 3 を先に開いてから受信機 2 を開くと、受信機 3 の TS が欠けた記録があります。
  受信機 2 を一度も選局していないときに受信機 3 だけで受けられるかは、確かめられていません
- DTV03A-1TU の復調器は型番が分かっておらず、仕様書にある値だけで動かします。受けられないときは、そのときの `--tune` の出力を貼ってください
- 衛星の強度は画面に出しません。仕様書の式は dB の値で、dBm として扱えるかが分からないためです。`--tune` の出力にだけ dB で出します。
  CXD2856ER の機種の地上波とスカパー！プレミアムは、強度 (dBm) も出します ([tuners.md](tuners.md#信号レベル))

## LNB の給電

**給電できるのは 15V だけです** (設定の LNB を「15V」にする)。11V を選ぶと衛星の選局を断ります。

- 給電は USB デバイスごとに 1 つで、その USB デバイスの受信機で共用します。衛星を選局している受信機が 1 つでも「15V」なら入れ、どれも使わなくなったら切ります。
  PX-Q3 系は、2 つの USB デバイスに別々にあります
- 受信機が 1 つの機種は LNB に給電できません。設定の LNB を「15V」にすると衛星の選局を断るので、空にして、ほかの機器から給電します
- 給電の電圧と、過電流の検出は実機で確かめていません

## 内蔵カードリーダー

**内蔵カードリーダーも、挿さっている機材のぶんをエージェントが開きます** (「PLEX PX-MLT5PE 4-12.1 Card Reader」のような名前)。
試す順は USB のリーダーのあと、CECH-ZD1 J・PIX-DT295 の前です。「使う」を外すと開きません ([tuners.md](tuners.md#カードリーダー))。

- カードの速さは ATR のとおり (B-CAS は 19200) で、ブリッジが扱えるのは 9600 と 19200 だけです
- 受信機と同じ電源の機種は、カードを使っている間は受信機を全部閉じても電源を切らず、カードだけを使うときも機材を開いて電源を入れます。
  受信機が 1 つの機種は、受信機の電源を入れずにカードを読みます
- PX-Q3 系は、シリアル番号の末尾が 1 の側だけを挙げます (PX-Q3U4 での記録。PX-Q3PE4 も、末尾が 1 の側でカードを読めました (2026-11-11)。PX-Q3PE5 は確かめていません)
- PX-MLT8PE は、5 つの受信機の側だけを挙げます

## ファームウェア

**ファームウェアはエージェントの実行ファイルに埋め込んであります。** IT930x は挿すたびにホストから RAM へファームウェアを流し込みます。
エージェントは機材を開くたびに、埋め込んだものを直に送ります (ファイルには書き出しません。`It930xFirmware.cs`)。
同梱しているのは ITE Tech. の IT930x の Linux ドライバに入っているデータをそのまま書き出したもの
(`agent/Denpa.Agent/firmware/it930x-firmware.bin`、2,169 バイト) で、ITE Tech. から無改変での再配布の許諾を得ています
([licenses.md](licenses.md#チューナーエージェントに同梱するファームウェア))。インターネットに繋がっていなくても使えます。

## Windows のドライバ

**Windows は、機材のドライバを WinUSB に替えます。** `install.ps1 -WinUsb` で替えます ([install-windows.md](install-windows.md#チューナーのドライバを-winusb-に替える))。Zadig でも替えられます。

- PX-Q3 系と PX-MLT8PE は USB の機材が 2 つ並ぶので、両方とも替えます (`-WinUsb` は挿さっている対応機材をまとめて替える)
- PLEX のドライバで TVTest などから使っていた機材は、WinUSB にするとそちらからは見えなくなります

## スカパー！プレミアムサービス光 (J.83B)

**選局とチャンネルスキャンまでです。** CXD2856ER の機種 (PX-MLT5 系・PX-MLT8PE・DTV02A-4TS-P) のどの受信機でも受けられます。
種別は `SKY` (画面では「スカパー！プレミアム」)、チャンネルは `H01`〜`H105` (93.25 MHz から 6.5 MHz おき) です。

- **TS はスクランブルされたまま流します。** スカパー！プレミアムのカードはまだ扱わず、B-CAS のカードにも問い合わせません
- 設定の「チューナー」の「受信できる種別」に「スカパー！プレミアム」が出るのは、CXD2856ER の機種の受信機があるときだけです。ほかの機材では選べません。
  選んだ受信機が 1 つでもあれば、「チャンネル」のスキャンの選び方にも出ます。`H01`〜`H105` を 1 つずつ選局し、NIT と SDT が読めたチャンネルの局を入れます (「すべて」にも入ります)
- **スカパー！プレミアムの局は、ライブと録画に使えません。** スクランブルを復号できないので、ライブの一覧に出さず、ロゴも取得しません。
  番組表 (EIT) がスクランブルされずに来ている局だけ、番組表に「観られません」の列で出します ([下記](#スカパープレミアムでカード無しで分かること))。
  局の一覧の API はほかの局と同じく返しますが、ライブの API は選局せずに `409` で断ります ([api.md](api.md#ライブ-get-apiservicesidlive))
- NIT と SDT の送り方 (スキャンで局が見つかるか) は実機で確かめていません。スキャンの記録 (「SKY: 105ch 中 …」の行と、局が見つかったチャンネルの行) も [#1578](https://github.com/danything/denpa/issues/1578) に貼ってください。
  局が見つかったチャンネルの行には、カード無しで分かること (CA_system_id と番組表が来ているか) も出ます ([下記](#スカパープレミアムでカード無しで分かること))
- H11・H12・H26〜H28・H44 は、地域によってずらした周波数 (+1 MHz・+4 MHz・+2.2 MHz) で送られます。両方を試し、次はロックしたほうから試します
- 電源を入れてから初めて J.83B か ISDB-C を選局したときに、全部の受信機に待機中の RF 入力の整合を保つ設定を立てます (受信機の待機と動作の切り替えで、隣の受信機の 256QAM に誤りが出た記録への対処)。
  いま選局する受信機は設定を立てるだけです。ほかの受信機のうち、使っていないものは初期化し直して待機させ、動作中のものは止めるときに設定を書きます
- J.83B の TS は約 40 Mbps になりえます (256QAM と見た推定)。5 つの受信機は USB 2.0 の 1 本で TS を返すので、5 つとも J.83B だと約 200 Mbps です。
  USB 2.0 で実際に出る速さには収まる見込みですが、余裕は大きくありません。5 つを同時に使って欠けが出たら、そのときの `--tune` の出力も貼ってください
- J.83B のあとに同じ受信機で衛星を受けられるかは確かめていません (J.83B のスリープで、復調器のレジスタの一部が J.83B の値のまま残るため)

ケーブル (ISDB-C) の受け方は [tuners.md](tuners.md#ケーブル-isdb-c) にあります。

## 実機で確かめたこと

**PX-MLT5PE (Linux) の実機で、受信機 0〜4 の選局と、内蔵カードリーダーの B-CAS の読み取りを確かめました** (2026-11)。

- 地上波 (T27・T22) は、5 台の受信機とも連続性の飛びが 0 個、C/N が 21〜23 dB でした。復号しながら 90 秒流しても飛びは 0 個でした。内蔵カードリーダーで復号できました
- 衛星は CS02・CS08・CS24 と BS15・BS21・BS23 がロックしました。BS の C/N は 8〜9 dB でした。分波器を使っていない環境で、同じ機材を px4-userland で動かしても同じ BS のチャンネルは受けられませんでした
- ケーブル (ISDB-C) は、J:COM の回線で 18 の搬送波がロックしました ([tuners.md](tuners.md#ケーブル-isdb-c))
- 内蔵カードリーダーは、`--card` で 5 回続けて ATR とカードの番号を読めました。カードの速さは 19200 です
- 機材を開き直しても選局できました
- LNB の給電、スカパー！プレミアムサービス光 (J.83B)、PX-MLT5U と DTV02A-5TS-P は確かめていません

**PX-Q3PE4 (Linux) の実機で、8 つの受信機の同時受信まで確かめました** (2026-11-11)。

- 2 つの USB デバイスの両方で、地上波と BS を受けられました。USB デバイスをまたいで続けて選局しても受けられました
- 8 つの受信機 (BS 4 つ・地上波 4 つ) で同時に 10 秒受けられました
- 内蔵カードリーダーで B-CAS を読めました
- 動いているファームウェアを REBOOT すると、機材が USB から一度外れます。エージェントは開き直してから続けます
- もう片方の USB デバイスの電源のためだけに開いた側は、ブリッジの TS 入力を閉じたままにします。開けていたときは、初期化していない TC90522 から入力にデータが入って溢れ、電源を抜くまで TS が出なくなりました。
  入力は、最初の受信機を開いたときに開けます

PX-W3 系、受信機が 1 つの機種、PX-MLT8PE、DTV02A-4TS-P は実機で確かめていません。Windows (WinUSB) と Mac (IOKit) では、どの機種も確かめていません。

## TS のバッファの溢れ

**ブリッジの TS のバッファが溢れると、その機材は電源を抜いて入れ直すまで TS を出しません。** 溢れの印 (全体の `0xDA39` と入力ごとの `0xDA57`・`0xDA8B`〜) は、
ファームウェアの REBOOT、受信機の電源の入れ直し、TS の経路のリセットのどれでも下りませんでした (PX-MLT5PE。2026-11-11)。電源を切らずに下ろす手順は、公開の資料にもありません。
PCIe の機種は、PC を再起動するのではなく、電源を切ってから入れ直します (再起動で溢れが下りるかは確かめていません)。

- 溢れるのは、ブリッジの TS 入力を開けたまま、EP 0x84 を読む側がいなくなったときです (推定)。エージェントは止まるときに入力を閉じてから読みを止め、それから電源を切ります。
  捕まえていない例外で落ちるときも閉じます。SIGKILL で止められたとき (Pod の猶予切れ・OOM)、ノードの電源が落ちたときは閉じられません
- **開いたときに全体の溢れが立ったままなら、その機材の受信機では選局せず、ほかのチューナーで選局します。** 記録に「リセットしても溢れたままです」と「この機材の受信機では選局しません」が出ます。
  内蔵カードリーダーはそのまま使えます。PX-MLT8PE の 2 つの USB デバイスは別のブリッジなので、溢れていない側の受信機は使えます
- 入力ごとの溢れだけが立ったままのときは選局を続けます。その受信機に TS が 30 秒届かなければ、選局を畳んでほかのチューナーを使います
- 溢れたまま選局していると、全体の溢れのあとに入力の溢れも立ちます (PX-MLT8PE の受信機 0。2026-11-12)。記録には、EP 0x84 から TS が出ずに入力に溜まったと出ます

電源を入れ直したあとは、次の順で確かめます。

1. エージェントを起動し、記録に「開いたときに TS のバッファが溢れていました」が出ないことを確かめる
2. その機材の受信機で選局し、TS が届くことを確かめる
3. 受信機が TS を流している間にエージェントを止め (SIGTERM。Pod なら入れ替え)、もう一度起動して、1 と 2 が同じになることを確かめる

## 実機で試すコマンド

機材をお持ちなら、次のコマンドの出力を [#1578](https://github.com/danything/denpa/issues/1578) に貼ってください (機種と OS も添えて)。
エージェントを止めてから流します。エージェントが動いていると機材を開いているので、開けずに止まります。

- `denpa-agent --tune it930x:<USB のポート>:<受信機> T27`: 地上波を選局して受ける。同期までの時間、ロックまでの時間、TS の量と連続性の飛び、C/N と強度を出す。
  `T27,T21` のように並べると、開いたまま選局し直します。USB のポートは `--it930x-probe` の 1 行目に出ます。
  初めて初期化した受信機は「初期化の前のチューナーの 62」も出します。前のプロセスで ISDB-C か J.83B を選局したあとに `10` なら、閉じたときにチューナーの電源が切れていなかったと読みます (推定)。
  ロックしたのに TS が 1 バイトも届かなかったときは、復調器の TS の出力のレジスタ 4 つと、ブリッジの TS の経路の状態 (残りのバッファ・入力ごとの溢れ・EP 0x84 のストールなど) と EP 0x84 から読んだバイトの数を出し、
  ブリッジの TS のバッファを捨ててからもう一度受けて、TS が届いたかを出します
- `denpa-agent --tune it930x:<USB のポート>:0+it930x:<USB のポート>:1+it930x:<USB のポート>:2 QC14,QU49`: `+` で並べた受信機を同時に選局する。
  受信機ごとにスレッドを立ててそろって始め、どの受信機もチャンネルの並びを順に選局します (常駐のエージェントが受信機を並べてスキャンするときと同じ形)。
  出力は受信機ごとにまとめ、1 つの受信機のときと同じ行に、そろって始めてからの時間を添えます。最後に、受信機とチャンネルごとのロックと Mbps を並べます。
  1 つでは受かるのに並べると受からないときは、この出力を貼ってください
- `denpa-agent --tune it930x:<USB のポート>:0+it930x:<USB のポート>:1+…+it930x:<USB のポート>:4 T27,T22 --steps 2,3,5`: TS を流す受信機を段階を追って増やす。
  `+` で並べた順に、チャンネルの並びを先頭から割り当てて (足りなければ先頭から繰り返す)、受信機を 1 つずつ足します。足すたびに 1 秒、段階ごとに `--seconds` (既定 3 秒) の間、流している受信機ごとの Mbps を出します。
  開いた直後、段階ごとの選局のあと、受けたあとに、ブリッジの TS の経路の状態と EP 0x84 から読んだバイトの数を出します。
  どれかの受信機に TS が 1 バイトも届かなくなったら、その先の受信機は足さずに止めます。5 つを同時に流して TS が止まった機材を、電源を入れ直したあと少しずつ確かめるためのものです
- `denpa-agent --tune it930x:<USB のポート>:<受信機> BS15:16625 --lnb 15v`: 衛星を TSID で選局して受ける。地上波と同じものに加えて、中継器の TMCC にある TSID (相対 TS 0〜7) を出します。
  `T27,BS15:16625,T21` のように並べると、同じ受信機で地上波と衛星を切り替えます。`--decode` を付けると、その機材の内蔵カードリーダーだけで復号します
- `denpa-agent --tune it930x:<USB のポート>:<受信機> H40`: スカパー！プレミアムサービス光 (J.83B) を選局して受ける。地上波と同じものに加えて、受けた周波数、変調 (256QAM など)、PER を出します。
  PER の読み方が J.83B で正しいかは確かめていないので、目安です。`--decode` を付けても復号しません。どのチャンネルで受けられたか、受けられなかったチャンネルも添えてください。
  CA_system_id や番組表が来ているかも出します ([下記](#スカパープレミアムでカード無しで分かること))
- `denpa-agent --tune it930x:<USB のポート>:<受信機> QC51`: ケーブルテレビのトランスモジュレーション方式 (ISDB-C。64QAM・256QAM) を選局して受ける。画面から使う手順は [tuners.md](tuners.md#ケーブル-isdb-c) にあります。
  チャンネルは `QC13`〜`QC63` (CATV の帯域の C13〜C63)、`QU13`〜`QU62` (UHF)、`QV1`〜`QV12` (VHF) です。1 つの搬送波に複数の TS が入っているとき (TSMF) は、
  `QC52:1` のように `:k` を付けて、有効な TS の k 本目 (0 から数える。付けなければ 0 本目) を受けます。
  受けた周波数、TSMF のヘッダーの有無、ヘッダーにある TS の一覧 (相対 TS 番号・TSID・ONID・有効かどうか・スロットの数) と選んだ TS、ヘッダーのパケットの 16 進、
  変調、C/N、PER、出力した TS の PAT の TSID を出します。
  受け終えたあとは、CRC が合わないヘッダーの数、前のヘッダーの割り当てで受けたフレームの数、1 フレームの選んだ TS のスロットの数、選んだ TS のスロットに来たパケットと出力したパケットの数、
  選ぶ前とあとの連続性の飛びと transport_error_indicator が 1 のパケットの数も出します。選ぶ前に飛んでいれば搬送波から受けた時点で欠けていて、選んだあとだけで飛んでいれば選ぶ処理で欠けています。
  1 つの PID だけが飛んだか所は、その PID も出します。選局できなかったときも、ロックしなかったのか、ロックしたが TS が届かなかったのか、指定した TS が無かったのかを出します。
  PX-MLT5PE の実機と J:COM の回線 (2026-11) で、QC13〜QC63・QU13〜QU62・QV1〜QV12 を順に選局し、18 波がロックしました。どれも 64QAM で、C/N は 21〜26 dB、連続性の飛びは 0 個でした。
  TSMF のヘッダーがある波は 8 つで、ヘッダーから読んだ TSID は、出力した TS の PAT の TSID とどれも同じでした。有効な TS はどの波も 1 本だったので、複数の TS から選ぶ動きと 256QAM は確かめていません。
  局の限定受信は、B-CAS (CA_system_id 0x0005) のものと、B-CAS 以外 (0x0006) のものがありました。PER などの値が正しいかは、ほかの受信機と比べていません。
  ほかの事業者の回線で試したら、受けられたチャンネルと受けられなかったチャンネル、事業者を添えてください
- `denpa-agent --card it930x:<USB のポート>`: 内蔵カードリーダーだけを開き、ATR とかかった時間、カードの番号を出す。
  カードの有無とリセットにはブリッジの GPIOH6・GPIOH14 を使います (ITE の SDK の評価基板の配線)。PX-MLT5PE では、この GPIO でカードを読めました。PX-MLT5U と DTV02A-5TS-P が同じ配線かは確かめていないので、「カードが挿さっていません」や「ATR を返しません」と出たときも貼ってください
- `denpa-agent --it930x-probe`: ブリッジのチップのバージョン、ストラップ、EEPROM の設定の写し (`0x4994` から 256 バイト) を読み、ファームウェアを読み込んで起動し、そのバージョンを出す。
  前のファームウェアが動いていれば、REBOOT してから読み込みます。復調器とチューナーには触りません。終わりに REBOOT して、挿した直後と同じ (ファームウェアが動いていない) 状態に戻し、REBOOT で USB がつなぎ直されたかも出します
  - `--port <USB のポート>`: 2 台以上挿してあるときに指す
  - `--ts <秒>`: 起動したあと TS の経路 (ブリッジの入力 0〜4 と EP 0x84) を設定し、入力を開けて EP 0x84 をその秒数だけ読み、入力ごとのパケットの数と捨てた数を出す。
    復調器を動かさないので、ふつうはどの数も 0 です。設定がエラーにならないことと、読みが止まらずに秒数どおりに終わることを確かめます
  - `--trace`: ブリッジへ送ったコマンドと応答を 1 行ずつ、時間つきで標準エラー出力に出す。うまくいかなかったときは、これも貼ってください
- `denpa-agent --it930x-cycle <USB のポート> <回数> [--no-wait]`: 機材を開いて電源を入れ、すぐ電源を切って閉じるのを、続けて決めた回数 (1〜100) 繰り返し、1 回ごとにかかった時間を出す。
  受信機の初期化と選局はしません。常駐のエージェントは最後に使い終えてから 30 秒は電源を切りませんが、これは待たずに切ります。
  `--no-wait` を付けると、電源を切ったあとの 100 ms も待ちません (この待ちを入れる前の動き)。
  電源を続けてオン/オフしたあとに TS が止まった記録を再現するためのもので、終えたら `--tune` で TS が届くかを確かめます

## 実機で確かめる順 (PX-Q3・PX-W3 系と受信機が 1 つの機種)

エージェントを止めてから、上から順に流します。前の項目が通らないと、後の項目は確かめられません。出力はそのまま [#1578](https://github.com/danything/denpa/issues/1578) に貼ってください (機種と OS も添えて)。
`<側 1>`・`<側 2>` は、1 つ目のコマンドが出す USB のポートです (PX-W3 系と受信機が 1 つの機種は、ポートは 1 つ)。

1. `denpa-agent --it930x-probe`: 見つけた機材を、USB の ID・ポート・シリアル番号と一緒に並べます。PX-Q3 系は 2 行出て、側 (1 か 2) と、もう片方の側のポートが付きます。
   2 台以上あるので、このあとは `--port` で指します
2. `denpa-agent --it930x-probe --port <側 1> --chips` (`<側 2>` も): ファームウェアを読み込み、受信機の電源を入れて、復調器の 4 つのアドレスが応答するか、
   チューナーの種類 (R850 の種類 0 か 1 と水晶の駆動の強さ、RT710 か RT720 か) を出します。「応答なし」「読めません」と出たときは `--trace` を付けた出力も貼ってください
3. `denpa-agent --tune it930x:<側 1>:2 T27`: 地上波の 1 局。ロックまでの時間、TS の量と連続性の飛び、C/N、TMCC、チューナー (R850) に書いた値を出します。選局に失敗したときも、チューナーに書いた値、PLL がロックしたか、ロックの判定で読む復調器のレジスタを出すので、そのまま貼ってください
4. `denpa-agent --tune it930x:<側 1>:3 T27`: 受信機 2 を選局していない状態で、受信機 3 だけで受けられるか
5. `denpa-agent --tune it930x:<側 1>:0 BS15:16625 --lnb 15v`: 衛星の 1 局。LNB に 15V が出ているかをテスターで測れるなら、その値も添えてください。
   TMCC にある TSID と、給電の短絡を検出する入力 (GPIOH10) の値も出します
6. `denpa-agent --tune it930x:<側 1>:1 BS15:16625 --lnb 15v`: 衛星の 2 つ目の受信機 (AGC の値が 1 つ目と違う)
7. `denpa-agent --tune it930x:<側 2>:2 T27` と `denpa-agent --tune it930x:<側 2>:0 BS15:16625 --lnb 15v`: 側 2 でも同じか
8. `denpa-agent --card it930x:<側 1>` と `denpa-agent --card it930x:<側 2>`: カードを挿して、どちらの側で読めるか
9. `denpa-agent --tune it930x:<側 1>:2 T14` (お住まいの地域で 14ch が出ていれば): 水晶を 4 で割る選局
10. `denpa-agent --tune it930x:<側 1>:2 T27,T21,T27`: 開いたまま選局し直せるか。もう一度同じコマンドを流して、閉じたあとに開き直せるか

4 つの受信機を同時に使ったときに、それぞれが正しい局の TS になっているかは、エージェントを動かして 4 つのチューナーで別々の局を観て確かめます。局が入れ替わっていたら、どの受信機にどの局が出たかを教えてください。

## スカパー！プレミアムでカード無しで分かること

**スカパー！プレミアムのカードに対応する前に、カードが無くても TS から分かることを集めています** ([#1578](https://github.com/danything/denpa/issues/1578))。
復号はせず、スカパー！プレミアムのカードにも B-CAS のカードにも ECM を渡しません。読むのはスクランブルされていない PSI/SI (ARIB STD-B10) だけです。

- PMT (局ごと) と CAT の CA 記述子にある CA_system_id と、ECM・EMM の PID を出します。B-CAS (`0x0005`) 以外の値には「B-CAS 以外」と付けます
- 番組表 (EIT) とロゴ (CDT) のセクションが来ているか、スクランブルされているかを出します。スクランブルされているかは、TS パケットの transport_scrambling_control で見ます。
  番組表は、ほかの TS の局のぶん (EIT の other) が来ているかも出します
- エージェントの出力には、network_id・transport_stream_id・局の数と、ECM・EMM の PID に来たセクションの table_id ごとの数と長さ、末尾の CRC が合うかも出します (EMM を扱えるかを決めるため。CRC で捨てずに全部数える)

出す場所は 3 つです。

- チャンネルスキャン: SKY の局が見つかったチャンネルの記録の行 (「H40: 3 局 CA_system_id …」) と、設定の「受信できるチャンネル」のそのチャンネルの下の「スキャンで分かったこと」。
  局が揃ってからも、番組表が来ているかが分かるまで、読み始めから 10 秒までは読み続けます。
  「受信できるチャンネル」に出すものは denpa の中にだけ持つので、denpa を再起動すると消えます (もう一度スキャンすると出ます)
- `denpa-agent --tune it930x:<USB のポート>:<受信機> H40`: 受けた TS で数えます (エージェントを止めてから流す)
- `denpa-agent --decode-file <in.ts>`: 録れた TS のファイルで数えます。書き出す先を省くと復号せず、カードも開きません

**実機ではまだ確かめていません。** 受けられたチャンネルについて、上のどれかの出力を [#1578](https://github.com/danything/denpa/issues/1578) に貼ってください。
CA 記述子の行 (「局 0x…」「CAT」)、「ECM・EMM」の行、「番組表 (EIT)」と「ロゴ (CDT)」の行が入っていれば足ります。光か衛星かも添えてください。

**番組表がスクランブルされていない (EIT が読める) と分かった SKY の局は、番組表に「観られません」の列で出します。**
ケーブルの局と同じ決まりです ([data.md](data.md#denpa-が持つもの))。EIT の中身が地上波と同じ読み方で読めるかは実機で確かめていないので、番組名が化けていたら報告に添えてください。
ロゴ (CDT) はまだ集めません。

## ケーブルの 4K を確かめる

**ケーブルで再送信している BS4K (MMT/TLV) は、エージェントが TLV パケットの並びに組み立てて、形式を変えずに流します** ([agent.md](agent.md#it930x-の機材を直に持つ作り))。
denpa はスキャンで局を入れ、番組表 (MH-EIT) を読んで、番組表に「観られません」の列で出します。ACAS のスクランブルにはまだ対応していないので、スクランブルされた局はライブで観られず、録画もできません。
受けられるか、カード無しで何が分かるかは、エージェントを止めてから `--tune` で確かめます。

```sh
denpa-agent --tune it930x:<USB のポート>:<受信機> QC26 --seconds 10
denpa-agent --tune it930x:<USB のポート>:<受信機> QC26 --seconds 10 --ecm-test
```

- TSMF のヘッダーの一覧で選んだ TS が「分割 TLV」なら、「TSMF: 選んだ TS は分割 TLV です。TLV に組み立てて出力します」と出ます
- 受け終えたあとに、組み立ての数を出します。受けた単位、開始の単位 (pointer のある単位)、組み立てた TLV パケット、捨てたバイト、合わせ直した回数 (中身の食い違いとフレームの欠け)、TLV パケットの種類ごとの数です。
  最初の開始の単位より前のバイトは捨てるので、捨てたバイトは欠けが無くても 0 になるとは限りません
- カード無しで分かること (`TlvObservation`) を出します。MMTP の packet_id ごとのスクランブルの印 (なし・偶数・奇数) の数、MPT のアクセス制御記述子の CA_system_id と ECM の packet_id、
  TLV-NIT・MH-SDT・MH-EIT が来ていて CRC が合うか (局名と番組名を 1 つずつ) です
- `--ecm-test` は、MPT が指す packet_id に来た ECM のセクションを 1 つ、B-CAS の ECM と同じ切り方 (先頭 8 バイトと末尾の CRC を除いた中身) でカードに渡し、返り値を出します。
  カードは、その機材の内蔵カードリーダーです (`--card-url` があればそちら)。鍵を返したかで、B-CAS のカードで復号できる見込みがあるかが分かります。MMT の復号はしません
- `--decode` を付けても、TLV は復号しません (B-CAS のカードに MMT の ECM を渡さないため。`--ecm-test` だけが渡します)

PX-MLT5PE と J:COM の回線で受けた QC26 (2026-11-11、先頭の 4 MB) は、TSMF の有効な TS が 1 本で、分割 TLV でした。MPT のアクセス制御記述子の CA_system_id は B-CAS と同じ `0x0005`、ECM の packet_id は `0xFFF1` で、
映像と音声はどれも奇数の鍵でスクランブルされ、信号 (MPT・ECM・MH-EIT・MH-SDT・TLV-NIT) はスクランブルされていませんでした。カードが ECM に鍵を返すかは、まだ確かめていません。
