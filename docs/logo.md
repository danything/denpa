# 局ロゴ

**放送波からしか手に入らないもの。** 番組表に出す PNG と、CM検出に使う白黒の `.lgd` の2つがあり、
集め方も置き場も別です。エージェントは中身を読まないので、PNG は denpa が開いているストリームに
相乗りして自分で読みます。

| 探しもの | 見る場所 |
| --- | --- |
| 全体像 | [architecture.md](architecture.md) |
| ロゴを使う CM 検出そのもの | [encode.md](encode.md) |
| チューナーの相乗りの決まり | [agent.md](agent.md#相乗りの決まり) |

**送られてくる PNG には色の表 (PLTE/tRNS) が入っていません。** ARIB (STD-B21) では 128色 +
半透明ぶんの表が決め打ちで送られず、受け取った側が入れ直して初めて絵になります。入れないと
「パレットの無いパレット PNG」で、ブラウザは何も描きません (実機では15局ぶん拾えているのに
番組表が空でした)。入れ直すのは `src/lib/ts/logo-palette.ts` で、Mirakurun も aribts の `TsLogo.decode`
で同じことをしています。置いてあるファイルは `logo.reconcile` が入れ直します。拾い直すと局によっては何時間も
かかるためです。

**開くのは物理チャンネル丸ごと**です。局を選り分けると、どの局の PMT にも載っていない CDT は
まるごと落ちます。実機での実測:

| 開き方 | 読んだ量 | CDT |
| --- | --- | --- |
| BS サービス単位 | 3分 / 427 MB | 0 |
| BS チャンネル丸ごと | 100秒 × 4中継 | 0 |
| GR チャンネル丸ごと | 60秒 | 2 |
| GR サービス単位 | 60秒 | 0 |

**普段はチューナーを掴みません。** 番組表集めが全チャンネルを定期的に開くので、その選局に相乗り
するだけで只で読めます (`logo.ride`。合図はエージェントの `tuners`。向こうの都合でいつ閉じるか
分からないので1回3分まで)。実機では **BS の38局ぶんが相乗りの一度で揃いました** (denpa が自分で
開いて拾えた記録は残っていません)。録画の流れからは拾いません (衛星のカルーセルは数百KBあり、
録画の一本道に混ぜたくないため。同じチャンネルなら相乗りでチューナーは増えない。
[相乗りの決まり](agent.md#相乗りの決まり))。以前は10分ごとに自分でも1チャンネル開いていましたが、
相乗りで埋まるのに録画とチューナーを取り合う理由がないのでやめました。

すぐ欲しいときは画面の「いますぐ取りに行く」(`logo.sweepNow`) が自分で開きます。**CDT は分単位で
待つもの**なので、地上波は1チャンネル6分 (数十秒〜3分では実機でほとんど当たりませんでした)、衛星は
[下記](#衛星は14分に1回しか流れてこない)のとおり最大20分です。空きは**種別まで見て数えます**。
「1本でも空いていれば」で数えていた頃は、地上波が1本しか空いていなくても2チャンネルを開きに
行っていました (衛星用の空きは地上波の役に立たない)。

## 地上波は CDT、衛星はデータカルーセル

**地上波と衛星で伝送方式が違います。** 地上波は CDT (PID 0x0029) に PNG の実体、SDT の
`logo_transmission_descriptor` に「どの局がどのロゴを使うか」を載せてくるので、両方揃って初めて
局に配ります。**衛星は CDT に載せません。** CDT だけを読んでいた頃は地上波 29/29 に対して
BS 0/38 (26中継)・CS 0/54 (12中継) でした (Mirakurun もネットワーク4は DSM-CC を読みに行きます。
`TSFilter.ts` の `_enableParseDSMCC`)。

衛星は**データカルーセル (DSM-CC)** から拾います (`src/lib/ts/logo-dsmcc.ts`)。道のりが
長く、PAT → **サービス929 (エンジニアリングサービス)** の PMT → `stream_identifier_descriptor`
の component_tag が 0x79/0x7A の ES → DII (どのモジュールが何バイトか。名前が `LOGO-05` /
`CS_LOGO-05` のものがロゴ) → DDB (ブロックに割られた中身) と辿ります。組み上がった
モジュールには**どの局のロゴかが入っている**ので、地上波と違って SDT を待ちません。

**ロゴが載っている中継は1つだけです。** 実機の BS はネットワーク4に26の中継がありますが、
サービス929 が居たのは `BS15_0` (NHK BS と同じ中継) だけでした。CS の12中継には1つも
居ません。 どれなのかは開いてみないと分からないので、**PAT を見た時点で外れなら
切り上げます**。PAT は1秒に何度も流れてくるので、外れの中継は1秒ほどで諦められます。
当たり外れは `logos/satellite-relays.json` に書き留めて、1週間は開き直しません。

**CS のロゴも、その BS の中継から流れてきます。** `BS15_0` のエンジニアリングサービスには
`LOGO-00`〜`LOGO-05` と `CS_LOGO-00`〜`CS_LOGO-05` が**並んで**載っています
(component_tag 0x79 と 0x7A)。実測でも、この中継を1つ開くだけで
**ネットワーク4が211局・6が28局・7が83局**ぶん (モジュール162個) 揃いました。

ここで踏んだ間違いは4つで、**どれも「先に来る BS のぶんで満足して打ち切る」形**です。

- DII で合致するモジュールを**全部**組み立てる (1つで打ち切ると CS が永久に揃わない)。
  `logo_id` は BS と CS で別々に振られ、同じ番号が出るので鍵も分けます
- **「開いた中継の局が揃ったら閉じる」で見ない。** BS で条件が満たされて閉じ、後ろの CS を毎回
  取りこぼしていました (`logo.missingSatellites`)
- **行き先の中継も中継単位で決めない。** BS が揃った中継が候補から外れ、そこにしか無い CS が
  埋まらず BS 38/38・CS 0/54 で止まっていました。衛星の局が1つでも足りなければ、まだ外れと
  分かっていない中継を当たります
- **「取れない局」も中継では数えない。** 中継で数えていた頃は、取れるはずの CS 54局を「放送側が
  流していない」と出していました。本当に取れないのは**カルーセルを1回読み切っても来なかった局**
  だけで、そのとき**局ごと**控えます (`absent`。時刻だけ控えていた頃は、そのあと衛星のロゴを
  1つ消しても1週間取りに行きませんでした)

## 衛星は14分に1回しか流れてこない

**衛星のカルーセルは流しっぱなしではありません。** `BS15_0` を15分読み続けると、**13分間はロゴの
ES に1パケットも流れず、14分目にまとめて来ました** (BS 2768・CS 8224 パケット)。6分では運任せ
だったので、衛星だけ最大20分開きます。待つのは当たりの1中継だけで、引ければ BS と CS の
全局ぶんがまとめて手に入ります。拾えたあと15秒何も来なければ、1回読み切ったとみなして切り上げます。

**一度取れた局も1週間経ったら取り直します** (持っていない局だけ見ていた頃は、局のマークが変わっても
永久に古いままでした)。消してから取りに行くのではなく上書きするだけなので、取れなければ今のものが
残ります。古さは PNG の更新時刻で見ます (列は足さない)。地上波は64×36 でない局も取り直し、
大きいものを小さいもので上書きしません。最初に来た 48×24 で満足していた頃は、実機の地上波26局が
小さいまま並んでいました。

**ロゴを保存しても `services.updated_at` は触りません。** あれは「最後に局を取り込んだ時刻」で、
番組表は*いちばん新しいものと同じ時刻の局だけ*を出します (`CURRENT_SERVICES`)。保存のたびに
進めていた頃は、**その局だけが「いまの局」になって他の局が番組表から消えていました**。

## 取りに行くときの決まり

**優先度で譲ります。** ロゴはいちばん下 (1) なので、空きが無ければエージェントが断り、開いている
最中でも番組表のほうが強ければ取り上げられます (ロゴが出なくても番組表は読めるが、逆は成り立たない)。
数の大小だけで並ぶので、「番組表を集めている間はロゴを取りに行かない」のような特別扱いは持っていません
(並びは [agent.md](agent.md#取り合いの決まり))。

取りに行く先は**いま選局できる局だけ**です。スキャンし直して消えた局まで見に行くと、開いては諦める
のを繰り返し、本当に要る局に順番が回ってきません。

何局ぶん持っているかは**チューナー画面に出します** (拾えていないのか出し方が悪いのかを見分けるため)。
同じ画面の「いますぐ取りに行く」は、残りを**空いているチューナーの数まで (最大2本)**、地上波も衛星も
1つの列で**地上波を先に**回します (中継ごとに局が違うので、数が捌けるのはこちら)。取りに行くものが
無ければボタンごと出しません。

- **前の「いますぐ」が回っていても押せます。** 押されたほうが走っている取得を畳んでから始めます
  (只で読む相乗りは別勘定で触りません)
- **進み具合を画面へ流します** (`logos` イベント)。1チャンネルに数分かかるので、出さないと何も
  起きていないように見えます。全部持っている・空きが無いときも、その場で断ります
- **相乗りは自分で開けたものには乗りません。** こちらが開くとエージェントが `tuners` を飛ばし、
  それを合図に同じチャンネルをもう1本開いて二重に読み、画面にも同じ中継が2つ並んでいました
  (実機で `BS01_1`)。番組表集めでも録画でも、他が開けたものには乗ります

番組表の見出しでは、**取れなかったロゴを DOM から取り除きません**。`onerror` で `img` を消していた
頃は、Svelte が持っている節点なので描き直すと並びが崩れ、denpa を入れ替えた直後は読みかけの画像が
まとめて途切れて全局ぶん消えていました。ロゴが無い局も場所は空けておきます。局名の頭が列ごとに
ずれると、どれがどの局か追えません。

## 置き場とファイル

`services.has_logo` は「番組表にロゴを出すか」にそのまま使うので、**ファイルを正としてときどき
突き合わせます** (`logo.reconcile`)。置き場ごと消えることは実際にあり (PVCの作り直しなど)、列だけ
立っていると壊れた画像が並ぶうえ、「もう持っている」とみなして永久に取りに行きません (実機で32局中
29局がこの状態でした)。

**これは CM検出のロゴとは別物です。** `join_logo_scp` が要るのは**画面のどこにロゴが出るかを書いた
`.lgd`** で、自分の録画から作るものなので、PNG が揃ってもそのままでは使えません
([検出方法は2つ](encode.md#検出方法は2つ-設定画面のcmの探し方))。

## CM検出用のロゴは、録ったものから覚える

`.lgd` は**録ってエンコードするときに、その録画から**覚えます (`cm-jls.ts`)。
在り処もそのとき絵から割り出して渡します (`logo-area.ts`)。**割り出しは外すことが
あります。** 外した枠を渡すと logoframe は降りるので、そのときは渡さずにもう一度
回し、通ったら枠を捨てて自動に戻します
([encode.md](encode.md#外したら無かったことにする))。ロゴと強い縁を取り合っている
隅では、枠を出しません ([encode.md](encode.md#言い切れないときは出さない))。

**チューナーは掴みません** (先に掴んで覚えに行くのをやめた理由と、覚え方の詳細は
[encode.md「ロゴの覚え方」](encode.md#ロゴの覚え方))。
