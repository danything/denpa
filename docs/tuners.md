# チューナー

使えるチューナーと、要るもの・B-CASカード・困ったときのことです。
入れ方は [install.md](install.md) (Mac は [install-mac.md](install-mac.md)、Windows は [install-windows.md](install-windows.md))、
エージェントの作りは [agent.md](agent.md)。

「Amazon で見る」は Amazon のアソシエイトのリンク (広告) です。ここから買っても値段は変わらず、紹介料が denpa の開発を続ける費用になります。どこで買っても動作は同じです。

## 設定の画面

設定の「受信」の「チューナー」に、1 台 1 行の表で出ます。いまの様子と設定を同じ行に並べてあり、
変えたらその場で保存します。

| 列             | 中身                                                                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| チューナー     | 名前と、その下にデバイス                                                                                                                                                                                 |
| 受信できる種別 | GR / BS / CS の切り替え。機材が受けられない種別は選べません。1 つは残します (使わないなら「使う」をオフにする)。ケーブルとスカパー！プレミアムは受けられる機材があるときだけ出ます ([下記](#px-mlt5-系)) |
| 状態           | 空き / 使用中 (選局しているチャンネル) / 無効と、使っている相手 (「録画: 番組名」「ライブ視聴」「番組表」「局ロゴ収集」「チャンネルスキャン」)。使用中なら受信の状態と C/N も                            |
| 使う           | 外すと選局に使いません (ほかのソフトに残すとき。[switch.md](switch.md))                                                                                                                                  |
| ⋯              | 名前・デバイス・LNB と削除                                                                                                                                                                               |

表の下の「追加」で 1 台足し、「自動検出に戻す」で書いた内容を消します。
**エージェントが動いている間に挿した機材は、挿した時点で有効なチューナーとして一覧の末尾に足します** (エージェントが USB の抜き差しを受け取る)。
チューナーを書いてあれば (「追加」や「使う」の切り替えで保存したあと)、抜いた機材は一覧から消さないので、挿し直すと名前や「使う」の設定がそのまま戻ります。要らなければ「使う」を外すか、「⋯」から削除します。
削除した機材は、挿したままなら戻りません。抜いて挿し直すと、また足します。
使用中のチューナーには、状態の列に受信の状態と C/N を出します ([下記](#信号レベル))。

## 信号レベル

**使用中のチューナーの受信の状態と C/N と強度を、測れる機材だけ出します。** エージェントが使用中のチューナーを 5 秒ごとに読み、
設定の「受信」の「チューナー」の状態の列に「同期しています・C/N: 25.3 dB」のように出します。
画面は開いている間、使用中のチューナーがあれば 5 秒ごとに読み直します。空いているチューナーは読みません (選局していないので測れない)。

| チューナー                           | 出るもの                                                      | dB の根拠                                                                 |
| ------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Linux DVB (PT3 など)                 | 受信の状態と C/N (dB)。ドライバが C/N を返さなければ C/N なし | ドライバが返す値 (`DTV_STAT_CNR`)。相対値で返すドライバは「C/N (生の値)」 |
| px4-userland・asicen-userland の機材 | 受信の状態と C/N (dB)。どちらも選局したときの値               | px4d・asicend の選局の応答 (`cnr_mdb`)                                    |
| CECH-ZD1 J                           | 受信の状態と C/N (dB)                                         | DiB8000 の仕様書の式                                                      |
| PX-MLT5 系                           | 受信の状態と C/N (dB)                                         | CXD2856ER の仕様書の式と表                                                |
| PIX-DT295                            | 受信の状態と C/N (dB)                                         | TC90522 系の換算式 (下記)                                                 |
| PX-S1UD (siano-userland)             | 出ない                                                        | siano-ts が C/N を返さない                                                |

px4d は受信の状態と C/N を選局の応答でしか返さないので、受信中も選局したときの値のままで、C/N に「(選局したとき)」と添えます。測り直すには選局し直すしかなく、それでは受信が途切れます。
DVB と px4-userland の C/N を画面まで通す流れは、実機では確かめていません (値を読む部分は単体テストで確かめた)。

**電波の強度は、dBm で測れる機材だけ C/N の前に出します** (「同期しています・強度: -35.0 dBm・C/N: 25.3 dB」)。
Linux DVB はドライバが `DTV_STAT_SIGNAL_STRENGTH` を dBm (`FE_SCALE_DECIBEL`) で返すときだけで、相対値 (0〜65535) で返すドライバでは出しません。
CECH-ZD1 J は DiB8000 の仕様書 8.2 の表から求めた値です (別の DiB8000 の機材で測った表なので目安)。
PX-MLT5 系は地上波とスカパー！プレミアムで出ます。チューナーの AGC の値から仕様書の式で求めた値です (衛星は dBm として扱えるかが分からないので出しません)。
px4-userland・asicen-userland・PIX-DT295・PX-S1UD では出ません。
強度に目安の値や判定は付けていません。dBm はドライバや表しだいで校正されておらず、機種どうしでもテレビの「アンテナレベル」とも比べられないためです。
強度も実機では確かめていません。

**PIX-DT295 の C/N は、TC90522 系の換算式で dB にした値です。** 復調のレジスタ (地上波は `0x8B` から 3 バイト、衛星は `0xBC` から 2 バイト) を読み、
PT1・PT2・PT3 (同じ系統の復調) の C/N の表示で使われてきた近似式に通します (`TunerSignal.Tc90522Db`)。復調が TC90522 系なのは推定です。
実機では T22・T25 が約 35 dB (生の値 2,130〜3,060)、BS13・BS15 が約 17 dB (9,880〜10,601)、CS22 が約 13 dB (14,446〜15,183) でした。
値が大きいほど雑音が多く、衛星は CS が BS より低く出ます。同じ地上波の局を CECH-ZD1 J で測ると約 22 dB で、機材をまたいだ dB はそろいません。同じチューナーで比べてください。

**チャンネルごとの受信品質は、設定の「チャンネル」の「測定」で測れます。** 空いているチューナーでそのチャンネルを 5 秒ほど受信し、行の下に次のものを出します。

- 誤り: 誤りの印 (transport_error_indicator) が立っていたパケットの割合。復調で直しきれなかったもの
- ドロップ: 連続性カウンタの飛びから数えた、欠けたパケットの割合
- 受信した速さ (Mbps) と、測っている間のチューナーの受信の状態と強度と C/N (出し方は上と同じ。測れる機材だけ)

測っている間は、設定の「チューナー」にも「受信品質の測定」として出ます。チューナーはスキャンと同じ順で取るので、録画・ライブ視聴・スキャン・「番組表をいますぐ集める」に使っているチューナーは取り上げません。
5 秒にしているのは、エージェントが C/N を読む間隔と同じにするためです (短いと C/N をまだ読んでいないことがある)。実機では確かめていません。

ブースターが要るかを見るときは、次のように使います。

- 同じチューナーで、分配器を入れる前とあと、配線を変える前とあとを、同じチャンネルで比べる。dB で出る機材なら、地上波 (64QAM) は約 20 dB、BS・CS (8PSK) は約 11 dB に近づくと映りが乱れやすくなる (一般に言われる受信に要る C/N。機材ごとに違う)
- 生の値と強度は、チャンネルどうし・チューナーの機種どうしでは比べられない。同じチャンネルの値がどちらへ動いたかだけを見る
- 「同期していません」が出たり消えたりするなら、C/N より先に配線と分配器を疑う
- C/N は受信できた信号の雑音の少なさで、電波の強さそのものではない。強すぎて歪んでいるときも C/N は下がるので、下がったからといってブースターが要るとは限らない

## CATV で受ける

CATV の回線には、地デジや衛星を放送の電波のまま送るパススルーと、ケーブル (ISDB-C) の局が入っています。

### パススルー

地デジには送り方が 2 つあります。どちらも地上波の局として入ります。

- **同一周波数パススルー**: UHF のチャンネルのまま送る。ふつうの「地上波」のスキャンで見つかります
- **周波数変換パススルー**: 地デジの電波 (変調は地デジと同じ OFDM) を CATV のチャンネル (C13〜C63) の周波数に移して送る。
  設定の「受信」の「チャンネル」で **「地上波 (パススルーも)」** を選んでスキャンします (UHF に加えて C13〜C63 も回すので、ふつうより長くかかります)。
  見つかった局は地上波の局として入り、チャンネルは `C25` のように出ます

BS・CS を衛星の周波数のまま流す「BS・CS パススルー」なら、ふつうの BS・CS のスキャンで受かります。

### ケーブル (ISDB-C)

**ケーブルの局 (種別 `CATV`) を受けられるのは PX-MLT5 系だけです** (エージェントが直に持つ IT930x の機材)。
BS・地上波をまとめ直して送るトランスモジュレーションと、ケーブルの局の自主放送が、この方式 (64QAM・256QAM) で送られます。
ほかのチューナーは QAM を選局できないので、ケーブルの局は受けられません。

1. 設定の「受信」の「チューナー」で、PX-MLT5 系の受信機の受信できる種別に「ケーブル」を選ぶ。受けられない機材では選べません。
   自動で見つけた受信機にも、初めは選んでありません
2. 「チャンネル」で「ケーブル」を選んでスキャンする。`QC13`〜`QC63` (C13〜C63)・`QU13`〜`QU62` (UHF)・`QV1`〜`QV12` (VHF) の
   113 チャンネルを総当たりし、TSMF (1 つの搬送波に複数の TS を束ねる方式) の搬送波は 2 つ目からの TS (`QC52:1`) も回します。
   「すべて」にも入るので、「すべて」は地上波 1 回ぶんほど長くなります
3. 見つかった局は種別「ケーブル」として入り、番組表とライブに「ケーブル」のタブが出ます (ケーブルの局が無ければ出ません)。
   地上波や BS を再送信しているチャンネルには、受信できるチャンネルの ch の下に「地上波の再送信」「BS の再送信」と出します。
   再送信の局も、アンテナで受けた同じ局とは別の局です

スクランブルは、B-CAS (CA_system_id 0x0005) の局と、スクランブルしていない局だけを復号できます。
B-CAS 以外の方式 (0x0006 など) だけでスクランブルされた局は、受信できるチャンネルの局名の後ろに「復号できません」と出し、
番組表とライブには出しません。スキャンで読んだ CA_system_id は、チャンネルの行の下の「スキャンで分かったこと」に出ます。
ケーブルの局のロゴは、まだ集めません。

PX-MLT5PE と J:COM の回線 (2026-11-10) で確かめました。18 の搬送波がロックし、どれも 64QAM で、BS と地上波の再送信が入っていました。
256QAM の搬送波と、TSMF で複数の TS を束ねた搬送波は確かめていません。4K の放送 (分割 TLV) は、エージェントが TLV のまま流しますが、denpa はまだ局として読みません ([下記](#ケーブルの-4k-を確かめる))。

## PX-W3U3 は asicen-userland で (試験的。上流のリリース待ち)

[asicen-userland](https://github.com/Khronos31/asicen-userland) は、px4-userland と同じ作者による
ASICEN 系 (PLEX PX-W3U3) のユーザー空間ドライバです。**まだリリースが無い** (0.1.0 の予定) ので、
いまは受け口だけ用意してあり、**イメージには何も入りません** (`agent/Dockerfile` の
`ASICEN_USERLAND_VERSION=0.0.0` が「まだ無い」の印)。配布物が無ければエージェントは機材を挙げません。
0.1.0 が出ると Renovate がバージョンを上げる PR を出し (自動では入れない)、その CI で配布物の名前や形式が
見込みどおりかを確かめます。

上流の現状 (2026-10): 実機で選局できるのは **受信機 0 の衛星と受信機 1 の T27 だけ**、使える受信機は**同時に 1 つ**、
1 台のホストで**1 筐体まで**。上流自身が「まだ 4 つの受信機として動くドライバではない」と言っています。

- **設定の `device` は `asicen:<USB ポート>:<受信機>`** (`asicen:1-2:1`)。USB の serial が無いので、
  内蔵ハブのポートで筐体を見分けます。**挿すポートを変えると別のチューナーになります**
- **LNB は出せません。** 設定に `15v` と書いてあっても 0V で選局し、設定の「受信」の「チューナー」にその旨を出します
- **ファームウェアは上流の配布アーカイブに入っているものをそのまま使います。再配布の権利は確かめられていません**
  ([licenses.md](licenses.md))。配布物に無ければ「ファームウェアがありません」と記録して、その機材は使いません
- 上流の第一弾は Linux x86_64 だけなので、arm64 のイメージ・Mac・Windows には入りません
- **実機には当てていません** (手元に PX-W3U3 が無い)。当てるなら `denpa-agent --tune asicen:1-2:1 T27`

エージェントの中でどう扱っているかは [agent.md](agent.md#asicen-userland-の作り)。

## Sony CECH-ZD1 J

PS3 の torne の地デジチューナー (USB `054c:04b2`)。**外のデーモンもファームウェアも要らず、エージェントが USB を直に持ちます**
(Linux は usbfs、Windows は WinUSB、Mac は IOKit。Windows はドライバを Zadig で WinUSB にします。[install-windows.md](install-windows.md)。
Windows と Mac は実機ではまだ確かめていません)。

- **設定の `device` は `zd1j:<USB のポート>`** (`zd1j:4-12.1`)。シリアルが無いので、ポートで見分けます。**設定に CECH-ZD1 J が 1 台だけなら、
  挿すポートを変えても付いていきます** (設定のポートに見当たらず、ほかに 1 台だけ挿さっていればそれを使い、記録に 1 行出す)。2 台以上なら、挿すポートを変えると別のチューナーになります。
  挿してあれば自動で見つけます (種別は地上波だけ)
- **地上波と CATV の C13〜C63** を受けます。C のうち ISDB-C (64QAM) の局はロックしません ([上記](#catv-で受ける))
- **内蔵の差し込み口の B-CAS も使えます** (CCID ではなく、ブリッジの UART をエージェントが直に読み書きする)。ほかのリーダーと同じく
  1 枚を全部のチューナーで使い回すので、CECH-ZD1 J のカードで PT3 の録画を復号することもあります。
  試す順は USB のリーダー → px4d → PX-MLT5 系 → asicend → CECH-ZD1 J → PIX-DT295
- **前面の LED は使っている間ずっと赤**で、使い終わると緑に戻ります (点滅はしません)
- **一度ほかのドライバ (PS3 など) が動かした CECH-ZD1 J は扱えません。** 「CECH-ZD1 J を抜いて挿し直してください」と出たら、そのとおりに
- 開いたあとは温めておきます。**エージェントが動いている間は開いたまま** (PT3 などと同じ) で、2 回目からの選局は速く済みます。
  一度ロックしたチャンネルは、その値を `zd1j-locks.json` (tuners.json の隣) に記録しておき、次から (エージェントを起動し直しても) 探索を飛ばします。
  このファイルは消してかまいません (次の選局で探索からやり直して、また記録します)。開いたままの間は使っていなくてもチューナーが動いたままなので、
  そのぶん電気を使います (LED は緑)

実機で確かめるときは、そのボードを使っているエージェントを止めて `denpa-agent --tune zd1j:4-12.1 27` (開く・ロック・最初の TS・2 回目の選局に
かかったミリ秒と、ロックまでの内訳 (段ごとの時間と待ち)・I2C の回数・C/N・電波の強度を出す。`--seconds N` で読む長さも。`--decode` はそのボードの内蔵の差し込み口だけで復号し、ロックから最初の復号できたパケットまでのミリ秒も出す。
`--repeat N` はチャンネルを N 回回して、ロックの成否と時間の最小・中央・最大を出す) と
`denpa-agent --card zd1j:4-12.1` (そのボードの内蔵の差し込み口だけを開き、ATR とカードの番号と、かかったミリ秒を出す)。
どちらもそのボードのほかには触りません (ほかのカードリーダーやチューナーは開かない)。
引数を打ち間違えたときはサーバとして立ち上がらず、使い方を出して終わります。

エージェントの中でどう扱っているかは [agent.md](agent.md#cech-zd1-j-の作り)。

## PIXELA PIX-DT295 (試験的)

PIXELA の USB チューナー (USB `06b8:103b`。地上波・BS・CS。B-CAS の差し込み口つき)。**外のデーモンもファームウェアも要らず、エージェントが機材のレジスタを USB で直に書いて動かします**
(Linux は usbfs、Windows は WinUSB、Mac は IOKit。Windows はドライバを Zadig で WinUSB にします。[install-windows.md](install-windows.md))。
同梱するものもありません。

- **設定の `device` は `dt295:<USB のポート>`** (`dt295:4-12.1`)。ポートで見分けるので、挿すポートを変えると別のチューナーになります。
  挿してあれば自動で見つけます (種別は地上波・BS・CS)
- **機材の中では復号しません。** スクランブルのままの TS を受けて、エージェントの B25 で復号します (ほかのチューナーと同じ)。
  差し込み口のカードはエージェントが直に読み書きし (CECH-ZD1 J と同じ)、ほかのチューナーの復号にも使います (カードリーダーの並びのいちばん後ろ)
- **開けるのは、USB でつないだ直後の機材だけです。** 閉じるときは書いたものを逆順に戻すので、エージェントの再起動ではそのまま開き直せます。
  途中で止まった機材やほかのファームウェアが動いた機材は、Linux ではエージェントがポートの電源を 1 回入れ直してから開きます
  (ハブの側にあるポートの `disable` に 1 を書いてから 0 を書く。機材の `authorized` を書き換えるだけでは戻りません)。
  コンテナの中 (`/sys` が読み取り専用) や Windows・Mac では、機材を 1 回挿し直してください
- **機材は、エージェントが動いている間は開いたままです。** チューナーの利用者が全員いなくなっても閉じず、設定でチューナーを無効にしたとき・チューナーの定義が変わったとき・
  エージェントを止めるときに手放します。次の利用者は選局と受信の確認だけで済み (全部の初期化には 150 ms ほどかかる)、代わりに使っていない間も USB を握ったままで、
  チップと復調とカードの電源が入ったままです。ほかのソフトから使うときは、設定でチューナーを無効にしてください。
  時間で閉じる仕組みは入れていません (閉じるたびに初期化し直すと、録画の開始が 150 ms 遅れ、USB の抜き差しの扱いも増えるため)

エージェントの中でどう扱っているか (機材に置くプログラム・書いてよいレジスタ・カードの準備・選局し直しの手順・仕様書) は [agent.md](agent.md#pix-dt295-の作り)。

**いまの限り:**

- **Linux の実機で、地上波 (T25)・BS15・CS22 の選局と TS の取り込み、差し込み口の B-CAS カードの読み取りを確かめました。**
  起動直後の機材から (3 回ずつの範囲)、設定は 146〜148 ms、選局から最初の TS までは T25 が 727〜789 ms (受信の確認が 411〜472 ms。電波の事情で決まる)、
  BS15 と CS22 が 395〜403 ms でした。6 秒の TS は T25 が約 30 Mbps、BS15 が約 24 Mbps、CS22 が約 39 Mbps で、同期バイト 100%・transport_error_indicator 0・連続性の飛び 0 でした。
  カードは電源を入れてから ATR まで約 0.5 秒、B-CAS の読み出しまで約 1.2 秒です。
  カードの送受信を機材のプログラムに行わせる形 (ホストが 1 バイトずつ読み書きする形の代わり) は、BS15 と地上波 (T22) の復号で確かめました。CS18 ではまだ確かめていません
  以前の方式 (mAgicVISION のファームウェアを入れる方式) と比べると、起動から最初の TS までが約 3 秒短くなりました
- **Windows・Mac と、CATV の C13〜C63 は、この方式では実機で確かめていません。** 以前の方式では Windows と Mac (M4) で確かめられていましたが、機材へ書く内容が違います。
  選局の周波数の式は地上波と同じです
- ライブ視聴・録画・復号を通した確認は、以前の方式のものです。この方式でも TS は同じ形 (放送のまま) で流れます
- 受信中にほかのチャンネルへ切り替えるときは、いったん取り込みを止めてから選局し直します。地上波と衛星を切り替える動作は、実機では確かめていません
- TS を出す受信部は、地上波か衛星の 1 つずつです。同時に受けられるのは 1 チャンネルだけです
- 衛星の名前の `/152` (番組番号) は使いません。中継器の TS を全部受けます
- LNB への給電は扱いません
- **C/N は、復調のレジスタの値を TC90522 系の換算式で dB にしたものです** ([信号レベル](#信号レベル))。レジスタは、復調が TC90522 系という推定から選んだ候補で、アンテナの信号を変えて値が動くかは確かめていません。
  候補が違っていたときは、`--dt295-probe --demod-dump` が出す復調のレジスタ 0x00〜0xFF の読み値を、アンテナの信号を変えて 2 回取って比べると、動くレジスタを探せます

**同じドライバーのほかの機材:** 公式ドライバー (`pxmb86m0x_usb`) の INF には、DT295 のほかに次の機材が並んでいます。
挿してあれば見つけますが、**未確認なので使いません** (記録に理由を出し、設定に書いても開かずに断ります)。
INF ではどれも DT295 と設定が違い (DT295 W・DT420・DT410 は DT295 に無い基板の設定が付き、PIX-DTxxx は SPI モード)、
その違いの扱いが分かっていないためです。どれも実機では試していません。

| 機材                   | USB         |
| ---------------------- | ----------- |
| PIX-DT295 (使う)       | `06b8:103b` |
| PIX-DT295 W            | `06b8:103c` |
| PIX-DT420              | `06b8:1038` |
| PIX-DT410              | `06b8:1039` |
| PIX-DTxxx (SPI モード) | `04c5:202f` |

実機で確かめるときは、エージェントを止めるか、設定の「チューナー」で DT295 のチューナーと差し込み口のカードリーダーの「使う」を両方外してから、次のどれかを流します。

- `denpa-agent --card dt295:4-12.1`: 差し込み口のカードだけを開き、ATR とカードの番号を出す
- `denpa-agent --tune dt295:4-12.1 T27 --decode` (`BS15:16625`・`CS22:29024` も): そのボードのカードだけで復号する
- `denpa-agent --dt295-probe --channel T27` (`BS15`・`BS15:16625`・`CS2` も): 機材を設定して選局し、決めた秒数 (`--seconds N`。既定 5) だけ受けて、
  設定・選局・最初の TS までの時間、制御転送の数、CPU 時間、1 秒ごとの受信の状態と C/N (生の値と dB)、カードの準備の時間、TS の統計を出す。
  最後に、設定の各段・固定の待ち・選局・受信の確認の周回・取り込み・最初の TS の時間を、制御転送と I2C の転送の数つきの表で出す。
  平均の Mbps は、最初に読めた時刻から最後に読めた時刻までで割る。足せるものは次のとおり
  - `--port <USB のポート>`: 2 台以上挿してあるときに指す
  - `--output <ファイル>`: TS をファイルに書く
  - `--switch T27,BS15,…`: 最初のチャンネルを測ったあと、機材を開いたまま続けて選局し直す時間を出す (種別が同じか替わるかも出す)
  - `--lock-test N`: 同じチャンネルを N 回選局して、成功の割合と、最初の TS まで・受信の確認までの時間を出す (`--alt` の別のチャンネルに合わせて離れてから測る。`--alt none` で離れず、同じチャンネルの選局し直しを測る。`--reopen` で毎回開き直す)
  - `--demod-dump`: 受信中の復調のレジスタ 0x00〜0xFF の読み値を出す
  - `--demod-trace`: 地上波を選局してから受信を確認するまで、T 復調のレジスタ 0x00〜0xFF を約 10 ms ごとに読み、途中で値が変わったものを時刻つきで出す (読むだけ。ロックの前後で動くレジスタから、復調が検出した結果を返すものを探すため)
  - `--replug`: 先にポートの電源を入れ直す (Linux)
  - `--trace`: 機材への読み書きと設定の読み戻しを 1 行ずつ、標準エラー出力に出す

Linux では、終わりにスレッドごとの CPU 時間も出します (`dt295-ts` が USB の読み、`dt295-kick` が機材への要求、`dt295-probe-ts` が probe の統計)。

## PX-MLT5 系

**PX-MLT5U (USB `0511:084e`)・PX-MLT5PE (`0511:024e`)・e-Better DTV02A-5TS-P (`0511:924e`) は、いつもエージェントが USB で直に持ちます** ([#1578](https://github.com/danything/denpa/issues/1578))。
px4d (px4-userland) は、この 3 機種を挙げず、起動もしません。
地上波と衛星 (BS・CS) とケーブル (ISDB-C) とスカパー！プレミアムサービス光 (J.83B) を選局でき、内蔵カードリーダーで B-CAS を読めます。
Linux の PX-MLT5PE の実機で確かめました ([下記](#実機で確かめたこと))。Windows (WinUSB) と Mac (IOKit) でも同じ `it930x:` で持ちますが、実機では確かめていません。Windows はドライバを WinUSB にします ([install-windows.md](install-windows.md))。

- **挿してあれば、1 台を 5 つのチューナーとして自動で見つけます。** `device` は `it930x:<USB のポート>:<受信機>` (`it930x:4-12.1:0`。受信機は 0〜4)、
  名前は「PLEX PX-MLT5PE 4-12.1 #0」のようになり、受信できる種別はどの受信機も GR・BS・CS・ケーブル・スカパー！プレミアムです。挿すポートを変えると別のチューナーになります
- **設定に `px4:` で書いてある PX-MLT5 系のチューナーは、選局できません** (前のバージョンまでは px4d が持っていました)。設定は自動では書き換えません。
  チューナーの行と記録に、理由と書き換える先の `device` が出ます。次のどれかで直します
  - 「⋯」の「デバイス」を `it930x:<USB のポート>:<受信機>` に書き換える。受信機の番号は `px4:` のときと同じで、名前・LNB・「使う」の設定はそのまま残ります
  - チューナーを書いていなかった (自動検出のまま使っていた) なら、何もしなくても `it930x:` で見つけ直します
  - 「自動検出に戻す」を押す (書いた内容が全部消えます)。USB の機材は、`px4:` のチューナーを削除してから挿し直しても足されます
- 受信機の番号は px4_drv と同じ並びです。機材は最初の選局で開いて電源を入れ、エージェントが動いている間は開いたままです。
  受信機を全部設定から外すと、30 秒待ってから電源を切って閉じます (短い間に電源を入り切りしないため。その間にまた使えば開いたまま)。エージェントを止めると、すぐ閉じます
- **LNB の給電は 15V だけです** (設定の LNB を「15V」にする)。5 つの受信機で 1 つの給電を共用し、衛星を選局している受信機が 1 つでも「15V」なら入れ、どれも使わなくなったら切ります。
  11V を選ぶと衛星の選局を断ります。給電の電圧と、過電流の検出は実機で確かめていません
- **内蔵カードリーダーも、挿さっている機材のぶんをエージェントが開きます** (「PLEX PX-MLT5PE 4-12.1 Card Reader」のような名前)。
  試す順は USB のリーダーと px4d の内蔵リーダーのあと、asicend・CECH-ZD1 J・PIX-DT295 の前です (px4d が持っていた頃と同じ順)。「使う」を外すと開きません。
  px4d の内蔵リーダーとは名前が違うので、前に「使う」を外していたら、もう一度外します。
  カードは受信機と同じ電源なので、カードを使っている間は受信機を全部閉じても電源を切らず、カードだけを使うときも機材を開いて電源を入れます。
  カードの速さは ATR のとおり (B-CAS は 19200) で、ブリッジが扱えるのは 9600 と 19200 だけです
- 衛星の強度は画面に出しません。仕様書の式は dB の値で、dBm として扱えるかが分からないためです。`--tune` の出力にだけ dB で出します
- **スカパー！プレミアムサービス光 (J.83B) は、選局とチャンネルスキャンまでです。** 種別は `SKY` (画面では「スカパー！プレミアム」)、チャンネルは `H01`〜`H105` (93.25 MHz から 6.5 MHz おき) で、
  どの受信機でも受けられます。
  - **TS はスクランブルされたまま流します。** スカパー！プレミアムのカードはまだ扱わず、B-CAS のカードにも問い合わせません
  - 設定の「チューナー」の「受信できる種別」に「スカパー！プレミアム」が出るのは、`it930x:` の受信機があるときだけです。ほかの機材では選べません。
    自動で見つけた受信機は、地上波・BS・CS を選んだ状態で並びます。スカパー！プレミアムを受けるときは、設定のチューナーで種別に足します。
    選んだ受信機が 1 つでもあれば、「チャンネル」のスキャンの選び方にも出ます。`H01`〜`H105` を 1 つずつ選局し、NIT と SDT が読めたチャンネルの局を入れます (「すべて」にも入ります)
  - **スカパー！プレミアムの局は、設定の「受信できるチャンネル」にだけ出ます。** スクランブルを復号できないので、番組表・ライブ・ロゴは取得せず、ライブの一覧にも出しません。
    局の一覧の API はほかの局と同じく返しますが、ライブの API は選局せずに `409` で断ります ([api.md](api.md#ライブ-get-apiservicesidlive))
  - NIT と SDT の送り方 (スキャンで局が見つかるか) は実機で確かめていません。スキャンの記録 (「SKY: 105ch 中 …」の行と、局が見つかったチャンネルの行) も [#1578](https://github.com/danything/denpa/issues/1578) に貼ってください。
    局が見つかったチャンネルの行には、カード無しで分かること (CA_system_id と番組表が来ているか) も出ます ([下記](#スカパープレミアムでカード無しで分かること))
  - H11・H12・H26〜H28・H44 は、地域によってずらした周波数 (+1 MHz・+4 MHz・+2.2 MHz) で送られます。両方を試し、次はロックしたほうから試します
  - 電源を入れてから初めて J.83B か ISDB-C を選局したときに、全部の受信機に待機中の RF 入力の整合を保つ設定を立てます (受信機の待機と動作の切り替えで、隣の受信機の 256QAM に誤りが出た記録への対処)。
    いま選局する受信機は設定を立てるだけです。ほかの受信機のうち、使っていないものは初期化し直して待機させ、動作中のものは止めるときに設定を書きます
  - J.83B の TS は約 40 Mbps になりえます (256QAM と見た推定)。5 つの受信機は USB 2.0 の 1 本で TS を返すので、5 つとも J.83B だと約 200 Mbps です。
    USB 2.0 で実際に出る速さには収まる見込みですが、余裕は大きくありません。5 つを同時に使って欠けが出たら、そのときの `--tune` の出力も貼ってください
  - J.83B のあとに同じ受信機で衛星を受けられるかは確かめていません (J.83B のスリープで、復調器のレジスタの一部が J.83B の値のまま残るため)

### 実機で確かめたこと

**PX-MLT5PE (Linux) の実機で、受信機 0〜4 の選局と、内蔵カードリーダーの B-CAS の読み取りを確かめました** (2026-11)。

- 地上波 (T27・T22) は、5 台の受信機とも連続性の飛びが 0 個、C/N が 21〜23 dB でした。復号しながら 90 秒流しても飛びは 0 個でした。内蔵カードリーダーで復号できました
- 衛星は CS02・CS08・CS24 と BS15・BS21・BS23 がロックしました。BS の C/N は 8〜9 dB でした。分波器を使っていない環境で、同じ機材の px4d も同じ BS のチャンネルを受けられませんでした
- 内蔵カードリーダーは、`--card` で 5 回続けて ATR とカードの番号を読めました。カードの速さは 19200 です
- 機材を開き直しても、px4d が使った直後でも選局できました
- LNB の給電、スカパー！プレミアムサービス光 (J.83B)、PX-MLT5U と DTV02A-5TS-P は確かめていません
- Windows (WinUSB) と Mac (IOKit) では、どの機種も確かめていません

機材をお持ちなら、次のコマンドの出力を [#1578](https://github.com/danything/denpa/issues/1578) に貼ってください (機種と OS も添えて)。
エージェントを止めてから流します。エージェントが動いていると機材を開いているので、開けずに止まります。

- `denpa-agent --tune it930x:<USB のポート>:<受信機> T27`: 地上波を選局して受ける。同期までの時間、ロックまでの時間、TS の量と連続性の飛び、C/N と強度を出す。
  `T27,T21` のように並べると、開いたまま選局し直します。USB のポートは `--it930x-probe` の 1 行目に出ます。
  初めて初期化した受信機は「初期化の前のチューナーの 62」も出します。前のプロセスで ISDB-C か J.83B を選局したあとに `10` なら、閉じたときにチューナーの電源が切れていなかったと読みます (推定)。
  ロックしたのに TS が 1 バイトも届かなかったときは、復調器の TS の出力のレジスタ 4 つと、ブリッジの TS の経路の状態 (残りのバッファ・入力ごとの溢れ・EP 0x84 のストールなど) と EP 0x84 から読んだバイトの数を出し、
  ブリッジの TS のバッファを捨ててからもう一度受けて、TS が届いたかを出します
- `denpa-agent --tune it930x:<USB のポート>:0+it930x:<USB のポート>:1+it930x:<USB のポート>:2 QC14,QU49`: `+` で並べた受信機を同時に選局する。
  受信機ごとにスレッドを立ててそろって始め、どの受信機もチャンネルの並びを順に選局します (常駐のエージェントが受信機を並べてスキャンするときと同じ形)。
  出力は受信機ごとにまとめ、1 つの受信機のときと同じ行に、そろって始めてからの時間を添えます。最後に、受信機とチャンネルごとのロックと Mbps を並べます。
  1 つでは受かるのに並べると受からないときは、この出力を貼ってください
- `denpa-agent --tune it930x:<USB のポート>:0+it930x:<USB のポート>:1+…+it930x:<USB のポート>:4 T27,T22 --steps 2,3,5`: TS を流す受信機を段階を追って増やす。
  `+` で並べた順に、チャンネルの並びを先頭から割り当てて (足りなければ先頭から繰り返す)、受信機を 1 つずつ足します。足すたびに 1 秒、段階ごとに `--seconds` (既定 3 秒) の間、流している受信機ごとの Mbps を出します。
  開いた直後、段階ごとの選局のあと、受けたあとに、ブリッジの TS の経路の状態と EP 0x84 から読んだバイトの数を出します。
  どれかの受信機に TS が 1 バイトも届かなくなったら、その先の受信機は足さずに止めます。5 つを同時に流して TS が止まった機材を、電源を入れ直したあと少しずつ確かめるためのものです
- `denpa-agent --tune it930x:<USB のポート>:<受信機> BS15:16625 --lnb 15v`: 衛星を TSID で選局して受ける。地上波と同じものに加えて、中継器の TMCC にある TSID (相対 TS 0〜7) を出します。
  `T27,BS15:16625,T21` のように並べると、同じ受信機で地上波と衛星を切り替えます。`--decode` を付けると、その機材の内蔵カードリーダーだけで復号します
- `denpa-agent --tune it930x:<USB のポート>:<受信機> H40`: スカパー！プレミアムサービス光 (J.83B) を選局して受ける。地上波と同じものに加えて、受けた周波数、変調 (256QAM など)、PER を出します。
  PER の読み方が J.83B で正しいかは確かめていないので、目安です。`--decode` を付けても復号しません。どのチャンネルで受けられたか、受けられなかったチャンネルも添えてください。
  CA_system_id や番組表が来ているかも出します ([下記](#スカパープレミアムでカード無しで分かること))
- `denpa-agent --tune it930x:<USB のポート>:<受信機> QC51`: ケーブルテレビのトランスモジュレーション方式 (ISDB-C。64QAM・256QAM) を選局して受ける。画面から使う手順は[上記](#ケーブル-isdb-c)です。
  チャンネルは `QC13`〜`QC63` (CATV の帯域の C13〜C63)、`QU13`〜`QU62` (UHF)、`QV1`〜`QV12` (VHF) です。1 つの搬送波に複数の TS が入っているとき (TSMF) は、
  `QC52:1` のように `:k` を付けて、有効な TS の k 本目 (0 から数える。付けなければ 0 本目) を受けます。
  受けた周波数、TSMF のヘッダーの有無、ヘッダーにある TS の一覧 (相対 TS 番号・TSID・ONID・有効かどうか・スロットの数) と選んだ TS、ヘッダーのパケットの 16 進、
  変調、C/N、PER、出力した TS の PAT の TSID を出します。
  受け終えたあとは、CRC が合わないヘッダーの数、前のヘッダーの割り当てで受けたフレームの数、1 フレームの選んだ TS のスロットの数、選んだ TS のスロットに来たパケットと出力したパケットの数、
  選ぶ前とあとの連続性の飛びと transport_error_indicator が 1 のパケットの数も出します。選ぶ前に飛んでいれば搬送波から受けた時点で欠けていて、選んだあとだけで飛んでいれば選ぶ処理で欠けています。
  1 つの PID だけが飛んだか所は、その PID も出します。選局できなかったときも、ロックしなかったのか、ロックしたが TS が届かなかったのか、指定した TS が無かったのかを出します。
  PX-MLT5PE の実機と J:COM の回線 (2026-11) で、QC13〜QC63・QU13〜QU62・QV1〜QV12 を順に選局し、18 波がロックしました。どれも 64QAM で、C/N は 21〜26 dB、連続性の飛びは 0 個でした。
  TSMF のヘッダーがある波は 8 つで、ヘッダーから読んだ TSID は、出力した TS の PAT の TSID とどれも同じでした。有効な TS はどの波も 1 本だったので、複数の TS から選ぶ動きと 256QAM は確かめていません。
  局の限定受信は、B-CAS (CA_system_id 0x0005) のものと、B-CAS 以外 (0x0006) のものがありました。PER などの値が正しいかは、ほかの受信機と比べていません。
  ほかの事業者の回線で試したら、受けられたチャンネルと受けられなかったチャンネル、事業者を添えてください
- `denpa-agent --card it930x:<USB のポート>`: 内蔵カードリーダーだけを開き、ATR とかかった時間、カードの番号を出す。
  カードの有無とリセットにはブリッジの GPIOH6・GPIOH14 を使います (ITE の SDK の評価基板の配線)。PX-MLT5PE では、この GPIO でカードを読めました。PX-MLT5U と DTV02A-5TS-P が同じ配線かは確かめていないので、「カードが挿さっていません」や「ATR を返しません」と出たときも貼ってください

- `denpa-agent --it930x-probe`: ブリッジのチップのバージョン、ストラップ、EEPROM の設定の写し (`0x4994` から 256 バイト) を読み、ファームウェアを読み込んで起動し、そのバージョンを出す。
  前のファームウェアが動いていれば、REBOOT してから読み込みます。復調器とチューナーには触りません。終わりに REBOOT して、挿した直後と同じ (ファームウェアが動いていない) 状態に戻し、REBOOT で USB がつなぎ直されたかも出します
  - `--port <USB のポート>`: 2 台以上挿してあるときに指す
  - `--ts <秒>`: 起動したあと TS の経路 (ブリッジの入力 0〜4 と EP 0x84) を設定し、入力を開けて EP 0x84 をその秒数だけ読み、入力ごとのパケットの数と捨てた数を出す。
    復調器を動かさないので、ふつうはどの数も 0 です。設定がエラーにならないことと、読みが止まらずに秒数どおりに終わることを確かめます
  - `--trace`: ブリッジへ送ったコマンドと応答を 1 行ずつ、時間つきで標準エラー出力に出す。うまくいかなかったときは、これも貼ってください
- `denpa-agent --it930x-cycle <USB のポート> <回数> [--no-wait]`: 機材を開いて電源を入れ、すぐ電源を切って閉じるのを、続けて決めた回数 (1〜100) 繰り返し、1 回ごとにかかった時間を出す。
  受信機の初期化と選局はしません。常駐のエージェントは最後に使い終えてから 30 秒は電源を切りませんが、これは待たずに切ります。
  `--no-wait` を付けると、電源を切ったあとの 100 ms も待ちません (この待ちを入れる前の動き)。
  続けて入り切りしたあとに TS が止まった記録を再現するためのもので、終えたら `--tune` で TS が届くかを確かめます

ファームウェアは px4d に渡しているものと同じ、同梱のものです ([tuner-px4.md](tuner-px4.md#ファームウェア))。エージェントの中でどう扱っているかは [agent.md](agent.md#it930x-の機材を直に持つ作り)。

### スカパー！プレミアムでカード無しで分かること

**スカパー！プレミアムのカードに対応する前に、カードが無くても TS から分かることを集めています** ([#1578](https://github.com/danything/denpa/issues/1578))。
復号はせず、スカパー！プレミアムのカードにも B-CAS のカードにも ECM を渡しません。読むのはスクランブルされていない PSI/SI (ARIB STD-B10) だけです。

- PMT (局ごと) と CAT の CA 記述子にある CA_system_id と、ECM・EMM の PID を出します。B-CAS (`0x0005`) 以外の値には「B-CAS 以外」と付けます
- 番組表 (EIT) とロゴ (CDT) のセクションが来ているか、スクランブルされているかを出します。スクランブルされているかは、TS パケットの transport_scrambling_control で見ます。
  番組表は、ほかの TS の局のぶん (EIT の other) が来ているかも出します
- エージェントの出力には、network_id・transport_stream_id・局の数と、ECM・EMM の PID に来たセクションの table_id ごとの数と長さ、末尾の CRC が合うかも出します (EMM を扱えるかを決めるため。CRC で捨てずに全部数える)

出す場所は 3 つです。

- チャンネルスキャン: SKY の局が見つかったチャンネルの記録の行 (「H40: 3 局 CA_system_id …」) と、設定の「受信できるチャンネル」のそのチャンネルの下の「スキャンで分かったこと」。
  局が揃ってからも、番組表が来ているかが分かるまで、読み始めから 10 秒までは読み続けます。
  「受信できるチャンネル」に出すものは denpa の中にだけ持つので、denpa を再起動すると消えます (もう一度スキャンすると出ます)
- `denpa-agent --tune it930x:<USB のポート>:<受信機> H40`: 受けた TS で数えます (エージェントを止めてから流す)
- `denpa-agent --decode-file <in.ts>`: 録れた TS のファイルで数えます。書き出す先を省くと復号せず、カードも開きません

**実機ではまだ確かめていません。** 受けられたチャンネルについて、上のどれかの出力を [#1578](https://github.com/danything/denpa/issues/1578) に貼ってください。
CA 記述子の行 (「局 0x…」「CAT」)、「ECM・EMM」の行、「番組表 (EIT)」と「ロゴ (CDT)」の行が入っていれば足ります。光か衛星かも添えてください。

**番組表がスクランブルされていない (EIT が読める) と分かっても、SKY の局の番組表はまだ取り込みません。** 取り込むかは、報告を見てから決めます。ロゴ (CDT) も同じです。

### ケーブルの 4K を確かめる

**ケーブルで再送信している BS4K (MMT/TLV) は、エージェントが TLV パケットの並びに組み立てて、形式を変えずに流します** ([agent.md](agent.md#it930x-の機材を直に持つ作り))。
denpa はまだ TLV を読まないので、スキャンしても局は入りません。受けられるか、カード無しで何が分かるかは、エージェントを止めてから `--tune` で確かめます。

```sh
denpa-agent --tune it930x:<USB のポート>:<受信機> QC26 --seconds 10
denpa-agent --tune it930x:<USB のポート>:<受信機> QC26 --seconds 10 --ecm-test
```

- TSMF のヘッダーの一覧で選んだ TS が「分割 TLV」なら、「TSMF: 選んだ TS は分割 TLV です。TLV に組み立てて出力します」と出ます
- 受け終えたあとに、組み立ての数を出します。受けた単位、開始の単位 (pointer のある単位)、組み立てた TLV パケット、捨てたバイト、合わせ直した回数 (中身の食い違いとフレームの欠け)、TLV パケットの種類ごとの数です。
  最初の開始の単位より前のバイトは捨てるので、捨てたバイトは欠けが無くても 0 になるとは限りません
- カード無しで分かること (`TlvObservation`) を出します。MMTP の packet_id ごとのスクランブルの印 (なし・偶数・奇数) の数、MPT のアクセス制御記述子の CA_system_id と ECM の packet_id、
  TLV-NIT・MH-SDT・MH-EIT が来ていて CRC が合うか (局名と番組名を 1 つずつ) です
- `--ecm-test` は、MPT が指す packet_id に来た ECM のセクションを 1 つ、B-CAS の ECM と同じ切り方 (先頭 8 バイトと末尾の CRC を除いた中身) でカードに渡し、返り値を出します。
  カードは、その機材の内蔵カードリーダーです (`--card-url` があればそちら)。鍵を返したかで、B-CAS のカードで復号できる見込みがあるかが分かります。MMT の復号はしません
- `--decode` を付けても、TLV は復号しません (B-CAS のカードに MMT の ECM を渡さないため。`--ecm-test` だけが渡します)

PX-MLT5PE と J:COM の回線で受けた QC26 (2026-11-11、先頭の 4 MB) は、TSMF の有効な TS が 1 本で、分割 TLV でした。MPT のアクセス制御記述子の CA_system_id は B-CAS と同じ `0x0005`、ECM の packet_id は `0xFFF1` で、
映像と音声はどれも奇数の鍵でスクランブルされ、信号 (MPT・ECM・MH-EIT・MH-SDT・TLV-NIT) はスクランブルされていませんでした。カードが ECM に鍵を返すかは、まだ確かめていません。

## カードリーダー

**USB のリーダーは、Linux なら usbfs を直接扱います** (`/dev/bus/usb` が見えていれば動く)。Mac と Windows は OS の PC/SC 越しです
([install-mac.md](install-mac.md#カードが読めないとき))。Linux では、ホストや別のコンテナで pcscd が動いていると使えません (「別のプロセスがカードリーダーを
使用中です」と出る)。TPDU 単位のリーダー (Gemalto PC Twin など) には T=1 の枠組みを
こちらで組み、APDU 単位のリーダーにはそのまま送ります。カードの無いリーダーや INT に
応答しないカードは飛ばし、USB のリーダーを内蔵リーダーより先に試します (`CardLinks.cs`)。

Amazon で見る (広告): [Gemalto PC Twin](https://www.amazon.co.jp/dp/B001NEIRH0?tag=doa08-22)、[IDBridge CT30](https://www.amazon.co.jp/dp/B003XF2JJY?tag=doa08-22) (Mac で読めないときは [install-mac.md](install-mac.md#カードが読めないとき))

動いているエージェントがカードと通信できているかは、設定の「受信」の「チューナー」にある「カードリーダー」の表で分かります
(denpa がエージェントの `/denpa/card` を呼び、INT を 1 回通す)。エージェントを止めた状態なら `denpa-agent --card` でも確かめられます (リーダーを並べ、
ATR とカードの番号を出す)。
チューナーを使わずに B25 だけ確かめるなら `denpa-agent --decode-file <in.ts> <out.ts>` (`/denpa/decode`
と同じことをする。スクランブルされたまま録れてしまったものを救うのにも使える)。
`<out.ts>` を省くと復号せず、CA_system_id と番組表が来ているかだけを出します ([上記](#スカパープレミアムでカード無しで分かること))。

## B-CASカードとデスクランブル

スクランブルは**エージェント自身が復号します** (`B25.cs`)。カードが読めないときは
スクランブルされたまま流し、理由を状態に出します。理由を出さずに素通しすると「録画は成功してサイズも
それらしいのに中身が全部スクランブル」という分かりにくい壊れ方になるためです。
選局を畳むときに、スクランブルされたまま流したパケットの数と理由を記録にも残します。

- **録画は止めません。** 電波は二度と来ないので、スクランブルされたままでも
  録ります。denpa がエンコードの前に見て、スクランブルされたままならエージェントに
  復号させます (`src/lib/server/scramble.ts` → `/denpa/decode`)
- やり取りするのはパスだけです。denpa とエージェントは元の TS の同じ置き場 (`RAW_DIR`。コンテナでは `/media/raw`) を
  見ているので、読み書きはエージェントが直接やり、数十 GB を HTTP で往復させません
  (`charts/denpa` が一緒に出すときは、置き場が RWO なので**両方の Pod が同じノードにあることが前提**です)
- 元の TS を残す設定のときは、残るのは復号した TS だけです。スクランブルされたままのものは、
  あとから復号できる保証がありません
- 状態は設定の「受信」の「チューナー」にある「カードリーダー」の表に出ます。
  リーダーごとに 1 行で、カードの番号・状態 (使用中・予備・カードなし・エラー・無効)・
  そのカードで復号しているチューナー・「使う」のスイッチを並べます。`CARD_URL` で鍵を受け取っているときは、
  表の代わりに配る側の URL を出します
- **使うカードは 1 枚です。** INT に応答した最初のリーダーのカードを全部のチューナーで
  使い回します (カードに問い合わせるのは ECM の中身が変わったときだけなので、1 枚で足ります)。残りの
  リーダーは予備で、使っているカードが応答しなくなると、繋ぎ直すときに探し直して
  使います。チューナーごとにカードは割り当てません
- **「使う」を外したリーダーは開きません。** カードの候補に入らず、表を出すときも開かずに「無効」の行にします。
  使っている最中のリーダーを外すと、エージェントはそのリーダーを手放して次のリーダーで繋ぎ直します。
  PIX-DT295・CECH-ZD1 J の差し込み口は、チューナーも無効にしてあれば USB を閉じます (ほかのソフトや `--dt295-probe` から使えるようになる)。PX-MLT5 系の内蔵カードリーダーは、受信機も機材を使っていなければ、30 秒待ってから USB を閉じます (電源を短い間に入り切りしないため)。
  カードを読めている最後の 1 台を外すと復号できなくなるので、「オフを確定」をもう 1 回押したときだけ外します。
  外したリーダーは、tuners.json の隣の `cards.json` に名前で残ります (USB のリーダーの名前にはポートが入るので、挿すポートを変えると別のリーダーになる)

### 直らないとき

まず設定の「受信」の「チューナー」にある「カードリーダー」の表で、見えているリーダーと、カードに INT が通るかを見ます
(中身はエージェントの `/denpa/card`)。使っているリーダーは開き直さずに INT を通し、ほかのリーダーは開いて確かめてから閉じます。

```json
{
  "ok": true,
  "message": "",
  "source": "local",
  "readers": [
    {
      "name": "Gemplus USB SmartCard Reader (usb 4-11)",
      "card": true,
      "ids": ["0000012345678901"],
      "active": true,
      "disabled": false,
      "tuners": ["PT3-T1", "PT3-S1"]
    },
    {
      "name": "px4-userland 0960 Internal Card Reader",
      "card": false,
      "ids": [],
      "active": false,
      "disabled": false,
      "tuners": []
    }
  ]
}
```

`message` は問題があるときだけ入ります (カードがどこにも無い、など)。確かめられなかった
リーダーは `error` に理由が入ります。`CARD_URL` のときは `source: "remote"` で、
`remote` (配る側の URL)・`ids`・`tuners` が付き、`readers` は空です。
鍵を配る範囲と、断られたときの文は [鍵を配るのは LAN の中だけ](agent.md#鍵を配るのは-lan-の中だけ) にあります。

エージェントは組んだ denpa (クライアント証明書) にしか応答しないので、curl などで `/denpa/card` を直に呼ぶことはできません
([agent.md](agent.md#denpa-とは-tls-で組む))。

- `readers` が空なら、`/dev/bus/usb` がコンテナに見えていません
- `card: false` で `error` が無ければ、そのリーダーにカードが挿さっていません
- 「別のプロセスがカードリーダーを使用中です」と出たら、ホストで pcscd が動いています。
  止めるか、リーダーをそちらから外します (`denpa-agent --card` を動いているエージェントの
  横で起動したときも、エージェントが使っているのでこう出る)
- 応答が無い (タイムアウト) なら、リーダーが固まっています。エージェントが USB のポートを 1 回リセットして
  立て直します。それでも戻らなければ USB レベルで入れ直します (`4-11` は `lsusb` と `/sys/bus/usb/devices` から引く)

```sh
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/unbind
sleep 2
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/bind
```

エージェントは起動し直さなくて構いません。次の ECM で探し直します。

実際に復号できているかは `--tune ... --decode` で見ます (復号したあとが 0% 近くなら正常)。
衛星で LNB に電源を送るなら `--lnb 15v` を足します。動いているエージェントは一度使ったチューナーと、起動したときに開いた
カードリーダーを開いたままにしていて、横から開くと断られるので、録画の無いときに止めてから同じイメージで流します
(compose の例。Kubernetes なら `tuner-agent` を 0 台にしてから、同じイメージを同じデバイスで 1 回だけ起動する。
Mac の止め方は [install-mac.md](install-mac.md#cech-zd1-j-の差し込み口が読めないとき))。

```sh
docker compose stop tuner-agent
docker compose run --rm tuner-agent --tune /dev/dvb/adapter1/frontend0 T27 --decode
docker compose start tuner-agent
```

それでも直らなければ、設定の「その他」→「ログ」の「Issue にする」で報告してください。サーバとエージェントのログと環境を、
