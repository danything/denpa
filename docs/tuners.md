# チューナー

使えるチューナーと、要るもの・B-CASカード・困ったときのことです。
入れ方は [install.md](install.md) (Mac は [install-mac.md](install-mac.md)、Windows は [install-windows.md](install-windows.md)、Android は [install-android.md](install-android.md))、
エージェントの作りは [agent.md](agent.md)。

「Amazon で見る」は Amazon のアソシエイトのリンク (広告) です。ここから買っても値段は変わらず、紹介料が denpa の開発を続ける費用になります。どこで買っても動作は同じです。

## 設定の画面

設定の「受信」の「チューナー」に、1 台 1 行の表で出ます。いまの様子と設定を同じ行に並べてあり、
変えたらその場で保存します。エージェントを 2 台以上つないでいても、表に出して書き換えるのは並びの先頭のエージェントのチューナーだけです
(選局はどのエージェントのチューナーも使います。[agent.md](agent.md#エージェントが何台もあるとき))。

| 列             | 中身                                                                                                                                                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| チューナー     | 名前と、その下にデバイス                                                                                                                                                                                                |
| 受信できる種別 | GR / BS / CS の切り替え。機材が受けられない種別は選べません。1 つは残します (使わないなら「使う」をオフにする)。ケーブルとスカパー！プレミアムは受けられる機材があるときだけ出ます ([tuner-it930x.md](tuner-it930x.md)) |
| 状態           | 空き / 使用中 (選局しているチャンネル) / 無効と、使っている相手 (「録画: 番組名」「ライブ視聴」「番組表」「局ロゴ収集」「チャンネルスキャン」)。使用中なら受信の状態と C/N も                                           |
| 使う           | 外すと選局に使いません (ほかのソフトに残すとき。[switch.md](switch.md))                                                                                                                                                 |
| ⋯              | 名前・デバイス・LNB と削除                                                                                                                                                                                              |

表の下の「追加」で 1 台足し、「自動検出に戻す」で書いた内容を消します。
**エージェントが動いている間に挿した機材は、挿した時点で有効なチューナーとして一覧の末尾に足します** (エージェントが USB の抜き差しを受け取る)。
チューナーを書いてあれば (「追加」や「使う」の切り替えで保存したあと)、抜いた機材は一覧から消さないので、挿し直すと名前や「使う」の設定がそのまま戻ります。要らなければ「使う」を外すか、「⋯」から削除します。
削除した機材は、挿したままなら戻りません。抜いて挿し直すと、また足します。
使用中のチューナーには、状態の列に受信の状態と C/N を出します ([下記](#信号レベル))。

## 信号レベル

**使用中のチューナーの受信の状態と C/N と強度を、測れる機材だけ出します。** エージェントが使用中のチューナーを 5 秒ごとに読み、
設定の「受信」の「チューナー」の状態の列に「同期しています・C/N: 25.3 dB」のように出します。
画面は開いている間、使用中のチューナーがあれば 5 秒ごとに読み直します。空いているチューナーは読みません (選局していないので測れない)。

| チューナー                          | 出るもの                                                      | dB の根拠                                                                 |
| ----------------------------------- | ------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Linux DVB (PT3 など)                | 受信の状態と C/N (dB)。ドライバが C/N を返さなければ C/N なし | ドライバが返す値 (`DTV_STAT_CNR`)。相対値で返すドライバは「C/N (生の値)」 |
| asicen-userland の機材              | 受信の状態だけ (C/N は出ない)                                 | asicend の選局の応答                                                      |
| CECH-ZD1 J                          | 受信の状態と C/N (dB)                                         | DiB8000 の仕様書の式                                                      |
| IT930x の機材                       | 受信の状態と C/N (dB)                                         | CXD2856ER の仕様書の式と表。TC90522 の機種は PIX-DT295 と同じ換算式       |
| PIX-DT295                           | 受信の状態と C/N (dB)                                         | TC90522 系の換算式 (下記)                                                 |
| PX-S1UD (エージェントが USB を直に) | 受信の状態と C/N (dB) と強度 (dBm)。実機で確かめていない      | 機材の統計の応答にある SNR と受信電力                                     |

DVB の C/N を画面まで通す流れは、実機では確かめていません (値を読む部分は単体テストで確かめた)。

**電波の強度は、dBm で測れる機材だけ C/N の前に出します** (「同期しています・強度: -35.0 dBm・C/N: 25.3 dB」)。
Linux DVB はドライバが `DTV_STAT_SIGNAL_STRENGTH` を dBm (`FE_SCALE_DECIBEL`) で返すときだけで、相対値 (0〜65535) で返すドライバでは出しません。
CECH-ZD1 J は DiB8000 の仕様書 8.2 の表から求めた値です (別の DiB8000 の機材で測った表なので目安)。
IT930x の機材のうち CXD2856ER の機種 (PX-MLT5 系など) は、地上波とスカパー！プレミアムで出ます。チューナーの AGC の値から仕様書の式で求めた値です (衛星は dBm として扱えるかが分からないので出しません)。
PX-S1UD (エージェントが USB を直に持つとき) は、機材の統計の応答にある受信電力をそのまま出します。
asicen-userland・PIX-DT295 と、IT930x の機材のうち TC90522 の機種 (PX-Q3・PX-W3 系など) では出ません。
強度に目安の値や判定は付けていません。dBm はドライバや表しだいで校正されておらず、機種どうしでもテレビの「アンテナレベル」とも比べられないためです。
強度も実機では確かめていません。

**PIX-DT295 の C/N は、TC90522 系の換算式で dB にした値です。** 復調のレジスタ (地上波は `0x8B` から 3 バイト、衛星は `0xBC` から 2 バイト) を読み、
PT1・PT2・PT3 (同じ系統の復調) の C/N の表示で使われてきた近似式に通します (`TunerSignal.Tc90522Db`)。復調が TC90522 系なのは推定です。
実機では T22・T25 が約 35 dB (生の値 2,130〜3,060)、BS13・BS15 が約 17 dB (9,880〜10,601)、CS22 が約 13 dB (14,446〜15,183) でした。
値が大きいほど雑音が多く、衛星は CS が BS より低く出ます。同じ地上波の局を CECH-ZD1 J で測ると約 22 dB で、機材をまたいだ dB はそろいません。同じチューナーで比べてください。

**チャンネルごとの受信品質は、設定の「チャンネル」の「測定」で測れます。** 空いているチューナーでそのチャンネルを 5 秒ほど受信し、行の下に次のものを出します。

- 誤り: 誤りの印 (transport_error_indicator) が立っていたパケットの割合。復調で直しきれなかったもの
- ドロップ: 連続性カウンタの飛びから数えた、欠けたパケットの割合
- 受信した速さ (Mbps) と、測っている間のチューナーの受信の状態と強度と C/N (出し方は上と同じ。測れる機材だけ)

測っている間は、設定の「チューナー」にも「受信品質の測定」として出ます。チューナーはスキャンと同じ順で取るので、録画・ライブ視聴・スキャン・「番組表をいますぐ集める」に使っているチューナーは取り上げません。
5 秒にしているのは、エージェントが C/N を読む間隔と同じにするためです (短いと C/N をまだ読んでいないことがある)。実機では確かめていません。

ブースターが要るかを見るときは、次のように使います。

- 同じチューナーで、分配器を入れる前とあと、配線を変える前とあとを、同じチャンネルで比べる。dB で出る機材なら、地上波 (64QAM) は約 20 dB、BS・CS (8PSK) は約 11 dB に近づくと映りが乱れやすくなる (一般に言われる受信に要る C/N。機材ごとに違う)
- 生の値と強度は、チャンネルどうし・チューナーの機種どうしでは比べられない。同じチャンネルの値がどちらへ動いたかだけを見る
- 「同期していません」が出たり消えたりするなら、C/N より先に配線と分配器を疑う
- C/N は受信できた信号の雑音の少なさで、電波の強さそのものではない。強すぎて歪んでいるときも C/N は下がるので、下がったからといってブースターが要るとは限らない

### 同期しなかったとき

**同期しなかったチャンネルは、同じ組 (受けられる種別がまったく同じ) の空いている別のチューナーで、もう 1 回選局します。**
2 台とも同期しなければ「adapter1・adapter2: 同期しませんでした (電波が来ていないか、その周波数に放送がありません)」のように、試したチューナーを並べて出します。
同期しなかったチューナーは、そのチャンネルでは 1 時間ほかのチューナーより後に使います。チャンネルスキャンとデバッグ用の名指しは選局し直しません。
決まりと理由は [agent.md](agent.md#同期しなかったら別のチューナーで選局し直す) にあります。

## CATV で受ける

CATV の回線には、地デジや衛星を放送の電波のまま送るパススルーと、ケーブル (ISDB-C) の局が入っています。

### パススルー

地デジには送り方が 2 つあります。どちらも地上波の局として入ります。

- **同一周波数パススルー**: UHF のチャンネルのまま送る。ふつうの「地上波」のスキャンで見つかります
- **周波数変換パススルー**: 地デジの電波 (変調は地デジと同じ OFDM) を CATV のチャンネル (C13〜C63) の周波数に移して送る。
  設定の「受信」の「チャンネル」で **「地上波 (パススルーも)」** を選んでスキャンします (UHF に加えて C13〜C63 も回すので、ふつうより長くかかります)。
  見つかった局は地上波の局として入り、チャンネルは `C25` のように出ます

BS・CS を衛星の周波数のまま流す「BS・CS パススルー」なら、ふつうの BS・CS のスキャンで受かります。

### ケーブル (ISDB-C)

**ケーブルの局 (種別 `CATV`) を受けられるのは、IT930x の機材のうち PX-MLT5 系・PX-MLT8PE・DTV02A-4TS-P と、DVB-C に対応した Linux DVB の機材です** ([tuner-it930x.md](tuner-it930x.md)・[tuner-pt3.md](tuner-pt3.md#ケーブル-isdb-c-を受ける-実機で確かめていない))。
BS・地上波をまとめ直して送るトランスモジュレーションと、ケーブルの局の自主放送が、この方式 (64QAM・256QAM) で送られます。
Linux DVB の機材は 64QAM だけを選局します。DVB-C の機材で受けられるかは、実機で確かめていません。
ほかのチューナーは QAM を選局できないので、ケーブルの局は受けられません。

1. 設定の「受信」の「チューナー」で、その機材の受信機の受信できる種別に「ケーブル」を選ぶ。受けられない機材では選べません。
   自動で見つけた受信機にも、初めは選んでありません。DVB-C しか受けられない Linux DVB の機材は、「ケーブル」を選んで「使う」をオフにして並ぶので、「使う」をオンにします
2. 「チャンネル」で「ケーブル」を選んでスキャンする。`QC13`〜`QC63` (C13〜C63)・`QU13`〜`QU62` (UHF)・`QV1`〜`QV12` (VHF) の
   113 チャンネルを総当たりし、TSMF (1 つの搬送波に複数の TS を束ねる方式) の搬送波は 2 つ目からの TS (`QC52:1`) も回します。
   「すべて」にも入るので、「すべて」は地上波 1 回ぶんほど長くなります
3. 見つかった局は種別「ケーブル」として入り、番組表とライブに「ケーブル」のタブが出ます (ケーブルの局が無ければ出ません)。
   地上波や BS を再送信しているチャンネルには、受信できるチャンネルの ch の下に「地上波の再送信」「BS の再送信」と出します。
   再送信の局も、アンテナで受けた同じ局とは別の局です

スクランブルは、B-CAS (CA_system_id 0x0005) の局と、スクランブルしていない局だけを復号できます。
B-CAS 以外の方式 (0x0006 など) だけでスクランブルされた局は、受信できるチャンネルの局名の後ろに「復号できません」と出し、
ライブと録画には使いません。番組表 (EIT) がスクランブルされずに来ている局は、番組表に「観られません」の列で出します。スキャンで読んだ CA_system_id は、チャンネルの行の下の「スキャンで分かったこと」に出ます。
ケーブルの局のロゴは、まだ集めません。

PX-MLT5PE と J:COM の回線 (2026-11-10) で確かめました。18 の搬送波がロックし、どれも 64QAM で、BS と地上波の再送信が入っていました。
256QAM の搬送波と、TSMF で複数の TS を束ねた搬送波は確かめていません。4K の放送 (分割 TLV) は、エージェントが TLV のまま流し、denpa がスキャンで局として入れます。番組表は「観られません」の列で出ます。ACAS のスクランブルにはまだ対応していないので、スクランブルされた局はライブで観られず、録画もできません。スクランブルしていない 4K の局はライブで観られ、録画もできます ([stream.md](stream.md#4k-の局のライブ)・[tuner-it930x.md](tuner-it930x.md#ケーブルの-4k-を確かめる))。

## Siano の Rio 系の USB チューナー

**エージェントは、PX-S1UD (`3275:0080`) のほかに USB `187f:0600` の機材も、同じ ISDB-T の機材として USB を直に持って動かします。**
`187f:0600` は Siano の Rio の標準の ID で、挿してあれば PX-S1UD と同じ手順で見つけ、`Siano RIO <ポート>` の名前で並べます。

- **どちらも実機では確かめていません。** エージェントの実装は仕様書 (denpa-spec の `siano/spec.md`) だけから書いたものです。`187f:0600` は、受信の記録がある資料もありません。どの製品がこの USB ID を持つかも確かめていません
- `187f:0302` は対象にしていません。公開の資料で扱いが食い違うので、仕様書が対象から外しています。挿しても並びません
- 入れ方と設定は PX-S1UD と同じです ([tuner-px-s1ud.md](tuner-px-s1ud.md))。Linux では、smsusb を blacklist したときだけエージェントが USB を持ちます。
  blacklist していなければカーネルのドライバが使い、DVB として見つかります

## PX-W3U3 など (asicen-userland。試験的)

[asicen-userland](https://github.com/Khronos31/asicen-userland) は、[px4-userland](https://github.com/Khronos31/px4-userland) と同じ作者による
ASICEN 系 (PLEX の USB チューナー) のユーザー空間ドライバです。
**試験的です。実機では確かめていません** (手元に ASICEN 系の機材が無い)。確かめたのは、上流の模擬のデーモン (`asicend-mock`) との通信までです。

エージェントのイメージ (Linux の amd64 と arm64) に、上流のプレリリース **v1.0.0-beta** (2026-11-05) の配布物を入れています (`agent/Dockerfile` の `ASICEN_USERLAND_VERSION`)。
Android のアプリにも、同じバージョンの上流の Android 版を入れています ([下記](#android))。
エージェントは筐体ごとに `asicend` を起動し、制御ソケットで UDTV 1.0 を送って選局し、TS を受け取ります。

**通信の形式の一部は、上流の契約の文書に書かれていません。** 書かれていない部分 (操作の番号、選局や TS のレコードのバイト配置) は、
配布物の公式のクライアント (`asicen-ts`・`asicenctl`) と模擬のデーモンの通信を記録して起こしました。上流のソースは読んでいません。
そのため、次の決まりで動かしています ([agent.md](agent.md#asicen-userland-の作り))。

- **バージョンを固定します。** asicend が asicen-userland 1.0.0 (UDTV 1.0) と応答しなければ、エージェントは何も送らずに断り、理由を記録に出力します。
  上流がバージョンを上げると動かなくなることがあります。上げるときは、通信を記録し直して実装を合わせます (Renovate は PR を出すだけで、自動では入れない)
- 意味を確かめていない欄には、公式のクライアントが送っていた値をそのまま送ります
- 応答の長さや値が記録と違うときは、読み進めずに失敗にします

### 使えるもの・使えないもの

- **設定の `device` は `asicen:<USB ポート>:<受信機>`** (`asicen:1-2:1`)。USB の serial が無いので、ポートで筐体を見分けます。
  USB 機能が 2 つの機種 (PX-W3U2・PX-W3U3・PX-W3U3 V2) は内蔵ハブのポート、1 つの機種 (PX-S3U・PX-S3U2) はその機能のポートが筐体の名前です。
  **挿すポートを変えると別のチューナーになります**
- **機材は `asicend --list-json` で見つけます** (Android は違う。[下記](#android))。使うのは、上流が見分ける 5 機種 (下の表) で、状態が `ready` の筐体だけです。
  使わない筐体は、理由と USB のポートを記録に出力します
- **局を替えるたびに、受信機を返して取り直します。** 公式のクライアントが、受信機を取ったまま選局し直す並びを送らないためです。
  ほかのチューナーより局の切り替えとスキャンに時間がかかるかもしれません (実機では測っていない)
- **LNB の給電は、設定に `15v` と書いた PX-W3U2・PX-W3U3・PX-W3U3 V2 の衛星の受信機だけ。** 既定は給電しません。
  エージェントは、その筐体の asicend を `--allow-lnb-power` 付きで起動し、衛星を選局する前に `asicenctl lnb-on` と同じ要求を送ります。
  給電が要るチューナーを全部閉じると `lnb-off` と同じ要求を送ります。上流の README によると、給電には AC アダプタが要ります。端子の電圧は上流も実測していません
- **PX-S3U・PX-S3U2 は LNB に給電できません。** 上流が、ソフトウェアから給電する経路を未解明としています。設定に `15v` と書いてあっても給電せずに選局し、
  設定の「受信」の「チューナー」にその旨を出します。アンテナへの給電はほかの機器からにします
- **内蔵カードリーダーは使えません。** カードの操作は形式が契約の文書に無く、模擬のデーモンもカードに対応していないので、通信を記録できませんでした。
  B-CAS カードは USB のカードリーダーで使います ([下記](#カードリーダー))
- **C/N は出ません。** 受信の状態 (同期しているか) だけ出ます
- **ファームウェアは上流の配布アーカイブに入っているものをそのまま使い、エージェントのイメージに同梱しています** ([下記](#ファームウェア))。
  挿した直後のファームウェア待ちの機材には、asicend が起動するときに流し込みます
- Mac と Windows の入れ方 (`install.sh`・`install.ps1`) は asicen-userland を取りません

### Android

Android のアプリ ([install-android.md](install-android.md)) は、上流の Android 版 (`android-aarch64`。Termux 用) の `asicend`・`asicenctl` を組み直さずに APK に入れています。
使えるもの・使えないものは Linux と同じで、次の所が違います。

- **機材を開くのはアプリです。** エージェントは、アプリから受け取った USB の fd の複製を `asicend --fd` に継がせて起動します。`asicend --list-json` は使わず (端末の機材を libusb で並べられない)、
  アプリから受け取った機材の USB ID から筐体を組みます。受信機は機種の表 (下記) のもので、asicend が起動したあとは `asicenctl list` のものに替わります
- **ファームウェア待ちの機材は、2 回の許可で動きます。** エージェントは `asicend --fd … --firmware …` でファームウェアを流し込ませ、asicend は流し込んだら終わります
  (`--fd` の asicend は、つながり直した機材を追えない。上流の README)。つながり直した機材は別の USB ID なので、Android がもう一度許可を求めます。
  許可すると、エージェントがその機材で asicend を起動します
- **USB 機能が 2 つの機種 (PX-W3U2・PX-W3U3・PX-W3U3 V2) は、端末のカーネルが 5.3 以上のときだけ使えます。** それより古いカーネルではポートの名前を `001-004` の形で作るので、
  2 つの機能が同じ内蔵ハブにあると分からず、記録に理由を出して使いません。USB 機能が 1 つの機種は、古いカーネルでも使えます (挿し直すと名前が変わる)
- asicend のソケットは `<アプリの置き場>/r/asicen-userland/v1/<筐体>/control.sock` です。`sun_path` の 108 バイトに収まらないパスになるときは、asicend を起動せずに理由を記録に出します

### 確かめたこと・確かめていないこと

模擬のデーモンで確かめたこと (CI の `agent-asicen-mock` と手元のコンテナ):

- 5 機種それぞれの模擬で、機種と受信機の問い合わせ、地上波と衛星 (TSID とスロット) の選局、TS の受け取り、選局し直し、受信機の返却
- LNB の給電のオン/オフ (給電できる 3 機種)。給電を許可せずに起動した asicend が断ること
- 同じ受信機を 2 つの接続で取ると、あとのほうが断られること
- Android と同じ起動の仕方 (`libasicend.so` の名前、`--fd` で fd を継がせる) で、模擬の asicend が起動して選局できること。USB 機能の fd が `.1` から順に継がれていること

Android のエミュレータ (x86_64。CI の `agent-android`) で確かめたこと:

- エージェントがアプリの子プロセスで、APK の `asicend --version` を起動できること (SELinux に実行を断られない)
- ファームウェア待ちの USB ID でファイルの fd を送ると、エージェントがその fd を `asicend --fd` に継がせ、asicend が受け取ること
  (usbfs でないので、asicend は USB の読み書きの失敗で終わる)。このとき SELinux は、asicend が `/dev/bus/usb` の一覧を読むことと、
  普通のファイルへの usbfs の ioctl を断る (API 29・35・36 で確かめた。一覧を読めなくても asicend は fd を使うところまで進む)

確かめていないこと:

- **実機での動作のすべて。** 同期・TS の中身・ファームウェアの流し込み・LNB の端子の電圧・機材を抜いたときの動き
- Android の実機で、usbfs の fd を継いだ asicend が機材を使えるか (SELinux が ioctl を許すか)。ファームウェアを流し込んだあとに、2 回目の許可で動き出すか
- 同期しないチャンネルの応答 (模擬は必ず同期する)。時間切れのエラーの番号は推定です
- 機材をつないだときの `asicend --list-json` の出力 (文書の例から読み方を書いた)。ファームウェア待ちの機材がどう出るかも分かりません
- 上流が未確認としていること: PX-W3U3 V2 で 4 つを同時に受けられるか、PX-S3U2 で地上波と衛星を同時に受けられるか、PX-S3U・PX-S3U2・PX-W3U3 V2 の実機での受信

### 上流が見分ける機種

**v1.0.0-beta は 5 機種を見分けます。** 下の表は、上流の README (v1.0.0-beta) と `asicend --models`、模擬のデーモンの `asicenctl list` の出力から読み取った内容です。denpa ではどの機種も実機で確かめていません。

| 機種       | USB         | USB 機能 | 受信機                            | LNB の給電                                            | 上流の実機での確認                                                   |
| ---------- | ----------- | -------- | --------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------- |
| PX-W3U3    | `0b06:0005` | 2 つ     | 4 つ (0・2 が衛星、1・3 が地上波) | できる (設定に `15v`)                                 | 短い時間の受信を確かめた。リリースの認定は終わっていない (README)    |
| PX-W3U2    | `0b06:0004` | 2 つ     | PX-W3U3 と同じ                    | できる (設定に `15v`)                                 | T27 を 10 秒受信し、誤りは 0 個だった (v1.0.0-beta のリリースノート) |
| PX-W3U3 V2 | `0b06:0006` | 2 つ     | PX-W3U3 と同じ                    | できる (設定に `15v`)                                 | していない。4 つを同時に受けられるかも未確認                         |
| PX-S3U2    | `0b06:0003` | 1 つ     | 2 つ (0 が衛星、1 が地上波)       | できない (上流がソフトウェアから給電する経路を未解明) | していない。地上波と衛星を同時に受けられるかも未確認                 |
| PX-S3U     | `0b06:0001` | 1 つ     | 1 つ (地上波と衛星のどちらか一方) | できない (上流がソフトウェアから給電する経路を未解明) | していない                                                           |

挿した直後はファームウェア待ち (`1738:5211` か `1738:5216`) で現れ、ファームウェアを流し込むと上の USB ID で出直します。
エージェントは、ファームウェア待ちの機材を見つけると、asicend を 1 度起動して流し込ませてから一覧を取ります。

LNB の給電と同時に受けられる数は、上流が未確認・未解明としている範囲を denpa でも同じ限界として扱います。

### ファームウェア

**ファームウェア (`asicen-loader.bin`) は、再配布の許諾を確かめられていません。上流と同じ判断で、エージェントのイメージに同梱しています。**
権利を持つ人から申し出があれば外します。分かっている事実は次のとおりです ([licenses.md](licenses.md#asicen-のファームウェアを同梱している判断) にも同じ内容があります)。

- ファームウェアは、PLEX の Windows 用ドライバ (`Loader.sys`) から上流が取り出した 16,384 バイトのイメージです。
  上流の配布アーカイブに入っているものをそのまま使います。イメージを組むときに、SHA-256 が `5db39facda140bdcb3a238dad10da5aac752a1ba3aaf17e2239f8d79a0ad6a2a` であることを確かめます (`agent/Dockerfile` の `ASICEN_FIRMWARE_SHA256`)。
  Android のアプリにも同じものを入れ、APK を組むときに同じ値を確かめます (`.github/asicen-android.sh`)
- チップの会社 ASICEN (昇亮科技股份有限公司 / Asicen Technology、台湾) は解散し、2017-02-23 に清算が完結したと登記されています。
  台湾の会社情報サイト (<https://www.twincn.com/item.aspx?no=80342850>) の記載で、経済部の公式の登記では確かめていません
- PLEX は 2026-11 の時点で、公式サイトの「旧製品ドライバ」のページ (<https://plex-net.co.jp/old-driver/>) で PX-W3U3・PX-W3U3 V2・PX-S3U2 の Windows 用ドライバを配っています。
  そのページにも、上流が調べた公式のパッケージにも、再配布を認める文はありません
- PLEX が以前配っていた Linux 用ドライバのモジュールには `license=GPL` の表示があり、同じファームウェアが埋め込まれています。
  それだけではファームウェア自体のライセンスは決まりません (上流の `NOTICES.md` の整理)
- 上流が添える通知 (`VENDOR-FIRMWARE-NOTICE.txt` など) は、配布物のままイメージに置いてあります (`/opt/asicen-userland/licenses/`)。
  Android のアプリは APK の `assets/licenses/asicen-userland/` に入れています

エージェントの中でどう扱っているかは [agent.md](agent.md#asicen-userland-の作り)。

## Sony CECH-ZD1 J

PS3 の torne の地デジチューナー (USB `054c:04b2`)。**外のデーモンもファームウェアも要らず、エージェントが USB を直に持ちます**
(Linux は usbfs、Windows は WinUSB、Mac は IOKit。Windows はドライバを WinUSB に替えます。[install-windows.md](install-windows.md#チューナーのドライバを-winusb-に替える)。
Windows と Mac は実機ではまだ確かめていません)。

- **設定の `device` は `zd1j:<USB のポート>`** (`zd1j:4-12.1`)。シリアルが無いので、ポートで見分けます。**設定に CECH-ZD1 J が 1 台だけなら、
  挿すポートを変えても付いていきます** (設定のポートに見当たらず、ほかに 1 台だけ挿さっていればそれを使い、記録に 1 行出す)。2 台以上なら、挿すポートを変えると別のチューナーになります。
  挿してあれば自動で見つけます (種別は地上波だけ)
- **地上波と CATV の C13〜C63** を受けます。C のうち ISDB-C (64QAM) の局はロックしません ([上記](#catv-で受ける))
- **内蔵の差し込み口の B-CAS も使えます** (CCID ではなく、ブリッジの UART をエージェントが直に読み書きする)。ほかのリーダーと同じく
  1 枚を全部のチューナーで使い回すので、CECH-ZD1 J のカードで PT3 の録画を復号することもあります。
  試す順は USB のリーダー → IT930x の機材 → CECH-ZD1 J → PIX-DT295
- **前面の LED は使っている間ずっと赤**で、使い終わると緑に戻ります (点滅はしません)
- **一度ほかのドライバ (PS3 など) が動かした CECH-ZD1 J は扱えません。** 「CECH-ZD1 J を抜いて挿し直してください」と出たら、そのとおりに
- 開いたあとは温めておきます。**エージェントが動いている間は開いたまま** (PT3 などと同じ) で、2 回目からの選局は速く済みます。
  一度ロックしたチャンネルは、その値を `zd1j-locks.json` (tuners.json の隣) に記録しておき、次から (エージェントを起動し直しても) 探索を飛ばします。
  このファイルは消してかまいません (次の選局で探索からやり直して、また記録します)。開いたままの間は使っていなくてもチューナーが動いたままなので、
  そのぶん電気を使います (LED は緑)

実機で確かめるときは、そのボードを使っているエージェントを止めて `denpa-agent --tune zd1j:4-12.1 27` (開く・ロック・最初の TS・2 回目の選局に
かかったミリ秒と、ロックまでの内訳 (段ごとの時間と待ち)・I2C の回数・C/N・電波の強度を出す。`--seconds N` で読む長さも。`--decode` はそのボードの内蔵の差し込み口だけで復号し、ロックから最初の復号できたパケットまでのミリ秒も出す。
`--repeat N` はチャンネルを N 回回して、ロックの成否と時間の最小・中央・最大を出す) と
`denpa-agent --card zd1j:4-12.1` (そのボードの内蔵の差し込み口だけを開き、ATR とカードの番号と、かかったミリ秒を出す)。
どちらもそのボードのほかには触りません (ほかのカードリーダーやチューナーは開かない)。
引数を打ち間違えたときはサーバとして立ち上がらず、使い方を出して終わります。

エージェントの中でどう扱っているかは [agent.md](agent.md#cech-zd1-j-の作り)。

## PIXELA PIX-DT295

PIXELA の USB チューナー (USB `06b8:103b`。地上波・BS・CS。B-CAS の差し込み口つき)。**外のデーモンもファームウェアも要らず、エージェントが機材のレジスタを USB で直に書いて動かします**
(Linux は usbfs、Windows は WinUSB、Mac は IOKit。Windows はドライバを WinUSB に替えます。[install-windows.md](install-windows.md#チューナーのドライバを-winusb-に替える))。
同梱するものもありません。

- **設定の `device` は `dt295:<USB のポート>`** (`dt295:4-12.1`)。ポートで見分けるので、挿すポートを変えると別のチューナーになります。
  挿してあれば自動で見つけます (種別は地上波・BS・CS)
- **機材の中では復号しません。** スクランブルのままの TS を受けて、エージェントの B25 で復号します (ほかのチューナーと同じ)。
  差し込み口のカードはエージェントが直に読み書きし (CECH-ZD1 J と同じ)、ほかのチューナーの復号にも使います (カードリーダーの並びのいちばん後ろ)
- **開けるのは、USB でつないだ直後の機材だけです。** 閉じるときは書いたものを逆順に戻すので、エージェントの再起動ではそのまま開き直せます。
  途中で止まった機材やほかのファームウェアが動いた機材は、Linux ではエージェントがポートの電源を 1 回入れ直してから開きます
  (ハブの側にあるポートの `disable` に 1 を書いてから 0 を書く。機材の `authorized` を書き換えるだけでは戻りません)。
  コンテナの中 (`/sys` が読み取り専用) や Windows・Mac では、機材を 1 回挿し直してください
- **機材は、エージェントが動いている間は開いたままです。** チューナーの利用者が全員いなくなっても閉じず、設定でチューナーを無効にしたとき・チューナーの定義が変わったとき・
  エージェントを止めるときに手放します。次の利用者は選局と受信の確認だけで済み (全部の初期化には 150 ms ほどかかる)、代わりに使っていない間も USB を握ったままで、
  チップと復調とカードの電源が入ったままです。ほかのソフトから使うときは、設定でチューナーを無効にしてください。
  時間で閉じる仕組みは入れていません (閉じるたびに初期化し直すと、録画の開始が 150 ms 遅れ、USB の抜き差しの扱いも増えるため)

エージェントの中でどう扱っているか (機材に置くプログラム・書いてよいレジスタ・カードの準備・選局し直しの手順・仕様書) は [agent.md](agent.md#pix-dt295-の作り)。

**いまの限り:**

- **Linux の実機で、地上波 (T25)・BS15・CS22 の選局と TS の取り込み、差し込み口の B-CAS カードの読み取りを確かめました。**
  起動直後の機材から (3 回ずつの範囲)、設定は 146〜148 ms、選局から最初の TS までは T25 が 727〜789 ms (受信の確認が 411〜472 ms。電波の事情で決まる)、
  BS15 と CS22 が 395〜403 ms でした。6 秒の TS は T25 が約 30 Mbps、BS15 が約 24 Mbps、CS22 が約 39 Mbps で、同期バイト 100%・transport_error_indicator 0・連続性の飛び 0 でした。
  カードは電源を入れてから ATR まで約 0.5 秒、B-CAS の読み出しまで約 1.2 秒です。
  カードの送受信を機材のプログラムに行わせる形 (ホストが 1 バイトずつ読み書きする形の代わり) は、BS15 と地上波 (T22) の復号で確かめました。CS18 ではまだ確かめていません
  以前の方式 (mAgicVISION のファームウェアを入れる方式) と比べると、起動から最初の TS までが約 3 秒短くなりました
- **Windows・Mac と、CATV の C13〜C63 は、この方式では実機で確かめていません。** 以前の方式では Windows と Mac (M4) で確かめられていましたが、機材へ書く内容が違います。
  選局の周波数の式は地上波と同じです
- ライブ視聴・録画・復号を通した確認は、以前の方式のものです。この方式でも TS は同じ形 (放送のまま) で流れます
- 受信中にほかのチャンネルへ切り替えるときは、いったん取り込みを止めてから選局し直します。地上波と衛星を切り替える動作は、実機では確かめていません
- TS を出す受信部は、地上波か衛星の 1 つずつです。同時に受けられるのは 1 チャンネルだけです
- 衛星の名前の `/152` (番組番号) は使いません。中継器の TS を全部受けます
- LNB への給電は扱いません
- **C/N は、復調のレジスタの値を TC90522 系の換算式で dB にしたものです** ([信号レベル](#信号レベル))。レジスタは、復調が TC90522 系という推定から選んだ候補で、アンテナの信号を変えて値が動くかは確かめていません。
  候補が違っていたときは、`--dt295-probe --demod-dump` が出す復調のレジスタ 0x00〜0xFF の読み値を、アンテナの信号を変えて 2 回取って比べると、動くレジスタを探せます

**同じドライバーのほかの機材:** 公式ドライバー (`pxmb86m0x_usb`) の INF には、DT295 のほかに次の機材が並んでいます。
挿してあれば見つけますが、**未確認なので使いません** (記録に理由を出し、設定に書いても開かずに断ります)。
INF ではどれも DT295 と設定が違い (DT295 W・DT420・DT410 は DT295 に無い基板の設定が付き、PIX-DTxxx は SPI モード)、
その違いの扱いが分かっていないためです。どれも実機では試していません。

| 機材                   | USB         |
| ---------------------- | ----------- |
| PIX-DT295 (使う)       | `06b8:103b` |
| PIX-DT295 W            | `06b8:103c` |
| PIX-DT420              | `06b8:1038` |
| PIX-DT410              | `06b8:1039` |
| PIX-DTxxx (SPI モード) | `04c5:202f` |

実機で確かめるときは、エージェントを止めるか、設定の「チューナー」で DT295 のチューナーと差し込み口のカードリーダーの「使う」を両方外してから、次のどれかを流します。

- `denpa-agent --card dt295:4-12.1`: 差し込み口のカードだけを開き、ATR とカードの番号を出す
- `denpa-agent --tune dt295:4-12.1 T27 --decode` (`BS15:16625`・`CS22:29024` も): そのボードのカードだけで復号する
- `denpa-agent --dt295-probe --channel T27` (`BS15`・`BS15:16625`・`CS2` も): 機材を設定して選局し、決めた秒数 (`--seconds N`。既定 5) だけ受けて、
  設定・選局・最初の TS までの時間、制御転送の数、CPU 時間、1 秒ごとの受信の状態と C/N (生の値と dB)、カードの準備の時間、TS の統計を出す。
  最後に、設定の各段・固定の待ち・選局・受信の確認の周回・取り込み・最初の TS の時間を、制御転送と I2C の転送の数つきの表で出す。
  平均の Mbps は、最初に読めた時刻から最後に読めた時刻までで割る。足せるものは次のとおり
  - `--port <USB のポート>`: 2 台以上挿してあるときに指す
  - `--output <ファイル>`: TS をファイルに書く
  - `--switch T27,BS15,…`: 最初のチャンネルを測ったあと、機材を開いたまま続けて選局し直す時間を出す (種別が同じか替わるかも出す)
  - `--lock-test N`: 同じチャンネルを N 回選局して、成功の割合と、最初の TS まで・受信の確認までの時間を出す (`--alt` の別のチャンネルに合わせて離れてから測る。`--alt none` で離れず、同じチャンネルの選局し直しを測る。`--reopen` で毎回開き直す)
  - `--demod-dump`: 受信中の復調のレジスタ 0x00〜0xFF の読み値を出す
  - `--demod-trace`: 地上波を選局してから受信を確認するまで、T 復調のレジスタ 0x00〜0xFF を約 10 ms ごとに読み、途中で値が変わったものを時刻つきで出す (読むだけ。ロックの前後で動くレジスタから、復調が検出した結果を返すものを探すため)
  - `--replug`: 先にポートの電源を入れ直す (Linux)
  - `--trace`: 機材への読み書きと設定の読み戻しを 1 行ずつ、標準エラー出力に出す

Linux では、終わりにスレッドごとの CPU 時間も出します (`dt295-ts` が USB の読み、`dt295-kick` が機材への要求、`dt295-probe-ts` が probe の統計)。

## IT930x の機材

**PLEX・e-Better・Digibest の機材のうち、USB ブリッジ IT930x を積んだものは、エージェントが USB を直に持ちます** ([#1578](https://github.com/danything/denpa/issues/1578))。
PX-MLT5 系 (PX-MLT5U・PX-MLT5PE・DTV02A-5TS-P)・PX-MLT8PE・DTV02A-4TS-P、PX-Q3・PX-W3 系 (PX-Q3U4・PX-Q3PE4・PX-W3U4 など)、受信機が 1 つの機種 (DTV02-1T1S-U・DTV02A-1T1S-U・PX-M1UR・PX-S1UR・DTV03A-1TU) です。
ホストにドライバもファームウェアも要りません (Windows はドライバを WinUSB に替えます)。

- 設定の `device` は `it930x:<USB のポート>:<受信機>` (`it930x:4-12.1:0`)。挿してあれば自動で見つけ、受信できる種別は受信機ごとに決まっています
- PX-MLT5 系・PX-MLT8PE・DTV02A-4TS-P は、地上波と衛星に加えて、ケーブル (ISDB-C) とスカパー！プレミアムサービス光 (J.83B) も選局できます
- LNB の給電は 15V だけです。内蔵カードリーダーも使えます
- Linux の PX-MLT5PE と PX-Q3PE4 の実機で確かめました。PX-Q3PE4 は 8 つの受信機の同時受信まで確かめています。ほかの機種と、Windows・Mac では確かめていません

機種ごとの USB の ID・受信機・設定・実機で確かめたこと・試すコマンドは [tuner-it930x.md](tuner-it930x.md) にあります。

## カードリーダー

**USB のリーダーは、Linux なら usbfs を直接扱います** (`/dev/bus/usb` が見えていれば動く)。Mac と Windows は OS の PC/SC 越しです
([install-mac.md](install-mac.md#カードが読めないとき))。Linux では、ホストや別のコンテナで pcscd が動いていると使えません (「別のプロセスがカードリーダーを
使用中です」と出る)。TPDU 単位のリーダー (Gemalto PC Twin など) には T=1 の枠組みを
こちらで組み、APDU 単位のリーダーにはそのまま送ります。カードの無いリーダーや INT に
応答しないカードは飛ばし、USB のリーダーを内蔵リーダーより先に試します (`CardLinks.cs`)。

Amazon で見る (広告): [Gemalto PC Twin](https://www.amazon.co.jp/dp/B001NEIRH0?tag=doa08-22)、[IDBridge CT30](https://www.amazon.co.jp/dp/B003XF2JJY?tag=doa08-22) (Mac で読めないときは [install-mac.md](install-mac.md#カードが読めないとき))

動いているエージェントがカードと通信できているかは、設定の「受信」の「チューナー」にある「カードリーダー」の表で分かります
(denpa がエージェントの `/denpa/card` を呼び、INT を 1 回通す)。エージェントを止めた状態なら `denpa-agent --card` でも確かめられます (リーダーを並べ、
ATR とカードの番号を出す)。
チューナーを使わずに B25 だけ確かめるなら `denpa-agent --decode-file <in.ts> <out.ts>` (`/denpa/decode`
と同じことをする。スクランブルされたまま録れてしまったものを救うのにも使える)。
`<out.ts>` を省くと復号せず、CA_system_id と番組表が来ているかだけを出します ([tuner-it930x.md](tuner-it930x.md#スカパープレミアムでカード無しで分かること))。

## B-CASカードとデスクランブル

スクランブルは**エージェント自身が復号します** (`B25.cs`)。カードが読めないときは
スクランブルされたまま流し、理由を状態に出します。理由を出さずに素通しすると「録画は成功してサイズも
それらしいのに中身が全部スクランブル」という分かりにくい壊れ方になるためです。
選局を畳むときに、スクランブルされたまま流したパケットの数と理由を記録にも残します。

- **録画は止めません。** 電波は二度と来ないので、スクランブルされたままでも
  録ります。denpa がエンコードの前に見て、スクランブルされたままならエージェントに
  復号させます (`src/lib/server/scramble.ts` → `/denpa/decode`)
- やり取りするのはパスだけです。denpa とエージェントは元の TS の同じ置き場 (`RAW_DIR`。コンテナでは `/media/raw`) を
  見ているので、読み書きはエージェントが直接やり、数十 GB を HTTP で往復させません
  (`charts/denpa` が一緒に出すときは、置き場が RWO なので**両方の Pod が同じノードにあることが前提**です)
- 元の TS を残す設定のときは、残るのは復号した TS だけです。スクランブルされたままのものは、
  あとから復号できる保証がありません
- 状態は設定の「受信」の「チューナー」にある「カードリーダー」の表に出ます。
  リーダーごとに 1 行で、カードの番号・状態 (使用中・予備・カードなし・エラー・無効)・
  そのカードで復号しているチューナー・「使う」のスイッチを並べます。`CARD_URL` で鍵を受け取っているときは、
  表の代わりに配る側の URL を出します
- **使うカードは 1 枚です。** INT に応答した最初のリーダーのカードを全部のチューナーで
  使い回します (カードに問い合わせるのは ECM の中身が変わったときだけなので、1 枚で足ります)。残りの
  リーダーは予備で、使っているカードが応答しなくなると、繋ぎ直すときに探し直して
  使います。チューナーごとにカードは割り当てません
- **「使う」を外したリーダーは開きません。** カードの候補に入らず、表を出すときも開かずに「無効」の行にします。
  使っている最中のリーダーを外すと、エージェントはそのリーダーを手放して次のリーダーで繋ぎ直します。
  PIX-DT295・CECH-ZD1 J の差し込み口は、チューナーも無効にしてあれば USB を閉じます (ほかのソフトや `--dt295-probe` から使えるようになる)。IT930x の機材の内蔵カードリーダーは、受信機も機材を使っていなければ、30 秒待ってから USB を閉じます (電源を短い間にオン/オフしないため)。
  カードを読めている最後の 1 台を外すと復号できなくなるので、「オフを確定」をもう 1 回押したときだけ外します。
  外したリーダーは、tuners.json の隣の `cards.json` に名前で残ります (USB のリーダーの名前にはポートが入るので、挿すポートを変えると別のリーダーになる)

### 直らないとき

まず設定の「受信」の「チューナー」にある「カードリーダー」の表で、見えているリーダーと、カードに INT が通るかを見ます
(中身はエージェントの `/denpa/card`)。使っているリーダーは開き直さずに INT を通し、ほかのリーダーは開いて確かめてから閉じます。

```json
{
  "ok": true,
  "message": "",
  "source": "local",
  "readers": [
    {
      "name": "Gemplus USB SmartCard Reader (usb 4-11)",
      "card": true,
      "ids": ["0000012345678901"],
      "active": true,
      "disabled": false,
      "tuners": ["PT3-T1", "PT3-S1"]
    },
    {
      "name": "PLEX PX-MLT5PE 4-12.1 Card Reader",
      "card": false,
      "ids": [],
      "active": false,
      "disabled": false,
      "tuners": []
    }
  ]
}
```

`message` は問題があるときだけ入ります (カードがどこにも無い、など)。確かめられなかった
リーダーは `error` に理由が入ります。`CARD_URL` のときは `source: "remote"` で、
`remote` (配る側の URL)・`ids`・`tuners` が付き、`readers` は空です。
鍵を配る範囲と、断られたときの文は [鍵を配るのは LAN の中だけ](agent.md#鍵を配るのは-lan-の中だけ) にあります。

エージェントは組んだ denpa (クライアント証明書) にしか応答しないので、curl などで `/denpa/card` を直に呼ぶことはできません
([agent.md](agent.md#denpa-とは-tls-で組む))。

- `readers` が空なら、`/dev/bus/usb` がコンテナに見えていません
- `card: false` で `error` が無ければ、そのリーダーにカードが挿さっていません
- 「別のプロセスがカードリーダーを使用中です」と出たら、ホストで pcscd が動いています。
  止めるか、リーダーをそちらから外します (`denpa-agent --card` を動いているエージェントの
  横で起動したときも、エージェントが使っているのでこう出る)
- 応答が無い (タイムアウト) なら、リーダーが固まっています。エージェントが USB のポートを 1 回リセットして
  立て直します。それでも戻らなければ USB レベルで入れ直します (`4-11` は `lsusb` と `/sys/bus/usb/devices` から引く)

```sh
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/unbind
sleep 2
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/bind
```

エージェントは起動し直さなくて構いません。次の ECM で探し直します。

実際に復号できているかは `--tune ... --decode` で見ます (復号したあとが 0% 近くなら正常)。
衛星で LNB に電源を送るなら `--lnb 15v` を足します。動いているエージェントは一度使ったチューナーと、起動したときに開いた
カードリーダーを開いたままにしていて、横から開くと断られるので、録画の無いときに止めてから同じイメージで流します
(compose の例。Kubernetes なら `tuner-agent` を 0 台にしてから、同じイメージを同じデバイスで 1 回だけ起動する。
Mac の止め方は [install-mac.md](install-mac.md#cech-zd1-j-の差し込み口が読めないとき))。

```sh
docker compose stop tuner-agent
docker compose run --rm tuner-agent --tune /dev/dvb/adapter1/frontend0 T27 --decode
docker compose start tuner-agent
```

それでも直らなければ、設定の「その他」→「ログ」の「Issue にする」で報告してください。サーバとエージェントのログと環境を、
カードの番号や IP アドレスを伏せて Issue のフォームに入れます ([screens.md](screens.md#バグの報告))。
