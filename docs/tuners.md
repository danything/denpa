# チューナー

使えるチューナーと、要るもの・B-CASカード・困ったときのことです。
入れ方は [install.md](install.md) (Mac は [install-mac.md](install-mac.md)、Windows は [install-windows.md](install-windows.md))、
エージェントの作りは [agent.md](agent.md)。

「Amazon で見る」は Amazon のアソシエイトのリンク (広告) です。ここから買っても値段は変わらず、紹介料が denpa の開発を続ける費用になります。どこで買っても動作は同じです。

  | PT3 ([tuner-pt3.md](tuner-pt3.md))                                                                                                                                                   | Linux DVB                                                        | ドライバ                                                                                                     |
  | **実機で確かめていない**: PT1 / PT2、PX-BCUD、PX-S1UD、Friio (白)、南米の地デジ (ISDB-Tb) の機材、DiB8096 のリファレンス基板 ([tuner-pt3.md](tuner-pt3.md#実機で確かめていない機材)) | Linux DVB                                                        | ドライバ (機材によってはファームウェアも)                                                                    |
  | PX-Q3U4 / PX-W3U4 / PX-MLT 系など (px4-userland の対応機種。Windows も。[tuner-px4.md](tuner-px4.md))                                                                                | px4-userland (同梱)                                              | なし (ファームウェアは初めて使うときに取ってくる。Mac・Windows は入れるとき。Windows はドライバを WinUSB に) |

  | PIXELA PIX-DT295 (**試験的**。地上波・BS・無料の CS を実機で受けられた。[下記](#pixela-pix-dt295-試験的))                                                                            | エージェントが USB を直に                                        | PIXELA の公式パッケージ (初めて使うときに取り出す。Windows はドライバを WinUSB に)                           |

- **OS**: Linux (amd64 / arm64)、Mac (Apple Silicon)、Windows (x64)。Talos Linux の 1 台に OS ごと入れるなら [install-talos.md](install-talos.md) (amd64・PT3。実機で確かめていない)

  Kubernetes なら Helm
- あれば Intel か AMD の GPU (`/dev/dri` を渡す) か NVIDIA の GPU (NVIDIA Container Toolkit で渡す。[install.md](install.md#用意するもの))。無ければソフトウェアでエンコードします

## 設定の画面

設定の「受信」の「チューナー」に、1 台 1 行の表で出ます。いまの様子と設定を同じ行に並べてあり、
変えたらその場で保存します。

| 列             | 中身                                                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| チューナー     | 名前と、その下にデバイス                                                                                                                       |
| 受信できる種別 | GR / BS / CS の切り替え。1 つは残します                                                                                                        |
| 状態           | 空き / 使用中 (選局しているチャンネル) / 無効と、使っている相手 (「録画: 番組名」「ライブ視聴」「番組表」「局ロゴ収集」「チャンネルスキャン」) |
| 使う           | 外すと選局に使いません (ほかのソフトに残すとき。[switch.md](switch.md))                                                                        |
| ⋯              | 名前・デバイス・LNB と削除                                                                                                                     |

表の下の「追加」で 1 台足し、「自動検出に戻す」で書いた内容を消します。
**エージェントが動いている間に挿した機材は、挿した時点で有効なチューナーとして一覧の末尾に足します** (エージェントが USB の抜き差しを受け取る)。
抜いた機材は一覧から消さないので、挿し直すと名前や「使う」の設定がそのまま戻ります。要らなければ「使う」を外すか、「⋯」から削除します。
削除した機材は、挿したままなら戻りません。抜いて挿し直すと、また足します。
電波の強さはエージェントが返さないので出しません。

## CATV で受ける

CATV の地デジには送り方が 2 つあります。

- **同一周波数パススルー**: UHF のチャンネルのまま送る。ふつうの「地上波」のスキャンで見つかります
- **周波数変換パススルー**: 地デジの電波 (変調は地デジと同じ OFDM) を CATV のチャンネル (C13〜C63) の周波数に移して送る。
  設定の「受信」の「チャンネル」で **「地上波 (CATV)」** を選んでスキャンします (UHF に加えて C13〜C63 も回すので、ふつうより長くかかります)。
  見つかった局は地上波の局として入り、チャンネルは `C25` のように出ます

C のチャンネルには ISDB-C (64QAM) も入っています (BS・CS をまとめ直して送るトランスモジュレーションや、CATV 局の独自の放送)。
対応しているチューナーは地デジ (OFDM) と衛星の復調しかできないので、**QAM の局は受けられず、スキャンでは素通りします**。
BS・CS を衛星の周波数のまま流す「BS・CS パススルー」なら、ふつうの BS・CS のスキャンで受かります。

## PX-W3U3 は asicen-userland で (試験的。上流のリリース待ち)

[asicen-userland](https://github.com/Khronos31/asicen-userland) は、px4-userland と同じ作者による
ASICEN 系 (PLEX PX-W3U3) のユーザー空間ドライバです。**まだリリースが無い** (0.1.0 の予定) ので、
いまは受け口だけ用意してあり、**イメージには何も入りません** (`agent/Dockerfile` の
`ASICEN_USERLAND_VERSION=0.0.0` が「まだ無い」の印)。配布物が無ければエージェントは機材を挙げません。
0.1.0 が出ると Renovate がバージョンを上げる PR を出し (自動では入れない)、その CI で配布物の名前や形式が
見込みどおりかを確かめます。

上流の現状 (2026-10): 実機で選局できるのは **受信機 0 の衛星と受信機 1 の T27 だけ**、使える受信機は**同時に 1 つ**、
1 台のホストで**1 筐体まで**。上流自身が「まだ 4 つの受信機として動くドライバではない」と言っています。

- **設定の `device` は `asicen:<USB ポート>:<受信機>`** (`asicen:1-2:1`)。USB の serial が無いので、
  内蔵ハブのポートで筐体を見分けます。**挿すポートを変えると別のチューナーになります**
- **LNB は出せません。** 設定に `15v` と書いてあっても 0V で選局し、設定の「受信」の「チューナー」にその旨を出します
- **ファームウェアは上流の配布アーカイブに入っているものをそのまま使います。再配布の権利は確かめられていません**
  ([licenses.md](licenses.md))。配布物に無ければ「ファームウェアがありません」と記録して、その機材は使いません
- 上流の第一弾は Linux x86_64 だけなので、arm64 のイメージ・Mac・Windows には入りません
- **実機には当てていません** (手元に PX-W3U3 が無い)。当てるなら `denpa-agent --tune asicen:1-2:1 T27`

エージェントの中でどう扱っているかは [agent.md](agent.md#asicen-userland-の作り)。

## Sony CECH-ZD1 J

PS3 の torne の地デジチューナー (USB `054c:04b2`)。**外のデーモンもファームウェアも要らず、エージェントが USB を直に持ちます**
(Linux は usbfs、Windows は WinUSB、Mac は IOKit。Windows はドライバを Zadig で WinUSB にします。[install-windows.md](install-windows.md)。
Windows と Mac は実機ではまだ確かめていません)。

- **設定の `device` は `zd1j:<USB のポート>`** (`zd1j:4-12.1`)。シリアルが無いので、ポートで見分けます。**設定に CECH-ZD1 J が 1 台だけなら、
  挿すポートを変えても付いていきます** (設定のポートに見当たらず、ほかに 1 台だけ挿さっていればそれを使い、記録に 1 行出す)。2 台以上なら、挿すポートを変えると別のチューナーになります。
  挿してあれば自動で見つけます (種別は地上波だけ)
- **地上波と CATV の C13〜C63** を受けます。C のうち ISDB-C (64QAM) の局はロックしません ([上記](#catv-で受ける))
- **内蔵の差し込み口の B-CAS も使えます** (CCID ではなく、ブリッジの UART をエージェントが直に読み書きする)。ほかのリーダーと同じく
  1 枚を全部のチューナーで使い回すので、CECH-ZD1 J のカードで PT3 の録画を復号することもあります。
  試す順は USB のリーダー → px4d → asicend → CECH-ZD1 J
- **前面の LED は使っている間ずっと赤**で、使い終わると緑に戻ります (点滅はしません)
- **一度ほかのドライバ (PS3 など) が動かした CECH-ZD1 J は扱えません。** 「CECH-ZD1 J を抜いて挿し直してください」と出たら、そのとおりに
- 開いたあとは温めておきます。**エージェントが動いている間は開いたまま** (PT3 などと同じ) で、2 回目からの選局は速く済みます。
  一度ロックしたチャンネルは、その値を `zd1j-locks.json` (tuners.json の隣) に覚えておいて、次から (エージェントを起こし直しても) 探索を飛ばします。
  このファイルは消してかまいません (次の選局で探索からやり直して、また覚えます)。開いたままの間は使っていなくてもチューナーが起きたままなので、
  そのぶん電気を使います (LED は緑)

実機で確かめるときは、そのボードを使っているエージェントを止めて `denpa-agent --tune zd1j:4-12.1 27` (開く・ロック・最初の TS・2 回目の選局に
かかったミリ秒と、ロックまでの内訳 (段ごとの時間と待ち)・I2C の回数・C/N・電波の強さを出す。`--seconds N` で読む長さも。`--decode` はそのボードの内蔵の差し込み口だけで復号し、ロックから最初の復号できたパケットまでのミリ秒も出す。
`--repeat N` はチャンネルを N 回回して、ロックの成否と時間の最小・中央・最大を出す) と
`denpa-agent --card zd1j:4-12.1` (そのボードの内蔵の差し込み口だけを開き、ATR とカードの番号と、かかったミリ秒を出す)。
どちらもそのボードのほかには触りません (ほかのカードリーダーやチューナーは開かない)。
引数を打ち間違えたときはサーバとして立ち上がらず、使い方を出して終わります。

エージェントの中でどう扱っているかは [agent.md](agent.md#cech-zd1-j-の作り)。

## PIXELA PIX-DT295 (試験的)

PIXELA の USB チューナー (USB `06b8:103b`。地上波・BS・CS をチューナー 1 つで切り替え)。**試験的です。** 地上波・BS・無料の CS は、Windows の実機で TS を受けられることを確かめました。
外のデーモンは要らず、エージェントが USB を直に持ちます (Linux は usbfs、Windows は WinUSB、Mac は IOKit。
Windows はドライバを Zadig で WinUSB にします。[install-windows.md](install-windows.md))。

- **設定の `device` は `dt295:<USB のポート>`** (`dt295:4-12.1`)。ポートで見分けるので、挿すポートを変えると別のチューナーになります。
  挿してあれば自動で見つけます (種別は地上波・BS・CS)
- **PIXELA の公式パッケージ** (StationTV X の更新パッケージ `stationtvx_updater12030002.zip`。160 MB ほど) **が要ります。** denpa には入っていません。
  初めて使うときに公式のサイト (届かなければ Internet Archive の同じもの) から取り、SHA-256 で確かめてから、要るものを取り出して
  `dt295-idle.bin`・`dt295-trc.bin`・`dt295-driver.bin` として tuners.json の隣に置きます (次からはそれを使う)。
  インターネットに繋がらない機械では、zip をそのまま tuners.json の隣に置いてください。
  取れなければ、理由を設定の「受信」の「チューナー」に出し、10 分おきに試し直します
- **B-CAS カードは本体の差し込み口に挿します。** スクランブルは機材の中で復号されるので、ほかのチューナーのカードとしては使えません。
  抜き差しは受信していないときに見ていて、カードが使えないときはその理由を「チューナー」に出します
- 使い終わると (エージェントを止めるときも) 機材を使い始める前の状態に戻してから閉じます。エージェントが落ちて戻せなかったときは、
  1 分ほどで機材がエラーの状態になりますが、次に使うときに戻してみます (戻らなければ抜いて挿し直してください)

**いまの限り:**

- **確かめたのは、地上波 (27ch)・BS (BS1)・無料の CS (CS22、TSID 29024 の 161) の TS を受けるところまでです** (Windows、PIX-DT295 の実機。同期バイト 100%・
  連続性カウンターの誤りは 0 か、ごく少数・映像と音声の PES が正しい。停止して機材が元の状態に戻る)。Linux と Mac、録画は確かめていません
- **衛星は、PID を機材に選ばせず、PSI から決めたルートで取ります。** 受信設定の 0x101A のビット 15 (`INIT_S_AUTO_PID_MODE`) を 0 にします。
  1 のときは機材が番組の映像・音声・データ放送の PID を選び、PMT の ES の一覧を空に書き換えるので、ServiceFilter が映像と音声を通せません。
  実機の測定 (BS1、TSID 0x4010、番組番号 152、各 4〜5 秒) では、ビット 15 が 1 で 7.6 MB、0 で 131 KB (SI だけ) が流れ、0 のときは PAT から PMT の PID を足してルートの計画をやり直すと映像と音声が流れ始めました。
  ルート計画は、PSI を AES で暗号化された状態では読めないため、AES を外したあとのパケットを渡します。
- **衛星のルートは、映像と PCR だけを専用のスロット (0・3) に入れ、音声と PMT は一般のスロット (5 以降) に入れます。**
  音声と PMT を専用のスロット (1・2) に入れると、機材が音声を流さず、PMT の ES の一覧を映像だけに書き換えました (実機の BS1)。
  この並びなら PMT は元の ES の一覧のままで、音声 (0x0141)・字幕 (0x0145・0x0146)・データ放送 (0x04D8〜0x04DC)・PCR (0x0111) が流れ、
  ServiceFilter は映像・音声・字幕を通しました (152 と 153。各 30 秒。起動から 5 秒で映像と音声が流れました)。地上波は今までどおり、専用のスロット 0〜3 を使います
- **衛星では、チャンネルの名前に `/152` のように番組番号を付けると (`BS01:16400/152`)、その番組の PMT と ES だけを追います。** 番号を 0x1018 にも書きます。
  この TS に無い番号 (101〜145、161 以降) では何も流れませんでした。付けなければ全番組を追うので、PID スロットが足りなくなる中継器があるかは未確認です。地上波は複数の番組が流れ、番組番号は使いません。
  受信中に PID を足す方法は、機材が完了コード 0x0580 で断ります
  ルートの計画を作り直せないとき (異なる ECM が 2 本以上要る・スロットが足りない) は、前の計画のまま受信を続け、ログに理由を出します (`ルートの計画を作り直せません (…)`)
- **起動で何も受けられないことが、一度ありました。** 番組番号を指定して 5・8・11・14 秒ずつ続けて受けたとき、11 秒の 1 回だけ何も受けられませんでした (原因は未調査)。同じ条件で 10 秒ずつ 12 回続けて受けたときは、12 回とも映像と音声が流れました
- **有料の CS は、B-CAS の契約が要ります。** 公式の StationTV X でも「スカパー！とのご契約が必要な番組です」と出て、映像と音声は流れません (ECM と PMT だけが流れます)
- **受信の設定は、実機で決めた 5 個のレジスターの値をコードに持っています** (衛星は、このあとに 0x101A のビット 15 を 0 にする 1 行を足す)。機材に当てる設定は、StationTV X では 677 行 (最終的に値のあるレジスターは 64 個) で、
  外せるものを外して、地上波と BS と無料の CS で受けられた最小の組にしました。録画に別の設定が要るかは、まだ分かっていません
- **TS の IV (機材が TS にかける AES の値、16 バイト) は固定で、コードに持っています。** 実機の TS から割り出した値で、地上波と BS で同じでした (受けるチャンネルでは変わりません)。StationTV X は要りません
- **選局は、TS が届くまで 1 回目が約 1.8〜2.0 秒、地上波どうし・衛星どうし (BS と CS を含む) の続けての選局が約 0.9 秒です** (実機の測定)
- **チューナーの初期化は、認証のあとの最初の選局と、地上波と衛星を切り替えたときだけ書きます。** 参照実装は選局のたびにやり直しますが、地上波どうし・衛星どうしを続けて選ぶときは周波数の設定だけで受けられました
- **受信設定の領域を 0 で埋めたあとは、計画に無いルートのスロットを書きません。** すでに 0 なので、書いても結果は同じです
- 地上波はロックを判定できません (機材から読む方法が分かっていない)。TS が 10 秒来なければ失敗にします
- チューナーは 1 つなので、同時に受けられるのは 1 チャンネルだけです
- CS は録画できない見込みです (複数の番組が別々の ECM を使うので。機材の中で同時に扱えるかが分かっていない)
- denpa の録画やライブから衛星を選局するのは、実機でまだ確かめていません。LNB への給電は扱いません

**同じドライバーのほかの機材:** 公式ドライバー (`pxmb86m0x_usb`) の INF には、DT295 のほかに次の機材が並んでいます。
挿してあれば見つけますが、**未確認なので使いません** (記録に理由を出し、設定に書いても開かずに断ります)。
INF ではどれも DT295 と設定が違い (DT295 W・DT420・DT410 は DT295 に無い基板の設定が付き、PIX-DTxxx は SPI モード)、
その違いの扱いが分かっていないためです。どれも実機では試していません。

| 機材                   | USB         |
| ---------------------- | ----------- |
| PIX-DT295 (使う)       | `06b8:103b` |
| PIX-DT295 W            | `06b8:103c` |
| PIX-DT420              | `06b8:1038` |
| PIX-DT410              | `06b8:1039` |
| PIX-DTxxx (SPI モード) | `04c5:202f` |

実機で確かめるときは、エージェントを止めて `denpa-agent --dt295-probe --no-tune` (データの取り出し・書き込み・カードまで。アンテナは要らない)。
`--terrestrial 27` / `--bs 1 --slot 0` / `--cs 2` で選局します。衛星は `--program 152` のように、受ける番組の番号も指定できます。決めた秒数 (`--seconds N`。既定 5) だけ受けて、
バイト数・同期バイトの割合・PID ごとの数・PAT と PMT が来たかだけを出します (TS はどこにも書きません)。
`--trace` は機材への書き込みを 1 行ずつ出します。どの場合も、使い始める前の状態に戻してから閉じます。

## カードリーダー

**USB のリーダーは usbfs を直接扱います** (Linux。Mac と Windows は OS の PC/SC 越し。[install-mac.md](install-mac.md#カードが読めないとき))。`/dev/bus/usb` が見えていれば動きます。
ホストや別のコンテナで pcscd が動いていると使えません (「別のプロセスがカードリーダーを
使用中です」と出る)。TPDU 単位のリーダー (Gemalto PC Twin など) には T=1 の枠組みを
こちらで組み、APDU 単位のリーダーにはそのまま送ります。カードの無いリーダーや INT に
答えないカードは飛ばし、USB のリーダーを内蔵リーダーより先に試します (`CardLinks.cs`)。

Amazon で見る (広告): [Gemalto PC Twin](https://www.amazon.co.jp/dp/B001NEIRH0?tag=doa08-22)、[IDBridge CT30](https://www.amazon.co.jp/dp/B003XF2JJY?tag=doa08-22) (Mac で読めないときは [install-mac.md](install-mac.md#カードが読めないとき))

動いているエージェントがカードと話せているかは、設定の「受信」の「チューナー」にある「カードリーダー」の表で分かります
(denpa がエージェントの `/denpa/card` を呼び、INT を 1 回通す)。止めた状態なら `denpa-agent --card` でも確かめられます (リーダーを並べ、
ATR とカードの番号を出す。動いているエージェントがリーダーを使っている間は断られます)。
チューナーを使わずに B25 だけ確かめるなら `denpa-agent --decode-file <in.ts> <out.ts>` (`/denpa/decode`
と同じことをする。掛かったまま録れてしまったものを救うのにも使える)。

## B-CASカードとデスクランブル

スクランブルは**エージェント自身が復号します** (`B25.cs`)。カードが読めないときは
掛かったまま流し、理由を状態に出します。黙って素通しすると「録画は成功してサイズも
それらしいのに中身が全部スクランブル」という分かりにくい壊れ方になるためです。
選局を畳むときに、掛かったまま流したパケットの数と理由を記録にも残します。

- **録画は止めません。** 電波は二度と来ないので、スクランブルされたままでも
  録ります。denpa がエンコードの前に見て、掛かったままならエージェントに
  復号させます (`src/lib/server/scramble.ts` → `/denpa/decode`)
- やり取りするのはパスだけです。元の TS の置き場 (`/media/raw`) を両方のコンテナに
  見せてあるので、読み書きはエージェントが直接やり、数十 GB を HTTP で往復させません
  (`charts/denpa` が一緒に出すときは、置き場が RWO なので**両方の Pod が同じノードにあることが前提**です)
- 元の TS を残す設定のときは、残るのは復号した TS だけです。掛かったままのものは、
  あとから復号できる保証がありません
- 状態は設定の「受信」の「チューナー」にある「カードリーダー」の表に出ます。
  リーダーごとに 1 行で、カードの番号・状態 (使用中・予備・カードなし・エラー)・
  そのカードで復号しているチューナーを並べます。`CARD_URL` で鍵を貰っているときは、
  表の代わりに配り役の URL を出します
- **使うカードは 1 枚です。** INT に答えた最初のリーダーのカードを全部のチューナーで
  使い回します (カードに聞くのは ECM の中身が変わったときだけなので、1 枚で足ります)。残りの
  リーダーは予備で、使っているカードが答えなくなると、繋ぎ直すときに探し直して
  使います。チューナーごとにカードは割り当てません

### 直らないとき

まず設定の「受信」の「チューナー」にある「カードリーダー」の表で、見えているリーダーと、カードに INT が通るかを見ます
(中身はエージェントの `/denpa/card`)。使っているリーダーは鍵の出どころに
INT を通させ、他のリーダーは開いて覗いて閉じます (USB のリーダーは使うと他から
開けないので、使っているリーダーは開き直しません)。

```json
{
  "ok": true,
  "message": "",
  "source": "local",
  "readers": [
    {
      "name": "Gemplus USB SmartCard Reader (usb 4-11)",
      "card": true,
      "ids": ["0000012345678901"],
      "active": true,
      "tuners": ["PT3-T1", "PT3-S1"]
    },
    {
      "name": "px4-userland 0960 Internal Card Reader",
      "card": false,
      "ids": [],
      "active": false,
      "tuners": []
    }
  ]
}
```

`message` は困ったときだけ入ります (カードがどこにも無い、など)。覗けなかった
リーダーは `error` に理由が入ります。`CARD_URL` のときは `source: "remote"` で、
`remote` (配り役の URL)・`ids`・`tuners` が付き、`readers` は空です。
鍵を配る範囲と、断られたときの文は [鍵を配るのは LAN の中だけ](agent.md#鍵を配るのは-lan-の中だけ) にあります。

エージェントは組んだ denpa (クライアント証明書) にしか答えないので、curl などで `/denpa/card` を直に呼ぶことはできません
([agent.md](agent.md))。手元で確かめるならエージェントを止めて `denpa-agent --card` を使います。

- `readers` が空なら、`/dev/bus/usb` がコンテナに見えていません
- `card: false` で `error` が無ければ、そのリーダーにカードが挿さっていません
- 「別のプロセスがカードリーダーを使用中です」と出たら、ホストで pcscd が動いています。
  止めるか、リーダーをそちらから外します (`denpa-agent --card` を動いているエージェントの
  横で起こしたときも、エージェントが使っているのでこう出る)
- 応答が無い (タイムアウト) なら、リーダーが固まっています。エージェントが USB のポートを 1 回リセットして
  立て直します。それでも戻らなければ USB レベルで入れ直します (`4-11` は `lsusb` と `/sys/bus/usb/devices` から引く)

```sh
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/unbind
sleep 2
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/bind
```

エージェントは起こし直さなくて構いません。次の ECM で探し直します。

実際に復号できているかは `--tune ... --decode` で見ます (復号したあとが 0% 近くなら正常)。
衛星で LNB に電源を送るなら `--lnb 15v` を足します。動いているエージェントは一度使ったチューナーと、起動したときに開いた
カードリーダーを開いたままにしていて、横から開くと断られるので、録画の無いときに止めてから同じイメージで流します
(compose の例。Kubernetes なら `tuner-agent` を 0 台にしてから、同じイメージを同じデバイスで 1 回だけ起こす)。

```sh
docker compose stop tuner-agent
docker compose run --rm tuner-agent --tune /dev/dvb/adapter1/frontend0 T27 --decode
docker compose start tuner-agent
```

それでも直らなければ、設定の「その他」→「ログ」の「Issue にする」で報告してください。サーバとエージェントのログと環境を、
カードの番号や IP アドレスを伏せて Issue のフォームに入れます ([screens.md](screens.md#バグの報告))。
