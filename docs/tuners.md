# チューナー

使えるチューナーと、要るもの・B-CASカード・困ったときのことです。
入れ方は [install.md](install.md) (Mac は [install-mac.md](install-mac.md)、Windows は [install-windows.md](install-windows.md))、
エージェントの作りは [agent.md](agent.md)。

「Amazon で見る」は Amazon のアソシエイトのリンク (広告) です。ここから買っても値段は変わらず、紹介料が denpa の開発を続ける費用になります。どこで買っても動作は同じです。

## 要るもの

- **チューナー**: 挿してあれば自動で見つけ、種別 (地上波 / 衛星) も見分けます

  | チューナー                                                                                                                                                                           | 使う仕組み                                                       | ホストに入れるもの                                                        |
  | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- | ------------------------------------------------------------------------- |
  | PT3 ([tuner-pt3.md](tuner-pt3.md))                                                                                                                                                   | Linux DVB                                                        | ドライバ                                                                  |
  | **実機で確かめていない**: PT1 / PT2、PX-BCUD、PX-S1UD、Friio (白)、南米の地デジ (ISDB-Tb) の機材、DiB8096 のリファレンス基板 ([tuner-pt3.md](tuner-pt3.md#実機で確かめていない機材)) | Linux DVB                                                        | ドライバ (機材によってはファームウェアも)                                 |
  | PX-Q3U4 / PX-W3U4 / PX-MLT 系など (px4-userland の対応機種。Mac・Windows も。[tuner-px4.md](tuner-px4.md))                                                                           | px4-userland (同梱)                                              | なし (ファームウェアはエージェントに同梱。Windows はドライバを WinUSB に) |
  | PX-S1UD (smsusb を blacklist したとき。Mac・Windows も。[tuner-px-s1ud.md](tuner-px-s1ud.md))                                                                                        | siano-userland (同梱)                                            | なし (Windows はドライバを WinUSB に)                                     |
  | PX-W3U3 ([下記](#px-w3u3-は-asicen-userland-で-試験的上流のリリース待ち))                                                                                                            | asicen-userland (**試験的**。上流のリリース待ちで、まだ入らない) | なし                                                                      |
  | Sony CECH-ZD1 J (PS3 の torne。Windows・Mac も。[下記](#sony-cech-zd1-j))                                                                                                            | エージェントが USB を直に                                        | なし                                                                      |
  | PIXELA PIX-DT295 (**試験的**。Linux の実機で地上波・BS・CS の受信と差し込み口の B-CAS の読み取りを確かめた。Windows・Mac は未確認。[下記](#pixela-pix-dt295-試験的))                 | エージェントが USB を直に                                        | なし (ファームウェアは入れない。Windows はドライバを WinUSB に)           |

  「実機で確かめていない」機材は、ドライバと denpa の選局の手順を照らし合わせて動くはずと見ているものです。
  使ってみたら、動いたか動かなかったかを [Issue](https://github.com/danything/denpa/issues) で教えてください
  (設定の「その他」→「ログ」の「Issue にする」から作れます。[tuner-pt3.md](tuner-pt3.md#動いたか教えてください))

- **B-CASカード** と USB のカードリーダー (px4-userland・asicen-userland の機材と CECH-ZD1 J・PIX-DT295 は内蔵リーダーでもよい。[下記](#カードリーダー))
- **OS**: Linux (amd64 / arm64)、Mac (Apple Silicon)、Windows (x64)。Talos Linux の 1 台に OS ごと入れるなら [install-talos.md](install-talos.md) (amd64・PT3。実機で確かめていない)
- **Docker** (Linux。Compose 込み)。Mac と Windows は要らない (denpa 本体もエージェントも OS の上でそのまま動かす)。
  Kubernetes なら Helm
- あれば Intel か AMD の GPU (`/dev/dri` を渡す) か NVIDIA の GPU (NVIDIA Container Toolkit で渡す。[install.md](install.md#用意するもの))。無ければソフトウェアでエンコードします

機材ごとの入れ方は表のリンク先に。

## 設定の画面

設定の「受信」の「チューナー」に、1 台 1 行の表で出ます。いまの様子と設定を同じ行に並べてあり、
変えたらその場で保存します。

| 列             | 中身                                                                                                                                                                          |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| チューナー     | 名前と、その下にデバイス                                                                                                                                                      |
| 受信できる種別 | GR / BS / CS の切り替え。1 つは残します                                                                                                                                       |
| 状態           | 空き / 使用中 (選局しているチャンネル) / 無効と、使っている相手 (「録画: 番組名」「ライブ視聴」「番組表」「局ロゴ収集」「チャンネルスキャン」)。使用中なら受信の状態と C/N も |
| 使う           | 外すと選局に使いません (ほかのソフトに残すとき。[switch.md](switch.md))                                                                                                       |
| ⋯              | 名前・デバイス・LNB と削除                                                                                                                                                    |

表の下の「追加」で 1 台足し、「自動検出に戻す」で書いた内容を消します。
**エージェントが動いている間に挿した機材は、挿した時点で有効なチューナーとして一覧の末尾に足します** (エージェントが USB の抜き差しを受け取る)。
チューナーを書いてあれば (「追加」や「使う」の切り替えで保存したあと)、抜いた機材は一覧から消さないので、挿し直すと名前や「使う」の設定がそのまま戻ります。要らなければ「使う」を外すか、「⋯」から削除します。
削除した機材は、挿したままなら戻りません。抜いて挿し直すと、また足します。
使用中のチューナーには、状態の列に受信の状態と C/N を出します ([下記](#信号レベル))。

## 信号レベル

**使用中のチューナーの受信の状態と C/N を、測れる機材だけ出します。** エージェントが使用中のチューナーを 5 秒ごとに読み、
設定の「受信」の「チューナー」の状態の列に「同期しています・C/N: 25.3 dB」のように出します。
画面は開いている間、使用中のチューナーがあれば 5 秒ごとに読み直します。空いているチューナーは読みません (選局していないので測れない)。

| チューナー                           | 出るもの                                                      | dB の根拠                                                                 |
| ------------------------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Linux DVB (PT3 など)                 | 受信の状態と C/N (dB)。ドライバが C/N を返さなければ C/N なし | ドライバが返す値 (`DTV_STAT_CNR`)。相対値で返すドライバは「C/N (生の値)」 |
| px4-userland・asicen-userland の機材 | 受信の状態と C/N (dB)。どちらも選局したときの値               | px4d・asicend の選局の答え (`cnr_mdb`)                                    |
| CECH-ZD1 J                           | 受信の状態と C/N (dB)                                         | DiB8000 の仕様書の式                                                      |
| PIX-DT295                            | 受信の状態と C/N の生の値 (「C/N (生の値): 2,748」)           | なし (下記)                                                               |
| PX-S1UD (siano-userland)             | 出ない                                                        | siano-ts が C/N を返さない                                                |

px4d は受信の状態と C/N を選局の答えでしか返さないので、受信中も選局したときの値のままで、C/N に「(選局したとき)」と添えます。測り直すには選局し直すしかなく、それでは受信が途切れます。
DVB と px4-userland の C/N を画面まで通す流れは、実機では確かめていません (値を読む部分は単体テストで確かめた)。

**PIX-DT295 の C/N は dB ではありません。** 復調のレジスタ (地上波は `0x8B` から 3 バイト、衛星は `0xBC` から 2 バイト) の値をそのまま出します。
復調は TC90522 系と推定されていますが、レジスタの値を dB に直す式が公開された資料 (データシートや規格書) に見当たらないので、換算していません。
値の向き (大きいほど良いか悪いか) も確かめていません。実機では T25 で約 2,130〜2,762、BS15 で約 10,425〜10,601、CS22 で約 14,446〜15,183 でした。

ブースターが要るかを見るときは、次のように使います。

- 同じチューナーで、分配器を入れる前とあと、配線を変える前とあとを、同じチャンネルで比べる。dB で出る機材なら、地上波 (64QAM) は約 20 dB、BS・CS (8PSK) は約 11 dB に近づくと映りが乱れやすくなる (一般に言われる受信に要る C/N。機材ごとに違う)
- 生の値は、チャンネルどうし・チューナーの機種どうしでは比べられない。同じチャンネルの値がどちらへ動いたかだけを見る
- 「同期していません」が出たり消えたりするなら、C/N より先に配線と分配器を疑う
- C/N は受信できた信号の雑音の少なさで、電波の強さそのものではない。強すぎて歪んでいるときも C/N は下がるので、下がったからといってブースターが要るとは限らない

## CATV で受ける

CATV の地デジには送り方が 2 つあります。

- **同一周波数パススルー**: UHF のチャンネルのまま送る。ふつうの「地上波」のスキャンで見つかります
- **周波数変換パススルー**: 地デジの電波 (変調は地デジと同じ OFDM) を CATV のチャンネル (C13〜C63) の周波数に移して送る。
  設定の「受信」の「チャンネル」で **「地上波 (CATV)」** を選んでスキャンします (UHF に加えて C13〜C63 も回すので、ふつうより長くかかります)。
  見つかった局は地上波の局として入り、チャンネルは `C25` のように出ます

C のチャンネルには ISDB-C (64QAM) も入っています (BS・CS をまとめ直して送るトランスモジュレーションや、CATV 局の独自の放送)。
対応しているチューナーは地デジ (OFDM) と衛星の復調しかできないので、**QAM の局は受けられず、スキャンでは素通りします**。
BS・CS を衛星の周波数のまま流す「BS・CS パススルー」なら、ふつうの BS・CS のスキャンで受かります。

## PX-W3U3 は asicen-userland で (試験的。上流のリリース待ち)

[asicen-userland](https://github.com/Khronos31/asicen-userland) は、px4-userland と同じ作者による
ASICEN 系 (PLEX PX-W3U3) のユーザー空間ドライバです。**まだリリースが無い** (0.1.0 の予定) ので、
いまは受け口だけ用意してあり、**イメージには何も入りません** (`agent/Dockerfile` の
`ASICEN_USERLAND_VERSION=0.0.0` が「まだ無い」の印)。配布物が無ければエージェントは機材を挙げません。
0.1.0 が出ると Renovate がバージョンを上げる PR を出し (自動では入れない)、その CI で配布物の名前や形式が
見込みどおりかを確かめます。

上流の現状 (2026-10): 実機で選局できるのは **受信機 0 の衛星と受信機 1 の T27 だけ**、使える受信機は**同時に 1 つ**、
1 台のホストで**1 筐体まで**。上流自身が「まだ 4 つの受信機として動くドライバではない」と言っています。

- **設定の `device` は `asicen:<USB ポート>:<受信機>`** (`asicen:1-2:1`)。USB の serial が無いので、
  内蔵ハブのポートで筐体を見分けます。**挿すポートを変えると別のチューナーになります**
- **LNB は出せません。** 設定に `15v` と書いてあっても 0V で選局し、設定の「受信」の「チューナー」にその旨を出します
- **ファームウェアは上流の配布アーカイブに入っているものをそのまま使います。再配布の権利は確かめられていません**
  ([licenses.md](licenses.md))。配布物に無ければ「ファームウェアがありません」と記録して、その機材は使いません
- 上流の第一弾は Linux x86_64 だけなので、arm64 のイメージ・Mac・Windows には入りません
- **実機には当てていません** (手元に PX-W3U3 が無い)。当てるなら `denpa-agent --tune asicen:1-2:1 T27`

エージェントの中でどう扱っているかは [agent.md](agent.md#asicen-userland-の作り)。

## Sony CECH-ZD1 J

PS3 の torne の地デジチューナー (USB `054c:04b2`)。**外のデーモンもファームウェアも要らず、エージェントが USB を直に持ちます**
(Linux は usbfs、Windows は WinUSB、Mac は IOKit。Windows はドライバを Zadig で WinUSB にします。[install-windows.md](install-windows.md)。
Windows と Mac は実機ではまだ確かめていません)。

- **設定の `device` は `zd1j:<USB のポート>`** (`zd1j:4-12.1`)。シリアルが無いので、ポートで見分けます。**設定に CECH-ZD1 J が 1 台だけなら、
  挿すポートを変えても付いていきます** (設定のポートに見当たらず、ほかに 1 台だけ挿さっていればそれを使い、記録に 1 行出す)。2 台以上なら、挿すポートを変えると別のチューナーになります。
  挿してあれば自動で見つけます (種別は地上波だけ)
- **地上波と CATV の C13〜C63** を受けます。C のうち ISDB-C (64QAM) の局はロックしません ([上記](#catv-で受ける))
- **内蔵の差し込み口の B-CAS も使えます** (CCID ではなく、ブリッジの UART をエージェントが直に読み書きする)。ほかのリーダーと同じく
  1 枚を全部のチューナーで使い回すので、CECH-ZD1 J のカードで PT3 の録画を復号することもあります。
  試す順は USB のリーダー → px4d → asicend → CECH-ZD1 J → PIX-DT295
- **前面の LED は使っている間ずっと赤**で、使い終わると緑に戻ります (点滅はしません)
- **一度ほかのドライバ (PS3 など) が動かした CECH-ZD1 J は扱えません。** 「CECH-ZD1 J を抜いて挿し直してください」と出たら、そのとおりに
- 開いたあとは温めておきます。**エージェントが動いている間は開いたまま** (PT3 などと同じ) で、2 回目からの選局は速く済みます。
  一度ロックしたチャンネルは、その値を `zd1j-locks.json` (tuners.json の隣) に覚えておいて、次から (エージェントを起こし直しても) 探索を飛ばします。
  このファイルは消してかまいません (次の選局で探索からやり直して、また覚えます)。開いたままの間は使っていなくてもチューナーが起きたままなので、
  そのぶん電気を使います (LED は緑)

実機で確かめるときは、そのボードを使っているエージェントを止めて `denpa-agent --tune zd1j:4-12.1 27` (開く・ロック・最初の TS・2 回目の選局に
かかったミリ秒と、ロックまでの内訳 (段ごとの時間と待ち)・I2C の回数・C/N・電波の強さを出す。`--seconds N` で読む長さも。`--decode` はそのボードの内蔵の差し込み口だけで復号し、ロックから最初の復号できたパケットまでのミリ秒も出す。
`--repeat N` はチャンネルを N 回回して、ロックの成否と時間の最小・中央・最大を出す) と
`denpa-agent --card zd1j:4-12.1` (そのボードの内蔵の差し込み口だけを開き、ATR とカードの番号と、かかったミリ秒を出す)。
どちらもそのボードのほかには触りません (ほかのカードリーダーやチューナーは開かない)。
引数を打ち間違えたときはサーバとして立ち上がらず、使い方を出して終わります。

エージェントの中でどう扱っているかは [agent.md](agent.md#cech-zd1-j-の作り)。

## PIXELA PIX-DT295 (試験的)

PIXELA の USB チューナー (USB `06b8:103b`。地上波・BS・CS。B-CAS の差し込み口つき)。
エージェントが機材のレジスタを USB で直に書いて動かします。機材にファームウェアは入れず、同梱するものもありません。
外のデーモンは要らず、エージェントが USB を直に持ちます (Linux は usbfs、Windows は WinUSB、Mac は IOKit。
Windows はドライバを Zadig で WinUSB にします。[install-windows.md](install-windows.md))。

- **設定の `device` は `dt295:<USB のポート>`** (`dt295:4-12.1`)。ポートで見分けるので、挿すポートを変えると別のチューナーになります。
  挿してあれば自動で見つけます (種別は地上波・BS・CS)
- **機材の中では復号しません。** スクランブルのままの TS を受けて、エージェントの B25 で復号します (ほかのチューナーと同じ)。
  差し込み口のカードは、ブリッジ (MB86M01) の UART (`0xFEA000`〜`0xFEA03C`) をエージェントが直に読み書きし、
  T=1 の枠組みをこちらで組みます (CECH-ZD1 J と同じ)。ほかのチューナーの復号にも使います (カードリーダーの並びのいちばん後ろ)
- **チップの設定・I2C・選局は、エージェントが制御転送 (ベンダー要求 `0xBC` のメモリ読み書き) で行います。**
  機材の中で動かすのは、小さな FR30 のプログラム 1 つだけです (boot0 の hook に置きます)。このプログラムは 2 つの仕事をします。
  1 つは、TS を取り込みのリングから USB の bulk IN へ送ることです。受信中は 512 パケット (256 KiB) ごとの要求を送り続けます。同じ機材のカードが読み書きしている間だけ、32 パケットにします。
  もう 1 つは、I2C の転送を順に行うことです。復調とチューナーへの書き込みを、読み・変更・書きを含めて 1 回の要求にまとめて渡すと、機材の中で順に行って読んだバイトだけを返します
  (ホストが 1 バイトずつ制御転送で動かすと、1 転送に約 16 回の制御転送がかかるため)。このプログラムが触るレジスタは I2C のブロック (`0xFD8FE0`〜`0xFD8FF0`) だけで、
  相手は復調の 2 つ (I2C のアドレス `0x10`・`0x11`) に限ります。長い並びは SDRAM の `0x380000` 台に置いて渡します。使えないと確かめられた機材では、ホストが 1 つずつ行います
- **開けるのは、USB でつないだ直後の機材 (状態 0x82008 が 0 で、boot0 の hook が元のまま) だけです。** 閉じるときは書いたものを逆順に戻すので、
  エージェントの再起動では、そのまま開き直せます。途中で止まって hook が残った機材やほかのファームウェアが動いた機材は、Linux ではエージェントが
  ポートの電源を 1 回入れ直してから開きます (ハブの側にあるポートの `disable` に 1 を書いてから 0 を書く。機材の `authorized` を書き換えるだけでは戻りません)。
  コンテナの中 (`/sys` が読み取り専用) や Windows・Mac では、機材を 1 回挿し直してください
- **機材は、エージェントが動いている間は設定したまま開いておきます。** チューナーの利用者が全員いなくなっても閉じません (設定を書き換えて無効にしたとき、チューナーの定義が変わったとき、エージェントを止めるときに手放します)。
  次の利用者が来たときに払うのは、選局と受信の確認だけです (全部の初期化には 150 ms ほどかかります)。代わりに、使っていない間も USB を握ったままで、チップと復調の電源が入ったままです。
  ほかのソフトから使いたいときは、設定でチューナーを無効にしてください。時間で閉じる仕組みは入れていません (閉じるたびに初期化し直すと、録画の開始が 150 ms 遅れ、USB の抜き差しの扱いも増えるため)
- **カードの準備は、選局と並べて進めます。** 機材を開いて最初に選局するとき、別のスレッドでカードの電源投入から ATR・T=1 の話し方の取り決めまでを始めます。
  選局の固定の待ちと受信の確認の周回の間に進むので、TS が届くころにはカードが使えます (制御転送は 1 つずつ通るので、選局の I2C と交互に入ります)。
  カードの電源は、機材を開いている間は入れたままで、機材を閉じるときに切ります
- **選局し直しは、前の選局で頭の手順が変わります。** 地上波から地上波へは、チューナーを動かす 0B=01 を省きます (仕様書 7.2.2)。衛星から衛星へは、T 側を休ませる表を省きます。
  種別が替わるときは、地上波へ戻る前に S 側を休ませる表 (仕様書 7.2.2。推定) を流し、衛星へ行く前に T 側を休ませます。TS の出し元は、選局のたびに復調の 0E・0F で替えます (仕様書 8.1.5)
- **書いてよいレジスタを絞っています。** USB コアの割り込み・クロックのレジスタ (`0xFD8000`〜`0xFD80FF`・`0xFD8300`〜`0xFD83FF`) は、
  I2C の準備に要る 4 つだけを許可し、カードの UART は許可したときだけ、カードの端子の向き (`0xF00222`〜`0xF0022E`) は読むだけです。
  実機で `0xFD8010` に 0x08080000 を書いたときは USB の制御がすべて時間切れになったので、新しいレジスタを足すときは実機の観測を根拠にします

**いまの限り:**

- **Linux の実機で、地上波 (T25)・BS15・CS22 の選局と TS の取り込み、差し込み口の B-CAS カードの読み取りを確かめました。**
  起動直後の機材からの時間 (3 回ずつの範囲) は、設定 146〜148 ms、選局は地上波 158 ms・衛星 173 ms です。選局から最初の TS までは、T25 が 727〜789 ms
  (受信の確認が 411〜472 ms。電波の事情で決まる)、BS15 と CS22 が 395〜403 ms でした。TS は 6 秒で T25 が約 30 Mbps、BS15 が約 24 Mbps、CS22 が約 39 Mbps で、
  同期バイト 100%・transport_error_indicator 0・連続性の飛び 0 でした。固定の待ちは仕様書の値のままです。ただし衛星の選局の約 40 ms だけは、実機で 20 ms でも BS15・CS22 が 30 回ずつ全部ロックし、20 ms ほど速くなったので 20 ms にしました。ほかの待ち (設定の 100 ms・20 ms、地上波の選局の 20 ms・100 ms、衛星の 100 ms) は、短くするとロックまでの時間が延びるか変わらないので、仕様書の値のままです。
  カードは電源を入れてから ATR まで約 0.5 秒、B-CAS の読み出しまで約 1.2 秒でした。同じ機材で mAgicVISION のファームウェアを入れる方式 (以前の方式) と比べると、
  起動から最初の TS までは約 3 秒短くなりました。
  I2C の転送を機材の中で順に行わせる前 (ホストが 1 バイトずつ制御転送で動かしていたとき) は、設定が 340 ms、1 回の実行の制御転送が 5,300〜6,900 回でしたが、
  いまは制御転送が 548〜924 回です (T25 の 6 秒で、以前の方式は 28,445 回)- **Windows・Mac と、CATV の C13〜C63 は、この方式では実機で確かめていません。** 以前の方式では Mac (M4) で確かめられていましたが、機材へ書く内容が違います。
  選局の周波数の式は地上波と同じです
- ライブ視聴・録画・復号を通した確認は、以前の方式のものです。この方式でも TS は同じ形 (放送のまま) で流れます
- 受信中にほかのチャンネルへ切り替えるときは、いったん取り込みを止めてから選局し直します。地上波と衛星を切り替える動作は、実機では確かめていません
- TS を出す受信部は、地上波か衛星の 1 つずつです。同時に受けられるのは 1 チャンネルだけです
- 衛星の名前の `/152` (番組番号) は使いません。中継器の TS を全部受けます
- LNB への給電は扱いません
- **機材のプログラムへの要求と応答の組は、1 つずつ通します。** TS の送り出し・I2C の順次実行の要求は、応答を同じ 64 バイトの場所から読むため、間に別の制御転送 (カードの読み書き・C/N の読み) が入ると応答が壊れます。エージェントは制御転送と、要求と応答の組を、1 つのスレッドずつ通します
- **信号レベルは、復調の C/N の生の値だけ読めます** ([信号レベル](#信号レベル))。設定の「チューナー」には「C/N (生の値)」として出し、`--dt295-probe` も受信中に 1 秒ごとに、受信の状態と C/N のレジスタを読んで出します。
  レジスタは地上波が `0x8B` から 3 バイト、衛星が `0xBC` から 2 バイトです。復調が TC90522 系という推定から選んだ候補で、アンテナの信号を変えて値が動くかは確かめていません。
  dB への換算式は仕様書に無いので換算していません。`--demod-dump` を付けると復調のレジスタ 0x00〜0xFF の読み値も出すので、
  アンテナの信号を変えて 2 回取れば、候補が違っていたときに動くレジスタを探せます
- コードのコメントが指す「仕様書」(`dt295-resident/spec.md`) は、このリポジトリの外 (denpa-spec) にあります。節の番号はそちらのものです

**同じドライバーのほかの機材:** 公式ドライバー (`pxmb86m0x_usb`) の INF には、DT295 のほかに次の機材が並んでいます。
挿してあれば見つけますが、**未確認なので使いません** (記録に理由を出し、設定に書いても開かずに断ります)。
INF ではどれも DT295 と設定が違い (DT295 W・DT420・DT410 は DT295 に無い基板の設定が付き、PIX-DTxxx は SPI モード)、
その違いの扱いが分かっていないためです。どれも実機では試していません。

| 機材                   | USB         |
| ---------------------- | ----------- |
| PIX-DT295 (使う)       | `06b8:103b` |
| PIX-DT295 W            | `06b8:103c` |
| PIX-DT420              | `06b8:1038` |
| PIX-DT410              | `06b8:1039` |
| PIX-DTxxx (SPI モード) | `04c5:202f` |

実機で確かめるときは、エージェントを止めるか、設定の「チューナー」で DT295 のチューナーと差し込み口のカードリーダーの「使う」を両方外してから `denpa-agent --card dt295:4-12.1` (差し込み口のカードだけを開き、ATR とカードの番号を出す)、
`denpa-agent --tune dt295:4-12.1 T27 --decode` (`BS15:16625`・`CS22:29024` も。そのボードのカードだけで復号する)、または
`denpa-agent --dt295-probe --channel T27` (`BS15`・`BS15:16625`・`CS2` も)。`--dt295-probe` は機材を設定して選局し、
決めた秒数 (`--seconds N`。既定 5) だけ受けて、設定・選局・最初の TS までの時間、制御転送の数、CPU 時間、TS の統計を出します。最後に、設定の各段・固定の待ち・選局・受信の確認の周回・取り込み・最初の TS の時間を、制御転送と I2C の転送の数つきの表で出します。平均の Mbps は、最初に読めた時刻から最後に読めた時刻までで割ります。`--output <ファイル>` を付けると TS を書きます。
`--switch T27,BS15,…` は、最初のチャンネルの測定のあと、機材を開いたまま続けて選局し直す時間を出します (種別が同じか替わるかも出す)。`--lock-test N` は、同じチャンネルを N 回選局して、成功の割合と最初の TS まで・受信の確認までの時間を出します (`--alt` の別のチャンネルに合わせて離れてから測る。`--reopen` で毎回開き直す)。
2 台以上挿してあるときは `--port <USB のポート>` で指します。`--replug` は、先にポートの電源を入れ直します (Linux)。`--trace` は機材への書き込みを 1 行ずつ出します。

## カードリーダー

**USB のリーダーは、Linux なら usbfs を直接扱います** (`/dev/bus/usb` が見えていれば動く)。Mac と Windows は OS の PC/SC 越しです
([install-mac.md](install-mac.md#カードが読めないとき))。Linux では、ホストや別のコンテナで pcscd が動いていると使えません (「別のプロセスがカードリーダーを
使用中です」と出る)。TPDU 単位のリーダー (Gemalto PC Twin など) には T=1 の枠組みを
こちらで組み、APDU 単位のリーダーにはそのまま送ります。カードの無いリーダーや INT に
答えないカードは飛ばし、USB のリーダーを内蔵リーダーより先に試します (`CardLinks.cs`)。

Amazon で見る (広告): [Gemalto PC Twin](https://www.amazon.co.jp/dp/B001NEIRH0?tag=doa08-22)、[IDBridge CT30](https://www.amazon.co.jp/dp/B003XF2JJY?tag=doa08-22) (Mac で読めないときは [install-mac.md](install-mac.md#カードが読めないとき))

動いているエージェントがカードと話せているかは、設定の「受信」の「チューナー」にある「カードリーダー」の表で分かります
(denpa がエージェントの `/denpa/card` を呼び、INT を 1 回通す)。エージェントを止めた状態なら `denpa-agent --card` でも確かめられます (リーダーを並べ、
ATR とカードの番号を出す)。
チューナーを使わずに B25 だけ確かめるなら `denpa-agent --decode-file <in.ts> <out.ts>` (`/denpa/decode`
と同じことをする。掛かったまま録れてしまったものを救うのにも使える)。

## B-CASカードとデスクランブル

スクランブルは**エージェント自身が復号します** (`B25.cs`)。カードが読めないときは
掛かったまま流し、理由を状態に出します。黙って素通しすると「録画は成功してサイズも
それらしいのに中身が全部スクランブル」という分かりにくい壊れ方になるためです。
選局を畳むときに、掛かったまま流したパケットの数と理由を記録にも残します。

- **録画は止めません。** 電波は二度と来ないので、スクランブルされたままでも
  録ります。denpa がエンコードの前に見て、掛かったままならエージェントに
  復号させます (`src/lib/server/scramble.ts` → `/denpa/decode`)
- やり取りするのはパスだけです。denpa とエージェントは元の TS の同じ置き場 (`RAW_DIR`。コンテナでは `/media/raw`) を
  見ているので、読み書きはエージェントが直接やり、数十 GB を HTTP で往復させません
  (`charts/denpa` が一緒に出すときは、置き場が RWO なので**両方の Pod が同じノードにあることが前提**です)
- 元の TS を残す設定のときは、残るのは復号した TS だけです。掛かったままのものは、
  あとから復号できる保証がありません
- 状態は設定の「受信」の「チューナー」にある「カードリーダー」の表に出ます。
  リーダーごとに 1 行で、カードの番号・状態 (使用中・予備・カードなし・エラー・無効)・
  そのカードで復号しているチューナー・「使う」のスイッチを並べます。`CARD_URL` で鍵を貰っているときは、
  表の代わりに配り役の URL を出します
- **使うカードは 1 枚です。** INT に答えた最初のリーダーのカードを全部のチューナーで
  使い回します (カードに聞くのは ECM の中身が変わったときだけなので、1 枚で足ります)。残りの
  リーダーは予備で、使っているカードが答えなくなると、繋ぎ直すときに探し直して
  使います。チューナーごとにカードは割り当てません
- **「使う」を外したリーダーは開きません。** カードの候補に入らず、表を出すときも開かずに「無効」の行にします。
  使っている最中のリーダーを外すと、エージェントはそのリーダーを手放して次のリーダーで繋ぎ直します。
  PIX-DT295・CECH-ZD1 J の差し込み口は、チューナーも無効にしてあれば USB を閉じます (ほかのソフトや `--dt295-probe` から使えるようになる)。
  カードを読めている最後の 1 台を外すと復号できなくなるので、「オフを確定」をもう 1 回押したときだけ外します。
  外したリーダーは、tuners.json の隣の `cards.json` に名前で残ります (USB のリーダーの名前にはポートが入るので、挿すポートを変えると別のリーダーになる)

### 直らないとき

まず設定の「受信」の「チューナー」にある「カードリーダー」の表で、見えているリーダーと、カードに INT が通るかを見ます
(中身はエージェントの `/denpa/card`)。使っているリーダーは開き直さずに INT を通し、ほかのリーダーは開いて覗いて閉じます。

```json
{
  "ok": true,
  "message": "",
  "source": "local",
  "readers": [
    {
      "name": "Gemplus USB SmartCard Reader (usb 4-11)",
      "card": true,
      "ids": ["0000012345678901"],
      "active": true,
      "tuners": ["PT3-T1", "PT3-S1"]
    },
    {
      "name": "px4-userland 0960 Internal Card Reader",
      "card": false,
      "ids": [],
      "active": false,
      "tuners": []
    }
  ]
}
```

`message` は困ったときだけ入ります (カードがどこにも無い、など)。覗けなかった
リーダーは `error` に理由が入ります。`CARD_URL` のときは `source: "remote"` で、
`remote` (配り役の URL)・`ids`・`tuners` が付き、`readers` は空です。
鍵を配る範囲と、断られたときの文は [鍵を配るのは LAN の中だけ](agent.md#鍵を配るのは-lan-の中だけ) にあります。

エージェントは組んだ denpa (クライアント証明書) にしか答えないので、curl などで `/denpa/card` を直に呼ぶことはできません
([agent.md](agent.md#denpa-とは-tls-で組む))。

- `readers` が空なら、`/dev/bus/usb` がコンテナに見えていません
- `card: false` で `error` が無ければ、そのリーダーにカードが挿さっていません
- 「別のプロセスがカードリーダーを使用中です」と出たら、ホストで pcscd が動いています。
  止めるか、リーダーをそちらから外します (`denpa-agent --card` を動いているエージェントの
  横で起こしたときも、エージェントが使っているのでこう出る)
- 応答が無い (タイムアウト) なら、リーダーが固まっています。エージェントが USB のポートを 1 回リセットして
  立て直します。それでも戻らなければ USB レベルで入れ直します (`4-11` は `lsusb` と `/sys/bus/usb/devices` から引く)

```sh
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/unbind
sleep 2
echo 4-11 | sudo tee /sys/bus/usb/drivers/usb/bind
```

エージェントは起こし直さなくて構いません。次の ECM で探し直します。

実際に復号できているかは `--tune ... --decode` で見ます (復号したあとが 0% 近くなら正常)。
衛星で LNB に電源を送るなら `--lnb 15v` を足します。動いているエージェントは一度使ったチューナーと、起動したときに開いた
カードリーダーを開いたままにしていて、横から開くと断られるので、録画の無いときに止めてから同じイメージで流します
(compose の例。Kubernetes なら `tuner-agent` を 0 台にしてから、同じイメージを同じデバイスで 1 回だけ起こす。
Mac の止め方は [install-mac.md](install-mac.md#cech-zd1-j-の差し込み口が読めないとき))。

```sh
docker compose stop tuner-agent
docker compose run --rm tuner-agent --tune /dev/dvb/adapter1/frontend0 T27 --decode
docker compose start tuner-agent
```

それでも直らなければ、設定の「その他」→「ログ」の「Issue にする」で報告してください。サーバとエージェントのログと環境を、
カードの番号や IP アドレスを伏せて Issue のフォームに入れます ([screens.md](screens.md#バグの報告))。
