# 観る

ライブ・追っかけ・録画をブラウザで観るときの使い方です。録画の観る画面 (`/watch/<id>`) とテレビのアプリは
[library.md](library.md#観るのはブラウザで)、画面の作りは [player.md](player.md) にあります。

## ライブ

**放送中のものもブラウザで観られます** (`/live`)。WebSocket + MSE で放送に追いつき続けます (作りは [stream.md](stream.md))。
局は右の一覧から切り替えます。止めれば追っかけ再生になり (速さを選べ、追いついたら自分でライブに戻る)、
二カ国語・解説放送の音声も選べます (⚙ の「音声」)。

**1000px より狭い画面 (タブレット・スマホ・狭めた窓) では、映像を端から端まで出し、局の一覧をその下に置きます** (ページごと巻きます。観る画面・追っかけの番組の中身も同じ)。
スマホを横にすると映像を画面の高さいっぱいにし、下のタブも隠します (局の一覧は映像の下へ巻いて見ます。ほかの画面へは縦に戻して移ります)。

## 折り畳み端末を机に置いたとき

**半分に折って横に置くと (テーブルトップ)、上の段を映像だけにし、右の列を下の段に出します** (ライブ・追っかけ・観る画面)。
映像は上の段の幅か高さいっぱいに広がります。上のヘッダーは出さず、スマホと同じく操作は下に寄せます (ライブは下の段の下端に下のタブ)。
下の段は黒い地で、ライブは局の一覧、観る画面と追っかけは番組の中身を今のまま出し、中で巻けます。
ブラウザのタブと URL の欄はページからは消せず、そのぶん上の段が低くなります。**ホーム画面に追加してアプリとして開く (PWA) か全画面にすると、ブラウザの欄のぶん映像が大きくなります。**
テーブルトップの全画面は映像だけでなくページごとで、上下の並べ方はそのままです。
アンビエントモードがオンなら、映像の光が机に映り込んだような色を下の段の地に敷きます (オン/オフは同じ ⚙ の「アンビエントモード」)。
折り目を報告するブラウザ (Android の Chrome・Edge・Samsung Internet) だけで、ほかの端末と、開いた・本の形に持ったときは今のままです。

## 操作バー

触らないでいると 2.5 秒で引っ込み、マウスを動かすか指で押せば戻ります (止めていても同じ)。
キーボードでは `空白`・`k` で再生、`←` `→` で 10秒、`c` で字幕、`s` で切り抜き、`f` で全画面、`<` `>` で速さ、`m` で消音、`↑` `↓` で音量です (3画面で同じ。ライブの `←` `→` はシークバーを出しているときだけ、速さは追っかけ中だけ。データ放送を出している間の `空白`・矢印・`f` はデータ放送のリモコン)。

端末ごとに決めておくものは操作バーの ⚙ (再生の設定) にまとめてあります: CMスキップ・実況・アンビエントモード・
バックグラウンド再生・互換モード・字幕 (オフと言語)・音声 (二カ国語・解説放送)・コーデック。

### 音量

**放送は動画サイトより小さめにそろえてあるので、既定で少し大きく鳴らしています。** 日本の放送は
-24 LKFS (ARIB TR-B32) にそろえてあり、動画サイト (-14 LUFS 前後) より 10 dB ほど小さく聞こえます。
既定の 100% はそれを +6 dB したもので、差の半分より多くを埋めます。全部は埋めません (大きな音の山を
抑え続けることになり、潰れた音になる)。

- 音量のつまみで 0%〜100% を選べます (5% 刻み。`↑` `↓` でも)。マウスの端末では、音のボタンに乗せると真上に縦のつまみが出ます (ホイールでも変えられます)。指の端末と、狭くて音のボタンが ⚙ に入っているときは ⚙ の「音量」です (つまみは画面に1つだけ)。端末ごとに覚えます (3画面で同じ)
- つまみの位置と聞こえる大きさがほぼ比例するように掛けます (掛ける大きさはつまみの値の2乗。70% でほぼ放送そのまま、50% は 100% より 12 dB 小さい)
- 割れないように、いつもリミッタ (-3 dBFS から抑える) を通します。0 dBFS の音を入れても、出口は -2 dBFS 前後に収まります
- 消音 (`m`・音のボタン) は音量とは別です。消しても音量はそのままです

`<video>` で観ているときは、`<video>` の音を Web Audio に通して掛けます (`<video>` の音量は 1 より
大きくできない)。自動再生の許しが出るまで (ページのどこかを押すまで) は通さず、放送のままの大きさで鳴らします。

### 切れたら繋ぎ直します

**サーバを入れ替えると（デプロイ）、観ている最中に配信が切れます。** コンテナごと作り直すので
数十秒戻りませんが、戻ることは分かっているので、すぐには諦めません。

|          | 切れたあと                                                                                                                                                                                                                                                                                                                                          |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ライブ   | WebSocket を張り直して同じ局を選び直す（1秒→2秒→…10秒で頭打ち）。回数の上限は無い                                                                                                                                                                                                                                                                   |
| 観る画面 | 同じファイルを読み直して切れた瞬間の位置へ戻す（15秒おきの続きではなく）。待ちは同じく倍々で10秒が頭打ち。続けて8回（約1分）で諦めて、観られる先 (Chrome・Edge かテレビのアプリ) を案内する。その場で流しているもの (`remux-player.ts`) と互換モードで canvas に描いているもの (`canvas-player.ts`) は、観ていた位置からリクエストし直す (数は同じ) |

どちらも待っている間は「繋ぎ直しています」と出します。**読めない形式や壊れたファイルは
読み直しません。** 何度やっても同じなので、すぐ観られる先を案内します。

### 裏に回したら止めます

**バックグラウンド再生は既定でオフです。** ホームへ戻る・別のアプリやタブへ移ると止め、戻ってきたら
続きから再開します（ライブで放送の今に張り付いていたなら、放送の今へ戻る）。オン/オフは再生画面の
⚙ の「バックグラウンド再生」で、端末ごとに覚えます（速さ・CM スキップと同じ `localStorage`）。

|                                                                        | オフ（既定）                          | オン                                                     |
| ---------------------------------------------------------------------- | ------------------------------------- | -------------------------------------------------------- |
| 裏に回したとき                                                         | 止める                                | 止めない                                                 |
| OS・ブラウザが自分で小窓にする（全画面からホームへ戻った iPhone など） | させない（`disablePictureInPicture`） | 任せる                                                   |
| canvas に描くときの音（Safari）                                        | Audio Session は `auto` のまま        | `playback`（裏でも鳴らす）                               |
| Web Audio で鳴らす音（Safari 以外）                                    | ページ（Web Audio）から直に鳴らす     | `<audio>` を通して鳴らす（メディアの再生として扱わせる） |

Web Audio で鳴らす音は、canvas に描くとき (放送のままの MPEG-2・互換モード) の音と、[音量](#音量)を掛けている
`<video>` の音です。`<video>` の音を Web Audio に通している間は、Safari ではオフでも Audio Session を
`playback` にします (`<video>` から直に鳴らしていたときと同じく、消音スイッチで黙らない)。

**押して開いた小窓（`pip.svelte.ts`）はオフでも使えます。** 出している間は裏に回しても止めず、
Web Audio の音もオンと同じ鳴らし方にします。閉じた時点でまだ裏なら、そこで止めます。

**Web Audio の音を `<audio>` に通すのは、Web Audio の音を効果音と同じに扱って裏で止めるブラウザが
あるからです**（テスラの車載ブラウザ）。`<audio>` を通すと「メディアの再生」になり、ロック画面・車の操作・
ブラウザの再生中の通知にも出て、そこで押した止める・再開は操作バーに反映します（`#lib/sound.ts` の `Outlet`）。
Media Session のタイトルはまだ出していません（ページのタイトルが出る）。

### 全画面にする方法は端末で変えます

**全画面にするのは枠ごとです**（映像だけでなく字幕・データ放送・操作列も一緒に大きくする）。
折り畳み端末のテーブルトップ ([上](#折り畳み端末を机に置いたとき)) だけは**ページごと**全画面にします (`document.documentElement`)。枠だけだと映像が折り目をまたいで画面いっぱいに広がり、上下の並べ方が崩れるためです。
ボタンのアイコン（広げる/縮める）はどの方法でも今の状態を映します。

| 端末                          | 全画面にする                                                                | 戻す                                                                              |
| ----------------------------- | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| PC・Android・iPadOS 16.4 以降 | `requestFullscreen()`                                                       | ボタン・`f`・Esc・端末の戻る（UA が持つ）                                         |
| それより前の iPadOS           | `webkitRequestFullscreen()`                                                 | 同上                                                                              |
| iPhone の Safari              | **枠を画面いっぱいに広げる**（`position: fixed`。後ろのページは止めて黒く） | ボタン・`f`・Esc・**戻る**（広げたときに履歴を1段積む。もう一度戻ると前の画面へ） |

iPhone は要素の全画面を持たず、あるのは `<video>` だけの `webkitEnterFullscreen` です。
あれは映像だけを OS の再生画面に渡すので字幕・データ放送・操作列が置いていかれ、使いません。
広げたときの向きは固定できません（iPhone の Safari は `screen.orientation.lock` を持たない）。
横に持てば横いっぱいになります。別の画面へ移ると畳みます。

## 実況のコメント

**ニコニコ実況のコメントを、映像の上に右から左へ流せます。既定はオフです。** 設定の「連携」の「実況」(世帯で 1 つ) をオンにすると、
⚙ に「実況」の行が出ます。流すかどうかはそこで端末ごとに決めます (覚えておきます)。

- **コメントは denpa のサーバを通りません。** 端末が NX-Jikkyo (公式のニコニコ実況のコメントも取り込んでいる非公式のサービス) に直接繋ぎます。
  相手には端末の IP と、どの局をいつ観ているかが見えます ([architecture.md](architecture.md#端末が外へ繋ぐもの-実況のコメント))
- 対応しているのは NX-Jikkyo のある局 (地上波のキー局と系列局・一部の独立局、主な BS、AT-X) です。系列の地方局ではキー局のコメントが流れ、
  地方局が独自の番組を流している間もそのままです。実況の無い局では ⚙ の行に「(この局にはありません)」と出ます
- **いま映しているコマの放送時刻までに書かれたものを流します。** ライブは放送より 1〜2 秒遅れて映るので、コメントもそのぶん手元で待ちます
  (時刻はサーバが送る放送の時計で合わせ、推測の遅れは置きません)。届くのが遅れても 10 秒以内ならすぐ流し、それより古いものは流しません。
  止めて追っかけにしたときも、映している場面の時刻に合います
- 映像の枠の全面に、黒い縁・半分の透明度で流します。字幕はコメントより上に出ます。1 件は 4 秒ほどで流れ、空いた行が無ければそのコメントは捨てます
  (重ねて描きません。同時に 60 件まで)。動きを減らす設定の端末では、流さずに上の行へ 3 秒置きます
- **色・位置・大きさのコマンドに従います。** 色はニコニコの色の名前 (`red`・`niconicowhite` など) と 16 進の色 (`#rrggbb`)、
  `ue`・`shita` は上・下の行に 3 秒止め、`big`・`small` は字を大きく・小さくします (大きいものも 1 行に収まる大きさまで)。読めないコマンドは無視し、
  指定の無いものは白で流します。止めるもので枠より広いものは、収まるまで字を縮めます
- データ放送を出している間・小窓・切り抜きには重ねません
- 読めなくなったら (NX-Jikkyo や過去ログ API が止まった・家の外へ出られない) 通知は出さず、⚙ の行に「(いまは読めません)」と添えます。戻れば流れ始めます
- NG ワード・字の大きさ・流れる速さの設定はありません

**録画と、録画中の追っかけでも流せます。** 録画のコメントは、その時刻のものをニコニコ実況 過去ログ API (同じく tsukumijima さんが運営する非公式のサービス) から取ります。
コメントは録画の隣に保存しないので、実況をオフにしていた間に録った録画でも、あとから流せます。

- **録画は、開いたときに録画の区間のコメントを 1 回で取ります** (運営者の負担を考え、再生に合わせて細かく取りません)。
  過去ログはおよそ 10 分遅れて入るので、録り終えてすぐに開いた録画は、末尾が入るまで 5 分おきに取り足します
- 再生位置を元の TS の秒に直し (CM を切ったものは切った区間を戻して)、**録画の頭の放送時刻**に足した時刻までのコメントを流します。
  頭の放送時刻は録っている間 (とエンコードのとき) に TS から測ります。測れない録画 (取り込んだものなど) は予定の時刻で合わせるので、数秒ずれることがあります
- **CM を切った録画では、切った区間に書かれたコメントは流れません** (その時刻を飛び越すため)。チャプターを打っただけの録画では CM の中のコメントも流れ、CM スキップで飛ばせば流れません
- 飛ばした (シーク) ときは、飛んだ先から流し直します。速さを変えると、流れる速さも同じだけ変わります (×2 では行が足りず多く捨てます)
- **録画中の追っかけ**は、10 分より前を過去ログ API から (開いたときと、その後は 5 分おきに新しいところだけ)、新しいところを NX-Jikkyo から受けます。
  過去ログはおよそ 10 分遅れて入るので、その間は NX-Jikkyo で 1 回だけ遡ります (1000 件まで)。4:00 をまたいだ直後の 10 分は、前の日のスレッドになるので抜けます
- 端末に保存した録画 (オフライン) では流しません

### 実況に書き込む

**ライブでは、NX-Jikkyo にコメントを書き込めます。** 書き込み用の設定はありません。実況を流しているとき (世帯の設定と端末の ⚙ の「実況」が両方オンで、
映している局に実況がある) は、映像の右端の列に「実況に書く」(鉛筆) が出ます。押すと入力の 1 行が開きます
(広い画面と全画面では操作バーのすぐ上、スマホの縦では下のタブのすぐ上。ソフトキーボードが出たらその上)。

- **書いたものは公開され、消せません。** NX-Jikkyo では誰でも読め、過去ログにも残ります。ニコニコのアカウントは使わず、いつも匿名 (184) で書きます。
  同じ端末から書いたものは、NX-Jikkyo の側で結び付けられます ([architecture.md](architecture.md#端末が外へ繋ぐもの-実況のコメント))
- **書けるのは「いま」に追い付いているときだけです** (止めていない・映しているコマが放送から 30 秒以内)。止めた・遡ったときは
  「ライブに戻ると書けます」と出ます。録画と、録画中の追っかけでは書けません
- Enter か「送る」で送ります (変換を決める Enter では送りません)。✕ か Esc で閉じます。開いている間は操作バーを引っ込めません
- 送れたら欄を空にし、すぐに自分の画面に流します。自分の書き込みは字の下に空色の短い線が付きます。NX-Jikkyo から戻ってきた同じものは流しません
  (送ってから 60 秒の間に、本文が同じものを 1 回だけ)
- 1 行の右のパレットのボタンで、色 (白・赤・ピンク・オレンジ・黄・緑・水色・青)・位置 (上・流れる・下)・大きさ (大・中・小) を選べます。端末ごとに覚えます
- **長さは 60 文字まで** (絵文字も 1 文字と数えます)。NX-Jikkyo のサーバは長さを確かめないので、NX-Jikkyo と KonomiTV の書き込みの欄の上限に合わせています。
  残りが 10 文字を切ると数を出します。空のもの・改行や制御文字を含むもの・「/」と英小文字で始まるもの (運営のコメントの形) は送りません
- **1 件ずつ、3 秒以上空けて送ります。** NX-Jikkyo は 0.5 秒以内の連投を、受け付けたように見せて捨て、続くとその接続の書き込みをすべて捨てるためです。
  早すぎると「3 秒待ってください」と出ます
- うまくいかなかったときは、入力の 1 行に理由を出して本文を残します (通知は出しません。自動で送り直しません)。
  「スレッドが替わりました。もう一度送ってください」(毎日 4:00 の替わり目)・「この書き込みは受け付けられませんでした」・
  「送れたか分かりません」(5 秒返事が無い・途中で切れた)・「(いまは書けません)」(NX-Jikkyo に繋がっていない)

## ホーム画面に置く

denpa は PWA なので、ブラウザの「ホーム画面に追加」でアプリのように開けます
(アドレス欄もタブも出ません)。

**名前が2つあると、置いたアイコンが見分けられません** (どちらも「denpa」でアイコンも同じ)。
そこで、どの名前で来たかで表示名を変えられます (`PWA_NAMES`)。

```sh
PWA_NAMES='tv.example.com=denpa,tv.lan.example.com=denpa 宅内'
```

書き方は `ホスト名=表示名` のカンマ区切りで、載っていない名前で来たら `denpa`。
`name` と `short_name` に同じものが入ります（アイコンの下に出るのは `short_name` で、
端末によっては十数文字で切られる）。

> [!IMPORTANT]
> **入れ直すまで名前は変わりません。** ブラウザは追加した時点のマニフェストを覚えます
> （Chrome は読み直すこともあるが当てにできない）。変えたらアイコンを入れ直してください。

**同じ端末に2つ置けます。** 名前が違えば別のサイトで、マニフェストの `id` も名前ごとに
分けてある（`/?host=<名前>`）ので、片方がもう片方の入れ直しと見なされません。

マニフェストは `static/` ではなく `/manifest.webmanifest` のエンドポイントで組み立てます
（`src/lib/server/manifest.ts`）。**認証は掛けていません。** ブラウザが資格情報を付けずに
取りに来るためで（[auth.md](auth.md)）、出しているのは名前・色・アイコンの場所だけです。

**色 (`background_color`・`theme_color`) はテーマの地に合わせます。** Android でホーム画面から開くと、
下のジェスチャーバーは `background_color` で塗られ、ページはその裏まで描けません。上のステータスバーも
theme-color で塗られるだけで、iPhone のように裏まで描く方法はありません (Chrome 155 で確かめた)。
ライトのときはページがマニフェストを `?theme=light` 付きで読ませ、白を返します。Chrome は入れたあとの
マニフェストを日を置いて読み直すので、テーマを替えてもジェスチャーバーの色が追いつくのは後になります。

### 開き直したら読み直します

**ホーム画面から開いたアプリは、閉じても捨てられません。** 端末が凍らせて残し、次に
開くとそのまま見せるので、前に閉じたときの一覧がリロードするまで出ていました。
見えるようになったところで1回読み直します（`+layout.svelte`）。通知（SSE）は
凍っている間に切られて自分では戻らず、繋ぎ直しても間に起きたことは流れてこない
（溜めていない）ので、それだけでは足りません。繋ぎも同じところで張り直します（`live-updates.svelte.ts`）。

## 端末に保存して観る (オフライン)

**端末に保存したものは denpa の中だけで観ます。** ブラウザの保存領域 (IndexedDB) に置き、
ファイルとして外へは出しません (持ち出すダウンロードが無い理由は [library.md](library.md#観るのはブラウザで))。
作りは [offline.md](offline.md)。

**電波の無いときは `/offline` で観ます。** `/watch/<id>` はサーバが組む画面なので開けず、
ナビゲーションが繋がらないとサービスワーカーが `/offline` へ落とします。
`/offline` はナビに並べません。保存・進み具合 (行の3段目に割合、下端にバー)・視聴は
ふだんの一覧と観る画面でできます (オンラインの `/watch` は端末のコピーがあればそちらを使う)。
「サーバからも消す」予約 (outbox) を積むのは `/offline` の削除だけです。一覧の行の削除は
その場でサーバから消し (端末のコピーも片付ける)、詳細の「端末から消す」はサーバに触りません。
