# PT3 など (Linux DVB)

Linux の DVB ドライバで動くチューナーです。**Linux だけで使えます** (Mac と Windows には DVB がありません)。
地上波か衛星かは、デバイスに問い合わせて自動で見分けます。DVB-C に対応した機材は、ケーブル (ISDB-C) も選局できます ([下記](#ケーブル-isdb-c-を受ける-実機で確かめていない))。
denpa が使える内蔵のカードリーダーは無いので、USB のカードリーダーを別に挿します ([tuners.md](tuners.md#カードリーダー))。

チューナーの一覧は [tuners.md](tuners.md)、エージェントの中でどう扱っているかは [agent.md](agent.md#デバイスを開いたままチャンネルを変える)。

「Amazon で見る」は広告のリンクです ([tuners.md](tuners.md))。

## 機材とドライバ

**実機で確かめているのは PT3 だけです。** ほかの機材は、カーネルのドライバと denpa の選局の手順を照らし合わせて「動くはず」と見ているもので、
実機では確かめていません。使ってみたら、動いた・動かなかったを教えてください ([下記](#動いたか教えてください))。

### カーネルに入っていないドライバで使う機材

**mainline に無い DVB のドライバを自分で組んで入れると、`/dev/dvb` に出て同じ手順で使える見込みの機材です。denpa では実機で確かめていません。ドライバを組んで動かすことも試していません。**
ドライバのソースを読み、周波数の単位 (地上波は Hz、衛星は中間周波数の kHz) と TSID の指定 (`DTV_STREAM_ID`) が PT3 のドライバと同じ受け方であることだけを確かめました。

| 機材                        | 種別             | 使うドライバ                                                                                                                                                               | メモ                                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------- | ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PX-Q3PE (PLEX、PCIe)        | 地上波 4・衛星 4 | [knight-rider/ptx](https://github.com/knight-rider/ptx) の `pxq3pe_pci`                                                                                                    | ブリッジは ASICEN の ASV5220、復調は PT3 と同じ TC90522 です。ドライバの最後の更新は 2021-07 で、いまのカーネルで組めるかは確かめていません。LNB の電源は、衛星の受信部を使っている間ドライバが自動で入れます。ドライバに電源の切り替えが無いので、denpa の LNB の設定は使われません                                                                                      |
| PX-W3PE Rev1.3 (PLEX、PCIe) | 地上波 2・衛星 2 | [ohayoyogi/pxw3pe-linux](https://github.com/ohayoyogi/pxw3pe-linux) の `pxw3pe_pci` ([inaba-garnet/pxw3pe-linux](https://github.com/inaba-garnet/pxw3pe-linux) のフォーク) | ブリッジは ASV5220 です。ホストに firmware `pxw3pe.fw` が要ります。配布されていないので、PLEX の公式ドライバから自分で作ります (ドライバの `firmware/README.md`)。無いと機材独自のスクランブルがかかったままの TS しか出ません。LNB の電源は出せないので、外から給電します。フォークは Rev1.2 にも対応したと書いていますが、README が動作環境に挙げているのは Rev1.3 です |

次の機材は、ドライバはあっても denpa では動かない見込みなので載せていません。

- Siano のうち PX-S1UD (Rio) と Pele 以外は、地上波の選局がワンセグになります
- Leadership ISDBT は、ワンセグのモジュールです
- Digital Devices の CXD2838 / CXD2854 は、mainline のチューナーのドライバが地デジの選局を受け付けません

## 入れ方

1. **ホストでドライバを読み込みます。** PX-Q3PE と PX-W3PE のほかは、どれも mainline のカーネルに入っているドライバです。
   `/dev/dvb/adapter0` などが出ていれば準備はできています。
   Talos Linux なら、ドライバは system extension `siderolabs/dvb-pt3` で入ります (PT3 だけ。[install-talos.md](install-talos.md))
2. **denpa を入れます** ([install.md](install.md#1行で入れる))。compose.prod.yml・`denpa-aio`・Helm は、
   どれも `/dev/dvb` をディレクトリごと渡してあります。compose.prod.yml と `denpa-aio` の手順は
   DVB のデバイス (212) を開く許可も付けてあるので、挿し直しても再起動は要りません
3. **設定の「受信」の「チューナー」で確かめ、「チャンネル」でスキャンします。** 見つかったチューナーと種別が並びます

## 設定

- **設定の `device` は `/dev/dvb/adapterN/frontendM`** です。挿さっていれば自動で組み立てるので、普段は書きません
- **衛星のアンテナに電源を送るなら、設定の「受信」の「チューナー」で行の「⋯」を開き、LNB で 15V を選びます。**
  DVB には 18V (`SEC_VOLTAGE_18`) を指示します (11V は 13V。recisdb と同じ対応)。
  ドライバに電源の切り替えが無い機材 (PX-BCUD など) では電源を指示せずに選局し、記録に「この機材は LNB の電源を出せません」と 1 回だけ残します
- **一度選局したチューナーは、エージェントを止めるまで開いたままにします。** チャンネルは開いたまま切り替えます

## ケーブル (ISDB-C) を受ける (実機で確かめていない)

**DVB-C に対応した機材 (`DTV_ENUM_DELSYS` に `SYS_DVBC_ANNEX_C` か `SYS_DVBC_ANNEX_A` があるもの) は、ケーブルの局 (種別 `CATV`) も選局します。**
どの機材でも、実機では確かめていません。受けられた・受けられなかったを教えてください ([下記](#動いたか教えてください))。

- Annex C があれば Annex C、無ければ Annex A で、64QAM・5.274 Mbaud を指定して選局します。周波数は IT930x の機材と同じ選局表 (`QC13`〜`QC63`・`QU13`〜`QU62`・`QV1`〜`QV12` の中心周波数) です
- Annex A はロールオフが 0.15 で、ISDB-C (Annex C) の 0.13 と違います。復調器によってはロックしません。256QAM の搬送波は選局しません
- 見つけたときには「ケーブル」を選んでいません。設定の「受信」の「チューナー」で、受信できる種別に「ケーブル」を選びます。
  DVB-C しか受けられない機材は、「ケーブル」を選んで「使う」をオフにして並ぶので、「使う」をオンにします。そのあと「チャンネル」で「ケーブル」をスキャンします ([tuners.md](tuners.md#ケーブル-isdb-c))
- TSMF (1 つの搬送波に複数の TS を束ねる方式) の搬送波から TS を選ぶのと、4K の分割 TLV を組み立てるのは、IT930x の機材と同じくエージェントがします ([agent.md](agent.md#dvb-の機材で-isdb-c-を受ける-実機で確かめていない))
- 1 つのチャンネルを試すには、`docker compose run --rm tuner-agent --tune /dev/dvb/adapter0/frontend0 QC30` のように流します。
  選局した方式 (`DVB-C Annex C` か `DVB-C Annex A`)・受けた周波数・TSMF の判定・C/N が出ます

## うまくいかないとき

- 設定の「受信」の「チューナー」に出てこないときは、ホストに `/dev/dvb/adapter*` があるか、コンテナに `/dev/dvb` を渡しているかを見ます
- 選局はできるのに映らない (スクランブルのまま) ときは、カードリーダーを見ます ([tuners.md](tuners.md#直らないとき))。
  `denpa-agent --tune ... --decode` で、選局と復号を 1 回だけ試せます (同じ節)

## 動いたか教えてください

実機で確かめていない機材を使ったら、動いたか動かなかったかを [Issue](https://github.com/danything/denpa/issues) で教えてください。
設定の「その他」→「ログ」の「Issue にする」を使うと、サーバとエージェントのログと環境を、カードの番号や IP アドレスを伏せて
Issue のフォームに入れられます ([screens.md](screens.md#バグの報告))。機材の名前と、地上波・衛星・ケーブルのどれで試したかを書き添えてもらえると助かります。
動いた報告をもらった機材は「実機で確かめた機材」に移します。
