# 観る画面の作り

ライブ・追っかけ・録画の観る画面の作りです (手を入れる人向け)。使い方は [watch.md](watch.md)。

## 操作まわりは3画面で共通

**同じものを 2 つ書かない。** ライブ (`/live`)・追っかけ (`/chase/<id>`)・観る画面
(`/watch/<id>`) はどれも映像の上にボタンを重ねる画面なので、部品は `src/lib/components/player/` に寄せてあります。

### アイコンは Lucide を、組むときに埋め込みます

**アイコンは [Lucide](https://lucide.dev/icons) に揃えています** (線の太さ 2・角丸。
`currentColor` で文字の色に従う)。読み込みは **Iconify のアイコンデータの束 (`@iconify-json/*`) を
[unplugin-icons](https://github.com/unplugin/unplugin-icons) で組むときに Svelte の部品へ
変える**やり方です (`import Play from '~icons/lucide/play'`。`vite.config.ts`)。

- **実行中に取得しない。** denpa は家の LAN だけ・オフラインでも開くものなので、
  Iconify の API からアイコンデータを取る `@iconify/svelte` の既定の使い方は採りません。束に入るのは
  使ったアイコンの `<svg>` だけで、SSR でもそのまま出ます (後からアイコンが差し込まれてずれることもない)。
  service worker が持つのも普通の JS の束です
- **`@iconify/svelte` にアイコンデータを渡す方式は採りません。** 実行時の部品とアイコンのデータを両方束に入れることになり、重くなります
- **`lucide-svelte` を直に使わないのは、ほかの集まりも同じ書き方で足せるから。**
  局やサービスのロゴが要るときは `@iconify-json/simple-icons` を足して `~icons/simple-icons/*`
- 足した依存はどちらも開発時だけ (`devDependencies`)。束に入るのは Lucide のアイコン (ISC) だけです
  ([licenses.md](licenses.md))
- **Lucide に無いアイコンは `src/lib/icons/*.svg` に置きます** (`~icons/denpa/*`)。いまはデータ放送の
  「d」だけ (リモコンと同じ字。線の太さと角は Lucide に揃えた)

ロゴ・PWA のアイコン (`static/`)・局ロゴ・データ放送の画面は「アイコン」ではないので対象外です。

## 観る画面は回線に合わせて画質の段を替えます

**段を決めるのは `adapt.ts`、測った値を渡すのは `watch-adapt.ts`、継ぎ目なく替えるのは `remux-player.ts` です。** 段の表と、サーバが測った送り出しの状態 (`pace`) は
[stream.md](stream.md#回線に合わせて画質を下げる)、使い方は [watch.md](watch.md#回線が細いと画質を下げます-観る画面) にあります。

- `watch-adapt.ts` が 1 秒ごとに `adapt.ts` を呼びます。渡すのは詰まっているか、先に読めている長さ、受け取りの速さ、送り出しの具合 (`GET /api/playback/pace?id=`。2 秒ごと) です。止めている間・切り替えの最中は呼びません
- **受け取りの速さは読んでいる間だけ数えます** (`ts/meter.ts`。5 秒の窓)。先が埋まって (`AHEAD` の 60 秒) 読むのを止めている間は、最後に測った値を渡します。
  止めていた間にブラウザが手元に溜めたぶんは待たずに返るので数えません。20 秒測れていなければ、測れるまで先の上限 (60 秒) を外して読みます
- **プレイヤーを替える切り替えは、裏の `<video>` で用意してから入れ替えます** (`prepareStep`。決め方は `handoff.ts`)。ファイルの直再生・MPEG-2 (段 0) から下げるとき、
  段 0 へ戻すとき、音声だけとの行き来がこれです。`<video>` を 2 つ置き、映していない側 (透明・消音) に次の観かたを読み込ませて、いまの位置の 3 秒先 (`HANDOFF_LEAD`) で止めて待たせます。
  いまの再生がそこまで来たら、同じコマの間に映す側と音を出す側を替え、前のプレイヤーを畳みます。止めている・詰まっている (2 秒) ならいまの位置で待たせて入れ替えます。
  用意している間 (たいてい数秒) は、サーバの読み出しと端末のデコードが 2 本ぶんになります。
  同じ `<video>` を作り直していた頃は、読み込み直す間が黒くなり、位置が 0 に戻った一瞬に先頭の CM を飛んで「CM を飛ばしました」と出ていました。
  イベントは映している側のものだけ受けます。断られた (503)・読めなかったら、いまのプレイヤーのまま続けます。15 秒 (`HANDOFF_GIVE_UP`。タブが裏に回っていた間は数えない) で入れ替えられなければ、
  いまのプレイヤーを作り直します。小窓を出している間と、描く先が canvas (MPEG-2) のときも作り直します。作り直す間は最後のコマで覆い (`hold`)、その間は CM を飛びません
- **段 1〜3 の間の上げ下げは同じ MSE のまま替えます** (`switchTo`)。いまの位置を含む区間の末尾 `E` から先を `stream?from=E&rung=` でリクエストし、
  応答が来てから前のストリームを止めます。`E` より前に溜まっているものはそのまま再生し、コーデックが違えば `changeType` で替えます。
  断られたら (503) 前のストリームのまま続けます。区間の途中で切らないのは、残したコマが参照するコマまで消えることがあるためです
- 段を下げた変換のコーデックはサーバが選ぶので、MSE の型は応答の `X-Denpa-Codec` から決めます (`#lib/live.ts` の `codecsFor`)。端末が受け取れるコーデックは `?playable=` で渡します
- **段 0 へ戻すときは、下げる前の観かた (ファイルの直再生・MPEG-2。初めから流していたならその詰め替え) を裏で用意して入れ替えます。**
  同じ MSE のまま詰め替えに替えると、詰め替えは `E` の手前のキーフレームから始まるので、溜めてあった下げた段のコマを途中から上書きし、デコーダも再生の途中で替わります。
  元の画質に戻したあと映像が遅れていたのはこのためと見ています (遅れが JS から見えない Windows では `unslip` も直せない。実機では確かめていない)
- **音声だけとの行き来もプレイヤーを替えます。** MSE は SourceBuffer の中のトラックの数を替えられないためです
- **互換モード (canvas) は段を替えるたびに canvas のプレイヤー (`canvas-player.ts`) を作り直します** (`canvasStep`)。裏で用意しないのは、
  デコーダを 2 つ並べると非力な端末ではどちらも間に合わないためです (`raw/budget.ts`。2 本観ていた端末でコマが大きく落ちた)。
  新しいプレイヤーが描き始めるまで、最後のコマで覆い (`grab`)、映像と音は止まります。受け取りの速さは `<video>` と同じく読んでいる間だけ数え (`ts/meter.ts`)、先のバッファは手元の音の尺 (`lead`)、
  詰まりはバッファを使い切った間 (`waiting`) です。段を下げた変換は `?playable=` に描けるコーデック (H.264・AV1) だけを渡し、MPEG-2 からは H.264 の変換として
  リクエストします。H.264 を描けない端末では段を動かしません (GPU が無ければ下げた先はソフトウェアの H.264)。音声だけにはせず、360p のまま流します (映像の無い fMP4 を canvas のプレイヤーで鳴らす経路を確かめていない)。作り直した変換が混んでいて断られたら (503)、替える前の段で作り直します。描けなくなったとき (`raw/budget.ts`) は段 0 に戻して形式を替えます
- 互換モードでない MPEG-2 (canvas に描く) から下げるときは、ファイルの直再生と同じく裏の `<video>` で変換を用意して入れ替え、段 0 へ戻すと MPEG-2 に作り直します
- 端末に保存した録画を描いている間は段を動かしません
- **映像だけ遅れたら飛び直します** (`components/player/unslip.ts`。飛び直す決まりはライブと同じで、遅れが戻っても段は下げない。[stream.md](stream.md#映像だけが遅れる音と字幕は合っている))。段を替えたあと、Android の Chrome で映像だけ遅れたまま戻らなかったためです。CM の先へ飛んでいる最中と、canvas に描いている間は見ません。シークした直後の 1 コマは、飛ぶ前の時刻を持っていることがあるので測りません

## ライブの 4K の局は、放送の HEVC を再生できるかで形式を決めます

**4K の局の「放送のまま」は HEVC の詰め替えで、画面は端末がそれを再生できるかを先に確かめてから形式を決めます** (`live-player.svelte.ts` の `decideFormat`)。
サーバの経路は [stream.md](stream.md#4k-の局のライブ) にあります。

- 局の一覧の `broadcast` (`#lib/live-choice.ts` の `BroadcastCodec`。4K の局は `hevc`) を `Tuned.broadcast` に入れて選局します。
  追っかけは録画の放送のコーデック (`chase/[id]/+page.server.ts` の `broadcast`。4K の局の録画 `.mmts` と、PMT の映像が HEVC の TS の録画は `hevc`) を使います
- 4K の局を初めて開くときに 1 回だけ、`#lib/hevc-4k.ts` の `broadcastHevcPlayable` で調べて覚えます。MSE の `isTypeSupported` と、
  `mediaCapabilities.decodingInfo` に放送の値 (3840x2160・59.94 コマ・10 ビット・HLG・BT.2020) を渡した答えの両方で決めます
- 自動の順は `autoOrder` に `broadcast` を渡して決めます (家の中は HEVC → H.264 → AV1)。MPEG-2 のデコードを確かめること (`raw/support.ts`) は、互換モードでなければ 4K の局ではしません
- メニューで「放送のまま」を選んでいると、4K の局では `codec: "hevc"` でリクエストします。メニューの行は「MPEG-2」ではなく「H.265」と出します (`components/player/settings.ts` の `liveCodecs`)
- 段を上げ下げする仕組み (`adapt.ts`・`RungAdapter`) は TS の局と同じです。詰め替えた HEVC は段 0 で、段を下げるとサーバが AV1 か H.264 を選びます
  (4K の局は H.265 にエンコードしない)。MSE が HEVC を受け取れなかったら、ほかの形式と同じく打ち切って次の形式に移ります (`hevcGaveUp`)
