# PX-S1UD

**地上波だけ**の USB チューナーで、1 台で 1 チャンネルを取ります。
denpa が使える内蔵のカードリーダーは無いので、USB のカードリーダーを別に挿します ([tuners.md](tuners.md#カードリーダー))。
Linux では、カーネルのドライバ (DVB) でも、エージェントが USB を直に持つ実装でも使えます。Mac (Apple Silicon) と Windows (x64) では、エージェントが USB を直に持つ実装だけです。

チューナーの一覧は [tuners.md](tuners.md)。エージェントの中でどう扱っているかは [agent.md](agent.md#siano-の機材を直に持つ作り-実機で確かめていない)。

[Amazon で見る (広告)](https://www.amazon.co.jp/dp/B006RQLNES?tag=doa08-22)

**エージェントが USB を直に持つ実装は、仕様書だけから書いたもので、実機 (PX-S1UD) ではまだ確かめていません。**
確かめたのは、仕様書の手順を偽の USB の上で流す単体テストだけです。機材を開く・ファームウェアを送る・選局する・TS を受ける・C/N を読む、のどれも実機では動かしていません。
動いたか動かなかったかを [Issue](https://github.com/danything/denpa/issues) で教えてください。動かなかったときは、記録に出る行 ([下記](#実機で確かめる順)) があると直せます。

**Linux で動かなかったときは、カーネルのドライバ (`smsusb` + `smsdvb`) で DVB として使えます。** PX-S1UD は mainline のドライバで Linux DVB になります
(ホストの `/lib/firmware` に `isdbt_rio.inp` が要る。[tuner-pt3.md](tuner-pt3.md))。下の blacklist を入れていなければ、挿すだけで DVB になり、エージェントは DVB のチューナーとして見つけます。
Mac と Windows にはカーネルのドライバが無いので、エージェントの実装が動かなければ PX-S1UD は使えません。

## カーネルのドライバとの使い分け (Linux)

**カーネルが使っている機材には触りません。** 動いている smsusb から機材を取ると、カーネルの側で異常が出た記録があるためです。
自動検出は、どのドライバにも繋がっていない機材だけを並べます。

| 機材の様子                                                                  | 使うドライバ                                    |
| --------------------------------------------------------------------------- | ----------------------------------------------- |
| smsusb が使っている (`/dev/dvb` に出ている)                                 | DVB (`DvbTuner`)。エージェントは USB を開かない |
| どのドライバにも繋がっていない (smsusb を blacklist した・モジュールが無い) | エージェントが USB を直に持つ (`SianoTuner`)    |

エージェントの実装で使うなら、ホストで `smsusb` / `smsdvb` / `smsmdtv` を blacklist して再起動します
(挿したまま unbind するのは、上の理由で勧めません)。DVB に戻すときは、このファイルを消して再起動します。

```sh
printf 'blacklist smsusb\nblacklist smsdvb\nblacklist smsmdtv\n' | sudo tee /etc/modprobe.d/denpa-siano.conf
sudo reboot
```

**カーネル 6.6 以降の DVB では、受信している間ずっとカーネルの警告がログに出続けます** (`smsdvb` の統計を書くたびに `sysfs_emit_at` の WARN)。
ログが数百 GB まで増えてディスクを埋めた報告があります (Ubuntu の Launchpad #2162139)。統計のファイル (`CONFIG_SMS_SIANO_DEBUGFS`) を
有効にして組んだカーネル (Ubuntu など) で起きます。直すパッチは linux-media に送ってあります。
エージェントの実装に切り替えるとカーネルのドライバを通らないので、この警告は出ません (受信できるかは、上のとおり実機で確かめていません)。

## 設定

- **設定の `device` は `siano:<USB のポート>`** (`siano:1-2`)。S1UD にはシリアルが無いので、挿したポートで見分けます。挿さっていれば組み立てるので
  (`Siano.Detect`)、普通は書きません。ポートを変えたら組み直します
- 対象は PX-S1UD (`3275:0080`) と、Siano の RIO の標準の ID (`187f:0600`) です。`187f:0302` は対象にしていません (公開の資料で扱いが食い違うため)。
  `187f:0600` は PX-S1UD と同じ手順で扱いますが、受信の記録がある資料もありません
- 自動検出が付ける名前は `PLEX PX-S1UD <ポート>` (`187f:0600` は `Siano RIO <ポート>`) です。`tuners.json` に書いてある名前は変わりません
- **ファームウェアは置かなくて構いません。** ISDB-T のファームウェア (`isdbt_rio.inp`) はエージェントの実行ファイルに埋め込んであり、機材に入っていないときだけ送ります
  ([licenses.md](licenses.md#チューナーエージェントに同梱するファームウェア))。別のファイルを使うときだけ、環境変数 `SIANO_FIRMWARE` で指定します
- Windows は、ドライバを `install.ps1 -WinUsb` で WinUSB に替えます ([install-windows.md](install-windows.md#チューナーのドライバを-winusb-に替える))
- 受信の状態と C/N (dB) と強度 (dBm) を、機材の統計の応答から出します。C/N と強度の欄の位置は公開の資料 1 つだけによるもので、値が正しいかは確かめていません
- **地上波だけ。** 衛星は機材を開く前に断ります。ワンセグだけの受信と PID の絞り込みはしません
- 別のモードのファームウェアが動いている機材は、挿し直しを求めて断ります

## 実機で確かめる順

実機で試すときは、この順に確かめます。Linux では smsusb などを blacklist してから行います。
記録の行は、そのポートで初めて開いたときに 1 回だけ出ます (エージェントを起動し直すとまた出ます)。Issue には、この行をそのまま貼ってください。

1. 自動検出に `PLEX PX-S1UD <ポート>` が 1 台だけ出る
2. `denpa-agent --tune siano:<ポート> T27` を、挿した直後の機材で流す。記録の次の行を控える
   - 「端点:」の行。バルク IN のアドレスと最大パケット長 (推定は `0x81`・512)、バルク OUT が `0x02` か
   - 「バージョンの応答 (開いたとき)」の行。モードが 255 か、対応モードのビット、ROM のバージョンの値
   - 「ファームウェアを送りました」の行 (358 個、かかった時間) と、「バージョンの応答 (ファームウェアを送ったあと)」の行。モードが 6 になるか 255 のままか
   - モードの初期化に機材が応答するか (応答しなければ「モードの初期化に機材が応答しません」で止まる)
3. 同期するか。同期までの時間と、「統計の応答」の行 (番号が 654 か 616 か、中身の長さ)。同期しなければ「ロックしませんでした (統計の要求 n 回、応答 m 回)」の応答の数
4. TS が流れるか。「TS のメッセージ」の行 (中身の長さが 188 の倍数か、先頭が `0x47` か)。`--seconds 30` を付けた `--tune` の出力で、約 65 MB、同期バイトの割合が 100%、連続性の飛びが 0 か
5. 「中身が転送の途中から始まるメッセージ」「扱わないメッセージ」「壊れたメッセージ」の行が出るか (出たら番号と長さを控える)
6. もう一度 `--tune` を流す (挿したまま)。バージョンの応答のモードが 6 で、ファームウェアを送らずに選局できるか。「送り直します」「送り直したバージョンの問い合わせに応答がありました」の行が出たら控える
7. `--tune siano:<ポート> T27,T22,T27` で、開いたまま選局し直せるか。放送の無いチャンネルで、10 秒ほどで「同期しませんでした」になり、次のチャンネルを選局できるか
8. 常駐させて、設定の画面に C/N と強度が出るか。値がほかのチューナーの映りと矛盾しないか
9. 受信中に抜く。記録に「抜かれました」が出るまでの時間。挿し直して、次の選局で受信できるか
10. 10 分以上の録画で、連続性の飛びと「TS を捨てています」の行が無いか。ここまで通ったら Windows (WinUSB) と macOS でも 1〜4 を流す (USB の層の `Pipes`・`ClearHalt`・`ReadTransfer` は、Windows と macOS では 1 度も動かしていない)
