# Xbox One Digital TV Tuner

Microsoft の USB チューナー (USB `045e:02d5`) で、**ケーブル (ISDB-C) だけ**を受けます。1 台で 1 チャンネルを取ります。地上波・BS・CS と、海外の DVB-T/T2 は受けません。
エージェントが USB を直に持ちます (Linux は usbfs、Windows は WinUSB、Mac は IOKit)。

チューナーの一覧は [tuners.md](tuners.md)。ケーブルの局の受け方とスキャンは [tuners.md](tuners.md#ケーブル-isdb-c) にあります。

**実機で確かめていません。** エージェントの実装は、GPL のドライバから事実だけを抜き出した仕様書から書いたもので ([licenses.md](licenses.md#チューナーエージェントに同梱するファームウェア))、
動かしたのは偽の USB の上の単体テストだけです。使ってみたら、動いたか動かなかったかを [Issue](https://github.com/danything/denpa/issues) で教えてください。
動かなかったときは、記録に出る行 ([下記](#実機で確かめる順)) があると直せます。

中身は USB ブリッジの DiBcom DiB0700、復調の Panasonic MN88472、チューナーの NXP TDA18250 です。

## 置くファームウェア

**復調のファームウェア `dvb-demod-mn88472-02.fw` は、利用者が置きます。** 再配布してよいかが分からないので、denpa には入れていません。
ブリッジのファームウェア (`dvb-usb-dib0700-1.20.fw`) はエージェントに入っているので、置かなくて構いません。

- ファイル: `dvb-demod-mn88472-02.fw` (2,012 バイト。SHA-256 が `7be4b830` で始まり `2e9c6196` で終わるもの)。LibreELEC の dvb-firmware のリポジトリにあります
- 置き場: `tuners.json` の隣の `firmware/` (コンテナは `/config/firmware/`、Mac と Windows は `~/denpa/config/firmware/`)。Linux はホストの `/lib/firmware/` も読みます。
  コンテナで `/lib/firmware/` を使うときは、そのディレクトリをコンテナに渡します
- Android (11 から) では、外部ストレージのアプリの置き場の `firmware/` に `adb push` で置き、アプリを「終了」してから起動し直します。
  エージェントの置き場 (`files/denpa/config/firmware/`) には利用者が書けないので、アプリがエージェントを起動するときにそこへ写します。
  Android 10 では写しません。ほかのアプリも書ける置き場のためです ([install-android.md](install-android.md#環境変数を足す-denpaenv) の `denpa.env` と同じ)。
  写したファイルは、外部の置き場から消しても残ります。書きかけのファイルが写っても、大きさと SHA-256 が違うのでエージェントは使わず、次に起動し直したときに写し直します

  ```sh
  adb push dvb-demod-mn88472-02.fw /sdcard/Android/data/io.github.danything.denpa/files/firmware/
  ```

- 大きさか SHA-256 が違うファイルは送りません。無いときと違うときは、どのファイルをどこに置けばよいかを、設定の「受信」の「チューナー」の状態の列と記録に出します。
  その機材だけを使わず、ほかのチューナーは止めません

復調にファームウェアがもう入っていれば (エージェントを起動し直したときなど)、ファイルを読まずに使います。

## 設定

- **設定の `device` は `xbox:<USB のポート>`** (`xbox:1-2`)。ポートで見分けるので、挿すポートを変えると別のチューナーになります
- 挿してあれば自動で見つけ、受信できる種別に「ケーブル」を選び、「使う」をオフにして並べます。ケーブルの回線をつないだら「使う」をオンにします
- 機材は最初の選局で開き、エージェントが動いている間は開いたままです。止めるときに、チューナーと復調をスリープにしてから閉じます
- 受信の状態と C/N (dB) を出します。電波の強度は出しません (機材から読めるのは 0〜65535 の相対値で、dBm にする式が分からないため)
- **Windows は、ドライバを WinUSB に替えます** (`install.ps1 -WinUsb`。[install-windows.md](install-windows.md#チューナーのドライバを-winusb-に替える))。替えると、Windows のほかのアプリからは使えなくなります
- **Linux では、カーネルのドライバ `dvb_usb_dib0700` が使っている機材には触りません。** エージェントで使うなら、ホストで blacklist して再起動します。
  このドライバを使うほかの機材 (DiB0700 のブリッジを積んだ USB チューナー) も、カーネルからは使えなくなります

```sh
echo 'blacklist dvb_usb_dib0700' | sudo tee /etc/modprobe.d/denpa-xbox.conf
sudo reboot
```

## 確かめていないこと

- **実機での動作のすべて。** ブリッジのファームウェアの流し込み、ロック、TS の受け取り
- USB の記述子。インターフェースと代替設定の番号、bulk の `wMaxPacketSize`、`0x83` の端点があるかは、資料で確かめられていません。
  エージェントは代替設定を選び直さず、開いたときに記述子を読んで記録に出し、TS の端点 (`0x82`) の `wMaxPacketSize` から転送の大きさを決めます
- 256QAM の搬送波。元の報告は J:COM の 64QAM でのロックだけです。変調とシンボルレートは復調に書かず、復調が自分で見分けると推定しています
- チューナーの AGC。仕様書が勧める側の値を書きます。帯域が 6 MHz ちょうどでないときに元のドライバが選ぶ値で、実機で受けられたと報告されている値です。もう一方の 6 MHz 用の値は試した記録が無く、入れていません
- 電波の強度の値。相対値で、dBm への換算は分かりません
- 仕様書に無い値: TS の転送要求を 16 本出したままにすること (元のドライバは 4 本)、ロックを 0.1 秒おきに 2 秒まで待つこと (元の報告では約 0.6〜0.7 秒でロック)
- 復調のファームウェアを配ってよいか

## 実機で確かめる順

エージェントを止めてから (動いているエージェントが機材を開いていると、横から開けません)、ケーブルの回線をつないで流します。

```sh
denpa-agent --tune xbox:1-2 QC13
```

1. 記録の `端点: …` の行 (記述子の端点の一覧)。`EP 0x82 bulk` があるか、`wMaxPacketSize` がいくつか
2. `ブリッジのファームウェアを送りました` と `ブリッジのバージョン: …` の行。RAM のバージョンが `0x00010201` 以上なら、TS は 1 回 3,948 バイトで届きます
3. `復調のファームウェア (dvb-demod-mn88472-02.fw) を送りました` の行
4. ロックするか。ロックしたら C/N と、TSMF の判定と、TS の速さ
5. 256QAM の搬送波 (スキャンの記録の NIT に変調が出ます) でもロックするか

Issue には、この出力と記録の行をそのまま貼ってください。
