## ライブ視聴の残り

**映像・音声・字幕 (第1〜2段階) は入りました** — 画面も焼き方も遅延の詰め方も
[stream.md](stream.md) に移してあります。残っているのはこれだけ。

- **データ放送** (第3段階) — **実機で出るところまで入りました**
  ([stream.md](stream.md#56-データ放送の統合))。解くのも自前
  (`ts/bml.ts` / `server/databroadcast.ts`)、描くのは web-bml の `BMLBrowser`
  を借りています (`components/player/DataBroadcast.svelte`)。指で押せる
  リモコンも郵便番号の受け渡しも入りました。**Hybridcast は在ることと行き先
  だけ出します** (§5.8。動かすのは受信機の認証まで要るので、やりません)。
  **残っているのは双方向 (通信系コンテンツ) のプロキシだけ**です (§5.7。
  設計だけで、まだ実装はありません)

**低遅延の追い込み (WebRTC/WHEP) はやめました。** 縮むのは受け側の貯め (0.2秒) だけで、
開いてから映るまではむしろ伸び、「止めた所から見られる」「5分戻れる」を捨てることに
なります ([stream.md](stream.md#webrtc--whep-による低遅延化--不採用))。
本当に縮めたいなら、運び方ではなく**焼くのをやめる**ほうが桁で効きます。
