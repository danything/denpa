# Android に入れる

**Android の端末 (タブレット・テレビの箱・スマートフォン) にチューナーを挿し、チューナーエージェントとして使えます。** denpa 本体は別の機械で動かし、
その denpa の `TUNER_AGENT_URL` にこの端末を書きます (Mac の `--agent-only` と同じ構成。[agent.md](agent.md#エージェントは別イメージ別プロセス))。

アプリ (`io.github.danything.denpa`) は画面を持ちません。起動すると常駐サービスになって通知に出て、エージェントを子プロセスとして動かします。
エージェントは Linux と同じ .NET のコードを Android 向けに組んだものです。アプリが USB の機材の許可を取り、開いた機材をエージェントへ渡します
([agent.md](agent.md#android-でアプリから-usb-を受け取る))。

**リリースにはまだ載せていません。** いまは CI の成果物 `denpa-android-debug` (debug の鍵で署名した APK) を入れます。
リリースの APK は別の鍵で署名するので、debug の APK を入れた端末には、消してから入れ直すことになります。

- 要るのは Android 10 以上で、arm64 の端末です (debug の APK には CI のエミュレータ用の x86_64 も入っています)。チューナーを挿すには、端末が USB のホストになれる必要があります
- Play では配りません。省電力の対象から外すよう求めることと、子プロセスの使い方が Play の決まりと合わないためです
- ASICEN 系の機材 (asicen-userland で動かすもの) は、Android ではまだ使えません

## 入れる

1. APK を端末に入れます。PC から `adb install denpa-android-debug.apk` で入れるか、端末のファイルのアプリから開きます (「提供元不明のアプリ」を許します)
2. ホーム画面の「denpa」を押します。Android 13 からは通知の許可を求められるので、許可します
3. 最初の 1 回は、省電力の対象から外すかを聞かれます。「許可」を選びます ([止まらないようにする](#止まらないようにする))
4. 通知に「denpa」と「チューナー 0 台」が出ます

## チューナーを挿す

1. チューナー (カードリーダーも) を挿すと、「denpa を開きますか」と聞かれます。「常にこのアプリで開く」に印を付けて「OK」を選びます
2. 通知が「チューナー 1 台」のように変わります。印を付けておけば、次からは挿すだけで使えます

- 許可を断った機材は、ホーム画面の「denpa」を押すと、もう一度許可を求められます

- 挿せる機材は、エージェントが USB を直に持つ機材 ([tuners.md](tuners.md)) と、USB の CCID のカードリーダーです
- 同じ機材を扱うテレビのアプリがほかにも入っていると、「常に」の選択を取り合います。denpa を選びます
- ポートの名前 (`tuners.json` の `device` に入る `1-2.3`) は、端末のカーネルが 5.3 以上なら挿した USB のポートから作ります。それより古いカーネルでは `001-004` の形になり、
  挿し直すと名前が変わります。そのときは denpa の設定の「受信」の「チューナー」で書き直します。カーネルのバージョンは `adb shell uname -r` で見られます

## denpa と組む

1. 通知の「URL をコピー」を押します。`https://<端末のアドレス>:25252#pair=<合言葉>` がクリップボードに入ります
2. denpa の `TUNER_AGENT_URL` にその URL を書き、denpa を起動し直します

- 合言葉が入るので、通知の本文には出さず、クリップボードには機密の印を付けます。URL を人に見せないでください
- アドレスは、いまつながっている Wi-Fi か有線の IPv4 です。どちらにもつながっていなければ「Wi-Fi のアドレスが無いため、denpa と組む URL を作れません」と出ます
- アドレスは DHCP で変わることがあります。ルーターでこの端末のアドレスを固定します
- エージェントは全部のインターフェースで 25252 を待ち受け、合言葉で組んだ denpa にだけ応答します

## 止まらないようにする

**電源につないだまま使います。** アプリは動いている間ずっと CPU を止めない (partial wake lock) ので、電池が減ります。
別の機械の denpa がいつ選局を求めるか分からず、画面を消すと CPU が止まって録画が欠けるためです。

- 省電力の対象から外します (入れるときの 3)。外さないと、画面を消してしばらくすると Doze でネットワークが止まります。
  あとから外すときは、端末の設定の「アプリ」の「denpa」の「電池」で「制限なし」を選びます
- メーカー独自の省電力 (使っていないアプリを止める機能) は、アプリから外せません。止められたら、その端末の設定で denpa を外します
- Android 12 からは、端末全体で子プロセスが多すぎると止められます。Android 14 からは、開発者向けオプションの「子プロセスの制限を無効にする」で外せます

## 止める・始める

- 通知の「終了」で止めます。録画中なら、通知が「録画が終わったら終了します」になり、録画が終わってから止まります。そのあいだに「すぐ終了」を押すと、録画を待たずに止まります
- 「終了」で止めると、次に端末を起動しても始まりません。ホーム画面の「denpa」を押すか、チューナーを挿すとまた始まり、次の端末の起動からも始まります
- エージェントが自分で終わったら (異常終了したら)、アプリが 5 秒から 1 分待って起動し直します
- 通知は指で消せます (Android 14 から)。消しても止まりません。ホーム画面の「denpa」を押すとまた出ます
- アプリを更新すると、Android がアプリを止めてから入れ替えます。録画中なら録画が切れるので、録画していないときに更新します

## 置き場

どれもアプリの置き場 (`/data/user/0/io.github.danything.denpa/`) の中で、アンインストールで消えます。端末のバックアップと引っ越しには載せません。

| 置き場                | 中身                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------- |
| `files/denpa/config/` | エージェントの `tuners.json`・`channels.json`・`cards.json`・`tls/` (`tls/pair-token` は組むときの合言葉) |
| `files/denpa/media/`  | `MEDIA_DIR`。いまは使いません                                                                             |
| `u`                   | アプリが USB の機材を渡すソケット (`USB_BROKER`)                                                          |

## 確かめる

- denpa の設定の「その他」の「バージョンと環境」に、この端末のエージェントが Android として出ます
- チューナーを挿すと、設定の「受信」の「チューナー」に出ます
- PC から `adb logcat -s denpa denpa-agent` でログを見られます。`denpa` はアプリ、`denpa-agent` はエージェントの出力です

**実機ではまだ確かめていません。** エミュレータで確かめたのは、常駐サービス・通知・エージェントの起動と応答・アプリからエージェントへ fd を渡すこと・「終了」・端末の起動までです
([development.md](development.md#android-のアプリ))。チューナーを挿して映るかと、画面を消したまま LAN から届くかは、実機で確かめる必要があります。
