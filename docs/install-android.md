# Android に入れる

**Android の端末 (タブレット・テレビの箱・スマートフォン) にチューナーを挿して使えます。使い方は 2 つあり、同時にもできます。**

- **端末 1 台で denpa を動かす。** 画面は、同じ LAN のブラウザやテレビのアプリ (denpa-tv) から `http://<端末のアドレス>:3000` で開きます ([denpa を開く](#denpa-を開く))
- **家の denpa のチューナーエージェントにする。** 別の機械で動かしている denpa に、この端末のチューナーを足します ([家の denpa と組む](#家の-denpa-と組む))

アプリ (`io.github.danything.denpa`) は画面を持ちません。起動すると常駐サービスになって通知に出て、チューナーエージェントと denpa 本体を子プロセスとして動かします。
エージェントは Linux と同じ .NET のコードを Android 向けに組んだもので、アプリが USB の機材の許可を取り、開いた機材をエージェントへ渡します
([agent.md](agent.md#android-でアプリから-usb-を受け取る))。denpa 本体は Mac・Windows の配布物と同じものを、APK に入れた bun と ffmpeg で動かします。

APK はリリースに `denpa-<バージョン>-android-arm64.apk` として添えています。同じリリースに `.sha256` と出所の証明 (attestation) もあります ([install.md](install.md#配布物を確かめる))。

- 要るのは Android 10 以上で、arm64 の端末です。チューナーを挿すには、端末が USB のホストになれる必要があります
- Play では配りません。省電力の対象から外すよう求めることと、子プロセスの使い方が Play の決まりと合わないためです
- ASICEN 系の機材 (PX-W3U3 など。asicen-userland で動かすもの) も試験的に使えます ([下記](#asicen-系の機材を挿す試験的))
- APK は約 75 MB です。入れると、APK そのものと、展開した実行ファイル (bun が 113 MB、エージェントが 22 MB、ffmpeg が 14 MB ほど)、書き出した denpa 本体 (12 MB ほど) で、
  端末の容量を 250 MB ほど使います。録画の分はこのほかに要ります

## 入れる

1. リリースの APK を端末に入れます。PC から `adb install denpa-<バージョン>-android-arm64.apk` で入れるか、端末のブラウザで落として開きます (「提供元不明のアプリ」を許します)
2. ホーム画面の「denpa」を押します。Android 13 からは通知の許可を求められるので、許可します
3. 最初の 1 回は、省電力の対象から外すかを聞かれます。「許可」を選びます ([止まらないようにする](#止まらないようにする))
4. 通知に「denpa」が出ます。本文は「denpa を起動しています」から「チューナー 0 台」に変わり、denpa を開く URL (`http://<端末のアドレス>:3000`) が出ます

## denpa を開く

- 通知を押すと、この端末のブラウザで denpa が開きます
- 通知の「URL をコピー」で、`http://<端末のアドレス>:3000` をクリップボードに入れます。同じ LAN の PC やテレビのブラウザ、denpa-tv にはこの URL を使います
- アドレスは、いまつながっている Wi-Fi か有線の IPv4 です。どちらにもつながっていなければ、URL は出ません
- アドレスは DHCP で変わることがあります。ルーターでこの端末のアドレスを固定します
- 既定では、この端末と、`192.168.0.0/16`・`10.0.0.0/8` の LAN から開くとログインを求めません ([環境変数を足す](#環境変数を足す-denpaenv))

## 家の denpa と組む

1. 通知の「QR を表示」を押します。2 分のあいだ、通知が登録用の URL (`https://<端末のアドレス>:25252#pair=<合言葉>`) の QR を出す大きな画像の形になります
2. 家の denpa の設定の「受信」の「エージェントを追加」の「QR を読む」で、その QR を読ませます。QR を出しているあいだの「登録用の URL をコピー」で URL をクリップボードに入れ、
   貼っても登録できます。`TUNER_AGENT_URL` に書いて denpa を起動し直しても足せます ([agent.md](agent.md#エージェントを足す))。
   `TUNER_AGENT_URL` に書いたときは、組んだあとも `#pair=` から後ろは消しません ([上げるときの注意](config.md#エージェントを-db-に持つようにした-前のバージョンから上げるとき))

- アプリはエージェントを LAN に知らせます (mDNS。`NsdManager`)。家の denpa が同じ LAN にいれば、「エージェントを追加」の入力欄の下に端末の名前が出ます。
  選んでも合言葉は入らないので、登録用の URL を貼るか QR を読ませます ([agent.md](agent.md#lan-で見つける))
- 端末のアドレスが変わっても、画面から登録した denpa は新しいアドレスに付け替えます。`TUNER_AGENT_URL` に書いた denpa は付け替えないので、ルーターでこの端末のアドレスを固定します
- エージェントは全部のインターフェースで 25252 を待ち受け、合言葉で組んだ denpa にだけ応答します。この端末の denpa も同じ合言葉で 127.0.0.1 から組んでいます
- 合言葉が入るので、通知の本文には出さず、クリップボードには機密の印を付けます。ロック画面には QR の無い通知を出します。URL と QR を人に見せないでください
- QR を出しているあいだのボタンは「終了」「登録用の URL をコピー」「閉じる」です (通知に出せるボタンは 3 つまで)。「閉じる」か 2 分たつと元の通知に戻ります
- denpa に出すエージェントの名前は、端末の名前 (設定の「デバイス名」。無ければ機種の名前) です。アプリが `AGENT_NAME` で渡します

## 上げる

新しいリリースの APK を、消さずにそのまま入れます (`adb install -r denpa-<バージョン>-android-arm64.apk`)。録画・DB・設定はそのまま残ります。
入れ替えると、アプリが APK の denpa 本体を書き出し直し、前のバージョンの分を消します。録画中に入れると録画が切れます ([止める・始める](#止める始める))。

- リリースの APK は、どれも同じ鍵で署名しています。証明書の SHA-256 は
  `9C:FA:63:96:57:69:C4:C2:4F:84:A9:51:6C:B5:7B:B4:63:E9:4F:EB:AF:4F:3F:D3:4C:BD:47:58:32:1A:82:77` です。
  `apksigner verify --print-certs <APK>` (Android SDK の build-tools) で確かめられます
- CI の成果物 `denpa-android-debug` (debug の鍵で署名した APK。開発で使う) は、リリースの APK と鍵が違います。鍵が違う APK は上書きで入れられないので、
  入れ替えるときは先にアプリを消してから入れ直します。消すと置き場 (下の表) も録画も消えます

## チューナーを挿す

1. チューナー (カードリーダーも) を挿すと、「denpa を開きますか」と聞かれます。「常にこのアプリで開く」に印を付けて「OK」を選びます
2. 通知が「チューナー 1 台」のように変わります。印を付けておけば、次からは挿すだけで使えます

- 許可を断った機材は、ホーム画面の「denpa」を押すと、もう一度許可を求められます
- 挿せる機材は、エージェントが USB を直に持つ機材 ([tuners.md](tuners.md))、ASICEN 系の機材 ([下記](#asicen-系の機材を挿す試験的))、USB の CCID のカードリーダーです
- 同じ機材を扱うテレビのアプリがほかにも入っていると、「常に」の選択を取り合います。denpa を選びます
- ポートの名前 (`tuners.json` の `device` に入る `1-2.3`) は、端末のカーネルが 5.3 以上なら挿した USB のポートから作ります。それより古いカーネルでは `001-004` の形式になり、
  挿し直すと名前が変わります。そのときは denpa の設定の「受信」の「チューナー」で書き直します。カーネルのバージョンは `adb shell uname -r` で見られます

## ASICEN 系の機材を挿す (試験的)

PX-W3U3・PX-W3U2・PX-W3U3 V2・PX-S3U2・PX-S3U は、APK に入れた asicen-userland で動かします。**Android でも Linux でも、実機では確かめていません**
([tuners.md](tuners.md#px-w3u3-など-asicen-userland試験的))。

1. 機材を挿すと、「denpa を開きますか」と聞かれます。「常にこのアプリで開く」に印を付けて「OK」を選びます。
   挿した直後の機材はファームウェア待ちで、エージェントがファームウェアを流し込みます
2. 流し込むと、機材が別の USB の ID でつながり直すので、もう一度「denpa を開きますか」と聞かれます。同じく印を付けて「OK」を選びます
3. 通知が「チューナー 4 台」のように変わります (PX-W3U3 は受信機が 4 つ)。2 回とも印を付けておけば、次からは挿すだけで使えます

- USB 機能が 2 つの機種 (PX-W3U2・PX-W3U3・PX-W3U3 V2) は、端末のカーネルが 5.3 以上のときだけ使えます。古いカーネルでは、同じ機材の 2 つの機能を見分けられないためです。
  PX-S3U2・PX-S3U は古いカーネルでも使えます
- 内蔵カードリーダーは使えません。B-CAS カードは USB のカードリーダーで使います
- 動かないときは、`adb logcat -s denpa-agent` の `asicend` と `asicen` の行に理由が出ます

## 環境変数を足す (`denpa.env`)

**denpa 本体の環境変数は、外部ストレージのアプリの置き場にある `denpa.env` に `KEY=値` で書きます** (変数の一覧は [config.md](config.md))。
アプリは無いときだけ雛形 (`TZ`・`TRUSTED_NETWORKS`) を作り、あとは触りません。`#` で始まる行は読みません。
この置き場は端末のファイルの画面からは開けないので、PC から adb で取り出して書き戻します。

```sh
adb pull /sdcard/Android/data/io.github.danything.denpa/files/denpa.env
# 直してから
adb push denpa.env /sdcard/Android/data/io.github.danything.denpa/files/denpa.env
```

- **直したら、通知の「終了」で止めてから、ホーム画面の「denpa」で始め直します。** アプリは denpa を起動するたびに読み直します
- 置き場 (`DENPA_DB`・`MEDIA_DIR`)・ffmpeg・字とデコーダの置き場・エージェントの宛先 (`TUNER_AGENT_URL`)・`PORT`・`DENPA_VERSION` はアプリが決め、`denpa.env` に書いても効きません
- `TRUSTED_NETWORKS` の雛形は `127.0.0.0/8,::1/128,192.168.0.0/16,10.0.0.0/8` です。`127.0.0.0/8` と `::1/128` はこの端末のブラウザです
- **Android 10 では `denpa.env` を読まず、雛形と同じ中身で動かします。** Android 10 は、ストレージの権限を持つほかのアプリもこの置き場に書けるので、
  `TRUSTED_NETWORKS` を書き換えられると誰でも denpa を開けてしまうためです。変数を足すなら Android 11 以上の端末で使います
- エンコードの本数 (`ENCODE_CONCURRENCY`) は、Linux と同じ既定 (2) のままです。端末の速さと熱に合う値は、実機で測ってから決めます ([encode.md](encode.md#android-でエンコードする))

## 止まらないようにする

**電源につないだまま使います。** アプリは動いている間ずっと CPU を止めない (partial wake lock) ので、電池が減ります。
いつ録画が始まるか分からず、画面を消すと CPU が止まって録画が欠けるためです。

- 省電力の対象から外します (入れるときの 3)。外さないと、画面を消してしばらくすると Doze でネットワークが止まります。
  あとから外すときは、端末の設定の「アプリ」の「denpa」の「電池」で「制限なし」を選びます
- メーカー独自の省電力 (使っていないアプリを止める機能) は、アプリから外せません。止められたら、その端末の設定で denpa を外します
- Android 12 からは、端末全体で子プロセスが多すぎると止められます。Android 14 からは、開発者向けオプションの「子プロセスの制限を無効にする」で外せます

## 止める・始める

- 通知の「終了」で、エージェントと denpa の両方を止めます。録画中なら、通知が「録画が終わったら終了します」になり、録画が終わってから止まります。
  そのあいだに「すぐ終了」を押すと、録画を待たずに止まります
- 「終了」で止めると、次に端末を起動しても始まりません。ホーム画面の「denpa」を押すか、チューナーを挿すとまた始まり、次の端末の起動からも始まります
- エージェントか denpa が自分で終わったら (異常終了したら)、アプリが 5 秒から 1 分待って起動し直します。そのあいだ、通知は「エージェントが終了したため、起動し直します」か
  「denpa が終了したため、起動し直します」になります
- 通知は指で消せます (Android 14 から)。消しても止まりません。ホーム画面の「denpa」を押すとまた出ます
- アプリを更新すると、Android がアプリを止めてから入れ替えます。録画中なら録画が切れるので、録画していないときに更新します

## 置き場

`denpa.env` のほかはアプリの置き場 (`/data/user/0/io.github.danything.denpa/`) の中です。どれもアンインストールで録画ごと消えます。端末のバックアップと引っ越しには載せません。
録画を USB のストレージや SD カードに置くことは、まだできません。

| 置き場                | 中身                                                                                                      |
| --------------------- | --------------------------------------------------------------------------------------------------------- |
| `files/denpa/config/` | エージェントの `tuners.json`・`channels.json`・`cards.json`・`tls/` (`tls/pair-token` は組むときの合言葉) |
| `files/denpa/data/`   | denpa の DB (`denpa.db`) と、その隣に置くもの (`logos/`・`tls/` など)                                     |
| `files/denpa/media/`  | 録画 (`MEDIA_DIR`。元の TS は `raw/`、エンコードしたものは `encoded/`)                                    |
| `files/denpa/server/` | APK から書き出した denpa 本体 (アプリ・字・デコーダ)。上げると入れ替わる                                  |
| `u`                   | アプリが USB の機材を渡すソケット (`USB_BROKER`)                                                          |
| `files/asicen/`       | ASICEN 系のファームウェア (`asicen-loader.bin`。APK から書き出したもの)                                   |
| `r`                   | asicend のソケット (`ASICEN_RUNTIME_DIR`)                                                                 |

## 確かめる

- 通知の URL で開いた denpa の設定の「受信」の「チューナー」に、挿したチューナーが出ます
- 設定の「その他」の「バージョンと環境」に、エージェントが Android として出ます
- PC から `adb logcat -s denpa denpa-agent denpa-server` でログを見られます。`denpa` はアプリ、`denpa-agent` はエージェント、`denpa-server` は denpa 本体の出力です

**実機ではまだ確かめていません。** エミュレータ (x86_64 の API 29・35・36) で確かめたのは、常駐サービス・通知・エージェントの起動と応答・アプリからエージェントへ fd を渡すこと・
エージェントが asicend を起動して fd を継がせること・denpa 本体が起動してエージェントと組み、画面が開くこと・bun から ffmpeg・ffprobe を流せること・更新・「終了」・端末の起動までです
([development.md](development.md#android-のアプリ))。チューナーを挿して映るかと、画面を消したまま LAN から届くかは、実機で確かめる必要があります。
