# 録画の置き場と配り方

**焼き上がったものをどこに置き、どう配るか。** 保存先の形、認証、削除、
録れたことの知らせまで。

| 探しもの | 見る場所 |
| --- | --- |
| 全体像 | [architecture.md](architecture.md) |
| 焼き方そのもの | [encode.md](encode.md) |
| ホーム画面に置く・ライブ視聴 | [player.md](player.md) |

```text
/library/
└── テストアニメ/
    ├── テストアニメ - 2026-08-01 - 2130 決戦.mkv
    ├── テストアニメ - 2026-08-01 - 2130 決戦-poster.jpg ← サムネイル (一覧の絵)
    └── テストアニメ - 2026-08-01 - 2130 決戦.bml.jsonl  ← データ放送 (持っている録画だけ)
```

**番組情報はDBが持ち、denpa の画面が出します。** 隣に置くのはサムネ
(`-poster.jpg`、一覧と詳細の絵) と、データ放送の変化ログ (`.bml.jsonl`。焼くときに
生TSから取り出したもので、観る画面の d ボタンが再生位置に合わせて流し直す —
`server/recorded-bml.ts`)。シリーズ名のフォルダにまとめるのは
**ディスク上で見やすくするため**です。同じシリーズ・同じ分に別の録画が
ぶつかったときだけ `… [39].mkv` のように録画IDを足します。

> **昔はメタデータの `.nfo` も書いて、WebDAV 経由のプレイヤー (Nova) に読ませて
> いましたが、その道ごとやめました** (下の「手元のプレイヤーで観る」)。昔のレイアウト
> (`Season 年/` + `<episodedetails>` + `-thumb.jpg`) は起動時にいまの形へ移し、
> 取り残された `.nfo` も片付けます (`server/relayout.ts`)。

**コーデックを両方選ぶと、1本の録画が2ファイルになります** (`… .mkv` = AV1、
`… [H264].mkv` = H.264)。どちらも Matroska (mp4 は PGS 字幕を持てない)。主 (再生・
ダウンロードで既定に使うほう) は AV1 で、DBの `library_path`、もう一方は
`alt_path`。ポスターは両方の隣に置く — 片方を消したときは**消したものだけ**を消し、
主が消えたら残ったほうを主に繰り上げ、もう一方だけが消えたら控え (`alt_path`) を外す
(実体との照合 `files.reconcile` が両方を見る) ので、そのときも一覧の絵が途切れません。
**自分がいま置いてあるファイルは衝突と
数えません** — 見ずに「あるかどうか」だけで決めていた頃は、焼き直すたびに素の名前と
ID付きを行き来していました (置き換えたあと古いほうを消すので、次はまた素の名前が空く)。

**名前を決めるのは、焼き上がってから**です。焼き始めに決めていた頃は、同じ番組を
2本同時に焼くと**どちらも「空いている」と見て同じ名前を選び**、作業ファイル
(`.encoding`) まで共有して**2つの ffmpeg が1つのファイルに書き込みました**。片方は
最後の置き換えで `ENOENT`、残ったほうは中身が壊れています (実機。復号すると145行の
エラーが出て、焼き直したものは0行)。いまは作業ファイルにジョブIDを入れ、置き場所は
置く直前に決め直します。

**焼き直すときは、始める前に前のものを消します。** 出来上がるまで別名 (`.encoding`) に
書くので、消さないと焼いている間ずっと同じ番組の mkv が2本ぶん場所を取ります。
**画面に出ている大きさより実際の使用量が多い**のは外から見て分かりません。
元は生TSで、これとは別のファイルなので消しても焼き直せます。引き換えに、失敗したり
途中でやめたりするとその間は保存先に何も無くなりますが、生TSは残っているので
もう一度押せば戻ります (その間の再生とダウンロードは生TSのほうを返します)。

このとき **DBの `library_path` も一緒に空けます。** 残したままだと実体との照合が
「保存先から消えていました」と読んで**録画ごと削除済みに倒し、生TSまで消します**。

## 観るのはブラウザで

**録画一覧の行を押すと `/watch/<id>` が開き、その場で再生が始まります**
(番組表からは詳細の「再生」)。**外部プレイヤーへ渡す口 (`denpa://`) は廃止しました。**

**焼いたものはブラウザがそのまま読めます。** AV1 + Opus の Matroska は
Chromium で `canPlayType` が `probably` を返し、実機の録画で再生も**シークも**
通ることを確かめました。渡す先を端末ごとに用意する理由が無くなったためです。

| | |
| --- | --- |
| 画面 | **タブレット以上は2段組** (左に映像、右に番組の中身)。狭い画面では映像が上 |
| 開いたとき | 指で触っている端末 (`pointer: coarse`) は**そのまま全画面**へ。抜けると2段組 |
| 押したとき | マウスは**どこを押しても再生/一時停止**。指は操作列の出し入れ (YouTube と同じ) |
| 左右の端を素早く2回 | **10秒 戻す/送る。** 続けて押せばそのぶん重なる |
| チャプター送り | **CM飛ばし。** 入っているときだけ出す |
| CMを自動で飛ばす | **既定で入っている** (切らずに焼いた録画で毎回ボタンを押さずに済むように)。**選んだ値は覚える** (端末ごと)。**ロゴでの判定に失敗した録画だけは、覚えていても切って始める** — あれは無音だけで当てていて外れやすく、外れると CM ではなく本編を飛ばす。押せばその場で入る。**CM のコマは1枚も出さない** (下の「CM は1コマも見せない」) |
| 削除 | **観たその場で消せる。** 末尾はたいてい CM なので、流したまま押せる |
| 字幕 | **持っている録画でだけ**ボタンが出る。**既定で出す** (ライブと同じ)。放送どおりの絵 (PGS) をそのまま重ねるので**ルビも出る** |
| 続き | **途中で止めたところから始まる。** 端末をまたいでも続く (覚えるのはサーバ側) |
| 読み込み待ち | **0.4秒 以上詰まったら輪を出す。** 絵が止まったのが詰まりなのか壊れたのかが分からないと、待てばいいのかどうかを決められない。短い詰まりで出さないのは、輪が点滅するだけになるため |
| 画面の明るさ | **止めている間も暗くさせない。** 一時停止して絵を見ている・番組の中身を読んでいる間に消えていた (観る画面は観るためだけに開くもの) |
| 速さ | 1〜2倍。**選んだ値は覚える** (端末ごと)。残り時間も倍速のぶんを割って出す |
| 切り抜き | **いまの1コマを字幕ごとクリップボードへ。** 貼れない繋ぎ (http) では落とす |
| 番組の中身 | **右に出たまま。** 長ければそこだけが巻き取られ、押すものは常に見えている |

### CM は1コマも見せない

自動で飛ばすとき、**CM のコマは1枚も出しません。** 跳ぶ位置を先読みするだけでは
消えません — ブラウザは**先のコマを何枚か合成器へ渡し終えている**ので、そこで
再生位置を変えても渡し済みのぶんは出ます。**予測で消せないので隠します。**

| | やること | なぜ |
| --- | --- | --- |
| 跨ぐ手前 | **0.1秒 (3コマ) 前に跳ぶ** | 入ってから跳ぶと必ず1コマ映る |
| 跳ぶ直前 | **そのコマを写して蓋にする** | 止め絵のほうが跳んだように見える (黒は切れて見える)。写すのは本編に居るときだけ — CM の中で写せば蓋そのものが CM になる |
| 観はじめ | **チャプターが届くまで黒い蓋** | チャプターは開いてから取りに行くので、揃うまで頭の CM がそのまま流れていた |
| 着いたあと | **4コマ数えてから外す** | `requestVideoFrameCallback` は「合成器へ渡した」ところで来るもので、画面に出るのはその先。さらに Windows の Chrome / Edge は**映像を DOM とは別の面**に出すので、蓋を外す更新のほうが映像より先に画面へ出る (位置も章も本編なのに画面だけ CM のまま、という絵が実機で撮れた) |

跳ぶ先が正しいことは焼くほうの仕事です — チャプターの時刻がずれていれば、
ここで何をしても CM の途中に着地します
([encode.md](encode.md#チャプターを詰める量は-ss-と同じではない))。

**`/watch` で観られるのは焼いたものだけです。** 生TSは MPEG-2 で、ブラウザに復号器が
ありません ([stream.md §5.5](stream.md#55-放送そのままmpeg-2は出せない))。
**焼き上がる前でも観られないわけではありません** — 録画中はもちろん、録り終えて
CM検出やエンコードを待っている間も、行を押すと追っかけ再生 (`/chase/<id>`) が開き、
サーバが焼き直して頭から観られます (エンコードに失敗した録画も生TSは無事なので同じ)。
焼き上がるとその画面から観る画面への案内が出ます。再生の印が消えるのは、消した録画と
**録画そのものが失敗したもの**だけです。

> **Safari では観られないはずです。** Matroska を扱えず、AV1 も新しい機材しか
> 持っていません。読めなかったときは、そうと出してダウンロードの口を添えます。

配信は `/api/recordings/<id>/file`。Range に対応しているのでプレイヤー側から早送り
できます (どのファイルを返すかは [app.md](app.md#画面))。

**どちらを寄越すかを名指しもできます** — `?source=ts` で生TS、`?source=encoded` で
焼いたほう (両方焼いたときは AV1)、`?source=alt` でもう一方 (H.264)。「生TSも残す」で
録ると両方が手元に残るので、詳細のダウンロードは残っているぶんだけ**口を分けて**出します
(「エンコード済み」「H.264」「生TS」)。1つしか出していなかった頃は
寄越されるのは焼いたほうだけで、画質を落としていない元には手が届きませんでした。
片方しか無い録画と焼いている最中はいままでどおり1つだけです (焼いている間の配信は
生TSのほうなので、2つ並べると押した先が同じものになります)。**観る画面は
`?source=encoded` と名指しします** — 焼いている最中に開かれると、名指ししなければ
生TSが返ってきて何も映りません。

## 手元のプレイヤーで観る

**プレイヤーにフォルダを漁らせるのではなく、denpa が URL を渡して再生させます。**
以前の WebDAV (`/dav`) + `.nfo` + Nova は丸ごとやめました — Nova が WebDAV 越しだと
隣のポスターを探しに行かない (ソースで確認) など、denpa 側では動かせない制約が
残ったためです。一覧・番組情報・サムネは denpa の画面が一番よく知っているので、
プレイヤーには**再生だけ**を頼みます。道は2つ:

- **テレビで再生**。テレビの VLC (Android 版 3.6+) で
  **その他 → リモートアクセス** を有効にしておくと、録画詳細から飛ばせます。
  テレビは設定に名前+IP+ポートで登録する — 登録したぶんだけ詳細にボタンが出ます
  (1台も無ければ出ません)。**AV1 を解けないテレビには、テレビごとのコーデック設定**で
  H.264 (両方焼いた録画) や生TSを渡せます (`?source=` の名指しを再生リンクに焼き込む)。
  **叩くのはサーバではなく、いま画面を開いている端末** — VLC の `/play` はただの
  GET なので、`http://<テレビ>:8080/play?id=0&path=<再生URL>` をトップレベルで
  開けばそのまま始まります (fetch は混在コンテンツ・自己署名・CORS・Cookie の
  4つに塞がれますが、ページ遷移にはどれも掛かりません)。サーバから叩く形だと
  **出先のテレビに届かない**ので、こちらに一本化しました。
  初回はペア設定の画面が開きます — ペア前の `/play` は素の 401 が返るだけなので、
  denpa がログイン画面 (`http://<テレビ>:8080/`) のほうを開きます。VLC の画面の誘導で
  **https (自己署名・8443) の証明書を受け入れ、テレビの画面の6桁コード**を入れると
  ペア完了 (Cookie 約1年。Secure が付かないので http の `/play` にも乗ります)。
  **映像は VLC が前に出ているときだけ始められます** (VLC 側の作り。始まらなければ
  テレビで VLC を開いてからもう一度)
- **再生リンク**。録画詳細の「その他…」→「再生リンクをコピー」で **24時間で切れるURL** を取り、
  どのプレイヤーにでも貼れます (`server/share.ts`)。形は `/api/recordings/<id>/file/<番組名>.mkv?token=…` —
  **尻に番組名を置くのは、テレビの VLC (Android) が URL の最後の区切りを再生画面の見出しに
  するため** (入れ物の title は履歴と通知にしか出ない)。サーバはその段を読み捨てます。**パスワードは
  入っていません** — プレイヤーはURLをストリーム履歴に残すので、恒久の資格情報を
  他人の機器に置いてこないための形です

どちらも渡すURLは期限付きリンクです。VLC は AV1 も Opus も Matroska も自前の
デコーダで解き、**PGS 字幕もそのまま出ます** (AV1 非対応の Fire TV でも dav1d の
ソフトデコードで滑らかでした)。

## 字幕はどこから出るか

**入れ物の中の、放送どおりに描いた絵 (PGS) だけです。** 隣に置く付き添いは
ありません。

| 観るところ | どこから |
| --- | --- |
| denpa の観る画面 | 入れ物の中の PGS を抜いて渡し、**ブラウザが解いて重ねる** (ライブと同じやり方) |
| 手元のプレイヤー (VLC など) | 入れ物の中の PGS をそのまま |

**絵なのは、そこだけが放送どおりだからです。** 一度は文字に直して `<track>` へ
渡す道も、文字の写しを動画の隣に置く道も通しましたが、左右の位置も、背景の箱も、
外字も、ルビも落ちました。絵にはそれが全部入っています。

> **既にある録画でもそのまま出ます。** 絵は焼いたものの中に最初から入っていて、
> 観るときに抜いています (実測 0.1〜1秒)。焼き直しは要りません。

## 誰が取れるか

ファイルを取りに来るプレイヤーはリダイレクト型の認証を扱えないので、**その口は
期限付きのリンクで開けます** (控えは DB の `share_links`。署名ではないので期限だけを後から延ばせます) (OIDC で入った画面のぶんはログインの控えも
受けます。[auth.md](auth.md#ファイルの口はログインの控えも受ける))。信頼したネットワーク
(`TRUSTED_NETWORKS`) からは何も聞きません。決まりごとと理由は
[auth.md](auth.md) にまとめてあります。

ダウンロードは、押されてから**期限付きのURL** (`share.ts` の `?token=`、
再生リンクと同じ) を作って始めます。以前は資格情報を URL に埋めていました
(`http://user:pass@.../file`) が、それだと**パスワードがダウンロード履歴と
URL欄に残り続けます**。token なら履歴に残っても、使わなくなって24時間で腐ります
(期限内に押し直すと同じURLのまま延びる。[auth.md](auth.md))。
**観るときは何も埋めません** — `<video>` は同じ元 (origin) から取りに行くので、
ブラウザが自分で認証を付けます (OIDC で入った人のぶんはログインの控えが受けます)。

## 削除

**denpa の画面から**行います(押し間違い防止に2回押させます)。自動削除はありません。

ファイルマネージャなど denpa を通さずに消された場合だけは気づけないので、
`RECONCILE_INTERVAL`(既定5分)ごとの突き合わせで拾います。すぐ反映したいときは「ファイルと照合」。

**見るのは両方向です。** 「行はあるが実体が無い」だけでなく、その逆も掃きます。
付き添い (`.nfo` / サムネイル / `.dtvi` / `.sup` などの作業ファイル) は**動画と同じ名前で
隣に置く**決まりなので、名前だけで連れ合いが分かります。実機では生TSの置き場に
`.dtvi` (chapter_exe と logoframe が作る索引、1本3MB) が9本 22MB 残っていました —
生TSを残さない設定だと TS が消えたあとも索引だけが居座り、録るたびに積もります。
空フォルダも一緒に片付けます。

**動画そのものには触りません。** 行の無い動画は手で置いたものかもしれないので、
**数えるだけ**にして、消すかどうかは人が決めます。

> inotify (`fs.watch`) で消した瞬間に拾えないか試しましたが、この構成 (bun + vite dev) では
> **最初の1件しかイベントが来ず**当てにできなかったので定期実行のままにしています。

## 通知

録画の節目を Webhook で外に飛ばせます。設定画面から追加してください(Discord や Slack の
Incoming Webhook の URL をそのまま入れられます)。

- 録画開始 / 録画完了 / 録画失敗 / エンコード完了 / エンコード失敗、および録画の外側の
  変事 (ディスク残量わずか / チューナー切断 / チューナー復帰)。選ばなければ全部
- **送信は投げっぱなし**です。通知先が遅いせいで録画が止まるほうが困るので、10秒で
  打ち切って結果だけ記録します。直近の結果は設定画面に出ます
- 録画の失敗は画面を開くまで気づけないので、**少なくとも失敗だけでも**入れておくのを勧めます
