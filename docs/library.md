# 録画の置き場と配り方

**焼き上がったものをどこに置き、どう配るか。** 保存先の形、認証、削除、
録れたことの知らせまで。

| 探しもの | 見る場所 |
| --- | --- |
| 全体像 | [architecture.md](architecture.md) |
| 焼き方そのもの | [encode.md](encode.md) |
| ホーム画面に置く・ライブ視聴 | [player.md](player.md) |

```text
/library/
└── テストアニメ/
    ├── テストアニメ - 2026-08-01 - 2130 決戦.mkv
    ├── テストアニメ - 2026-08-01 - 2130 決戦-poster.jpg ← サムネイル (一覧の絵)
    └── テストアニメ - 2026-08-01 - 2130 決戦.bml.jsonl  ← データ放送 (持っている録画だけ)
```

**番組情報はDBが持ち、denpa の画面が出します。** 隣に置くのはサムネ
(`-poster.jpg`、一覧と詳細の絵) と、データ放送の変化ログ (`.bml.jsonl`。焼くときに
生TSから取り出したもので、観る画面の d ボタンが再生位置に合わせて流し直す —
`server/recorded-bml.ts`)。シリーズ名のフォルダにまとめるのは
**ディスク上で見やすくするため**です。同じシリーズ・同じ分に別の録画が
ぶつかったときだけ `… [39].mkv` のように録画IDを足します。

> 昔のレイアウト (`Season 年/` + `.nfo` + `-thumb.jpg`。WebDAV 越しのプレイヤー向け) は、
> 起動時にいまの形へ移して `.nfo` も片付けます (`server/relayout.ts`)。

**コーデックを両方選ぶと、1本の録画が2ファイルになります** (`… .mkv` = AV1、
`… [H264].mkv` = H.264。どちらも Matroska — mp4 は PGS 字幕を持てない)。主 (再生・
ダウンロードの既定) は AV1 で DB の `library_path`、もう一方は `alt_path`。ポスターは
両方の隣に置きます。外から片方を消されたときは実体との照合 (`files.reconcile`) が
**消えたほうだけ**を外し、主が消えたら残ったほうを主に繰り上げるので、一覧の絵は途切れません。
**自分がいま置いてあるファイルは衝突と数えません** — 数えていた頃は、焼き直すたびに
素の名前と `[ID]` 付きを行き来していました (`library.libraryPath`)。

**名前を決めるのは、焼き上がってから**です。焼き始めに決めていた頃は、同じ番組を
2本同時に焼くと**どちらも同じ名前と作業ファイル (`.encoding`) を選び、2つの ffmpeg が
1つのファイルに書き込みました** (実機。片方は `ENOENT`、残ったほうは復号すると145行の
エラー。焼き直したものは0行)。いまは作業ファイルにジョブIDを入れ
(`<名前>.<jobId>.<codec>.encoding`)、置き場所は置く直前に決め直します。

**焼き直すときは、始める前に前のものを消します** (DB の `library_path`/`alt_path` も一緒に空ける)。
出来上がるまで別名 (`.encoding`) に書くので、消さないと焼いている間は同じ番組の mkv が
2本ぶん場所を取り、しかも**画面の大きさより実際の使用量が多い**ことが外から分かりません。
元の生TSは別にあるので、失敗・中止してももう一度押せば戻ります (その間の再生と
ダウンロードは生TSを返す)。DB を空けずに残すと、実体との照合が「保存先から消えた」と読んで
**録画ごと削除済みに倒し、生TSまで消します**。

## 観るのはブラウザで

**録画一覧の行を押すと `/watch/<id>` が開き、その場で再生が始まります**
(番組表からは詳細の「再生」)。**外部プレイヤーへ渡す口 (`denpa://`) は廃止しました。**

**焼いたものはブラウザがそのまま読めます。** AV1 + Opus の Matroska は
Chromium で `canPlayType` が `probably` を返し、実機の録画で再生も**シークも**
通ることを確かめました。渡す先を端末ごとに用意する理由が無くなったためです。

| | |
| --- | --- |
| 画面 | **タブレット以上は2段組** (左に映像、右に番組の中身)。狭い画面では映像が上 |
| 開いたとき | 指で触っている端末 (`pointer: coarse`) は**そのまま全画面**へ。抜けると2段組 |
| 押したとき | マウスは**どこを押しても再生/一時停止**。指は操作列の出し入れ (YouTube と同じ) |
| 左右の端を素早く2回 | **10秒 戻す/送る。** 続けて押せばそのぶん重なる |
| チャプター送り | **CM飛ばし。** 入っているときだけ出す |
| CMを自動で飛ばす | **既定で入っている** (切らずに焼いた録画で毎回ボタンを押さずに済むように)。**選んだ値は覚える** (端末ごと)。**ロゴでの判定に失敗した録画だけは、覚えていても切って始める** — あれは無音だけで当てていて外れやすく、外れると CM ではなく本編を飛ばす。押せばその場で入る。**CM のコマは1枚も出さない** (下の「CM は1コマも見せない」) |
| 削除 | **観たその場で消せる。** 末尾はたいてい CM なので、流したまま押せる |
| 字幕 | **持っている録画でだけ**ボタンが出る。**既定で出す** (ライブと同じ)。放送どおりの絵 (PGS) をそのまま重ねるので**ルビも出る** |
| 続き | **途中で止めたところから始まる。** 端末をまたいでも続く (覚えるのはサーバ側) |
| 読み込み待ち | **0.4秒 以上詰まったら輪を出す。** 絵が止まったのが詰まりなのか壊れたのかが分からないと、待てばいいのかどうかを決められない。短い詰まりで出さないのは、輪が点滅するだけになるため |
| 操作列 | **触らないでいると引っ込む。止めていても同じ** (2.5秒)。マウスは動かせば、指は押せば戻る。理由は [player.md](player.md#操作まわりは3画面で共通) |
| 画面の明るさ | **止めている間も暗くさせない** (同上) |
| 速さ | 1〜2倍。**選んだ値は覚える** (端末ごと)。残り時間も倍速のぶんを割って出す |
| 切り抜き | **いまの1コマを字幕ごとクリップボードへ。** 貼れない繋ぎ (http) では落とす |
| 番組の中身 | **右に出たまま。** 長ければそこだけが巻き取られ、押すものは常に見えている |

### CM は1コマも見せない

自動で飛ばすとき、**CM のコマは1枚も出しません。** 跳ぶ位置を先読みするだけでは
消えません — ブラウザは**先のコマを何枚か合成器へ渡し終えている**ので、そこで
再生位置を変えても渡し済みのぶんは出ます。**予測で消せないので隠します。**

| | やること | なぜ |
| --- | --- | --- |
| 跨ぐ手前 | **0.1秒 (3コマ) 前に跳ぶ** | 入ってから跳ぶと必ず1コマ映る |
| 跳ぶ直前 | **そのコマを写して蓋にする** | 止め絵のほうが跳んだように見える (黒は切れて見える)。写すのは本編に居るときだけ — CM の中で写せば蓋そのものが CM になる |
| 観はじめ | **チャプターが届くまで黒い蓋** | チャプターは開いてから取りに行くので、揃うまで頭の CM がそのまま流れていた |
| 着いたあと | **4コマ数えてから外す** | `requestVideoFrameCallback` は「合成器へ渡した」ところで来るもので、画面に出るのはその先。さらに Windows の Chrome / Edge は**映像を DOM とは別の面**に出すので、蓋を外す更新のほうが映像より先に画面へ出る (位置も章も本編なのに画面だけ CM のまま、という絵が実機で撮れた) |

跳ぶ先が正しいことは焼くほうの仕事です — チャプターの時刻がずれていれば、
ここで何をしても CM の途中に着地します
([encode.md](encode.md#チャプターを詰める量は-ss-と同じではない))。

**`/watch` で観られるのは焼いたものだけです。** 生TSは MPEG-2 で、ブラウザに復号器が
ありません ([stream.md §5.5](stream.md#55-放送そのままmpeg-2は出せない))。
**焼き上がる前でも観られないわけではありません** — 録画中はもちろん、録り終えて
CM検出やエンコードを待っている間も、行を押すと追っかけ再生 (`/chase/<id>`) が開き、
サーバが焼き直して頭から観られます (エンコードに失敗した録画も生TSは無事なので同じ)。
焼き上がるとその画面から観る画面への案内が出ます。再生の印が消えるのは、消した録画と
**録画そのものが失敗したもの**だけです。

> **Safari では観られないはずです。** Matroska を扱えず、AV1 も新しい機材しか
> 持っていません。読めなかったときは、そうと出してダウンロードの口を添えます。

配信は `/api/recordings/<id>/file` (Range 対応。既定で返すものは [app.md](app.md#画面))。
**`?source=` で名指しもできます** — `ts` = 生TS、`encoded` = 焼いたもの (両方焼いたときは AV1)、
`alt` = もう一方 (H.264)。詳細の「その他…」のダウンロードは、残っているぶんだけ**口を分けて**
出します (「ダウンロード (AV1)」または「(エンコード済み)」、「(H.264)」「(生TS)」) — 1つだけだと
焼いたほうしか取れず、画質を落としていない元に手が届きませんでした。焼いている最中は1つだけです
(配信が生TSに切り替わるので、並べると押した先が同じになる)。**観る画面は `?source=encoded`
と名指しします** — 焼いている最中に名指しなしで開くと生TSが返り、何も映りません。

## 手元のプレイヤーで観る

**プレイヤーにフォルダを漁らせず、denpa が URL を渡して再生だけを頼みます。** 以前の
WebDAV (`/dav`) + `.nfo` + Nova は、プレイヤー側の制約 (WebDAV 越しだと隣のポスターを
探さない等) を denpa から動かせないのでやめました。道は2つ:

- **テレビで再生**。テレビの VLC (Android 版 3.6+) で **その他 → リモートアクセス** を
  有効にし、設定に名前+IP+ポートで登録すると、そのぶん録画詳細にボタンが出ます。
  **AV1 を解けないテレビにはテレビごとのコーデック設定**で H.264 (両方焼いた録画) や
  生TSを渡せます (`?source=` を再生リンクに焼き込む)。
  - **叩くのはサーバではなく、画面を開いている端末です。** VLC の `/play` はただの GET
    なので、`http://<テレビ>:8080/play?id=0&path=<再生URL>` をトップレベルで開けば
    始まります (fetch は混在コンテンツ・自己署名・CORS・Cookie に塞がれるが、
    ページ遷移には掛からない)。サーバから叩くと**出先のテレビに届かない**ので一本化しました
    (`server/vlc.ts`)。
  - 開いた白いタブは**テレビの返事に切り替わったら**畳みます (`win.document` に触れて
    例外が出れば切り替わっている。`closeWhenLanded`)。決め打ちの秒数では、返事の遅い
    テレビで届く前に畳んで再生が始まらなかったためです。15秒で切り替わらなければ残します。
  - 初回はペア設定です。ペア前の `/play` は素の 401 なので、VLC のログイン画面
    (`http://<テレビ>:8080/`) を開きます。**https (自己署名・8443) の証明書を受け入れ、
    テレビの6桁コード**を入れれば完了 (Cookie 約1年。Secure が無いので http の `/play` にも乗る)。
    **映像は VLC が前に出ているときだけ始まります** (始まらなければテレビで VLC を開いてから)。
  - **途中まで観たものは続きから。** `/play` に位置を渡す口が無いので、続きの位置
    (`vlc:option` の `start-time`) を書いた XSPF (`/api/recordings/<id>/playlist/<番組名>.xspf`、
    `server/playlist.ts`) を渡します。中身は取りに来た瞬間に作るので、履歴の同じ URL でも
    そのときの続きから。**テレビで観た位置は戻ってきません** (VLC から知らせる道が無い)。
- **再生リンク**。録画詳細の「その他…」→「再生リンクをコピー」で **24時間で切れるURL**
  を取り、どのプレイヤーにも貼れます (`server/share.ts`)。形は
  `/api/recordings/<id>/file/<番組名>.mkv?token=…` — **尻の番組名は、テレビの VLC が
  URL の最後の区切りを再生画面の見出しにするため** (入れ物の title は履歴と通知にしか
  出ない。サーバは読み捨てる)。**パスワードは入っていません** — プレイヤーは URL を
  履歴に残すので、恒久の資格情報を他人の機器に置いてこないためです。

VLC は AV1・Opus・Matroska を自前で解き、**PGS 字幕もそのまま出ます** (AV1 非対応の
Fire TV でも dav1d のソフトデコードで滑らか)。

## 字幕はどこから出るか

**入れ物の中の、放送どおりに描いた絵 (PGS) だけです** (隣に付き添いは置かない)。
denpa の観る画面は PGS を抜いて渡し**ブラウザが解いて重ね** (ライブと同じ。抜くのは
実測 0.1〜1秒なので、既にある録画も焼き直し不要)、VLC などは入れ物の PGS をそのまま出します。
絵にした理由 (文字に直すと位置・背景の箱・外字・ルビが落ちる) は
[encode.md](encode.md#字幕は-pgs-1本だけ) に。

## 誰が取れるか

プレイヤーはリダイレクト型の認証を扱えないので、**ファイルの口は期限付きリンク
(`share.ts` の `?token=`、24時間) で開けます**。信頼したネットワーク (`TRUSTED_NETWORKS`)
からは何も聞かず、OIDC で入った画面のぶんはログインの控えも受けます
([auth.md](auth.md#ファイルの口はログインの控えも受ける))。
**ダウンロードも押されてから同じリンクを作ります** — 資格情報を URL に埋めていた頃
(`http://user:pass@…`) は、**パスワードがダウンロード履歴に残り続けました**。
**観るときは何も埋めません** (`<video>` は同じ origin なのでブラウザが認証を付ける)。
決まりごと (1録画1本・押し直すと延びる・`share_links`) と理由は [auth.md](auth.md) に。

## 削除

**denpa の画面から**行います (押し間違い防止に2回押し)。自動削除はありません。
denpa を通さずに消されたものは `RECONCILE_INTERVAL` (既定5分) ごとの突き合わせで拾います
(すぐなら「ファイルと照合」)。

**見るのは両方向です。** 「行はあるが実体が無い」だけでなく、連れ合いを失った付き添い
(サムネイル・`.bml.jsonl`・`.dtvi`・`.sup` などの作業ファイル、昔の `.nfo`) と空フォルダも
掃きます。付き添いは**動画と同じ名前で隣に置く**決まりなので、名前だけで連れ合いが分かります。
実機では生TSの置き場に `.dtvi` (chapter_exe / logoframe の索引、1本3MB) が9本 22MB 残っていました
— 生TSを残さない設定だと索引だけが居座り、録るたびに積もります。

**動画そのものには触りません。** 行の無い動画は手で置いたものかもしれないので、数えるだけです。

> inotify (`fs.watch`) は、この構成 (bun + vite dev) では**最初の1件しかイベントが来ず**
> 当てにできないので、定期実行のままです。

## 通知

録画の節目を Webhook で外に飛ばせます。設定画面から追加します (Discord や Slack の
Incoming Webhook の URL をそのまま入れられます)。

- 録画開始 / 録画完了 / 録画失敗 / エンコード完了 / エンコード失敗、および録画の外側の
  変事 (ディスク残量わずか / チューナーに繋がらない / チューナーに繋がった)。選ばなければ全部
  (種類は `src/lib/webhook-events.ts`)
- **送信は投げっぱなし**です。通知先が遅いせいで録画が止まるほうが困るので、10秒で
  打ち切って結果だけ記録します。直近の結果は設定画面に出ます
- 録画の失敗は画面を開くまで気づけないので、**少なくとも失敗だけでも**入れておくのを勧めます
