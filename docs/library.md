# 録画の置き場と配り方

**エンコードが終わったものをどこに置き、どう配るか。** 保存先の構成、認証、削除、
録画の節目の通知まで。

エンコード方法そのものは [encode.md](encode.md)、外から一覧を取る API は [api.md](api.md)。

**コピー禁止の番組は録らないので、置き場にも来ません** (市販のレコーダーと同じ。
[data.md](data.md#コピー禁止の番組は録らない)、[Discussion #760](https://github.com/danything/denpa/discussions/760))。
置き場にあるものは、端末への保存 (オフライン視聴) を含めてこれまでどおり配ります。

```text
/media/encoded/                 ← ENCODED_DIR
├── テストアニメ/
│   ├── テストアニメ - 2026-08-01 - 2130 決戦.mkv
│   ├── テストアニメ - 2026-08-01 - 2130 決戦-poster.jpg ← サムネイル (一覧の画像)
│   └── テストアニメ - 2026-08-01 - 2130 決戦.bml.jsonl  ← データ放送 (持っている録画だけ)
└── clips/                      ← 切り抜き (下の「切り抜き」)
    └── 2026-10/
        ├── 12.avif
        ├── 12-small.avif       ← 一覧用
        └── 12.src/             ← 元の画像 (字幕・コメントを出していたときだけ)
            ├── frame.webp
            ├── captions.png
            └── comments.png
```

**番組情報は DB が持ち、denpa の画面が出します。** 隣に置くのはサムネ
(`-poster.jpg`、一覧と詳細の画像) と、データ放送の変化ログ (`.bml.jsonl`) だけ。変化ログは
エンコードするときに元の TS から取り出し、観る画面のデータ放送 (⚙ から出す) が再生位置に合わせて流し直します
(`server/recorded-bml.ts`)。シリーズ名のフォルダにまとめるのはディスク上で見やすくするためで、
同じシリーズ・同じ分に別の録画がぶつかったときだけ `… [39].mkv` のように録画 ID を足します。

**コーデックをいくつも選ぶと、1 本の録画が最大 3 ファイルになります** (`… .mkv` = AV1、`… [H265].mkv` = H.265、
`… [H264].mkv` = H.264。mp4 は ARIB 字幕を持てないので、どれも Matroska)。

| 列 (DB)        | 入るもの                                                                |
| -------------- | ----------------------------------------------------------------------- |
| `library_path` | 主 (再生の既定)。選んだうち **AV1 → H.265 → H.264 の先頭** (小さいほう) |
| `hevc_path`    | H.265。主でないとき (AV1 も選んだとき) だけ                             |
| `alt_path`     | H.264。主でないとき (AV1 か H.265 も選んだとき) だけ                    |

AV1 を選ばずに H.265 と H.264 を選べば H.265 が主で、`hevc_path` は空です。ポスターは
どれの隣にも置きます。外から一部を消されたら、実体との照合 (`files.reconcile`) が
消えたものだけを外し、主なら残ったものを繰り上げます (H.265 が先。一覧の画像は途切れない)。
自分がいま置いてあるファイルは衝突と数えません (再エンコードのたびに名前が変わらないように。`library.libraryPath`)。

**名前を決めるのは、エンコードが終わってから**です。作業ファイルにはジョブ ID を入れ
(`<名前>.<jobId>.<codec>.encoding`)、置き場所は置く直前に決め直します。同じ番組を 2 本同時に
エンコードしても、2 つの ffmpeg が 1 つのファイルに書き込みません。

**再エンコードするときは、始める前に前のものを消します** (DB の `library_path`/`hevc_path`/`alt_path` も空ける)。
出来上がるまで別名 (`.encoding`) に書くので、消さないとエンコードしている間は mkv が
2 本ぶん場所を取り、画面に出る大きさより使用量が多いことが外から分かりません。
元の TS は別にあるので、失敗・中止してももう一度押せば戻ります (その間の再生は
元の TS を返す)。DB を空けずに残すと、実体との照合が「保存先から消えた」と読んで
録画ごと削除済みに倒し、元の TS まで消します。

## 置き場を別のディスクに移す

**どこに置いても、置き場を世帯の外から見られるようにはしないでください** (NAS の共有リンクや外からのアクセス、
クラウドへの同期など)。置き場の mkv は暗号の掛かっていない普通のファイルなので、外から見られるようにすると、
録画をファイルとして世帯の外へ持ち出せる状態になります。denpa の使ってよい範囲と、持ち出す機能を持たない理由は
[Discussion #760](https://github.com/danything/denpa/discussions/760) に。

**コンテナの中の場所 (`/media/encoded`) は変えず、外側だけを付け替えます。** DB は録画の場所を
置き場からの相対で持つので (`schema.ts` の `mediaPath`)、`ENCODED_DIR` を変えても中身ごと写せば辿れますが、外側を付け替えれば変数に触らずに済みます。

Docker Compose なら、録画もエンコードもしていないときに次の順で付け替えます。

1. **denpa を止める** (`docker compose stop denpa`)。動かしたまま付け替えると、突き合わせ (`files.reconcile`) が
   「保存先から消えた」と読んで、録画を削除済みにします
2. 今のボリュームの中身を新しいディスクへ写す。ボリュームの名前は `docker volume ls` で確かめる
   (`install.sh` で入れたなら `denpa_denpa-library`)

   ```sh
   docker run --rm -v denpa_denpa-library:/from -v /mnt/disk2/denpa:/to alpine cp -a /from/. /to/
   ```

3. `compose.override.yml` に新しい場所を書く (`compose.yml` は `install.sh` が上げ直すたびに上書きするので触らない)。
   Compose はコンテナの中の場所が同じものを上書きとして重ねるので、これだけで付け替わる。
   NAS なら、先にホストで NFS か SMB をマウントしておき、その場所を書く

   ```yaml
   services:
     denpa:
       volumes:
         - /mnt/disk2/denpa:/media/encoded
   ```

4. 起動して、一覧のサムネイルと再生を確かめてから、古いボリュームを消す (`docker volume rm denpa_denpa-library`)

元の TS (`/media/raw`) も同じ手順で移せます。**エージェントも同じ場所を見る**ので、denpa と `tuner-agent` の
両方を書き換えます。Kubernetes なら、新しいストレージに PVC を作り、chart の `persistence.encoded.existingClaim`
(元の TS は `persistence.raw.existingClaim`) に名前を入れます。こちらもコンテナの中の場所は変わりません。

Mac と Windows の置き場は、インストーラが決めるフォルダ (`~/Movies/denpa/library`・`~/Videos/denpa/library`) です。
`denpa.env` に `ENCODED_DIR` を書いても効きません ([install-mac.md](install-mac.md#環境変数を足す-denpaenv)・[install-windows.md](install-windows.md#環境変数を足す-denpaenv))。

## 観るのはブラウザで

**録画一覧の行を押すと `/watch/<id>` が開き、その場で再生が始まります**
(番組表からは詳細の「再生」)。ほかに観られるのはテレビのアプリだけです ([下](#テレビのアプリ))。

エンコードしたものはブラウザがそのまま読めます (AV1 + Opus の Matroska は Chromium で
`canPlayType` が `probably` を返し、再生もシークも通る)。端末ごとに渡す先を用意する必要はありません。

|                       |                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 画面                  | 1000px から映像の右に番組の中身のサイドバー (長ければそこだけ巻き取る)。狭い画面では映像を端から端まで出し、番組の中身をその下に。折り畳み端末を机に置いたとき (テーブルトップ) は映像が上の段、中身が下の段 ([watch.md](watch.md#折り畳み端末を机に置いたとき))                                                                                                                                  |
| 開いたとき            | 指で触っている端末 (`pointer: coarse`) はそのまま全画面へ。抜けると上の「画面」の並び                                                                                                                                                                                                                                                                                                             |
| 押したとき            | マウスはどこを押しても再生/一時停止。指は操作バーの出し入れ (YouTube と同じ)                                                                                                                                                                                                                                                                                                                      |
| 左右の端を素早く 2 回 | 10 秒 戻す/送る。続けて押せばそのぶん重なる                                                                                                                                                                                                                                                                                                                                                       |
| チャプター送り        | CM 飛ばし。入っているときだけ出す                                                                                                                                                                                                                                                                                                                                                                 |
| シークバー            | 映像の上に重ねる細い半透明の溝。CM の区間は柔らかい琥珀で分け、観たぶんは濃い琥珀 (続いている CM は 1 本に。色は denpa-tv と同じ `#FFB300`)。本編の観たぶんは主の色。CM の端とそれ以外の切れ目 (引き継いだ録画の名前の付いたチャプター) で溝を 2px 区切る。マウスを載せた・触っている間だけ太くなり、つまみが出る。読み上げでは位置にチャプターの名前を添える (`SeekBar.svelte`・`seek-track.ts`) |
| CM を自動で飛ばす     | **既定でオン** (エンコードは CM を切らずにチャプターを打つだけなので、毎回ボタンを押さずに済むように)。選んだ値は端末ごとに覚える。ロゴでの判定に失敗した録画だけは、覚えていてもオフで始める (無音だけで当てていて外れやすく、外れると本編を飛ばす)。⚙ の「CM スキップ」で切り替える。CM のコマは 1 枚も出さない (下の「CM は 1 コマも見せない」)                                                |
| 削除                  | 観たその場で消せる。末尾はたいてい CM なので、流したまま押せる                                                                                                                                                                                                                                                                                                                                    |
| 字幕                  | 持っている録画でだけボタンが出る。既定で出す (ライブと同じ)。放送の字幕を放送どおりの置き場所で描くのでルビも出る                                                                                                                                                                                                                                                                                 |
| 続き                  | 途中で止めたところから始まる。端末をまたいでも続く (覚えるのはサーバ側)                                                                                                                                                                                                                                                                                                                           |
| 読み込み待ち          | **1.5 秒以上詰まったら輪を出す** (ライブ・追っかけと同じ幕 `PlayerVeil`。映っている映像は覆わない)。詰まりか壊れたかが見えないと待つか決められない。短い詰まりで出すと点滅するだけ                                                                                                                                                                                                                |
| 速さ                  | 1〜2 倍。選んだ値は端末ごとに覚える。残り時間も倍速のぶんを割って出す                                                                                                                                                                                                                                                                                                                             |
| 切り抜き              | いまの 1 コマを字幕・コメントごとサーバに保存する (下の「切り抜き」。字幕・コメントはあとから外せる)。PC はクリップボードにもコピーする (http で開いているときはしない)。送れなかったときだけ端末に保存する (`番組名_YYYYMMDD-HHMMSS.png`。スマホは共有シート)                                                                                                                                    |

操作バーとキー操作は [watch.md](watch.md#操作バー)、なぜそうしたかは [player.md](player.md)。

### CM は 1 コマも見せない

自動で飛ばすとき、**CM のコマは 1 枚も出しません。** ブラウザは先のコマを何枚かコンポジタへ
渡し終えているので、飛ぶ位置を先読みしても渡し済みのぶんは出ます。予測で消せないので隠します。

|            | やること                   | なぜ                                                                                                                                                                                                                                                               |
| ---------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 跨ぐ手前   | 0.1 秒 (3 コマ) 前に飛ぶ   | 入ってから飛ぶと必ず 1 コマ映る                                                                                                                                                                                                                                    |
| 飛ぶ直前   | そのコマを写して蓋にする   | 止めたコマのほうが飛んだように見える (黒は切れて見える)。写すのは本編にいるときだけ。CM の中で写せば蓋そのものが CM になる                                                                                                                                         |
| 観はじめ   | チャプターが届くまで黒い蓋 | チャプターは開いてから取得するので、揃うまで先頭の CM がそのまま流れていた                                                                                                                                                                                         |
| 着いたあと | 4 コマ数えてから外す       | `requestVideoFrameCallback` は「コンポジタへ渡した」ところで来て、画面に出るのはその先。さらに Windows の Chrome / Edge は映像を DOM とは別の面に出すので、蓋を外す更新が映像より先に画面へ出る (位置も章も本編なのに画面だけ CM のまま、という画面が実機で撮れた) |

飛ぶ先を正しくするのはエンコードするほうの仕事です。チャプターの時刻がずれていれば、
ここで何をしても CM の途中に着地します
([cm.md](cm.md#チャプターは--ss-と同じだけ詰める))。

**録り終えた録画はどれも `/watch` で観ます** (エンコードを待っている間も、失敗したものも)。
録っている最中のものは「いま」の線のすぐ上にいて、その行の「追っかけ」で追っかけ再生 (`/chase/<id>`) が開きます。録り終えるとその画面に
観る画面への案内が出ます。再生の印が消えるのは、消した録画と録画そのものが失敗したものだけです。

配信は `/api/recordings/<id>/file` (Range 対応。既定で返すものは [app.md](app.md#画面))。
`?source=` で名指しもできます。`ts` = 元の TS、`encoded` = エンコードしたものの主 (AV1 → H.265 → H.264 の先頭)、
`hevc` = H.265 (主でないとき)、`alt` = H.264 (主でないとき)。テレビのアプリと端末に保存も名指しします。再生のためのエンドポイントなので、
添付 (`Content-Disposition: attachment`) にはしません。

**録画をファイルとして外へ持ち出す機能 (ダウンロード) は持ちません。** エンコードした録画 (mkv) にはコピー制御の符号が
引き継がれないためです (元の TS は符号が
入ったまま保存していて、取り除いたり書き換えたりはしていません。[Discussion #760](https://github.com/danything/denpa/discussions/760))。
端末に保存 ([offline.md](offline.md)) は denpa の中だけで観るもので、こちらは残しています。

**観る画面はファイルを名指しします** (`?source=encoded`・`hevc`・`alt`。下)。エンコードしている最中に
名指しなしで開くと元の TS が返り、何も映りません。

### 何で観るかは、サーバが出せるものから画面が選ぶ

**分担: サーバは「何を出せるか・どの形式で出すか・時刻の物差し」を決め、画面は「どれを使うか」を決めます**
(端末で再生できるか、人が選んだコーデック)。サーバは端末の種類では決めません。開いたときに
`api/recordings/<id>/playback` を聞きます ([api.md](api.md#録画の観方-get-apirecordingsidplayback))。

| 録画にあるもの                                                                               | 出せるもの                                                                                                     |
| -------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| エンコード済み                                                                               | ファイルそのまま。読めない端末にはサーバが fMP4 に詰め替えて流す (映像は写すだけ。軽い)                        |
| エンコード済みと違うコーデックを選んだ                                                       | **エンコード済みを元に**サーバがその場で変換して流す                                                           |
| 元の TS だけ (エンコード前・失敗・「エンコードしない」)                                      | サーバが元の TS をその場で変換して流す                                                                         |
| 元の TS (v2.37 までに CM を切ってエンコードした録画と、捨てた先頭が分からない古い録画は除く) | MPEG-2 のまま流す (端末でデコードして canvas に描く。⚙ のコーデックで選ぶか、録画しか無いときは家の中の自動で) |
| 4K の局の元の録画 (`.mmts`) だけ                                                             | 放送の HEVC の詰め替えか、縮めて SDR にした変換 ([下](#4k-の局の録画))                                         |

画面の選び方 (`ts/playback.ts` の `pickOffer`): **そのまま読めるファイル** (`canPlayType` を Matroska と WebM で。
端末の名前では決めない) → **詰め替え** (MSE が受け取れるもの) → **変換** (家の中なら H.264 → AV1、外なら AV1 → H.264)。
**録画しか無い (エンコード済みが無い) ときは、ライブ・追っかけと同じ順** (家の中なら MPEG-2 → H.264 → AV1、外なら AV1 → H.264。
[stream.md](stream.md#どの形式で流すか))。MPEG-2 は互換モードと同じく canvas に描くので、速さは等速だけです。
エンコード済みがいくつもあれば、ファイルも詰め替えも **AV1 → H.265 → H.264** の順に、端末で観られる最初のもの
(小さいほうが回線を食わない)。H.265 はエンコード済みがあるときだけで、変換では作りません
([encode.md](encode.md#h265-は-gpu-でだけ))。互換モードも H.265 は描かず、AV1 か H.264 を使います。
コーデックのメニュー (この端末で観られる方式が 2 つ以上あるときだけ) で「自動」か AV1・MPEG-2 を選べ、
選んだものは端末ごとに覚えます。MPEG-2 は元の TS が残っていて、この端末でデコードできるときだけ並びます (エンコード済みがあっても選べる)。
H.264 と H.265 はメニューに並べません。自動では今までどおり選ぶので、AV1 を再生できない端末でも観られます (H.264 しか無ければサーバが変換する)。
前に H.264・H.265 を選んでいた端末は自動になります ([stream.md](stream.md#どの形式で流すか))。

**ファイルをそのまま読んでいるときの音声の切り替えは、ブラウザが入れ物の音声を出せるか次第です**
(`video.audioTracks`)。Chrome・Firefox は既定で出さないので、そのままでは 2 本目 (副音声・解説) を選べません。
そこで 2 本以上あれば `playback` の名前で並べ、2 本目を選んだら、いまの位置からその場で流すほうへ移ります
(`ts/playback.ts` の `streamForAudio`。同じコーデックの詰め替えを先に)。

**その場の変換には同時に走らせる本数の上限があります** (設定の「録画」の「同時に変換する本数」。既定は
[encode.md](encode.md#録画のその場の変換も同じエンコード方式本数に上限を置く))。埋まっていると
「サーバが混んでいます」と出し、サーバに変換させずに観られるコーデックがあればそれを勧めます。

**時刻の物差しは 1 ページで 1 つです。** エンコード済みがあればその時刻、無ければ元の TS の先頭を 0。
サーバはどの方式でもストリームの時刻をこれに乗せるので、続きの位置・CM 飛ばし・字幕・データ放送・速さは
`currentTime` のまま効きます。まだエンコードしていない録画は、チャプター (CM 飛ばし) を検出した区間
(`cm_ranges`。元の TS の先頭からの秒) から組み、字幕を元の TS から取り出します。データ放送は
エンコード済みの時刻で書いてあるので、エンコードするまで出しません。

|                                                     | その場で流しているとき                                                                                  |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| バー                                                | 最初から全長。飛んだ先が溜まっていなければ、そこからリクエストし直す (少し先へ送るぶんは届くのを待つ)   |
| 続き・字幕・チャプター・CM 飛ばし・データ放送・速さ | そのまま効く (先頭から観たときだけ数十 ms ずれる)                                                       |
| 音声の切り替え                                      | 選ぶと、いまの位置からリクエストし直す (流しているのは選んだ 1 本だけ)                                  |
| 端末に保存したもの                                  | 使わない。オフラインではそのまま渡し、読めなければ観られる先 (Chrome・Edge かテレビのアプリ) を案内する |
| 切れたとき                                          | 観ていた位置からリクエストし直す (待ちは倍々で 10 秒が頭打ち、続けて 8 回で諦める)                      |

**互換モード (再生画面の ⚙ の「互換モード」) では `<video>` を使いません。** 同じ `/stream` を fetch で読んで canvas に
描きます (H.264・AV1 の fMP4 か、元の TS の MPEG-2。速さは等速だけ)。端末に保存したものも、保存した Matroska を読んで canvas に描きます。
作りは [stream.md](stream.md#録画の観る画面も-canvas-に描く) に。

**iPhone の Safari は H.264 の録画をそのまま読めません** (#503)。Matroska を WebM としてしか読まず、
WebM に入れてよい映像は VP8 / VP9 / AV1 だけです (H.264 は開発者向けの設定の奥。WebKit の
`SourceBufferParserWebM`)。そこでサーバが詰め替えて MSE (`ManagedMediaSource`) に流します。
**対応は iOS 17.1 以降です** (iOS 16 までの iPhone は MSE の実装を持たないので、今までどおり
「このブラウザでは再生できませんでした」と出し、Chrome・Edge かテレビのアプリを案内する)。**実機 (iPhone) ではまだ確かめていません。**

ほかに読めなかったときも、そうと出して観られる先を案内します。

## 4K の局の録画

**4K の局 (ケーブルで受けた MMT/TLV の局) の録画は、1 局に絞った TLV のまま `.mmts` で置きます。** 画質を落とさずに残すためで、
TS の局の元の TS (`.m2ts`) と同じ考え方です。エージェントは形式を変換しません (録画は denpa が 1 局に絞るだけ。`recorder.ts` の `MmtServiceFilter`)。

- 置き場と名前は元の TS と同じで、拡張子だけが違う (`RAW_DIR` の `<シリーズ>-<録り始め>-<録画ID>.mmts`。「エンコードしない」なら置き場の `….mmts`)。
  形式は録画の行に持たず、拡張子から引く (`#lib/source.ts` の `recordedTransport`。拡張子は `RECORDED_EXT`)
- 1 時間で約 15 GB (1 局で約 33 Mbps。推定)。エンコードすると AV1 の 2160p・10bit・HLG になり、元の録画は今までどおり消す
  (設定の「元の TS も残す」なら残す。[encode.md](encode.md#4k-の局の録画))
- 録り始めの番組の情報の読み直し (p/f) と延長の追従は MH-EIT で読む (`PfEvent`・`MmtEpgReader`)。TS の録画が測る先頭の放送時刻 (`ts_head`) は測らない
  (MMT には PCR が無い)。実況のコメントは録り始める予定の時刻で合わせる
- コピー禁止は予約の時点で止める (番組表の MH-EIT のコンテンツコピー制御記述子。[data.md](data.md#コピー禁止の番組は録らない))。録っている最中には MPT から読まない (読み方を確かめていない)
- エンコードしない 4K の録画にはサムネイルが無い (ffmpeg が TLV を読めない)

**観るときは、denpa が `.mmts` を読んで fMP4 にします** (`server/mmts.ts`)。ffmpeg も ffprobe も TLV を読めません。

| 何で観るか                       | 出し方                                                                                                                                               |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 録っている最中 (追っかけ)        | ライブの 4K の局と同じ。放送のまま (H.265) は放送の HEVC と AAC の詰め替え、ほかは縮めて SDR にした変換 ([stream.md](stream.md#4k-の局のライブ))     |
| 録り終えて、エンコード済みが無い | 同じく、詰め替え (`stream?codec=hevc`。ffmpeg を起こさず、変換の枠も使わない) か変換 (`h264`・`av1`)。MPEG-2 は出さない                              |
| エンコード済みがある             | エンコード済みの AV1 (2160p・10bit・HLG) をそのまま。読めない端末と段を下げるときの変換は、縮めて SDR に直す (`playback.fileTranscodeArgs` の `hlg`) |

- 物差しは録画の先頭 (ファイルの最初の頭出しできる映像のコマの DTS) を 0 とした秒。字幕・チャプター・続きの位置もこれで数える
- 飛ぶときはバイト比例で当たりを付けて読み (`mmts.mmtsOffset`。追っかけの `chase.chasePlan` と同じ考え)、時刻は物差しのまま出す
- 自動の順は、MPEG-2 の場所に放送の HEVC の詰め替えが入る (家の中なら HEVC → H.264 → AV1、外なら AV1 → H.264。`PlaybackInfo.broadcast`)。
  詰め替えを再生できるかは、ライブの 4K の局と同じく `decodingInfo` で決める (`#lib/hevc-4k.ts`)
- 回線が足りないときは、ライブと同じ段の仕組みで AV1 か H.264 に下げる (4K の局は H.265 にエンコードしない。`live.liveRungCodec`)
- テレビのアプリ向けの一覧 (`GET /api/recordings` の `files`) には `.mmts` を並べない (アプリはそのまま読めない)。観るのは `playback` の `auto` から

**字幕は TTML から作ります。** エンコード済みが無ければ `.mmts` を丸ごと読んで文字の配置にし (`mmts.mmtsCaptions`。元の TS と同じく覚えない)、
エンコード済みがあれば、その隣に置いた文字の配置 (`….captions.json`) をそのまま渡します。Matroska には入れられないためです
([encode.md](encode.md#4k-の局の録画))。

実際の 4K の放送は ACAS でスクランブルされていて、どの局も復号できないので録画できません (予約もできない)。確かめたのは合成の素材と、
偽エージェントのスクランブルしていない 4K の局 (QC28。`65-catv.spec.ts`) だけです。

## 切り抜き

**観る画面・追っかけ・ライブで押した 1 コマ (出している字幕・実況のコメントごと) は、サーバに AVIF で置きます** (`ENCODED_DIR/clips/<年月>/<ID>.avif` と、
一覧用の幅 480 の `<ID>-small.avif`)。画面は映像を WebP (作れないブラウザは JPEG) で、字幕とコメントはそれぞれ透明な PNG で分けて送り、
サーバが ffmpeg で重ねて AVIF (SVT-AV1 の静止画) にします (1080 の 1 コマで数百 KB。画像として読めないものはここで断ります)。
受けた元の画像は `<ID>.src/` に残し、字幕・コメントをあとから出し入れするたびに元から重ね直します (AVIF から作り直さないので、
何度切り替えても崩れません)。開いた 1 枚の画面は元の画像を受け取って重ねて見せるので、切り替えは待たずに替わり、
作り直した AVIF は一覧・端末に保存・アプリで使います。使っている量には元の画像も入ります。字幕を重ねて 1 枚にしていた古い切り抜き (元の画像が無いもの) は今までどおりで、
出し入れはできません。番組名・局名・番組の始めからの位置・出していた字幕の文字は
撮ったときのものを DB に写すので、番組表が流れても、録画を消しても残ります (録画を消すと、その録画へ戻る先が無くなるだけ)。
自動では消しません。世帯で共有し、誰が撮ったかは持ちません。画像は他の API と同じ資格で開け (`Cache-Control: private`。添付にはしない)、
EXIF は書かず、まとめて書き出す機能もありません。置き場をエンコード済みの下にしたのは、既定の構成で残る置き場が
DB (`/data`) と元の TS・エンコード済みだけだから (`MEDIA_DIR` そのものはボリュームではない) で、置き場を別のディスクに移すときも録画と一緒に写ります。
並べる画面は `/clips` ([screens.md](screens.md#切り抜き))、API は [api.md](api.md#切り抜き-post-apiclips)。

## テレビのアプリ

**ブラウザのほかには、テレビのアプリで観られます** ([danything/denpa-tv](https://github.com/danything/denpa-tv))。
Android TV / Fire TV でライブと録画を観られます (続きから・CM 飛ばし・低遅延のライブ)。家の外からは QR で繋いで
アクセストークンで入ります ([auth.md](auth.md#アプリのペアリング))。

外部のプレイヤー (VLC など) には対応しません。XSPF などの出力も、ログインせずに開ける URL を渡す仕組みもありません。

### 再生リンクをやめた (前のバージョンから上げるとき)

**「再生リンクをコピー」と、それが作っていた期限付きの URL (`/api/recordings/<id>/file?token=…`) をやめました。**

- 出したリンクは、上げた時点で開けなくなる (期限内でも)。テーブル (`share_links`) はマイグレーションで消える
  (`drizzle/0011_drop-share-links.sql`)。リンクを作る API (`POST /api/recordings/<id>/share`) も無くした
- ファイルのエンドポイントを資格なしで呼んだときの答えを、403 (text/plain) から、ほかの API と同じ 401 の JSON に
  した (ログイン方法を何も設定していない denpa は、これまでどおり 403)
- テレビのアプリ (denpa-tv) はアクセストークンで開くので、何もしなくてよい

## 字幕はどこから出るか

**入れ物の中の、放送の ARIB 字幕 (`S_ARIBSUB`) です** (隣に字幕のファイルは置かない)。denpa の観る画面はサーバでデコードして
文字の配置で渡し、ブラウザが描きます (ライブと同じ。`api/recordings/<id>/captions.json`)。字幕の入れ方は
[encode.md](encode.md#字幕は放送の-arib-字幕をそのまま) に。
4K の局の録画だけは、TTML を文字の配置にしたものを隣に置きます (`….captions.json`。[上](#4k-の局の録画))。

## 誰が取れるか

**ファイルのエンドポイントは、画面と同じ資格で開けます** (信頼するネットワーク・ログインの控え・アクセストークン)。
観る画面の `<video>` も端末に保存も同じ URL にそのままリクエストして、URL に資格情報は埋めません。
決まりごとと理由は [auth.md](auth.md) に。

## 削除

**denpa の画面から**消します (押し間違い防止に 2 回押し)。自動削除はありません。
denpa を通さずに消されたものは `RECONCILE_INTERVAL` (既定 5 分) ごとの突き合わせで見つけます
(すぐなら「ファイルと照合」)。

**見るのは両方向です。** 実体の無い行だけでなく、動画が無くなった付属ファイル
(サムネイル・`.bml.jsonl`・`.chapters.txt` などの作業ファイル) と空フォルダも
片付けます。付属ファイルは動画と同じ名前で隣に置くので、名前でどの動画のものか分かります
(元の TS を残さない設定だと、付属ファイルだけが録るたびに積もるため)。
落ちたエンコードの作業ファイル (`<名前>.<jobId>.<codec>.encoding` とその `.post` など、名前にジョブ ID を持つもの) は、
同じ名前の動画が残っていても、そのジョブが走っていなければ片付けます (再エンコードで落ちると、置き換える前の動画が残るため)。

動画そのものには触りません。行の無い動画は手で置いたものかもしれないので、数えるだけです。

> [!NOTE]
> inotify (`fs.watch`) は、この構成 (bun + vite dev) では最初の 1 件しかイベントが来ず
> 当てにできないので、定期実行のままです。

## 通知

録画の節目を Webhook で外に送れます。設定の「連携」の「通知」に Discord や Slack の
Incoming Webhook の URL をそのまま入れられます。

- 録画開始 / 録画完了 / 録画失敗 / エンコード完了 / エンコード失敗、および録画の外側の
  変事 (ディスク残量わずか / チューナーエージェント切断 / チューナーエージェント復帰 / チャンネルの変更)。選ばなければ全部
  (種類は `src/lib/webhook-events.ts`)
- 「同じ回は最初の放送だけ」のルールの予約は、録り始めに同じ回かを見直してから録画開始を送ります (番組の EIT[p/f] を最大 15 秒待つ)。
  同じ回と分かってやめた録画には送りません ([data.md](data.md#同じ回は最初の放送だけ録る))
- Discord の URL には、Discord が読む `content` に本文だけを入れて送ります。2000 字を超える分は切り詰め、
  `@everyone` などのメンションは効かせません。ほかの通知先には `text`・`event`・`recording` などを JSON で送ります
- **送信は結果を待たない**。通知先が遅くても録画を止めないよう、10 秒で打ち切って結果だけ
  記録します。直近の結果は同じ節に出ます
- 通知先は LAN の中 (自宅の Home Assistant など) でも構いません。**リダイレクトは追わず**、
  結果に残すのは HTTP のステータスコードだけです (相手の本文は残しません)。ログには URL ではなくホストだけを出します
- 通知先の追加・切り替え・削除・テスト送信はブラウザからだけです。テレビのアプリのアクセストークンでは断ります (403。[auth.md](auth.md#アプリのペアリング))
- 録画の失敗は画面を開くまで気づけないので、せめて失敗だけでも入れておくのを勧めます
