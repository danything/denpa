# 録画の置き場と配り方

**焼き上がったものをどこに置き、どう配るか。** 保存先の形、認証、削除、
録れたことの知らせまで。

| 探しもの | 見る場所 |
| --- | --- |
| 全体像 | [architecture.md](architecture.md) |
| 焼き方そのもの | [encode.md](encode.md) |
| ホーム画面に置く・ライブ視聴 | [player.md](player.md) |

```text
/library/
└── テストアニメ/
    ├── tvshow.nfo                                     ← シリーズ情報
    └── Season 2026/
        ├── テストアニメ - 2026-08-01 - 2130 決戦.mkv
        ├── テストアニメ - 2026-08-01 - 2130 決戦.nfo       ← 番組名・概要・放送日・放送局
        └── テストアニメ - 2026-08-01 - 2130 決戦-thumb.jpg ← サムネイル
```

日本の番組は話数が無い/リセットされるものが多く SxxExx に落とせないため、
**日付ベースのエピソード**として並べています。同じ分に別の録画がぶつかったときだけ
`… [39].mkv` のように録画IDを足します。

**コーデックを両方選ぶと、1本の録画が2ファイルになります** (`… .mkv` = AV1、
`… [H264].mkv` = H.264)。同じフォルダに並ぶので、フォルダを辿るプレイヤー
(Nova など) には1話が2エントリで出ます — 古いテレビでは名前で分かる H.264 の
ほうを選びます。どちらも Matroska (mp4 は PGS 字幕を持てない)。主 (再生・
ダウンロードで既定に使うほう) は AV1 で、DBの `library_path`、もう一方は
`alt_path`。片方を消したときは**消したものだけ**を消し、主を消したら残ったほうを
主に繰り上げます (照合も WebDAV の削除も同じ)。**自分がいま置いてあるファイルは衝突と
数えません** — 見ずに「あるかどうか」だけで決めていた頃は、焼き直すたびに素の名前と
ID付きを行き来していました (置き換えたあと古いほうを消すので、次はまた素の名前が空く)。

**名前を決めるのは、焼き上がってから**です。焼き始めに決めていた頃は、同じ番組を
2本同時に焼くと**どちらも「空いている」と見て同じ名前を選び**、作業ファイル
(`.encoding`) まで共有して**2つの ffmpeg が1つのファイルに書き込みました**。片方は
最後の置き換えで `ENOENT`、残ったほうは中身が壊れています (実機。復号すると145行の
エラーが出て、焼き直したものは0行)。いまは作業ファイルにジョブIDを入れ、置き場所は
置く直前に決め直します。

**焼き直すときは、始める前に前のものを消します。** 出来上がるまで別名 (`.encoding`) に
書くので、消さないと焼いている間ずっと同じ番組の mkv が2本ぶん場所を取ります。
**画面に出ている大きさより実際の使用量が多い**のは外から見て分かりません。
元は生TSで、これとは別のファイルなので消しても焼き直せます。引き換えに、失敗したり
途中でやめたりするとその間は保存先に何も無くなりますが、生TSは残っているので
もう一度押せば戻ります (その間の再生とダウンロードは生TSのほうを返します)。

このとき **DBの `library_path` も一緒に空けます。** 残したままだと実体との照合が
「保存先から消えていました」と読んで**録画ごと削除済みに倒し、生TSまで消します**。

## 観るのはブラウザで

**録画一覧の行を押すと `/watch/<id>` が開き、その場で再生が始まります**
(番組表からは詳細の「再生」)。**外部プレイヤーへ渡す口 (`denpa://`) は廃止しました。**

**焼いたものはブラウザがそのまま読めます。** AV1 + Opus の Matroska は
Chromium で `canPlayType` が `probably` を返し、実機の録画で再生も**シークも**
通ることを確かめました。渡す先を端末ごとに用意する理由が無くなったので、
Windows/Mac も Android も iOS も、端末ごとに用意していた渡し口はまとめて落としました。

| | |
| --- | --- |
| 画面 | **タブレット以上は2段組** (左に番組の中身、右に映像)。狭い画面では映像が上 |
| 開いたとき | 指で触っている端末 (`pointer: coarse`) は**そのまま全画面**へ。抜けると2段組 |
| 押したとき | マウスは**どこを押しても再生/一時停止**。指は操作列の出し入れ (YouTube と同じ) |
| 左右の端を素早く2回 | **10秒 戻す/送る。** 続けて押せばそのぶん重なる |
| チャプター送り | **CM飛ばし。** 入っているときだけ出す |
| 削除 | **観たその場で消せる。** 末尾はたいてい CM なので、流したまま押せる |
| 字幕 | **持っている録画でだけ**ボタンが出る。最初は消えている (テレビと同じ)。**ルビも出る** |
| 続き | **途中で止めたところから始まる。** 端末をまたいでも続く (覚えるのはサーバ側) |
| 速さ | 1〜2倍。**選んだ値は覚える** (端末ごと)。残り時間も倍速のぶんを割って出す |
| 切り抜き | **いまの1コマを字幕ごとクリップボードへ。** 貼れない繋ぎ (http) では落とす |
| 番組の中身 | **左に出たまま。** 長ければそこだけが巻き取られ、押すものは常に見えている |

**観られるのは焼いたものだけです。** 生TSは MPEG-2 で、ブラウザに復号器が
ありません ([stream.md §5.5](stream.md#55-放送そのままmpeg-2は出せない))。
焼き上がるまでの録画と、エンコードに失敗した録画には再生の印を出しません —
落として手元のプレイヤーで観てください。

> **Safari では観られないはずです。** Matroska を扱えず、AV1 も新しい機材しか
> 持っていません。読めなかったときは、そうと出してダウンロードの口を添えます。

配信は `/api/recordings/<id>/file`。Range に対応しているのでプレイヤー側から早送り
できます (どのファイルを返すかは [app.md](app.md#画面))。

**どちらを寄越すかを名指しもできます** — `?source=ts` で生TS、`?source=encoded` で
焼いたほう。「生TSも残す」で録ると両方が手元に残るので、詳細のダウンロードは
**口を2つ**出します (「エンコード済み」と「生TS」)。1つしか出していなかった頃は
寄越されるのは焼いたほうだけで、画質を落としていない元には手が届きませんでした。
片方しか無い録画と焼いている最中はいままでどおり1つだけです (焼いている間の配信は
生TSのほうなので、2つ並べると押した先が同じものになります)。**観る画面は
`?source=encoded` と名指しします** — 焼いている最中に開かれると、名指ししなければ
生TSが返ってきて何も映りません。

**手元のプレイヤーから観るときは Nova Video Player を想定しています。** `/dav` を
**WebDAV サーバー**として追加すると、フォルダ構成そのままで開けます (Android TV や
Fire TV でも同じです)。

**相手を1つに絞っているのは、確かめる先を増やさないためです。** denpa が外に
出しているのは3つだけで、Nova はその全部を持っています — **WebDAV**
(HTTP/HTTPS)、**Kodi 仕様の `.nfo`**、そして**入れ物の中の PGS 字幕**。
どれか1つでも欠ける相手を並べると、字幕か番組情報のどちらかが「出る相手と
出ない相手」に割れます。
`.nfo` とサムネイルが動画の隣にあるので番組名・概要・放送局・サムネイルも出ます。
**削除も受けます**(denpa の画面から消したときと同じ道を通るので、DBもすぐ揃います)。
消せるのは denpa が知っている録画だけで、フォルダごとや手で置いたファイルは断ります。
置く側 (PUT / MKCOL / COPY / MOVE) は受けません。

## 字幕はどこから出るか

**入れ物の中の、放送どおりに描いた絵 (PGS) だけです。** 隣に置く付き添いは
ありません。

| 観るところ | どこから |
| --- | --- |
| denpa の観る画面 | 入れ物の中の PGS を抜いて渡し、**ブラウザが解いて重ねる** (ライブと同じやり方) |
| Nova | 入れ物の中の PGS をそのまま |

**絵なのは、そこだけが放送どおりだからです。** 一度は文字に直して `<track>` へ
渡す道も、文字の写しを動画の隣に置く道も通しましたが、左右の位置も、背景の箱も、
外字も、ルビも落ちました。絵にはそれが全部入っています。

> **既にある録画でもそのまま出ます。** 絵は焼いたものの中に最初から入っていて、
> 観るときに抜いています (実測 0.1〜1秒)。焼き直しは要りません。

## ベーシック認証

ファイルを取りに来るプレイヤーはリダイレクト型の認証を扱えないので、**その口は
ベーシック認証**で守ります (OIDC で入った画面のぶんはログインの控えも受けます。
[auth.md](auth.md#ファイルの口はログインの控えも受ける))。**無ければ起動時に作る**ので、何も設定しなくても
掛かった状態で上がります。決まりごとは [auth.md](auth.md) にまとめてあります。

- **ユーザー名は `denpa` 固定**。変えられるようにしていましたが、変えて嬉しいことが
  無いのに、忘れると登録済みの端末が全部つながらなくなるだけでした
- パスワードは**画面にそのまま出します**。プレイヤーに入れるときに要るものを
  隠していると、思い出せないたびに作り直すことになります。「作り直して保存」を
  押すと、URLに埋めても壊れない文字だけで24文字作って、そのまま保存します
- **掛かる範囲は選べません。** 掛けたら全部に掛かり、OIDC を設定してあるところだけ
  画面をそちらに譲ります

ダウンロードの URL には資格情報を埋め込みます (`http://user:pass@.../file`)。
ブラウザはページの認証をダウンロードに引き継がず、プレイヤーに貼るときも
ダイアログを出せないためです。**画面にも認証が掛かっている**ので、URL の中の
パスワードが見えるのは中に入れている人だけです。

> **観るときは埋めません。** `<video>` は同じ元 (origin) から取りに行くので、
> ブラウザが自分で資格情報を付けます。**OIDC で入った人だけは持っていない**ので、
> ファイルの口はログインの控えも受けるようにしてあります (`auth.sessionMayRead`)。
> そうしないと、映像を出そうとした瞬間にブラウザの認証ダイアログが立ちます。

## 削除

**denpa の画面から**行います(押し間違い防止に2回押させます)。自動削除はありません。

**WebDAV 経由の削除**も同じ扱いで、消した時点で一覧に反映されます。

ファイルマネージャなど denpa を通さずに消された場合だけは気づけないので、
`RECONCILE_INTERVAL`(既定5分)ごとの突き合わせで拾います。すぐ反映したいときは「実体と照合」。

**見るのは両方向です。** 「行はあるが実体が無い」だけでなく、その逆も掃きます。
付き添い (`.nfo` / サムネイル / `.dtvi` / `.sup` などの作業ファイル) は**動画と同じ名前で
隣に置く**決まりなので、名前だけで連れ合いが分かります。実機では生TSの置き場に
`.dtvi` (chapter_exe と logoframe が作る索引、1本3MB) が9本 22MB 残っていました —
生TSを残さない設定だと TS が消えたあとも索引だけが居座り、録るたびに積もります。
空フォルダも一緒に片付けます。

**動画そのものには触りません。** 行の無い動画は手で置いたものかもしれないので、
**数えるだけ**にして、消すかどうかは人が決めます。

> inotify (`fs.watch`) で消した瞬間に拾えないか試しましたが、この構成 (bun + vite dev) では
> **最初の1件しかイベントが来ず**当てにできなかったので定期実行のままにしています。

## 通知

録画の節目を Webhook で外に飛ばせます。設定画面から追加してください(Discord や Slack の
Incoming Webhook の URL をそのまま入れられます)。

- 録画開始 / 録画完了 / 録画失敗 / エンコード完了 / エンコード失敗。選ばなければ全部
- **送信は投げっぱなし**です。通知先が遅いせいで録画が止まるほうが困るので、10秒で
  打ち切って結果だけ記録します。直近の結果は設定画面に出ます
- 録画の失敗は画面を開くまで気づけないので、**少なくとも失敗だけでも**入れておくのを勧めます
