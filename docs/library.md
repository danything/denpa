# 録画の置き場と配り方

**焼き上がったものをどこに置き、どう配るか。** 保存先の形、認証、削除、
録れたことの知らせまで。

焼き方そのものは [encode.md](encode.md)、外から一覧を引く口は [api.md](api.md)。

```text
/media/encoded/                 ← ENCODED_DIR
└── テストアニメ/
    ├── テストアニメ - 2026-08-01 - 2130 決戦.mkv
    ├── テストアニメ - 2026-08-01 - 2130 決戦-poster.jpg ← サムネイル (一覧の絵)
    └── テストアニメ - 2026-08-01 - 2130 決戦.bml.jsonl  ← データ放送 (持っている録画だけ)
```

**番組情報はDBが持ち、denpa の画面が出します。** 隣に置くのはサムネ
(`-poster.jpg`、一覧と詳細の絵) と、データ放送の変化ログ (`.bml.jsonl`) だけ。変化ログは
焼くときに生TSから取り出し、観る画面の d ボタンが再生位置に合わせて流し直します
(`server/recorded-bml.ts`)。シリーズ名のフォルダにまとめるのはディスク上で見やすくするためで、
同じシリーズ・同じ分に別の録画がぶつかったときだけ `… [39].mkv` のように録画IDを足します。

> 昔のレイアウト (`Season 年/` + `.nfo` + `-thumb.jpg`。WebDAV 越しのプレイヤー向け) は、
> 起動時にいまの形へ移して `.nfo` も片付けます (`server/relayout.ts`)。

**コーデックを両方選ぶと、1本の録画が2ファイルになります** (`… .mkv` = AV1、
`… [H264].mkv` = H.264。mp4 は ARIB 字幕を持てないので、どちらも Matroska)。主 (再生・
ダウンロードの既定) は AV1 で DB の `library_path`、もう一方は `alt_path`。ポスターは
両方の隣に置きます。外から片方を消されたら、実体との照合 (`files.reconcile`) が
消えたほうだけを外し、主なら残ったほうを繰り上げます (一覧の絵は途切れない)。
自分がいま置いてあるファイルは衝突と数えません。数えていた頃は、焼き直すたびに
素の名前と `[ID]` 付きを行き来していました (`library.libraryPath`)。

**名前を決めるのは、焼き上がってから**です。焼き始めに決めていた頃は、同じ番組を
2本同時に焼くと同じ名前と作業ファイル (`.encoding`) を選び、2つの ffmpeg が
1つのファイルに書き込みました (実機。片方は `ENOENT`、残ったほうは復号すると145行の
エラー。焼き直したものは0行)。いまは作業ファイルにジョブIDを入れ
(`<名前>.<jobId>.<codec>.encoding`)、置き場所は置く直前に決め直します。

**焼き直すときは、始める前に前のものを消します** (DB の `library_path`/`alt_path` も空ける)。
出来上がるまで別名 (`.encoding`) に書くので、消さないと焼いている間は mkv が
2本ぶん場所を取り、画面に出る大きさより使用量が多いことが外から分かりません。
元の生TSは別にあるので、失敗・中止してももう一度押せば戻ります (その間の再生と
ダウンロードは生TSを返す)。DB を空けずに残すと、実体との照合が「保存先から消えた」と読んで
録画ごと削除済みに倒し、生TSまで消します。

## 観るのはブラウザで

**録画一覧の行を押すと `/watch/<id>` が開き、その場で再生が始まります**
(番組表からは詳細の「再生」)。外部プレイヤーへ渡す口 (`denpa://`) は廃止しました。

焼いたものはブラウザがそのまま読めます。AV1 + Opus の Matroska は
Chromium で `canPlayType` が `probably` を返し、実機の録画で再生もシークも通ったので、
端末ごとに渡す先を用意する理由が無くなりました。

| | |
| --- | --- |
| 画面 | タブレット以上は2段組 (左に映像、右に番組の中身)。狭い画面では映像が上 |
| 開いたとき | 指で触っている端末 (`pointer: coarse`) はそのまま全画面へ。抜けると2段組 |
| 押したとき | マウスはどこを押しても再生/一時停止。指は操作列の出し入れ (YouTube と同じ) |
| 左右の端を素早く2回 | 10秒 戻す/送る。続けて押せばそのぶん重なる |
| チャプター送り | CM飛ばし。入っているときだけ出す |
| CMを自動で飛ばす | **既定で入っている** (切らずに焼いた録画で毎回ボタンを押さずに済むように)。選んだ値は端末ごとに覚える。ロゴでの判定に失敗した録画だけは、覚えていても切って始める (無音だけで当てていて外れやすく、外れると本編を飛ばす)。押せばその場で入る。CM のコマは1枚も出さない (下の「CM は1コマも見せない」) |
| 削除 | 観たその場で消せる。末尾はたいてい CM なので、流したまま押せる |
| 字幕 | 持っている録画でだけボタンが出る。既定で出す (ライブと同じ)。放送の字幕を放送どおりの置き場所で描くのでルビも出る |
| 続き | 途中で止めたところから始まる。端末をまたいでも続く (覚えるのはサーバ側) |
| 読み込み待ち | **0.4秒 以上詰まったら輪を出す。** 詰まりか壊れたかが見えないと待つか決められない。短い詰まりで出すと点滅するだけ |
| 操作列 | 触らないでいると引っ込む。止めていても同じ (2.5秒)。マウスは動かせば、指は押せば戻る。理由は [player.md](player.md#操作まわりは3画面で共通) |
| 画面の明るさ | 止めている間も暗くさせない (同上) |
| 速さ | 1〜2倍。選んだ値は端末ごとに覚える。残り時間も倍速のぶんを割って出す |
| 切り抜き | いまの1コマを字幕ごと PNG に (`番組名_YYYYMMDD-HHMMSS.png`)。スマホは共有シート (写真へ保存)、PC は落としてクリップボードにも置く (貼れない繋ぎ (http) では落とすだけ) |
| 番組の中身 | 右に出たまま。長ければそこだけ巻き取られる |

### CM は1コマも見せない

自動で飛ばすとき、**CM のコマは1枚も出しません。** ブラウザは先のコマを何枚か合成器へ
渡し終えているので、跳ぶ位置を先読みしても渡し済みのぶんは出ます。予測で消せないので隠します。

| | やること | なぜ |
| --- | --- | --- |
| 跨ぐ手前 | 0.1秒 (3コマ) 前に跳ぶ | 入ってから跳ぶと必ず1コマ映る |
| 跳ぶ直前 | そのコマを写して蓋にする | 止め絵のほうが跳んだように見える (黒は切れて見える)。写すのは本編に居るときだけ。CM の中で写せば蓋そのものが CM になる |
| 観はじめ | チャプターが届くまで黒い蓋 | チャプターは開いてから取りに行くので、揃うまで頭の CM がそのまま流れていた |
| 着いたあと | 4コマ数えてから外す | `requestVideoFrameCallback` は「合成器へ渡した」ところで来て、画面に出るのはその先。さらに Windows の Chrome / Edge は映像を DOM とは別の面に出すので、蓋を外す更新が映像より先に画面へ出る (位置も章も本編なのに画面だけ CM のまま、という絵が実機で撮れた) |

跳ぶ先を正しくするのは焼くほうの仕事です。チャプターの時刻がずれていれば、
ここで何をしても CM の途中に着地します
([encode.md](encode.md#チャプターは--ss-と同じだけ詰める))。

**`/watch` で観られるのは焼いたものだけです。** 生TSは MPEG-2 で、ブラウザに復号器が
ありません (ライブだけは WASM の復号器で生のまま見られる。[stream.md §5.5](stream.md#55-放送そのままmpeg-2を送る))。
焼き上がる前は、録画中も CM検出やエンコードを待っている間も、行を押すと
追っかけ再生 (`/chase/<id>`) が開き、サーバが焼き直して頭から観られます
(エンコードに失敗した録画も生TSは無事なので同じ)。焼き上がるとその画面に
観る画面への案内が出ます。再生の印が消えるのは、消した録画と録画そのものが失敗したものだけです。

配信は `/api/recordings/<id>/file` (Range 対応。既定で返すものは [app.md](app.md#画面))。
`?source=` で名指しもできます。`ts` = 生TS、`encoded` = 焼いたもの (両方焼いたときは AV1)、
`alt` = もう一方 (H.264)。詳細の「その他…」のダウンロードは、残っているぶんだけ口を分けて
出します (「ダウンロード (AV1)」または「(エンコード済み)」、「(H.264)」「(生TS)」)。1つだけだと
画質を落としていない元に手が届かなかったためです。焼いている最中は配信が生TSに切り替わるので、
1つだけにします。**観る画面は `?source=encoded` と名指しします** (AV1 を解けない端末では
`alt` のこともある。下)。焼いている最中に
名指しなしで開くと生TSが返り、何も映りません。

### そのまま読めないブラウザでは詰め替えて流す

**iPhone の Safari は H.264 の録画をそのまま読めません** (#503)。Matroska を WebM としてしか
読まず、WebM に入れてよい映像は VP8 / VP9 / AV1 だけです (H.264 は開発者向けの設定の奥。
WebKit の `SourceBufferParserWebM`)。AV1 の録画は、AV1 を解ける機材 (iPhone 15 Pro 以降) ならそのまま出ます。

そこで観る画面は、開いたときにファイルの中身を聞き (`api/recordings/<id>/media`)、ブラウザに
読めるか尋ねます (`canPlayType` を Matroska と WebM で。端末の名前では決めない)。読めなければ、
**サーバで fMP4 に詰め替えて MSE に流します** (`api/recordings/<id>/remux`。映像は焼き直さず写し、
音声だけ Opus → AAC)。両方焼いた録画で AV1 を解けない端末は、H.264 のほうを詰め替えます。

| | 詰め替えたとき |
| --- | --- |
| バー | 最初から全長。跳んだ先が溜まっていなければ、そこから頼み直す (少し先へ送るぶんは届くのを待つ) |
| 続き・字幕・チャプター・CM 飛ばし・データ放送・速さ | そのまま効く。流れの時刻はファイルの時刻のまま (頭から観たときだけ数十ms ずれる) |
| 音声の切り替え | 選ぶと、いまの位置から頼み直す (流しているのは選んだ1本だけ) |
| 端末に保存したもの | 使わない (そのまま読めないのは同じ)。オフラインではそのまま渡し、読めなければ落とす口を出す |
| 切れたとき | 観ていた位置から頼み直す (待ちは倍々で10秒が頭打ち、続けて8回で諦める) |

**対応は iOS 17.1 以降です** (`ManagedMediaSource` が要る)。iOS 16 までの iPhone (iPhone X 以前) は
MSE の器を持たないので、今までどおり「このブラウザでは再生できませんでした」とダウンロードの口を出します。
**実機 (iPhone) ではまだ確かめていません。** Chromium の MSE で、続きから始める・遠くへ跳ぶ・
少し送る・戻る・音声の切り替え・末尾まで観る、を確かめてあります。

**2027-09 以降に外します** (この詰め替えの道ごと)。AV1 を解けない iPhone (無印の 15 まで) は
2025-09 で売られなくなり、その2年後には AV1 で焼けば済むと見ています。

ほかに読めなかったときは、そうと出してダウンロードの口を添えます。

## 手元のプレイヤーで観る

**プレイヤーにフォルダを漁らせず、denpa が URL を渡して再生だけを頼みます。** 以前の
WebDAV (`/dav`) + `.nfo` + Nova は、プレイヤー側の制約 (WebDAV 越しだと隣のポスターを
探さない等) を動かせないのでやめました。道は2つ:

- **テレビのアプリ** ([danything/denpa-tv](https://github.com/danything/denpa-tv))。Android TV / Fire TV で
  ライブと録画を観られます (続きから・CM 飛ばし・低遅延のライブ)。家の外からは QR で繋いでアプリの鍵で入ります
  ([auth.md](auth.md))
- **再生リンク**。録画詳細の「その他…」→「再生リンクをコピー」で 24時間で切れるURL
  を取り、どのプレイヤーにも貼れます (`server/share.ts`)。形は
  `/api/recordings/<id>/file/<番組名>.mkv?token=…` (生TSなら `.m2ts`)。尻の番組名は、
  VLC などのプレイヤーが URL の最後の区切りを再生画面の見出しにするため (入れ物の title は履歴と
  通知にしか出ない。サーバは読み捨てる)。見出しはこれしか出ないので、`[字]` `[デ]` などの
  記号は残します (`title.ts` の `markedTitle`)。パスワードは入れません。プレイヤーは URL を
  履歴に残すので、恒久の資格情報を他人の機器に置いてこないためです。
  - 途中まで観たものを続きから始めさせたいプレイヤー向けに、続きの位置 (`vlc:option` の `start-time`) を
    書いた XSPF もあります (`/api/recordings/<id>/playlist/<番組名>.xspf`、`server/playlist.ts`)。
    中身は取りに来たときに作るので、履歴の同じ URL でもそのときの続きから

VLC は AV1・Opus・Matroska を自前で解きます (AV1 非対応の
Fire TV でも dav1d のソフトデコードで滑らか)。

## 字幕はどこから出るか

**入れ物の中の、放送の ARIB 字幕 (`S_ARIBSUB`) です** (隣に付き添いは置かない)。denpa の観る画面はサーバで解いて
文字の配置で渡し、ブラウザが描きます (ライブと同じ。`api/recordings/<id>/captions.json`)。ずっと前に焼いた録画は
絵 (PGS) が入っていて、そちらはもう読みません (字幕が出ない。生TSが残っていれば焼き直すと出る)。入れ方は [encode.md](encode.md#字幕は放送の-arib-字幕をそのまま) に。

## 誰が取れるか

**ファイルの口は期限付きリンク (`?token=`、24時間) で開けます。** ダウンロードも押されてから
同じリンクを作ります (資格情報を URL に埋めていた頃は、パスワードがダウンロード履歴に
残り続けた)。観る画面はログインの控えで通ります。決まりごとと理由は [auth.md](auth.md) に。

## 削除

**denpa の画面から**消します (押し間違い防止に2回押し)。自動削除はありません。
denpa を通さずに消されたものは `RECONCILE_INTERVAL` (既定5分) ごとの突き合わせで拾います
(すぐなら「ファイルと照合」)。

**見るのは両方向です。** 実体の無い行だけでなく、連れ合いを失った付き添い
(サムネイル・`.bml.jsonl` などの作業ファイル、昔の `.sup` `.nfo`) と空フォルダも
掃きます。付き添いは動画と同じ名前で隣に置くので、名前で連れ合いが分かります。
実機では生TSの置き場に、以前の CM検出の道具 (chapter_exe) の索引が9本 22MB 残っていました。
生TSを残さない設定だと付き添いだけが居座り、録るたびに積もります。
いまは作りませんが、**生TSを残している録画の隣の `.dtvi` は連れ合いがいるので残ります** (要らなければ手で消せます)。

動画そのものには触りません。行の無い動画は手で置いたものかもしれないので、数えるだけです。

> inotify (`fs.watch`) は、この構成 (bun + vite dev) では最初の1件しかイベントが来ず
> 当てにできないので、定期実行のままです。

## 通知

録画の節目を Webhook で外に飛ばせます。設定画面で Discord や Slack の
Incoming Webhook の URL をそのまま入れられます。

- 録画開始 / 録画完了 / 録画失敗 / エンコード完了 / エンコード失敗、および録画の外側の
  変事 (ディスク残量わずか / チューナーエージェント切断 / チューナーエージェント復帰)。選ばなければ全部
  (種類は `src/lib/webhook-events.ts`)
- **送信は投げっぱなし**。通知先が遅くても録画を止めないよう、10秒で打ち切って結果だけ
  記録します。直近の結果は設定画面に出ます
- 録画の失敗は画面を開くまで気づけないので、せめて失敗だけでも入れておくのを勧めます
